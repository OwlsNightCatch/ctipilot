    Adobe fixes unauthenticated CVSS 10.0 flaws in ColdFusion, Experience Manager and Commerce; no exploitation known

    first published 2026-10-14 03:41 UTCupdated 2026-10-16 04:13 UTC

    Defender actions

    • Update every internet-facing ColdFusion server to 2025.0.14 or 2023.0.26, every AEM instance to Cloud Service 2026.9.28386 or the per-issue hotfixes for 6.5 Service Pack 25 and 6.5 LTS Service Pack 3, and Adobe Commerce and Magento Open Source to the 2026-oct build of the installed 2.4.x line (together with the CVE-2026-75650 hotfix from the September APSB26-146 update where it is missing); on a Composer-installed Commerce or Magento store apply the 2026-oct release or Adobe's isolated patch explicitly, because the base version stays vulnerable; Magento Open Source 2.4.6 has no listed fix.

    Analysis

    Adobe's 2026-10-13 bulletins put critical fixes into three server products: ColdFusion, Experience Manager and Commerce. Adobe says it is not aware of any exploits in the wild for the ColdFusion issues (Adobe ColdFusion APSB26-144, 2026-10-13). ColdFusion 2025 up to 2025.0.13 and 2023 up to 2023.0.25 are affected and 2025.0.14 and 2023.0.26 fix them; the bulletin lists five network flaws that need no privileges at CVSS 9.0 or above: an unrestricted file upload leading to arbitrary code execution (CVE-2026-105899, 10.0), a server-side request forgery rated privilege escalation (CVE-2026-106622, 10.0), an input-validation flaw leading to code execution (CVE-2026-106624, 9.8), a code injection rated privilege escalation (CVE-2026-106621, 9.1) and a further input-validation code-execution flaw (CVE-2026-106619, 9.0, high complexity), besides code-execution flaws that need a low-privileged account at 9.9 (Adobe ColdFusion APSB26-144, 2026-10-13).

    Experience Manager APSB26-152 covers Cloud Service 2026.9.28187 and earlier, 6.5 up to Service Pack 25 and 6.5 LTS up to Service Pack 3: three incorrect-authorization flaws that lead to arbitrary code execution are scored 10.0 with no privileges required (CVE-2026-90532, CVE-2026-48383, CVE-2026-48382), fixed by Cloud Service 2026.9.28386 and, on 6.5 and 6.5 LTS, by per-issue hotfixes, and Adobe is not aware of exploits of these either (Adobe Experience Manager APSB26-152, 2026-10-13). Commerce and Magento APSB26-153 fixes a template-engine injection leading to code execution (CVE-2026-103849, 10.0, which Adobe marks as needing no authentication) and an incorrect-authorization code-execution flaw (CVE-2026-92909, 9.8, which Adobe's note tags B2B) in builds up to the 2026-sep release; the fixes are the 2026-oct builds, Adobe Commerce B2B has its own 2026-oct builds, Magento Open Source gets them for 2.4.9, 2.4.8 and 2.4.7, and Adobe asks customers to apply the CVE-2026-75650 hotfix from its September APSB26-146 update as well, and Adobe is likewise not aware of exploits (Adobe Commerce APSB26-153, 2026-10-13).

    Exposure
    ColdFusion 2025 and 2023, Experience Manager Cloud Service, 6.5 and 6.5 LTS, and Adobe Commerce or Magento Open Source 2.4.x that untrusted networks can reach; none of the flaws named by CVE id above needs an account.
    Detection
    Adobe publishes no exploit behavior. As an inference from the flaw classes: after unexpected requests to upload or administrative endpoints, look for new script files in web-accessible directories (the upload flaw), and for outbound requests from the application server to internal addresses (the request forgery).
    Defender takeaway
    Update internet-facing ColdFusion, Experience Manager and Commerce or Magento instances first, because the flaws need no login and the order is set by exposure; Adobe reports no exploitation as of 2026-10-13. A Composer-installed Commerce or Magento store needs the 2026-oct release or Adobe's isolated patch applied explicitly (Sansec, 2026-10-15).

    Cited evidence

    Updates1

    Update16 Oct 2026 04:13 UTC

    Sansec reports that it reproduced four different attack routes to code execution for the Commerce and Magento template-engine flaw CVE-2026-103849 within 24 hours of Adobe's fix and expects threat actors to do the same, and that it has not seen attacks on live stores (Sansec, 2026-10-15). It describes the flaw as a second-pass directive injection like September's StyleSmuggler, where attacker-controlled data in a child template can still be signed and re-scanned at the root level so that a smuggled block directive runs inside Magento's rendering, and says Adobe's October patch replaces that generic re-scan with registered placeholders (Sansec, 2026-10-15). Sansec questions Adobe's priority 2 rating for the Commerce bulletin, a 30-day patch window, because StyleSmuggler went from a priority 1 hotfix to mass exploitation in three days and it judges BlockStrap to be of similar complexity (Sansec, 2026-10-15).

    Two cautions for the patch: a plain Composer install still has the vulnerable base version, so the 2026-oct release or Adobe's isolated patch must be applied, and BlockStrap and StyleSmuggler are separate fixes, so the September hotfix for CVE-2026-75650 has to stay in place as well (Sansec, 2026-10-15). Sansec lists Adobe Commerce up to 2.4.9, Adobe Commerce B2B up to 1.5.3 and Magento Open Source up to 2.4.9 as affected (Sansec, 2026-10-15).
