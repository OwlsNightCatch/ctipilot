    NOTABLENATOB2threat

    LLMjacking: stolen cloud identities and keys enable managed model services in victim accounts and resell the quota through proxy gateways (GTIG and Mandiant), with control-plane hunting guidance for AWS, Azure and Google Cloud

    GTIG: stolen cloud keys enable Bedrock and Gemini model services, then resell the quota; hunt the control-plane logs

    first published 2026-11-09 03:26 UTC

    Analysis

    Mandiant responded to multiple 2026 incidents in which actors hijacked enterprise access to large language models ("LLMJacking") with charges above USD 100,000 in a single day (GTIG, 2026-11-02). The dominant initial access was exposed or stolen cloud identity tokens (IAM credentials, service-account keys, GitHub tokens, session tokens). One actor harvested LLM API keys from public GitHub repositories and validated them with single-token requests that stayed under EDR and SIEM volume alerts; another scripted calls against exposed Ollama endpoints to register its own models; cluster UNC6993 had users paste a raw JSON payload holding an active access token into a fake application-portal page, which bypasses password and MFA (GTIG, 2026-11-02).

    After the foothold the actors enumerated cloud services and repositories for credentials, took secrets from cloud secret managers, created unauthorized IAM and service accounts, attached administrative policies to service roles and injected SSH keys into compute instances or instance metadata; one rotated short-lived service accounts to get around rate limits (GTIG, 2026-11-02). In multiple incidents the model services were not enabled at compromise, and the stolen keys were used to enable them and to create further API keys (GTIG, 2026-11-02). A follow-on cluster holding pre-validated virtual keys exploited the victim's LiteLLM gateway at its /key/regenerate endpoint to lift standard virtual keys to proxy-admin credentials (GTIG, 2026-11-02). "LLM Mixers" proxy, aggregate and resell the stolen access; UNC6993 used the open-source new-api and gcli2api gateways (GTIG, 2026-11-02).

    Exposure
    Any cloud account where a stolen identity, key or token can enable or call a managed model service (Amazon Bedrock, Azure's Microsoft.CognitiveServices, the Gemini Enterprise Agent Platform), and any model endpoint reachable from the internet; accounts with model services not enabled are in scope too, because the actors enabled them (GTIG, 2026-11-02). Azure model invocations need Diagnostic Logs, and Gemini Agent Platform inference calls appear only in Data Access logs, which are off by default (GTIG, 2026-11-02).
    Detection
    Cloud control-plane audit logs first; GTIG says to treat any unauthorized enablement of LLM services as a critical security event. In AWS CloudTrail, events from bedrock.amazonaws.com (Converse, InvokeModel, ListFoundationModels, PutUseCaseForModelAccess); in Azure, Microsoft.CognitiveServices/accounts/deployments/write and diagnostic-setting changes; in Google Cloud, ServiceUsage.EnableService for the Agent Platform and, with Data Access logs on, Predict and GenerateContent calls (GTIG, 2026-11-02). Validation sweeps show in gateway logs as unusually small requests such as max_tokens=1; GTIG suggests reading user agents for automation SDKs (aws-sdk-go-v2, aws-sdk-rust, claude-cli) (GTIG, 2026-11-02). Datadog saw similar probing at 12 organizations in 30 days, mostly as failed ListFoundationModels calls across several regions (Datadog, 2026-10-06). Wiz's Google Cloud variant starts with search-ad phishing and ends with external billing administrators and foreign projects linked to the billing account (Wiz, 2026-10-20); watch for both. GTIG describes new IAM and service accounts, policy attachments and SSH keys as the actors' persistence, so review those after revoking a stolen key (GTIG, 2026-11-02).

    Triage: GTIG treats any call that disables model invocation logging, made by a principal outside infrastructure-as-code, as high severity (GTIG, 2026-11-02).

    Defender takeaway
    Deny model-service permissions to identities that do not need them, set per-model quotas and spending caps, patch model gateways such as LiteLLM, and alert on any enablement of a model service or call that disables its logging (GTIG, 2026-11-02). Switch on model-call logging where it is not on by default, or inference calls go unseen.
