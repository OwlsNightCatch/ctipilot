    ConnectWise SkyKick app credential used in 162+ Microsoft 365 tenants; disabling it does not undo planted access

    first published 2026-10-18 03:30 UTCupdated 2026-10-29 04:59 UTC

    Defender actions

    • In every Entra tenant you or your MSP administer, disable without deleting the seven ConnectWise application identities that ConnectWise lists by client ID (Cloud Backup is 506e08f9-6e9a-4da4-942b-a099a03644ae; the other six are in ConnectWise's advisory), dormant connections included, and keep them disabled, because ConnectWise's restoration of 2026-10-28 has partners consent a new application, “ConnectWise Cloud Backup for M365”, in each tenant, so take its details only from the instructions on ConnectWise's Trust Center; where Graph activity logs were enabled, review them for these apps until at least 90 minutes after you disabled them, because a token issued before the disable stays valid for up to 90 minutes, and preserve the sign-in and audit logs promptly without delaying containment, because Entra ID Free keeps only 7 days.
    • In the same tenants list the apps owned by the ConnectWise tenant (ID 3f9cd7a0-127a-4ed4-bf06-2f830d5616b7), and disable each that you do not use or cannot verify as safe.
    • In the same tenants review every enterprise application and app registration, MSP management and security tools first but none skipped (Huntress saw the secrets planted on apparently random applications, in one tenant on some of the least privileged ones), for client secrets, certificates and federated credentials added since 2026-10-13 and remove any you did not create; also check the directory roles, owners and consent grants held by ConnectWise and SkyKick service principals, Conditional Access exclusions for them, and mailbox forwarding, inbox and transport rules and delegated access, because disabling the vendor applications does not remove access planted through them.

    Analysis

    ConnectWise says it identified unauthorized access to application identities within its Cloud Backup (formerly SkyKick) environment; on 2026-10-17 it disabled seven application identities, suspended the service, says the shared Cloud Backup credentials are no longer valid, and warns that disabling does not reverse changes already made in a tenant (ConnectWise, 2026-10-19). As of ConnectWise's update of 2026-10-19 01:15 UTC, Cloud Backup, SaaS Security and Cloud Management remained suspended with no confirmed restoration time (ConnectWise, 2026-10-19), and its status page of 2026-10-28 says partners can now re-authorize Microsoft 365 backup and restore through a new application (ConnectWise status page, 2026-10-28); ConnectWise reports no successful threat activity in the environments it monitors since it implemented mitigations (ConnectWise, 2026-10-19) and says it cannot independently determine whether a given partner or customer tenant was affected (ConnectWise, 2026-10-19). Huntress and Todyl report that on 2026-10-15 the app's identity signed in to customer Microsoft 365 tenants from one hosting-provider address and received app-only Microsoft Graph tokens; the credential sits in the vendor's own tenant, so no user, MFA prompt or user Conditional Access was involved, and the app's consent covers read and write access to mail, files and Teams chats (Huntress, 2026-10-16; Todyl, 2026-10-15). Huntress confirmed unauthorized sign-ins in 162 tenants by 2026-10-16 and later counted almost 1,000 tenants with sign-in activity from that address, over 300 successful, after password spraying against four law-firm tenants on 13 and 14 October, and a separate failed wave targeted 16 tenants in policy and national-security sectors (Huntress, 2026-10-16). In about 50 of its tenants, ConnectWise Cloud Management apps assigned themselves directory roles, mostly Exchange Administrator; in one the Teams app added itself to Global Administrator and client secrets were added to an MSP management application and to Huntress's own application within about five minutes, the credential additions from private Azure space (Huntress, 2026-10-16). Huntress later identified a second tenant with the same sequence, the application granting itself Global Administrator and then planting a new secret on a small number of other applications, within two minutes of the first around 03:45 UTC on 2026-10-15, with the choice of applications apparently random (Huntress, 2026-10-16). It says the unauthorized sign-ins with the credential were bunched across the morning of 2026-10-15 UTC, that the last successful one it observed was at 08:44 UTC that day with only failed attempts afterwards in the tenants where it can read sign-in logs, and that in the two tenants it reviewed it found no mailbox or file manipulation and no user or policy changes (Huntress, 2026-10-16). Microsoft Threat Intelligence, as BleepingComputer relays it, called it an active supply-chain attack and assessed likely abuse of existing permissions including Directory.ReadWrite.All (BleepingComputer, 2026-10-17). Microsoft Threat Intelligence later assessed that Storm-0940, a China-state aligned actor, was responsible, using the ARTEX agentic-AI framework to attempt sign-ins to more than 2,250 tenants (Microsoft, 2026-10-21). How the credential was obtained and what was read remain unknown (ConnectWise, 2026-10-19; BleepingComputer, 2026-10-17).

    Exposure
    Every Entra tenant, including each customer tenant an MSP manages, in which a ConnectWise or SkyKick Cloud Backup or Cloud Management app was ever consented, dormant connections included; ConnectWise lists seven application client IDs, among them Cloud Backup (506e08f9-6e9a-4da4-942b-a099a03644ae), and says to match on client ID (ConnectWise, 2026-10-19). Todyl identifies the application as "ConnectWise Cloud Backup" (formerly SkyKick Backup), app ID 506e08f9-6e9a-4da4-942b-a099a03644ae; SpecterOps hunts for applications owned by the ConnectWise tenant (ID 3f9cd7a0-127a-4ed4-bf06-2f830d5616b7) and notes that older tenants may list them under SkyKick names (Todyl, 2026-10-15; SpecterOps, 2026-10-17).
    Detection
    Entra service-principal sign-in logs for these apps from any address outside Microsoft and Azure ranges, which misses the credential additions, made from private Azure space (Huntress, 2026-10-16); the sweep of sign-ins itself, which Sophos saw come from a single virtual private server in strictly ascending tenant-ID order with Python HTTP-library user agents (Sophos, 2026-10-19); directory audit events Add member to role, Update application and Add service principal credentials initiated by a ConnectWise or SkyKick app (Huntress, 2026-10-16); Graph activity logs (Entra ID P1 or P2, not retroactive) for per-request source addresses (Todyl, 2026-10-15); and mailbox forwarding, inbox and transport rule and delegation changes (ConnectWise, 2026-10-19). Huntress notes that Microsoft Graph directory reads leave no audit record, so a clean audit log does not rule out reads of the directory (Huntress, 2026-10-16). Disabling the apps does not remove credentials, roles or consents already planted, and revoking user sessions does not end this access (ConnectWise, 2026-10-19; Todyl, 2026-10-15). Disabling an app stops new tokens only: a token issued before the disable stays valid for up to 90 minutes (Todyl, 2026-10-15; SpecterOps, 2026-10-17), and ConnectWise says that after its own certificate revocation previously issued tokens may remain usable until they expire (ConnectWise, 2026-10-19). The service-principal sign-in log records an application's authentication (ConnectWise, 2026-10-19), while per-request use of a token appears in the Graph activity logs named above (Todyl, 2026-10-15), so the review of that period belongs there. Microsoft asks tenants to review service-principal sign-ins from at least 2026-10-15, and from 2026-10-01 where records exist, and to search by application ID rather than display name (Microsoft, 2026-10-21). As of 2026-10-19, any alerting a tenant took from ConnectWise SaaS Security was out of service while that service was suspended (ConnectWise, 2026-10-19).

    Triage: the vendor's apps sign in from Azure addresses with a .NET SDK user agent, while the credential additions used a Python user agent; Python and curl are common in administration, so Huntress says the combination of actor, operation and user agent is the signal (Huntress, 2026-10-16). Role self-assignments carrying the vendor's own user agent are not proven benign, since Huntress has not confirmed vendor automation (Huntress, 2026-10-16).

    Defender takeaway
    Where any ConnectWise or SkyKick app is consented, disable it by client ID without deleting it, keep it disabled (ConnectWise's restoration works through a new application that each tenant consents separately), and review credentials, roles, owners, consents and Conditional Access exclusions since 13 October (ConnectWise, 2026-10-19; Huntress, 2026-10-16). An MSP should review its own management and security tools first, since a foothold there can reach its customers, but the review covers every application, because Huntress saw secrets planted on apparently random ones (Huntress, 2026-10-16). ConnectWise cannot independently determine whether a given partner or customer tenant was affected, so the answer for a tenant has to come from its own sign-in and audit logs (ConnectWise, 2026-10-19).

    Cited evidence

    Updates7

    Improvement19 Oct 2026 03:47 UTC

    ConnectWise's update of 2026-10-18 01:00 UTC took SaaS Security and Cloud Management offline in addition to Cloud Backup, which had been suspended since 2026-10-17, so ConnectWise SaaS Security monitoring and alerting is out of service as well, and the update of 2026-10-19 01:15 UTC still gives no restoration time (ConnectWise, 2026-10-19). Disabling an app stops new tokens only: Todyl and SpecterOps each state that tokens already issued stay valid for up to 90 minutes, and ConnectWise says that after it revoked the Cloud Backup certificates previously issued tokens may remain usable until they expire (Todyl, 2026-10-15; SpecterOps, 2026-10-17; ConnectWise, 2026-10-19). SpecterOps hunts for applications owned by the ConnectWise tenant, noting that older tenants may list them under SkyKick names (SpecterOps, 2026-10-17).

    Update20 Oct 2026 03:57 UTC

    Huntress's update of 2026-10-19 13:30 ET identified a second tenant with post-compromise activity, a tenant Huntress did not originally protect, where it got deployed to collect telemetry (Huntress, 2026-10-16). In both tenants the activity was fast and scripted, within two minutes of each other around 03:45 UTC on 2026-10-15: the application granted itself Global Administrator and then planted a new secret on a small number of other applications to keep a foothold (Huntress, 2026-10-16). The choice of applications appeared random: the same flow picked two different sets, one application present in both was backdoored in only one, and in one tenant the applications that received secrets were among the least privileged in the environment while far more powerful ones were untouched (Huntress, 2026-10-16).

    Huntress says the unauthorized sign-ins with the credential were tightly bunched across the morning of 2026-10-15 UTC, the last confirmed successful sign-in it observed was at 08:44 UTC, and it saw only failed attempts afterwards in the tenants where it can read sign-in logs (Huntress, 2026-10-16). The access may have been used for Microsoft Graph directory reads, which leave no audit record, and in the two tenants Huntress reviewed it found no evidence of mailbox or file manipulation or of user or policy changes (Huntress, 2026-10-16). The check for planted credentials therefore has to cover every application registration and enterprise application in the tenant, and a clean audit log does not exclude directory reads. ConnectWise's latest readable update (2026-10-19 01:15 UTC) gives no restoration time (ConnectWise, 2026-10-19).

    Improvement21 Oct 2026 03:47 UTC

    Sophos X-Ops independently observed the token requests: on 2026-10-15 a single virtual private server authenticated as the ConnectWise Cloud Backup application and requested app-only Microsoft Graph tokens for about 96 minutes, from 07:11 UTC, in strictly ascending tenant-ID order, one to six minutes apart, using Python HTTP-library user agents, and the sweep included tenants with no active backup subscription (Sophos X-Ops, 2026-10-19). Sophos found no hands-on-keyboard activity and no evidence that the application created new secrets, applications, consents or role assignments in the tenants it reviewed, which differs from the role grants and added secrets Huntress reports in other tenants; Sophos says it is unclear how the credential was obtained and what was done with the tokens (Sophos X-Ops, 2026-10-19). The two vendors' sweep timings differ: Huntress puts the first app sign-ins at 06:13 to 08:34 UTC on 2026-10-15 with tenants taken in sorted GUID order a few seconds apart (Huntress, 2026-10-16), where Sophos gives about 96 minutes from 07:11 UTC, one to six minutes apart; the vantage points differ, so both are reported as stated.

    Update22 Oct 2026 03:46 UTC

    Microsoft Threat Intelligence assesses that Storm-0940, a China-state aligned actor active since 2021, was responsible for the compromise. It says AI agents running the ARTEX framework kept signing in to customer tenants as the ConnectWise applications, without an interactive user sign-in, and in multiple tenants went on to Microsoft Graph reconnaissance, application credential changes and attempts to change privileges (Microsoft, 2026-10-21). It counts attempted sign-ins to more than 2,250 tenants and links the activity to an automated cross-tenant password spray between 2026-10-10 and 2026-10-14 against 327 accounts at eight organizations, from the same network range and including an address that ConnectWise's advisory later listed among its indicators; the spray peaked on 2026-10-11 at 2,900 failed logons a minute and produced no successful authentication (Microsoft, 2026-10-21).

    Microsoft warns that the application credential changes can remain active as a backdoor after the vendor application is remediated, and asks tenants to review service-principal sign-ins from at least 2026-10-15, and from 2026-10-01 where records exist, together with the Entra audit trail for credential additions, role assignments, consents and owner changes (Microsoft, 2026-10-21). Expel, which analysed the activity separately, relays the attribution, notes that ConnectWise's fix leaves secrets planted on other applications in place and that Graph directory reads leave no Entra audit record, and says Huntress has not tied its Global Administrator observation to the same operator (Expel, 2026-10-21). ConnectWise itself says that, based on the evidence available to it, including threat intelligence shared by Microsoft, it appears a China state-aligned group was responsible and used an openly available agentic AI framework (ConnectWise, 2026-10-21). It began restoring services in controlled phases on 2026-10-21, expects it to take several days, says the start of restoration does not mean all capabilities are available, and tells partners to keep affected connections disabled until formal instructions apply to their service, while noting that its actions do not remove unauthorized access already established in individual customer tenants (ConnectWise, 2026-10-21; heise online, 2026-10-21).

    Correction25 Oct 2026 13:43 UTC

    The update of 2026-10-22 attached a rate of 2,900 attempts a minute to the ARTEX sign-ins against more than 2,250 tenants. Microsoft gives no rate for those sign-ins: 2,900 a minute is the peak of failed logons in the separate password spray of 10 to 14 October, reached on 11 October (Microsoft, 2026-10-21). The figure now sits with the spray.

    Improvement27 Oct 2026 03:46 UTC

    Huntress published its analysis of what drove the 2026-10-15 activity on 2026-10-26, working from Entra sign-in and directory audit logs in the tenants it monitors. It says its telemetry aligns with Microsoft's Storm-0940 and ARTEX account without independently confirming it, that it is highly confident an operator, a person or an LLM, adapted the tooling between runs, and that its confidence that an LLM was involved in the escalation tooling is low to medium on its own telemetry and medium to high once Microsoft's attribution is included (Huntress, 2026-10-26). Its evidence for adaptation: a certificate upload that failed on a thumbprint mismatch ended one run with no retry, and the next run 55 seconds later retried the same error with growing waits until it worked; in a second tenant that refused removal of the Global Administrator role, the actor granted a different role to a sibling principal and the original service principal was then deleted (Huntress, 2026-10-26). Microsoft Graph reads are not recorded in the Entra audit log and no victim Huntress knows of had Graph activity logging enabled, so a clean audit log does not show that no Graph access took place (Huntress, 2026-10-26). Huntress recommends alerting when a service principal assigns itself Global Administrator or Privileged Role Administrator, deletes itself, or when one vendor principal grants a role to a sibling, and turning on Graph activity logs where licensing allows (Huntress, 2026-10-26).

    Update29 Oct 2026 04:59 UTC

    ConnectWise's status page announced on 2026-10-28 at 17:09 UTC, after restoration in controlled phases had begun on 2026-10-21, that it is beginning phased restoration for partners, starting with Microsoft 365 backups and restores through a new, security-hardened application, with other features returning in phases over the coming days (ConnectWise status page, 2026-10-28). Partners must re-authorize each Microsoft 365 tenant using the new application, “ConnectWise Cloud Backup for M365”, to resume backup and restore operations, and ConnectWise points to its Trust Center for the detailed instructions (ConnectWise status page, 2026-10-28). Before that, from 2026-10-26, it had said it would first enable a process to restore data from existing backups and then phased re-enrollment, and it still told partners to keep affected connections disabled until instructions applied to their service (ConnectWise status page, 2026-10-28).
