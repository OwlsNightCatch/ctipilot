    Gyazo (Helpfeel): an image-upload-server vulnerability reaches arbitrary command execution, exposing 23.62 million user records and 490 million image-metadata records

    Helpfeel's 'unguessable link' privacy model for Gyazo collapsed once the image IDs themselves leaked from the backend

    first published 2026-09-18 05:00 UTC

    Analysis

    Helpfeel Inc. (Kyoto, Japan) disclosed on 2026-09-16 that on 2026-09-11 a third party exploited a vulnerability in the image-upload server of Gyazo, its screenshot-sharing service, executed arbitrary commands and accessed Gyazo's database (Helpfeel Inc., 2026-09-16). Helpfeel has not named the flaw class (The Hacker News, 2026-09-17). About 23.62 million user records were exposed, including email addresses, password hashes and login session IDs, together with about 490 million image-metadata records, mostly for images registered in or before January 2019, that include the image IDs used to build Gyazo image links (Helpfeel Inc., 2026-09-16). A capture at Gyazo's default setting is protected only by its link, so the leaked image IDs remove that protection (The Hacker News, 2026-09-17). Helpfeel says the attacker also obtained a list identifying private images and that it cannot rule out that some of them were viewed (Helpfeel Inc., 2026-09-16).

    Defender takeaway
    Where staff shared screenshots through Gyazo links, treat captures at the default setting as possibly viewed, since Helpfeel says the leaked image IDs could be used to view the corresponding images without authorization. Helpfeel asks every Gyazo user to change their password, and any same or similar password used on other services, and to watch for suspicious emails or messages related to the incident (Helpfeel Inc., 2026-09-16).
