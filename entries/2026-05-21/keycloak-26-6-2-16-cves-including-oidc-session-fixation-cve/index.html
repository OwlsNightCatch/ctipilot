    Keycloak 26.6.2 fixes 16 security issues, among them an OIDC login session fixation (CVE-2026-7507) and a WebAuthn execute-actions token replay (CVE-2026-37982)

    Keycloak 26.6.2: a crafted link can hand an attacker the victim's session, up to the master-realm admin account

    first published 2026-05-21 05:00 UTC

    Analysis

    The Keycloak project released 26.6.2 on 2026-05-19 with fixes for 16 security issues carrying 18 CVE ids, several of them in bundled third-party components such as Bouncy Castle (Keycloak, 2026-05-19); BSI's WID-SEC-2026-1612, first released at 22:00 UTC that day, lists nine of the Keycloak CVEs and rates them high (BSI WID-SEC-2026-1612). CVE-2026-7507, which Red Hat calls a critical session fixation flaw although it scores CVSS 7.5, lets an unauthenticated attacker pre-create an authentication session and lure a victim to a crafted link: the /login-actions/restart endpoint lacks CSRF protection and cookie ownership checks, so single sign-on authenticates the victim and the attacker takes over the required-action form, which in default deployments reaches full takeover of the master-realm admin account (Red Hat CVE-2026-7507). CVE-2026-37982 (6.8) lets an attacker who intercepts an execute-actions e-mail link replay its token and register their own WebAuthn authenticator on the victim's account, where WebAuthn required actions are enabled (Red Hat CVE-2026-37982). CVE-2026-37979 (6.5) lets any confidential client with valid credentials read, through the token introspection endpoint, claims of lightweight access tokens meant for other resource servers (Red Hat CVE-2026-37979); CVE-2026-4630 (6.8) lets an authenticated client that knows the UUID of another resource server's resource in the same realm read, change or delete it through the Authorization Services Protection API (Red Hat CVE-2026-4630); CVE-2026-37978 (4.9) lets a low-privilege administrator with the view-clients role read other users' profile and role data through the evaluate-scopes Admin API (Red Hat CVE-2026-37978); and CVE-2026-6856 lets an authenticator that sends self-attestation bypass the acceptable-AAGUID allowlist during WebAuthn registration (Keycloak issue #48388). Red Hat fixed CVE-2026-7507 in Red Hat build of Keycloak 26.2.16 (RHSA-2026:19594) and it, CVE-2026-37982, CVE-2026-37979, CVE-2026-4630 and CVE-2026-37978 in 26.4.12 (RHSA-2026:19596).

    Exposure
    Keycloak before 26.6.2; CVE-2026-7507 needs only a victim who follows a link, while the others need a confidential or authenticated client, an intercepted execute-actions e-mail link or an administrator holding view-clients (Red Hat CVE-2026-7507) (Red Hat CVE-2026-37982) (Red Hat CVE-2026-37978).
    Detection
    Keycloak user and admin event logs: CVE-2026-37982 ends in an attacker's WebAuthn authenticator on the victim account, which Red Hat calls persistent account takeover (Red Hat CVE-2026-37982), so the upgrade does not remove it; review WebAuthn credentials registered through execute-actions links before the upgrade.
    Defender takeaway
    Upgrade Keycloak to 26.6.2 (Keycloak, 2026-05-19), or Red Hat build of Keycloak to 26.4.12 or 26.2.16 on those branches (RHSA-2026:19596) (RHSA-2026:19594); deployments whose users could be sent a crafted login link are the first in line because of CVE-2026-7507.

    Correction21 Oct 2026 20:33 UTC

    CVE-2026-4630 is not a cross-realm flaw: it lets an authenticated client reach another resource server's resources within the same realm (Red Hat CVE-2026-4630). CVE-2026-7507 works through the /login-actions/restart endpoint, with an attacker-created authentication session and a crafted link the victim follows, not through a crafted state parameter (Red Hat CVE-2026-7507), and CVE-2026-37982 needs an intercepted execute-actions e-mail link (Red Hat CVE-2026-37982). The highlighted CVEs carry Red Hat CVSS scores from 4.9 to 7.5 rather than none, CVE-2026-37979, CVE-2026-4630 and CVE-2026-37978 need an authenticated client or administrator, and the release fixes 16 issues with 18 CVE ids, nine of which BSI lists (Keycloak, 2026-05-19) (BSI WID-SEC-2026-1612). No source links the release to the Akira ransomware group.
