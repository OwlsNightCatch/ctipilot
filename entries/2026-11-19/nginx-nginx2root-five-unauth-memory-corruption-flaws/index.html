    HIGHCVE-2026-123007 +10updatedNATOA1vulnerability

    NGINX nginx2root: five unauthenticated memory-corruption flaws (CVE-2026-123007 and CVE-2026-123633 in HTTP/2, CVE-2026-121810 in HTTP/3, CVE-2026-123634 in the resolver, CVE-2026-113425 in the mail proxy) can lead to code execution as the worker process; fixed in nginx 1.31.9 and 1.30.7 and NGINX Plus 37.3.0.1 and 37.0.8.1, Rapid7 proof of concept public, no exploitation reported (CVSS 4.0 9.2)

    nginx2root: five unauthenticated flaws reach worker RCE, Rapid7 PoC public; update to 1.31.10, 1.30.8, Plus 37.3.1.1

    first published 2026-11-19 05:12 UTCupdated 2026-11-28 04:51 UTC

    Defender actions

    • Update every internet-facing nginx to 1.31.10 or 1.30.8 (NGINX Plus to 37.3.1.1 or 37.0.9.1) and restart the process, because a reload does not replace the running executable, 1.31.9 and 1.30.7 leave the ssl_early_data CPU-exhaustion flaw open and five unauthenticated flaws reach code execution as the worker with Rapid7's proof of concept for one of them public.
    • On every Veeam Software Appliance and Infrastructure Appliance 13.1 install the Veeam Updater package now instead of waiting for the automatic Sunday 14:00 install, and limit TCP 443 to trusted networks until then, because Veeam lists both as affected by the two HTTP/2 flaws and HTTP/2 cannot be disabled on them.
    • Update Synology DSM 7.4 to 7.4.1-90080-2 or above, DSM 7.3 to 7.3.2-86009-6, DSM 7.2.2 to 7.2.2-72806-11, DSM 7.2.1 to 7.2.1-69057-14, DSM 7.1 to 7.1.1-42962-10, BeeStation OS 1.5 to 1.5.6-68000 and APM 2.0, 1.2, 1.1 and 1.0 to 2.0.2-88107 (Synology recommends 7.3.2-86009-6 or above on DSM 7.2.x), and on DSM Enterprise 1.0, where the fix is still listed as ongoing, turn HTTP/2 off under Control Panel, Network, Connectivity, because CVE-2026-123007 affects DSM with HTTP/2 enabled.

    Analysis

    F5 and the nginx project published the nginx2root fixes (nginx.org, 2026-11-18); CERT-EU counts five vulnerabilities, all able to lead to unauthenticated code execution with the privileges of the NGINX worker process (CERT-EU, 2026-11-18). CVE-2026-123007 is an HTTP/2 flow-control overflow: cancelling queued response data makes nginx use an invalid length when copying a later response (Rapid7, 2026-11-18), and Wiz demonstrated code execution on nginx serving ordinary static files (Wiz Research, 2026-11-18).

    Rapid7 published a working proof of concept for CVE-2026-123007 against nginx 1.31.8; the exploit needs about 128 GB of HTTP/2 traffic and likely fails with concurrent clients (Rapid7, 2026-11-18; Rapid7 repository, 2026-11-18). CERT-EU reports no exploitation in the wild and NCSC.ch rates exploitation unknown with a proof of concept available (CERT-EU, 2026-11-18; NCSC.ch, 2026-11-18).

    The memory-corruption fixes are in nginx 1.31.9 and 1.30.7 (nginx.org, 2026-11-18); nginx 1.31.10 and 1.30.8 of 2026-11-23 add a fix for CPU exhaustion when ssl_early_data is on (CVE-2026-132779, affecting 1.21.4 to 1.31.9 per nginx.org, 2026-11-27), as do NGINX Plus 37.3.1.1 and 37.0.9.1 (nginx.org, 2026-11-23; nginx.org, 2026-11-23; F5 NGINX Plus release notes, 2026-11-23). CERT.at lists NGINX Plus 37.3.0.1 and 37.0.8.1 as fixing four of the five (CVE-2026-123007, CVE-2026-121810, CVE-2026-123633 and CVE-2026-113425); it also says 37.2.0.1 and 37.0.7.1 already carry the fix for CVE-2026-123633 but stay affected by CVE-2026-123007 and CVE-2026-121810, and NGINX Plus R33 to R36 have no update (translated from German) (CERT.at, 2026-11-18).

    Exposure
    An nginx build from the first affected release of each flaw (1.9.5, 1.19.7, 0.6.18, 1.25.0 and 0.5.33) up to 1.31.8 whose configuration uses the feature: an HTTP/2 or HTTP/3 listener, the resolver with variable proxy_pass destinations plus mirror or SSI, or the mail proxy with auth_http (nginx.org, 2026-11-18; Xint, 2026-11-18). A distribution backport can fix a flaw without changing the version nginx -v reports (Xint, 2026-11-18). Veeam Software Appliance and Infrastructure Appliance 13.1 are affected by the two HTTP/2 flaws and cannot disable HTTP/2; Veeam ships the fix through Veeam Updater (Veeam, 2026-11-25). GitLab's Linux package and Docker images carry nginx 1.31.9 from 19.6.2, 19.5.9 and 19.4.11 (GitLab, 2026-11-25).
    Detection
    Process-creation or audit telemetry for any program started by the worker's user, since a normal nginx worker runs no external programs and that is the clearest sign of success; worker exits and core dumps in the error log mark attempts, not successes (Xint, 2026-11-18; CERT-EU, 2026-11-18).

    Triage: a large upload is a legitimate cause of an inbound-heavy connection and workers crash for unrelated reasons, so a program started by the worker is the discriminator, not the traffic shape alone (Xint, 2026-11-18).

    Defender takeaway
    Update and restart nginx, because a configuration reload does not replace the running executable; disabling HTTP/2 on exposed listeners blocks only the two HTTP/2 flaws (Xint, 2026-11-18) and, if it stays on elsewhere, leaves connection pressure (Unit 42, 2026-11-24), and Xint gives interim measures for the others: a fixed upstream group in place of request-time DNS lookups for CVE-2026-123634, no QUIC listeners for CVE-2026-121810 and bound or firewalled mail listeners for CVE-2026-113425 (Xint, 2026-11-18). An empty execution-audit result after the update cannot rule out an earlier compromise, and Xint chained CVE-2026-123007 with a separate Linux kernel SCTP flaw, unpatched when it published, to reach root on the host and escape a Docker container; hosts that do not use SCTP can block the module from loading (Xint, 2026-11-18).

NCSC-NL scores them CVSS 4.0 8.7 (CVE-2026-118899), 6.3 (CVE-2026-120967) and 6.9 (CVE-2026-120993, CVE-2026-123640 and CVE-2026-125283) (NCSC-NL, 2026-11-18), and Fortinet rates CVE-2026-118899 high and the other four medium (Fortinet PSIRT, 2026-11-20).     Update26 Nov 2026 05:07 UTC

    Unit 42 published a first-person account of reaching pre-authentication code execution through CVE-2026-123633 as the non-root NGINX worker on a two-VM lab target running 1.31.8: the first attempt recovered a libc address without a shell and the second opened an interactive shell. The chain needed a non-default configuration and a separate memory disclosure that F5 assessed as limited to a non-typical configuration and has not given a CVE, whose details Unit 42 withholds (Unit 42, 2026-11-24). The tested path needs HTTP/2 on the listener and a reverse-proxy route whose upstream is a variable resolved at request time, with free worker connections at or below one sixteenth of worker_connections; static upstream routes still need review, and Unit 42 publishes no confirmed indicators of compromise. A log signal Unit 42 gives is the error-log warning that worker connections are not enough and are being reused, which needs the warn log level (Unit 42, 2026-11-24). Raising worker_connections adds only headroom and disabling HTTP/2 on some listeners leaves extra HTTP/1.1 connections, so neither replaces the upgrade; no source reports exploitation.

    Palo Alto Networks removed the ETA for 12.1.7-h15, 11.2.10-h19 and 11.2.13-h6 on 2026-11-24 because those builds are released, so every fixed build named above is available, marked PAN-OS 11.1 and 10.2 as not impacted, and says the impacted products for CVE-2026-121810, CVE-2026-123634 and CVE-2026-113425 are the same as for the two HTTP/2 flaws; it knows of no malicious exploitation (Palo Alto Networks, 2026-11-20).
