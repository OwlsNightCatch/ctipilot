    HIGHCVE-2026-123007 +4updatedNATOA1vulnerability

    NGINX nginx2root: five unauthenticated memory-corruption flaws (CVE-2026-123007 and CVE-2026-123633 in HTTP/2, CVE-2026-121810 in HTTP/3, CVE-2026-123634 in the resolver, CVE-2026-113425 in the mail proxy) can lead to code execution as the worker process; fixed in nginx 1.31.9 and 1.30.7 and NGINX Plus 37.3.0.1 and 37.0.8.1, Rapid7 proof of concept public, no exploitation reported (CVSS 4.0 9.2)

    NGINX nginx2root: five unauthenticated flaws reach worker RCE, Rapid7 PoC public; update 1.31.9, 1.30.7 or Plus 37.3.0.1

    first published 2026-11-19 05:12 UTCupdated 2026-11-21 04:37 UTC

    Defender actions

    • On every PAN-OS firewall and Panorama with the HTTP/2 option enabled, upgrade to 12.2.4-h3, 12.1.10-h6 or 11.2.16-h3 or later (12.1.7-h15, 11.2.10-h19 and 11.2.13-h6 are listed with a 2026-11-23 ETA) or disable HTTP/2, because Palo Alto Networks lists CVE-2026-123007 and CVE-2026-123633 as affecting them with that option on.
    • Update every internet-facing nginx to 1.31.9 or 1.30.7 (NGINX Plus to 37.3.0.1 or 37.0.8.1) and restart the process, because a reload does not replace the running executable; where the update waits, disable HTTP/2 on exposed listeners, which blocks only CVE-2026-123007 and CVE-2026-123633, since five unauthenticated flaws reach code execution as the worker and Rapid7's proof of concept for one of them is public.

    Analysis

    F5 and the nginx project published the nginx2root fixes (nginx.org, 2026-11-18); CERT-EU counts five vulnerabilities, all able to lead to unauthenticated code execution with the privileges of the NGINX worker process (CERT-EU, 2026-11-18). CVE-2026-123007 is an HTTP/2 flow-control overflow: cancelling queued response data makes nginx use an invalid length when copying a later response (Rapid7, 2026-11-18), and Wiz demonstrated code execution on nginx serving ordinary static files (Wiz Research, 2026-11-18).

    Rapid7 published a working proof of concept for CVE-2026-123007 against nginx 1.31.8; the exploit needs about 128 GB of HTTP/2 traffic and likely fails with concurrent clients (Rapid7, 2026-11-18; Rapid7 repository, 2026-11-18). Rapid7 says execution has the worker's permissions and root is not established; F5, as CERT.at relays it, frames the base effect as worker crashes, with code execution possible where ASLR is disabled or can be bypassed, which Wiz says attackers can do by reading memory first (translated from German) (Rapid7, 2026-11-18; CERT.at, 2026-11-18; Wiz Research, 2026-11-18). CERT-EU reports no exploitation in the wild, NCSC.ch rates exploitation unknown with a proof of concept available, and NCSC-NL expects large-scale exploitation once proof-of-concept code is public (translated from Dutch) (CERT-EU, 2026-11-18; NCSC.ch, 2026-11-18; NCSC-NL, 2026-11-18).

    The fixes are in nginx 1.31.9 and 1.30.7 (nginx.org, 2026-11-18). CERT.at lists NGINX Plus 37.3.0.1 and 37.0.8.1 as fixing four of the five (CVE-2026-123007, CVE-2026-121810, CVE-2026-123633 and CVE-2026-113425); it also says 37.2.0.1 and 37.0.7.1 already carry the fix for CVE-2026-123633 but stay affected by CVE-2026-123007 and CVE-2026-121810, and NGINX Plus R33 to R36 have no update (translated from German) (CERT.at, 2026-11-18).

    Exposure
    An nginx build from the first affected release of each flaw (1.9.5, 1.19.7, 0.6.18, 1.25.0 and 0.5.33) up to 1.31.8 whose configuration uses the feature: an HTTP/2 or HTTP/3 listener, the resolver with variable proxy_pass destinations plus mirror or SSI, or the mail proxy with auth_http (nginx.org, 2026-11-18; Xint, 2026-11-18). A distribution backport can fix a flaw without changing the version nginx -v reports (Xint, 2026-11-18).
    Detection
    Process-creation or audit telemetry for any program started by the worker's user, since a normal nginx worker runs no external programs and that is the clearest sign of success; worker exits and core dumps in the error log mark attempts, not successes (Xint, 2026-11-18; CERT-EU, 2026-11-18). Network flow data showing a long-lived TLS connection with fast-growing received volume and little sent data, and many short connections from the same address, hints at CVE-2026-123007 (Xint, 2026-11-18).

    Triage: a large upload is a legitimate cause of an inbound-heavy connection and workers crash for unrelated reasons, so a program started by the worker is the discriminator, not the traffic shape alone (Xint, 2026-11-18).

    Defender takeaway
    Update and restart nginx, because a configuration reload does not replace the running executable; disabling HTTP/2 on exposed listeners blocks only the two HTTP/2 flaws, and Xint gives interim measures for the others: a fixed upstream group in place of request-time DNS lookups for CVE-2026-123634, no QUIC listeners for CVE-2026-121810 and bound or firewalled mail listeners for CVE-2026-113425 (Xint, 2026-11-18). An empty execution-audit result after the update cannot rule out an earlier compromise, and Xint chained CVE-2026-123007 with a separate Linux kernel SCTP flaw, unpatched when it published, to reach root on the host and escape a Docker container; hosts that do not use SCTP can block the module from loading (Xint, 2026-11-18).

    Updates1

    Update21 Nov 2026 04:37 UTC

    Palo Alto Networks lists PAN-OS and Panorama (virtual and M-Series) as affected by CVE-2026-123633 and CVE-2026-123007 only where the HTTP/2 option is enabled, and says it knows of no malicious exploitation; disabling HTTP/2 is its workaround (Palo Alto Networks PSIRT, 2026-11-20). The fixed builds are PAN-OS 12.2.4-h3, 12.1.10-h6 and 11.2.16-h3; 12.1.7-h15, 11.2.10-h19 and 11.2.13-h6 carry an ETA of 2026-11-23, and 12.1.2 to 12.1.4 and 11.2.0 to 11.2.7 need no action (Palo Alto Networks PSIRT, 2026-11-20).

    Cisco's interim advisory (version 1.0, 2026-11-20) lists NX-OS Software, Smart PHY (fix 27.1.0, March 2027), the Intersight Virtual Appliance (1.1.9-0, December 2026), Cloud Hosted Services Vulnerability Management (1.30.7, November 2026) and Identity Services Engine 3.5 (3.5 Patch 5, December 2026) as affected, lists Catalyst Center, the SD-WAN Controller and Manager, ASA, FMC, FTD and UCS Central as not affected, and has IOS XE, IOS XR and UCS Director under investigation; its PSIRT knows of proof-of-concept code and of no malicious use (Cisco PSIRT, 2026-11-20). Siemens (SSA-935812, 2026-11-20) lists Industrial Edge products as affected in all versions with no fix available and names disabling HTTP/2 or HTTP/3 on the affected listeners as the mitigation (Siemens ProductCERT, 2026-11-20). Fortinet says none of its products uses NGINX Plus and is still investigating FortiManager, FortiAnalyzer, FortiAuthenticator and dozens of others (Fortinet PSIRT, 2026-11-20).
