    CISA contractor's public GitHub repo exposed AWS GovCloud admin keys and plaintext passwords for internal systems

    first published 2026-05-19 05:00 UTC

    Analysis

    GitGuardian researcher Guillaume Valadon alerted KrebsOnSecurity on 2026-05-15 to a public GitHub repository named Private-CISA, kept by an employee of the government contractor Nightwing, that held cloud keys, tokens, plaintext passwords, logs and files describing how CISA builds, tests and deploys software (Krebs on Security, 2026-05-18). One file held administrative credentials to three AWS GovCloud servers, which Philippe Caturegli of Seralys validated as authenticating to three GovCloud accounts at a high privilege level; a CSV of browser-saved passwords listed plaintext credentials for dozens of internal CISA systems, among them LZ-DSO (Landing Zone DevSecOps), the agency's secure code development environment; and the archive also held plaintext credentials to CISA's internal Artifactory package repository (Krebs on Security, 2026-05-18). The commit logs show the administrator had disabled GitHub's default setting that blocks publishing SSH keys or other secrets, and many passwords were each platform's name followed by the current year (Krebs on Security, 2026-05-18).

    The repository was created on 2025-11-13 and taken offline shortly after KrebsOnSecurity and Seralys notified CISA, but the AWS keys stayed valid for another 48 hours (Krebs on Security, 2026-05-18); Gizmodo puts the exposure at about six months, possibly much shorter depending on when each item was added (Gizmodo, 2026-05-19). Caturegli suspects the contractor used the repository to synchronize files between a work laptop and a home computer, and calls the Artifactory credentials a prime place to move laterally and backdoor software packages (Krebs on Security, 2026-05-18). CISA said it was investigating, that there was no indication any sensitive data was compromised, and that it was adding safeguards (Krebs on Security, 2026-05-18). For public bodies the case is a transferable pattern: a contractor's own repository holding an agency's privileged cloud and build-system credentials.

    Exposure
    Organizations whose staff or contractors can push agency material to public code repositories and can switch off the platform's secret-blocking setting, as this administrator did (Krebs on Security, 2026-05-18).
    Detection
    In code-hosting and secret-scanning telemetry, alerts on public repositories outside the organization's own namespace that contain its credentials, the kind of finding GitGuardian raised here; in cloud control-plane audit logs, use of long-lived access keys after the material they leaked from has been taken down, since these keys kept working for 48 hours (Krebs on Security, 2026-05-18).
    Defender takeaway
    When a secret leaks through a public repository, revoke the keys and passwords at once rather than relying on the takedown, and check that administrators cannot disable the code platform's secret blocking for repositories that hold agency material (Krebs on Security, 2026-05-18).

    Correction21 Oct 2026 20:38 UTC

    LZ-DSO, which appears to stand for Landing Zone DevSecOps, the agency's secure code development environment, was one of the dozens of internal systems whose passwords sat in the exposed CSV; the plaintext credentials to CISA's internal Artifactory package repository were a separate item in the archive (Krebs on Security, 2026-05-18). CISA did not link the exposure to staffing: it said there was no indication that any sensitive data was compromised and that it was working to add safeguards, while the loss of nearly a third of its workforce is Krebs's own context (Krebs on Security, 2026-05-18). That the repository synchronized files between a work laptop and a home computer is Caturegli's suspicion, and his point about the Artifactory credentials is a risk he describes, a prime place to move laterally and backdoor software packages, rather than an established write access (Krebs on Security, 2026-05-18). The exposure ran from the repository's creation on 2025-11-13 until it was taken offline in mid-May 2026, up to about six months (Gizmodo, 2026-05-19).
