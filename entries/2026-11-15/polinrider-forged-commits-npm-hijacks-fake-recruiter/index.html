    PolinRider: a North Korea-linked loader reaches developers through force-pushed forged commits in at least 7,609 GitHub repositories, hijacked npm releases and a fake employer's take-home test, and reads its server address from an Ethereum wallet

    PolinRider: forged backdated commits, npm hijacks and a fake recruiter run a loader at build or folder open

    first published 2026-11-15 04:26 UTCupdated 2026-11-26 05:07 UTC

    Defender actions

    • Search every branch of your organisation's and suppliers' GitHub repositories for a semicolon followed by 200 or more spaces or tabs in JavaScript, TypeScript and build configuration files, for a utils package or conftest.py that runs node, and for .vscode/tasks.json tasks that run node when a folder opens; on any hit, rotate every GitHub and npm token reachable from the developer machines and CI runners that built the repository and review force-pushes, deploy keys, Actions secrets and releases since the infection, because deleting the loader does not revoke the access that pushed it.

    Analysis

    Apiiro calls PolinRider a North Korea-linked worm and found it in at least 7,609 GitHub repositories owned by 2,330 accounts, mostly developers' own (Apiiro, 2026-11-09). Three routes, none relying on an npm install script. Forged commits: with stolen GitHub access the worm force-pushes a copy of a commit the owner already made, with the same author, message and date, plus a loader hidden after hundreds of spaces in a build configuration file; in 94% of 9,990 injection pushes the copy claims to be more than an hour older than the push, so git log shows an old commit under the owner's name. Cloning runs nothing; building the project or running its dev, build or lint scripts loads the file, and in the newest wave opening the folder in VS Code is enough (Apiiro, 2026-11-09). Hijacked npm releases: Sonatype found concealed loaders in 12 releases across 10 hijacked packages with no install or postinstall hook, so disabling install scripts does not help (Sonatype, 2026-11-04). A fake employer: JFrog traced AccuraSoftHire, a decoy recruiter with ID-verified LinkedIn recruiters and job ads, whose take-home loads a look-alike npm package and whose scripted camera check fails and hands the candidate a command that installs the same loader (JFrog, 2026-11-09); StepSecurity says taking its site down, as had happened by 2026-11-13, does not end the operation (StepSecurity, 2026-11-13).

    The loader reads the latest outbound transaction of a hard-coded Ethereum wallet and decodes two IPv4 addresses from its recipient field (Apiiro, 2026-11-09), then fetches XOR-encoded JavaScript over plain HTTP on port 443, so blocking one server changes nothing; the wallet in the hijacked npm releases also appears in GitGuardian's GhostAction report, which Sonatype says does not establish a shared operator (Sonatype, 2026-11-04). Cleanup does not hold: 1,949 repositories were infected again after being publicly listed, and where owners cleaned up the stolen access often still worked; Apiiro counts roughly 2,300 developers reached (Apiiro, 2026-11-09).

    Exposure
    Any developer machine, CI runner or coding agent that builds or opens a checkout the worm reached, installs one of the hijacked npm packages, or runs a take-home from an unverified recruiter. Apiiro's checks are a semicolon followed by 200 or more spaces on any branch, a .vscode/tasks.json task with runOn set to folderOpen that runs node, and force-pushes in the GitHub Activity view whose commit is dated days before the push (Apiiro, 2026-11-09).
    Detection
    In process telemetry, a detached node child with no console started from a build script, editor or package entrypoint; in egress telemetry, build hosts and CI runners resolving public blockchain RPC endpoints and then making plain HTTP requests on port 443 to a bare IP address; in GitHub audit telemetry, force-pushes whose replacement commit repeats the replaced commit's author and message (Apiiro, 2026-11-09; Sonatype, 2026-11-04).

    Triage: blockchain developers legitimately call public RPC endpoints; the discriminator is a build or lint process in a project with no Web3 purpose doing so and then spawning a detached node child (Apiiro, 2026-11-09).

    Defender takeaway
    Treat a machine or runner that built an infected checkout as compromised and rotate what it could reach, because the stolen access, not the file, reinfects; run take-home tests from unknown recruiters only in a throwaway virtual machine with no tokens or keys, and block public blockchain RPC from CI runners (Apiiro, 2026-11-09; JFrog, 2026-11-09).

    Cited evidence

    Updates1

    Update26 Nov 2026 05:07 UTC

    SafeDep reports that PolinRider now plants a Python loader in GitHub repositories, hidden in a small utils package or in conftest.py with five import lines added to a start file, and found it in 375 public repositories under 260 accounts on 2026-11-24; no PyPI or npm package carries it, and because it uses only the standard library a scan of requirements files or a lockfile does not show it (SafeDep, 2026-11-24). When Python imports the file, the loader reads the input data of the newest transaction an Ethereum wallet sent to itself, writes it as JavaScript to a temporary file and runs node on it; the next stage is written to the standard input of a detached interactive node process, so it is absent from the process command line, and the node child starts from python or pytest. pytest runs the loader through conftest.py every time, and fixing an import error for the missing utils package also starts it. SafeDep did not contact the command server, so later stages are unobserved, and the stealer behavior it describes comes from the September chain. Its remedy is to delete the planted package, import lines and conftest.py loader, then clean the machines that push to the repository and replace their GitHub tokens and SSH keys (SafeDep, 2026-11-24).

    StepSecurity reports that the loader reached open-source projects through commits force-pushed on 2026-10-19 into pull requests that were still open, from one GitHub account, at AsyncAPI Generator, CircuitVerse and Open Food Facts; the malicious commits reuse a clean commit's message and date but are unsigned and carry a different committer name, and none of the merged pull requests contains the loader (StepSecurity, 2026-11-26). In the files it read, the added line is about 315 tab characters followed by the loader, so GitHub's diff looks empty, and the loader runs from a prefix on the build and dev scripts, from a Jest or PostCSS config file or from a hidden VS Code folder-open task. CircuitVerse's pull_request workflows ran on the poisoned fork commits with no approval step, and its maintainers confirmed the loader ran in the desktop build and deleted 40 installers that had stayed downloadable for more than a month; AsyncAPI's CI did not run it, and Open Food Facts' builds failed and its maintainers rotated a secret. StepSecurity counts 576 infected repositories of 622 it fetched, across 311 accounts, and assesses from a shared funding wallet that the fake interviews and these infections share an operator (StepSecurity, 2026-11-26).
