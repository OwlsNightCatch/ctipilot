    Hunt.io: exposed attacker directories show a crew staging a Swiss tax office's domain-controller database through ntdsutil install-from-media, a Java loader posing as the SQL Server JDBC driver and an exploit kit for edge services; the Swiss victim is unnamed, the access route is not shown and complete transfer is unconfirmed

    Hunt.io: crew staged a Swiss tax office's AD database via ntdsutil IFM; fake JDBC driver loader; edge exploit kit

    first published 2026-11-28 05:01 UTC

    Analysis

    Hunt.io recovered the contents of three exposed open directories and, reading the operators' own files, reports a domain-controller workflow against a Swiss tax office: a log records ntdsutil install-from-media creation, and a script copies the domain database and the registry hives from a controller share to a staging area, decodes them with a single-byte XOR and then requests removal of the install-from-media set (Hunt.io, 2026-11-25). Hunt.io says complete off-host transfer is not independently confirmed, that an NTLM-relay run against an internal LDAP service belongs to the same environment, and that the Swiss output begins after code execution was already available, so how the crew first got in is not shown (Hunt.io, 2026-11-25). The report names no canton, commune or federal body, and Hunt.io says it notified CISA before publishing (Hunt.io, 2026-11-25).

    The same files hold a Java class registered as a java.sql.Driver service provider that poses as Microsoft's SQL Server JDBC driver: its boot routine runs when an application loads the JAR, with no scheduled task needed, and either polls an HTTPS endpoint on TCP 8443 for commands passed to cmd.exe or decodes a packed file into an Apollo-derived Windows executable written under the Java temp directory and started from Java (Hunt.io, 2026-11-25). Hunt.io also describes a Poseidon-derived Linux implant behind a server labelled Mythic, a commercial employee-monitoring product whose agents the operators drive with custom clients, and a reconnaissance stage that sends base64-encoded output in chunks inside GET request paths; it says the artifacts show a Poseidon-derived build, which does not establish that it ran on an external victim, and an Apollo derivation with no verified runtime command-and-control configuration (Hunt.io, 2026-11-25). Staged exploits cover edge and remote-access services, among them Citrix NetScaler (CVE-2025-5777), FreePBX (CVE-2025-57819) and PHP2Shell (CVE-2026-109618 and CVE-2026-109619), and Hunt.io states that their presence establishes availability, not successful operation against any named target (Hunt.io, 2026-11-25). Hunt.io reads the operation as a Chinese-speaking, Southeast Asia-based cybercrime crew running a Russian-authored toolkit and ties it to no named group and no state sponsor (Hunt.io, 2026-11-25).

    Exposure
    Active Directory domain controllers and Java application servers that load third-party JARs; Hunt.io's other victims are a US hospital system, a US manufacturer and a Bangladeshi university; law firms and US federal agencies are mainly reconnaissance targets, and one law firm was attacked without success (Hunt.io, 2026-11-25).
    Detection
    On domain controllers, ntdsutil install-from-media creation that no administrator requested, followed by reads of the database and the SYSTEM and SECURITY hive copies from the share by another host and a removal of the media; NTLM relay and coercion activity against domain controllers; on Java application servers, a JAR whose service-provider descriptor names a com.microsoft.sqlserver.jdbc class that matches no vendor build, java writing an executable under the temp directory and then starting a child process, and HTTPS polling from application servers to TCP 8443; in proxy logs, GET paths carrying long base64 chunks (Hunt.io, 2026-11-25).
    Defender takeaway
    Hunt domain controllers for install-from-media creation and share-staged copies of the directory database and hives, and enforce SMB signing and LDAP channel binding, which Hunt.io names as the hardening against the relay and coercion tooling; review Java servers for unexpected JDBC providers, and treat the Swiss victim claim as a single-source reading of recovered files until a Swiss body or the victim comments.
