    SAP: suspicious activity in its GitHub development platform (Project Granite), with reports that employee authentication tokens were stolen and source code copied or modified; SAP says it found no evidence of unauthorized access to customer business data and has not said whether any delivered software is affected

    SAP confirms suspicious activity; GitHub, Project Granite and token theft reported; no customer-data access found

    first published 2026-11-28 05:06 UTC

    Analysis

    SAP told BleepingComputer and dpa that it identified suspicious activity, promptly took the necessary measures to protect its customers, and found no evidence of unauthorized access to customer business data on the investigation to date; it gave no vector, actor, discovery date or list of affected systems (BleepingComputer, 2026-11-27; tagesschau.de, 2026-11-27; Handelsblatt, 2026-11-27). A letter that dpa saw in part places the activity within SAP's platform for developer productivity and software delivery on GitHub and asks staff to check whether they must change credentials (translated from German) (tagesschau.de, 2026-11-27). Handelsblatt, citing company circles, says SAP detected the incident the week before and that software development was attacked (translated from German) (Handelsblatt, 2026-11-27).

    Reported by media from internal sources and not confirmed by SAP: DER SPIEGEL's insider says the attacker stole authentication tokens of SAP employees and used them to copy and also modify SAP source code on GitHub, and that the attackers may have had help from AI systems; heise, relaying Handelsblatt, reports that SAP restricted access to GitHub, stopped automated processes in software development and replaced signing keys; BleepingComputer, Handelsblatt and heise add that, according to SPIEGEL, SAP tracks the incident internally as Project Granite, a name SAP has not confirmed (BleepingComputer, 2026-11-27; DER SPIEGEL, 2026-11-26; heise online, 2026-11-27; Handelsblatt, 2026-11-27). SecurityWeek notes that none of the reports indicate tampered code reached software delivered to SAP customers, and WirtschaftsWoche that SAP has left open whether customers must act (SecurityWeek, 2026-11-27; WirtschaftsWoche, 2026-11-27). SAP is part of the Swiss public sector's estate: the Federal Audit Office says the federal administration runs SAP R/3, supported until the end of 2027 and being replaced with S/4HANA, and Inside IT reports an existing S/4HANA landscape in the canton of Zurich's administration; no Swiss impact is reported (EFK, 2023-05-10; Inside IT, 2026-11-27).

    Exposure
    Organisations that consume SAP-delivered code, packages or updates, or verify SAP signatures; SAP has said nothing on which artifacts or keys are in scope, and no source says delivered software is affected (SecurityWeek, 2026-11-27).
    Detection
    The reported behaviour is use of stolen employee tokens against a source-control platform; for SAP customers the observable is on their side of the boundary, namely the provenance of SAP-delivered artifacts and any signing-key change in SAP's own communications.
    Defender takeaway
    SAP customers should watch SAP's own security communications for which artifacts or signing keys are in scope and verify any key change through SAP's channel; no customer action has been published, and SAP declined to say whether customers pulling SAP code from GitHub should act (BleepingComputer, 2026-11-27). For your own pipelines, 1Password disclosed on 2026-11-25 an intrusion through an employee's corporate GitHub account (1Password, 2026-11-25); review how employee tokens reach source control and CI.
