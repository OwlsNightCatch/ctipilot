    Exposed application credentials: Microsoft sees an agentic framework search GitHub for OAuth and cloud application secrets and then sign in as the applications from 2026-10-28, and Todyl sees an operator use MSP applications to reach 27 organisations, government clients among them

    Entra app-credential abuse: agents hunt GitHub for secrets, an operator reaches MSP clients, government among them

    first published 2026-11-06 03:46 UTCupdated 2026-11-08 13:59 UTC

    Defender actions

    • In every Entra tenant you run or manage for others, list the app registrations that hold client secrets, starting with multitenant, delegated-admin (GDAP) and Partner Center apps, security-tool integration apps and Azure DevOps service connections, and search the service-principal and non-interactive sign-in logs for the invalid-secret or expired-secret errors AADSTS7000215 and AADSTS7000222 followed by a success for the same app; on any hit remove all client secrets, certificates and federated credentials on that app, including ones you did not add, disable its service principal if needed and rotate everything stored in any Key Vault it could read, because issued tokens stay valid until they expire.

    Analysis

    Microsoft reports that since August 2026 threat actors have used the agentic offensive framework ARTEX to submit large volumes of queries to public GitHub for secrets (Microsoft Threat Intelligence, 2026-11-05). As early as 2026-10-28 it saw successful service-principal sign-ins from two IP addresses, one a Tor exit node that may carry unrelated activity, across dozens of applications in several tenants, including a vendor-owned multitenant application whose credential was compromised at the source and used to reach multiple downstream tenants (Microsoft Threat Intelligence, 2026-11-05). Microsoft states that a similar campaign involving the same addresses was also reported by Todyl (Microsoft Threat Intelligence, 2026-11-05).

    Todyl, from its managed-detection telemetry, describes one operator who since 2026-11-01 has signed in to MSPs' Microsoft 365 and Azure environments as their own applications with stolen credentials that are still valid: about 45 app registrations at roughly 18 organisations were targeted, more than 33 authenticated, and 27 organisations were reached, among them the MSPs' downstream clients in government (Todyl, 2026-11-03). For nearly every credential the operator requests an Azure Resource Manager token, then a Key Vault token, and within minutes applications that had never been used start authenticating; MSP multitenant and delegated-admin apps and Partner Center tokens reach client tenants, one app sweeping 15 client tenants in about 10-second loops (Todyl, 2026-11-03). Todyl says no Microsoft vulnerability is involved and that it saw no persistence (Todyl, 2026-11-03). Its update of 2026-11-06 assesses the operator as an automated agentic credential crawler and the likely credential source as public repositories or web apps, citing credential scanning from the actor's address before the first sign-in, no sign of earlier compromise and custom-built affected apps (Todyl, 2026-11-03). After its detections fired on 2026-11-03 the operator switched to spoofed browser user agents and replayed users' refresh tokens, all blocked by Conditional Access (Todyl, 2026-11-03).

    Exposure
    Any Entra tenant, an MSP's or a customer's, that holds app registrations with client secrets, above all multitenant, delegated-admin and Partner Center applications and Azure DevOps service connections, security-tool integration apps among those abused (Todyl, 2026-11-03); Conditional Access for workload identities needs the Workload ID Premium licence and covers only single-tenant apps (Microsoft Threat Intelligence, 2026-11-05).
    Detection
    In Entra service-principal and non-interactive sign-in logs, an invalid-secret or expired-secret error for an application followed by a success, one address authenticating as service principals in several unrelated tenants within 24 hours, an Azure Resource Manager token followed at once by a Key Vault token and then by previously unused apps authenticating, and failed service-principal sign-ins from hosting space that never succeed, which success-only logic misses (Todyl, 2026-11-03). In Azure DevOps auditing, personal access token creation and first use, federated service connections and pipeline edits (Microsoft Threat Intelligence, 2026-11-05).

    Triage: the invalid-secret and expired-secret errors alone only show that someone holds an old or wrong credential for the app; Microsoft treats a failure followed by a success as the urgent case (Microsoft Threat Intelligence, 2026-11-05).

    Defender takeaway
    Inventory the client secrets on app registrations and hunt the sign-in pattern above in every tenant you run or manage, MSP-managed communal tenants included; on an affected app remove every client secret, certificate and federated credential, including those the actor added, and rotate what any Key Vault it could read holds, because tokens already issued stay valid until expiry (Microsoft Threat Intelligence, 2026-11-05).

    Update08 Nov 2026 13:59 UTC

    Todyl updated its post on 2026-11-06 after Microsoft's research of 2026-11-05: it says Microsoft's findings match its assessment that the activity is an automated, agentic credential crawler, and it now names public repositories or web apps as the likely source of the stolen secrets, citing credential scanning from the actor's address before the first sign-in, no sign of earlier compromise and custom-built affected apps (Todyl, 2026-11-03). It quotes Microsoft for the GitHub access path and the ARTEX name, and adds that the operator replays harvested material within minutes, in one case signing in as a connector's app about 2.5 minutes after downloading its archive (Todyl, 2026-11-03). Todyl says AI agents using or posting credentials in cleartext on the command line have been the largest contributor to the exposed credentials it has observed, and advises hunting service-principal and non-interactive sign-in logs back to at least 2026-10-28 (Todyl, 2026-11-03).
