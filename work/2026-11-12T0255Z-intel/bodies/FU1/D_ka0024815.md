### Apex Central Workaround

**1.** Make sure the Apex Central is using Build 7328 or later (latest patch available from [Download Center](https://downloadcenter.trendmicro.com/index.php?regs=nabu&prodid=1746)).

**2.** Open a command prompt as Administrator, then stop the related services:

```
NET STOP TMCM
NET STOP "TrendMicro Infrastructure"
NET STOP W3SVC
```
**3.** Download the file package from [PowerBox Global](https://powerbox-file.trend.org/publicdownload?share_id=ojEst9tfwGm9Gv5lf17Jk1PKgnA_2FKK3h_2ByVQvY_2FMp9Z62WL9ltqVvKsxV9R56plM) and extract the zip file into `\Control Manager\` folder.

**4.** Start related services:

```
NET START "TrendMicro Infrastructure"
NET START TMCM
NET START W3SVC
```
### Apex One Workaround

**1.** Make sure the Apex One server is at Build 18012 or later (latest patch available from [Download Center](https://downloadcenter.trendmicro.com/index.php?regs=nabu&prodid=1745)).

**2.** Open a command prompt as Administrator, then stop the Plug-in Manager and IIS services:

```
NET STOP W3SVC
NET STOP OfcAoSMgr
```
**3.** Rename `PCCSRV\PLM\PHP` folder to `PCCSRV\PLM\PHP_bak`.

**4.** Create `PCCSRV\PLM\PHP` folder.

**5.** Download the file package from [PowerBox Global](https://powerbox-file.trend.org/publicdownload?share_id=kXEe8lkB3sf_2FeIs12bhBXN4LCtmVDBP6m_2FRtCOxXzn9vSLtSYFxdDsoXohoXz0Aw) and extract the zip file into `PCCSRV\PLM\PHP` folder.

**6.** Copy `PCCSRV\PLM\PHP_bak\php.ini` to replace `PCCSRV\PLM\PHP\php.ini`.

**7.** Start the Plug-in Manager service and IIS service:

```
NET START W3SVC
NET START OfcAoSMgr
```
**8.** Move the `PCCSRV\PLM\PHP_bak` folder to separate storage as a backup. Do not leave it on the server's local storage, or scan tools might still detect the vulnerable PHP files in the backup folder.
