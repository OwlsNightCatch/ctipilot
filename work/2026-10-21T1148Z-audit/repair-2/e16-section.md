The mitigation does not ship as microcode in a Windows update for every affected chip: AMD lists an OS update only for EPYC 7002 and EPYC Embedded 7002 processors, and for Ryzen 3000 to 7030 series, Threadripper PRO 3000 WX and Ryzen Embedded V2000 it recommends the Platform Initialization versions in its table, delivered as OEM BIOS updates ([AMD Product Security, 2026-05-12](https://www.amd.com/en/resources/product-security/bulletin/amd-sb-7052.html)). Microsoft says the latest Windows builds enable the mitigation, not that they carry it for all processors ([MSRC, CVE-2025-54518](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2025-54518)), so a Windows build check cannot confirm a Ryzen host is protected, and a processor-ID query reports the CPU model rather than whether the mitigation is in place.

The CVE table that accompanied the earlier text belonged to other findings: Exchange CVE-2026-42897 and four OpenClaw CVEs, three of them paired with the wrong GitHub advisory, and an Exchange "no permanent patch" status that has since changed; it is removed. NCSC-NL lists Fedora and Lenovo among the vendors with updates ([NCSC-NL, 2026-05-15](https://advisories.ncsc.nl/advisory?id=NCSC-2026-0158)), but the package and model detail given earlier could not be confirmed and is dropped.
