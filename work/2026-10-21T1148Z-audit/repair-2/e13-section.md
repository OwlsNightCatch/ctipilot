The framework's source was not leaked: its README reads "Love - TeamPCP" and "Change keys and C2 as needed", its commits are authored as TeamPCP_OSS, and GitHub removed the repository shortly after publication, though not before it was forked, so the code remains available to other actors ([Datadog Security Labs, 2026-05-13](https://securitylabs.datadoghq.com/articles/shai-hulud-open-source-framework-static-analysis/)). Datadog's analysis describes no pull-request exploitation, `pull_request_target` targeting or expression-injection capability; the pwn-request vector belongs to the TanStack intrusion, not to this code. The framework harvests credentials where it already runs, reads Runner.Worker memory, poisons repository branches and npm packages with stolen tokens, and uses a workflow's own OIDC token only inside a release workflow and for a package it was hardcoded to target, so that path was manually targeted while the token-driven spread is opportunistic ([Datadog Security Labs, 2026-05-13](https://securitylabs.datadoghq.com/articles/shai-hulud-open-source-framework-static-analysis/)).

The analysis also documents what defenders need for a compromise check: an exit on Russian-locale systems, a daemon that deletes the home directory when a stolen GitHub token is revoked and must be disabled before rotation, and the hook files, commits and npm releases it leaves behind ([Datadog Security Labs, 2026-05-13](https://securitylabs.datadoghq.com/articles/shai-hulud-open-source-framework-static-analysis/)).
