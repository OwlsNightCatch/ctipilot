Mini Shai-Hulud's first wave hit four official SAP npm packages on 2026-04-29 with malicious preinstall scripts ([The Register, 2026-04-30](https://www.theregister.com/2026/04/30/supply_chain_attacks_sap_npm_packages/)). In the TanStack compromise no reconnaissance step is reported; the pull request added a bundled payload file that the `pull_request_target` benchmark job executed when it checked out and built the PR's merge ref, rather than slipping in lockfile, dependency or `.github` changes, and the release job never reached its publish step: tests failed, Publish Packages was skipped, and the malware published directly with the OIDC token it read from runner memory ([TanStack, 2026-05-11](https://tanstack.com/blog/npm-supply-chain-compromise-postmortem)). No npm token was needed for that publish, but the payload itself steals credentials and spreads with them ([StepSecurity, 2026-05-11](https://www.stepsecurity.io/blog/mini-shai-hulud-is-back-a-self-spreading-supply-chain-attack-hits-the-npm-ecosystem)).

The SLSA provenance on the malicious packages is genuine, an attestation of a compromised pipeline rather than a forgery, and no source ties it to EU procurement ([StepSecurity, 2026-05-11](https://www.stepsecurity.io/blog/mini-shai-hulud-is-back-a-self-spreading-supply-chain-attack-hits-the-npm-ecosystem)). The payload runs from the `prepare` script of an optional git dependency, not from `postinstall` ([TanStack advisory, 2026-05-11](https://github.com/TanStack/router/security/advisories/GHSA-g7cv-rxg3-hmpx)), and its memory scraper runs as `sudo python3`, so a filter for non-root readers of `/proc/<pid>/mem` misses it ([StepSecurity, 2026-05-11](https://www.stepsecurity.io/blog/mini-shai-hulud-is-back-a-self-spreading-supply-chain-attack-hits-the-npm-ecosystem)). The compromise is CVE-2026-45321, scored 9.6 ([TanStack advisory, 2026-05-11](https://github.com/TanStack/router/security/advisories/GHSA-g7cv-rxg3-hmpx)) and listed by CISA as known exploited on 2026-05-27 ([CISA KEV catalog, 2026-05-27](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json)). The cache action has no `save: false` input; restore-only caching is the separate restore action ([actions/cache README](https://github.com/actions/cache)), npm verifies attestations with `npm audit signatures` ([npm Docs](https://docs.npmjs.com/generating-provenance-statements)), and pinning actions to SHAs does not stop a `pull_request_target` workflow that builds fork code ([GitHub Security Lab, 2021-08-03](https://securitylab.github.com/resources/github-actions-preventing-pwn-requests/)).
