The two flaws are fixed by separate updates rather than one combined out-of-band release: Malware Protection Engine version 1.1.26040.8 fixes CVE-2026-41091, and Microsoft typically ships engine updates once a month or as needed ([MSRC, 2026-05-19](https://msrc.microsoft.com/update-guide/en-US/vulnerability/CVE-2026-41091)); Antimalware Platform version 4.18.26040.7 fixes CVE-2026-45498, which is a denial of service (CWE-400), not a privilege escalation ([MSRC, 2026-05-19](https://msrc.microsoft.com/update-guide/en-US/vulnerability/CVE-2026-45498)). The "Turn off routine remediation" policy named earlier only decides whether Defender remediates detected threats automatically or prompts the user ([Microsoft Learn](https://learn.microsoft.com/en-us/defender-endpoint/configure-remediation-microsoft-defender-antivirus)); it does not hold back engine updates, so the check is whether engine and platform updates reach each host.

The hunt signals given earlier, junction events on Defender paths and SYSTEM processes spawned by MsMpEng.exe, have no source. The behavior observed in the wild is renamed exploit binaries staged in the user's Pictures and Downloads folders ([Help Net Security, 2026-04-17](https://helpnetsecurity.com/2026/04/17/microsoft-defender-zero-days-exploited/)) and, for RedSun, a Defender remediation of an EICAR test string whose file rewrite is redirected so that the Cloud Files infrastructure runs the attacker's binary as SYSTEM ([Vectra AI, 2026-04-21](https://www.vectra.ai/blog/when-the-defender-becomes-the-door-bluehammer-redsun-and-undefend-in-the-wild)). The researcher has since said CVE-2026-41091 is RedSun and CVE-2026-45498 is UnDefend ([The Hacker News, 2026-05-21](https://thehackernews.com/2026/05/microsoft-warns-of-two-actively.html)).
