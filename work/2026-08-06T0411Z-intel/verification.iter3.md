### Surface contradiction

**F3 — 2026-08-06/hpe-aruba-sd-wan-orchestrator-rest-api-auth-bypass.** The two cited sources disagree on the affected-version scope, which is this entry's headline fact. HPE's HPESBNW05100 states: *"No branches outside of 9.6.x.x are affected by these vulnerabilities."* CERT-FR's CERTFR-2026-AVI-0969 — cited as corroborating — lists under "Systèmes affectés": *"EdgeConnect SD-WAN Orchestrator versions 9.6.2.x antérieures à 9.6.2.40210 / … 9.6.3.x antérieures à 9.6.3.40140 / **EdgeConnect SD-WAN Orchestrator versions 9.7.0.x antérieures à 9.7.0.43264**"* (raw page fetched this iteration). The entry follows HPE silently — title "9.6.x branch only", summary "Only the 9.6.x software branch is affected", and `cves[].affected` "No branches outside 9.6.x.x are affected". The vendor is the authority and the entry's choice is defensible, but an operator on a 9.7.0 build below 43264 who reads the entry concludes "not affected" while the European CERT feed that carried this advisory says otherwise. Surface it — one clause in the body plus a `Contradiction:` line in the run record's § Verification Notes.

**F4 — 2026-08-06/chaindrop-shai-hulud-npm-worm-onchain-c2-resolver.** OX Security, cited on this entry, reports a destructive trigger the entry does not carry: *"The malware has a dead man's switch trigger, to delete the current machine if the stolen GitHub token is revoked"* and, in its step list, *"Setup a dead man's drop triggering when the GitHub token is revoked"*. Elastic, the primary, does not mention it and recommends the opposite action: *"Revoke all GitHub tokens (PATs, session tokens) for any impacted machines"*. The entry silently follows Elastic, and its second published action tells readers to *"treat the AI-assistant, cloud, GitHub, Vault, SSH and Kubernetes credentials present on that host as disclosed and rotate them"* — an action that renders into the brief's aggregated § Action Items and that, if OX is right, may destroy a live infected host when executed in the wrong order. This is the most operationally consequential gap I found: containment sequencing (isolate and image before revoking) is exactly what a Tier 2/3 responder needs from this entry. Fix: state the divergence plainly — OX reports a revocation-triggered wiper, Elastic does not corroborate it — and let the action inherit the ordering caveat. The entry's sourcing note currently frames OX as a source of counts only, which is why the claim fell out.
