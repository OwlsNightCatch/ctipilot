    <h1>vBulletin &lt;= 6.2.1 (runMaths) Remote Code Execution Vulnerability</h1>
    
    <div>
        <h4 id="-software-link">• Software Link:</h4>
<p><a href="https://www.vbulletin.com">https://www.vbulletin.com</a></p>
<h4 id="-affected-versions">• Affected Versions:</h4>
<p>Version 5.7.5 and prior 5.x versions.</p>
<p>Version 6.2.1 and prior 6.x versions.</p>
<h4 id="-vulnerability-description">• Vulnerability Description:</h4>
<p>The vulnerable code is located within the <strong>/includes/vb5/template/runtime.php</strong> script.</p>

<p>The <code>$str</code> parameter is not sufficiently sanitized before being used in an <code>eval()</code> call at line 17. The regex used to validate the input parameter (at line 5) will filter the string only allowing for digits, parentheses, math and binary operators (the XOR, particularly). As such, this can be exploited to inject and execute (semi) arbitrary PHP code through &ldquo;<a href="https://github.com/arxenix/phpfuck">phpfuck</a>&rdquo; techniques.</p>
<p>The vulnerability could be exploited by e.g. administrator users, by editing a template/style in the admin panel and adding a specially crafted <code>{vb:math}</code> tag (which is a sort of wrapper around the <code>vB5_Template_Runtime::runMaths()</code> method).</p>
<p>However, this can also be exploited by unauthenticated attackers by abusing the <code>ajax/render/[template]</code> route, rendering a template which uses the <code>{vb:math}</code> tag with an user-tainted parameter. One of the possible templates that can be abused that way is the default &ldquo;<strong>pagenav</strong>&rdquo; template:</p>
<div class="highlight"><pre tabindex="0" style="color:#f8f8f2;background-color:#272822;-moz-tab-size:4;-o-tab-size:4;tab-size:4"><code class="language-html" data-lang="html">[...]

	{vb:set pagenav.currentpage, {vb:raw pagenav.pagenumber}}

	&lt;<span style="color:#f92672">a</span> <span style="color:#a6e22e">class</span><span style="color:#f92672">=</span><span style="color:#e6db74">&#34;js-pagenav-button [...] data-page=&#34;</span><span style="color:#960050;background-color:#1e0010">{</span><span style="color:#a6e22e">vb:math</span> <span style="color:#960050;background-color:#1e0010">{</span><span style="color:#a6e22e">vb:var</span> <span style="color:#a6e22e">pagenav</span><span style="color:#960050;background-color:#1e0010">.</span><span style="color:#a6e22e">currentpage</span><span style="color:#960050;background-color:#1e0010">}</span> <span style="color:#a6e22e">-</span> <span style="color:#a6e22e">1</span><span style="color:#960050;background-color:#1e0010">}&#34;</span>
</code></pre></div><p>Here, user input passed through the <code>pagenav[pagenumber]</code> parameter will be assigned to the &ldquo;<strong>pagenav.currentpage</strong>&rdquo; template variable, which is later used within a <code>{vb:math}</code> tag, thus passed to the <code>vB5_Template_Runtime::runMaths()</code> method, which in turn will pass this string to <code>eval()</code>, eventually resulting in execution of (semi) arbitrary PHP code on the web server.</p>

<h4 id="-solution">• Solution:</h4>
<p>Apply the vendor patch or upgrade to version 6.2.2 or later.</p>
