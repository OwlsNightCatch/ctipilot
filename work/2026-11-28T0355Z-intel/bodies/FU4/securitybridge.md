On 26 and 27 November 2026, SAP confirmed a security incident in its software development environment. Press reports say attackers used stolen employee tokens to copy and alter SAP source code on GitHub. So far, SAP has confirmed far less.

**Below are the facts as they stand, and what SAP customers can do now.**

## What SAP has confirmed

SAP says it identified suspicious activity and took measures to protect its customers and the security of its services. In its statement to [BleepingComputer](https://www.bleepingcomputer.com/news/security/sap-confirms-security-incident-after-suspicious-github-activity/), SAP says it has **“found no evidence of unauthorized access to customer business data.”** SAP has not said which environments, repositories or products are involved, and a spokesperson declined to give more detail.

The German press agency dpa saw part of an internal letter to SAP employees. The letter placed the suspicious activity on GitHub, which SAP uses for developer productivity and software deployment. It asked staff to check whether they needed to act, for example by changing their login credentials. It went out days before SAP publicly confirmed the incident.

As of 27 November, SAP’s [Trust Center](https://www.sap.com/about/trust-center/security/incident-management.html) carries no statement about the incident.

## What is reported but not confirmed

*   **Der Spiegel, citing an insider:** attackers stole authentication tokens belonging to SAP employees and used them to copy and alter SAP source code on GitHub. SAP is handling the incident internally under the code name “Project Granite”.
*   Der Spiegel’s sources also say the attackers may have used AI agents. No report explains what role, if any, AI played.
*   **Handelsblatt, citing insiders:** SAP restricted GitHub access, paused automated development processes and replaced its code-signing keys. Many development teams were affected.

**SAP has not officially confirmed any of these points.**[SecurityWeek](https://www.securityweek.com/sap-confirms-cyberattack-source-code-reportedly-compromised/) has summarized the Spiegel and Handelsblatt reporting.

## What we don’t know yet

*   Which repositories were accessed, and whether they hold public or private code.
*   Whether any altered code was published, or reached software and updates delivered to customers.
*   How the tokens were obtained, and what permissions they had.
*   Whether customers who use SAP code from GitHub, npm or other registries need to act. SAP has not said.

## Is this linked to Mini Shai-Hulud?

A link is possible, but no one has shown one. On 29 April 2026, SAP’s open-source npm packages for the Cloud Application Programming Model and the MTA Build Tool were compromised with credential-stealing malware (SAP Note 3747787). SAP’s [FAQ on that incident](https://www.sap.com/norway/documents/2026/05/8203a8b9-4d7f-0010-bca6-c68f7e60039b.html) is titled “Mini Shai Hulud”. It lists GitHub tokens, npm tokens, GitHub Actions secrets and personal access tokens among the credentials the malware could steal.

Project Granite reportedly involves stolen GitHub tokens of SAP employees. That makes a connection worth asking about. **It is not evidence of one.**

## What SAP customers can do now

Nothing published so far shows that customer systems are affected. These steps make sense whatever the investigation finds:

1.   **Know what SAP code you pull in.**List the SAP-published open-source code you use, such as CAP, UI5 tooling and SDKs from GitHub, npm or Maven. Pin versions, and review updates before taking them until SAP gives guidance.
2.   **Watch SAP’s channels.**Check the Trust Center, security notes and knowledge base articles in SAP for Me, and the next Patch Day on 8 December.
3.   **Be ready for key changes.**If SAP confirms it replaced code-signing keys, check whether your signature checks or trust stores need updating.
4.   **Check your own tokens.**The reported attack pattern applies to your landscape too. Review GitHub tokens and personal access tokens, CI/CD secrets, BTP service keys and destinations with stored credentials. Narrow their scope, shorten their lifetime and rotate them.
5.   **Watch code changes in your SAP systems.**Know who can change code in production, and alert on code that arrives outside the normal transport path.

**SecurityBridge is following this incident closely and will post an update as soon as concrete information calls for action.**
