Optimizely says an unauthorized party exploited a vulnerability in Experimentation and used it to add malicious JavaScript to some customer projects, that it has fixed the vulnerability and removed the injected code, and that it secured affected user accounts; the status entry names no flaw class, CVE, count or stolen credentials ([Optimizely, 2026-11-17](https://status.optimizely.com/incidents/ftw0fh9wx43z)). That settles the access question for the Optimizely files only; the entry's statement that the Kissmetrics, StorifyMe and minute-ly mechanism is unknown stands.

Report URI, which found the injection, counts 188 snippets belonging to 178 organisations that served the code on 2026-11-16 and calls that a floor; its first injection into an Optimizely snippet is at 04:21 UTC, the card skimmer was added to the clipper at 13:43 UTC, a mass clean-up ran between about 20:40 and 21:10 UTC, and a snippet that was cleaned and then re-infected shows the writer still had access at that point ([Report URI, 2026-11-16](https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/)). The Optimizely files therefore carried the code from 2026-11-16, not from 2026-11-13 as the Ohey figures the entry first relied on suggested; the earlier Kissmetrics, StorifyMe and minute-ly wave is not in the 178 ([Report URI, 2026-11-16](https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/)).

The injected loader came in three forms: a plain script tag, the same address hidden in base64 and decoded with atob(), which a search for the host name misses, and a full inline copy that runs through eval ([Report URI, 2026-11-16](https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/)). Cards entered in hosted payment iframes were out of the skimmer's reach, while cards typed into a site's own form fields were not ([Report URI, 2026-11-16](https://blog.report-uri.com/worlds-largest-brands-infected-with-malware-via-optimizely/)).
