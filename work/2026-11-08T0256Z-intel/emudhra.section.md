Apple's support page of 2026-10-30 says that the curl, git, python3, ruby, perl and openssl that ship with macOS or the Xcode command-line tools check certificates against /etc/ssl/cert.pem and apply neither Apple's block nor revocation, so they keep trusting the intermediates until a future macOS update, which Apple has not dated; apps and tools that keep their own root list need the developer's update ([Apple, 2026-10-30](https://support.apple.com/de-de/149555)). Administrators can remove emSign ECC Root CA - G3 from the file and, to stop the six Sectigo cross-signed certificates as well, AAA Certificate Services; a macOS software update can replace the file with Apple's version, so the check has to be repeated after each update until the one that carries Apple's change ([Apple, 2026-10-30](https://support.apple.com/de-de/149555)). heise reports that macOS 27.2, which brought no fix, undid the workaround for users who had applied it, that the macOS 27.3 developer beta replaces the file, and that the final release will take at least until December ([heise, 2026-11-06](https://www.heise.de/news/macOS-27-3-Apple-behebt-letztes-eMudhra-Leck-aber-es-wird-dauern-11513443.html)).
