# Cisco Security Advisory

# Cisco Informational for Emergency Distrust of eMudhra Root and Intermediate Certificate Authorities

- Between October 17 and October 20, 2026, a critical security compromise involving Certificate Authorities that are managed by **eMudhra** was uncovered.
A security researcher demonstrated that the private keys for eight eMudhra intermediate certificates were fundamentally broken due to an unprecedented error in their Key Generation Ceremony (KGC) in April 2025. This allows anyone to brute-force acquire these private keys within seconds. For more information, see [eMudhra Intermediate CA Compromise](https://emudhra.we-have-a-problem.com/) and the Cisco Talos blog post [Compromised eMudhra intermediate certificates](https://blog.talosintelligence.com/compromised-intermediate-certificates/).
For information about Splunk products and offerings, see [Compromised eMudhra Intermediate Certificate Authorities on Splunk Products - October 2026](https://advisory.splunk.com/advisories/SVD-2026-1014).
**Important:** If a product is not listed within this advisory, Cisco's review indicates that the product is not affected by this vulnerability.

- ### Impact Anyone in possession of these weak private keys can issue **fraudulent TLS/HTTPS certificates** for any domain on the internet. The eight compromised Issuing CAs include:
  - **6 TLS Issuing CAs:** Covering Domain Validated (DV), Organization Validated (OV), and Extended Validation (EV).
  - **2 Code Signing CAs:** Allowing for the signing of malicious software that appears to come from a trusted source.
**Critically**, all eight certificates were **cross-signed by Sectigo’s AAA Certificate Services root** in May 2025. This cross-signature ensured that the compromised keys were trusted by almost every device, browser, and operating system globally, even if those systems did not natively trust the eMudhra roots.
This issue impacts any Cisco product that trusts these compromised eMudhra intermediate certificates, regardless of whether the trust is managed through Cisco's Trusted Root Store (TRS) bundles, embedded certificates, or other third-party trust mechanisms.
