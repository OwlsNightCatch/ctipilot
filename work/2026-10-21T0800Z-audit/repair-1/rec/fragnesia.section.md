Aikido's statement that working Kubernetes proof-of-concept exploits have been published concerns the Dirty Frag family as a whole, which it defines as CVE-2026-43284, CVE-2026-43500 and CVE-2026-46300, and its link for the container-escape risk is Ubuntu's page for CVE-2026-43284 ([Aikido Security, 2026-09-04](https://www.aikido.dev/blog/dirty-frag)). No cited source describes a Kubernetes exploit for CVE-2026-46300 itself; its public exploit overwrites `/usr/bin/su` in the page cache ([Help Net Security, 2026-05-14](https://www.helpnetsecurity.com/2026/05/14/fragnesia-cve-2026-46300-linux-lpe-vulnerability/)). On a host, that exploit shows as an unprivileged process creating user and network namespaces and installing an ESP security association over NETLINK_XFRM before `su` starts a root shell ([Wiz Research, 2026-05-13](https://www.wiz.io/blog/fragnesia-linux-kernel-local-privilege-escalation-via-esp-in-tcp)).
