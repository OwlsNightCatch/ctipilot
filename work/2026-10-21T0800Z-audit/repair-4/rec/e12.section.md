Cisco scopes both flaws to Cisco ISE and ISE-PIC "regardless of device configuration" on releases before the fixed patch levels (3.1 Patch 12, 3.2 Patch 11, 3.3 Patch 12, 3.4 Patch 7, 3.5 Patch 4), so a node already on its train's fixed patch is not affected ([Cisco PSIRT, 2026-09-16](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-ISE-ABP-VNSW7Tn5); [Cisco PSIRT, 2026-09-16](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-ise-multi-hrP9jQSQ)). Cisco's access-log check is to look for suspicious usernames in each node's access.log, and its command, filtering `show logging application ise-kong/access.log` output, is a non-exhaustive example rather than a fixed search string ([Cisco PSIRT, 2026-09-16](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-ISE-ABP-VNSW7Tn5)).
