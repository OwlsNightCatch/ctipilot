With reverse-proxy authentication on, legitimate logins also arrive as an `X-WEBAUTH-USER` header, which the authenticating proxy sets; the advisory's exploit is that header sent on a direct connection from any other source, which signs the sender in as the named user with no password and no cookie ([GitHub Security Advisory GHSA-f75j-4cw6-rmx4, 2026-06-21](https://github.com/go-gitea/gitea/security/advisories/GHSA-f75j-4cw6-rmx4)).
