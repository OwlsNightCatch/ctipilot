CISA added CVE-2026-40217 to its Known Exploited Vulnerabilities catalog on 2026-11-18 on evidence of active exploitation it does not describe ([CISA, 2026-11-18](https://www.cisa.gov/news-events/alerts/2026/11/18/cisa-adds-four-known-exploited-vulnerabilities-catalog)). LiteLLM's own advisory describes the flaw as a sandbox escape using bytecode-level techniques at POST /guardrails/test_custom_code that gives code execution in the proxy process, root in the default Docker image, requires a proxy-admin credential in default configurations, rates it Moderate at CVSS 4.0 5.9 and offers blocking the endpoint at the reverse proxy as the workaround; it names 1.83.11 as the fix in its text and 1.83.10 in its patched-versions field ([LiteLLM advisory, 2026-05-07](https://github.com/BerriAI/litellm/security/advisories/GHSA-wxxx-gvqv-xp7p)). The analysis above now uses the advisory's description in place of the earlier statement that the guardrail runs attacker-supplied Python through exec(); v1.83.14-stable remains the fix for the whole chain.
