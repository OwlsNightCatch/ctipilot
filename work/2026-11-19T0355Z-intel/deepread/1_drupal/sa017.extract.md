`drupal`
Drupal core ships with an `install.php` file for installing Drupal core.

Under specific conditions, an attacker can use the installer to attempt to reinstall Drupal. This can lead to a site takeover or remote code execution.

Some exploit paths are mitigated if the web server cannot write to or change permissions on `settings.php`. In addition to upgrading, the Drupal Security Team recommends [securing the Drupal installer](https://www.drupal.org/docs/administering-a-drupal-site/security-in-drupal/securing-the-installer-installphp) after installation.

*Discovered by Anthropic's OSS Scanner, as vulnerability ANT-2026-GMRPK0BU.*

#### Drupal Steward protection:

This issue is being protected by [Drupal Steward](https://www.drupal.org/steward). Sites that use Drupal Steward are already protected from known attack vectors, but sites should upgrade in the near future in case additional attack vectors are discovered.

Install the latest version:

**Drupal 11**

- If you use Drupal 11.4.x, update to [Drupal 11.4.13](https://www.drupal.org/project/drupal/releases/11.4.13).
- If you use Drupal 11.3.x, update to [Drupal 11.3.22](https://www.drupal.org/project/drupal/releases/11.3.22).
- Drupal 11.2.x and below are end-of-life and do not receive security coverage.

**Drupal 10**

- If you use Drupal 10.6.x, update to [Drupal 10.6.22](https://www.drupal.org/project/drupal/releases/10.6.22).
- Drupal 10.5.x and below are end-of-life and do not receive security coverage.

[Drupal 8](https://www.drupal.org/psa-2021-06-29) and [Drupal 9](https://www.drupal.org/psa-2023-11-01) have both reached end-of-life.

#### If you cannot upgrade immediately:

Follow the [instructions for securing the Drupal installer](https://www.drupal.org/docs/administering-a-drupal-site/security-in-drupal/securing-the-installer-installphp) to protect your site from attacks.
