# One leftover build path links an infostealer, a remote-access tool, and a ransomware family

*   Date:2026-09-01

_VMRay Labs Note. By Emre Güler, VMRay Labs. 01.09.2026._

**Key finding.** A single artifact left in a binary during compilation, a developer’s home directory path, connected a Rust-based infostealer that VMRay Labs calls “Zer0day Stealer” to a separate HVNC remote-control tool and to a recently reported ransomware family, ENIGMA Locker. Searching for that one string surfaced earlier versions of the stealer, multiple droppers, and a wider cross-platform malware operation, a reminder that the small artifacts a build process leaves behind can undo an operator’s anonymity.

[](https://www.vmray.com/wp-content/uploads/2026/09/1.png)

### What was observed

Zer0day Stealer is written in Rust and carries a build path, `/home/tcherber/.cargo/`, baked into the binary. That path is the thread. A search for it turned up earlier versions of the stealer and, more tellingly, an unrelated ransomware family, ENIGMA Locker, carrying the same path. The same developer is also the likely author of an HVNC remote-control sample often deployed alongside the stealer: it shares the home path and was compiled within seconds of related samples. Across the set, compilation timestamps showed everything was built within a span of a few weeks.

The search also surfaced the surrounding toolkit: a dropper written in C, another in Rust, and a PowerShell loader that abuses the legitimate `certutil` utility, all of which deliver a variant of the same stealer and HVNC pair.

A few details stand out. The stealer exfiltrates crypto wallets and browser credentials, and newer versions show active development, from changed C2 addresses to file-extension-based theft targeting Office documents and VPN configuration files. The HVNC sample ships with a hardcoded password and uses a single-byte patch to evade AMSI and ETW, the Windows interfaces security tools rely on to inspect activity. One dropper variant shows the build path changed to `/root/.cargo`, suggesting the developer moved to a different machine. And the C2 interface leaked further evidence of cross-platform builds for Windows, Linux, and macOS, alongside other tools labelled “FUD-Crypter,” “Botnet,” and “C2 Agent.”

[](https://www.vmray.com/wp-content/uploads/2026/09/2.png)

### Why it matters

The theft capability is ordinary. The lesson is in how the operation was mapped. Strings like build paths, PDB filenames, and other compilation artifacts are easy for a developer to overlook and hard to scrub after the fact, and they persist across otherwise unrelated tools. Here, one path was enough to cluster a stealer, a remote-access tool, and a ransomware family under a common developer, and to expose an actively developed, multi-platform malware line. For defenders and threat researchers, those artifacts are a durable pivot for attribution and for finding related samples that no signature would connect.

[](https://www.vmray.com/wp-content/uploads/2026/09/3.png)

### FAQ

**What is an HVNC tool?** A “hidden virtual network computing” tool that gives an attacker interactive remote control of a machine in a hidden desktop session, so the activity stays invisible to the person using the computer.

**What are AMSI and ETW?** Windows interfaces that security products use to inspect scripts and system activity. Malware that tampers with them, as this HVNC sample does, is trying to blind those defenses.

**Why does a build path leak matter?** Compilation artifacts such as a developer’s home-directory path are often left in binaries unintentionally. Because the same artifact can appear across unrelated tools, it lets researchers link samples, and sometimes a developer, that would otherwise look unconnected.

[](https://www.vmray.com/wp-content/uploads/2026/09/4.png)
