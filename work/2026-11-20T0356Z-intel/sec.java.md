Three more vendors published product status. Elastic says Elasticsearch 7.17.3 and later is affected with mitigating factors: remote code execution needs an authenticated user with at least read access on an affected CPU architecture, while unauthenticated actors can cause denial of service; Logstash 8.6.2 and later is affected only through the elastic_integration filter when an ingest pipeline decodes Base64 from an untrusted source, with a crash as the result, and Kibana, Beats, Elastic Agent, APM Server, ECK and Elastic Maps Server are not affected ([Elastic, 2026-11-19](https://discuss.elastic.co/t/java4shell-remote-code-execution-rce-vulnerability-cve-2026-114938/391703)). Elastic plans fixes in 8.19.26, 9.4.10, 9.5.7 and 9.6.0 with a bundled JDK 27.0.1.1+4 and gives no dates, hot-fixed Elastic Cloud Serverless on 2026-11-18, and says fewer than about 5% of Elastic Cloud Hosted deployments, on Azure only, run an affected CPU architecture; a self-managed node is affected only on an x86-64 CPU with AVX512_VBMI ([Elastic, 2026-11-19](https://discuss.elastic.co/t/java4shell-remote-code-execution-rce-vulnerability-cve-2026-114938/391703)).

Broadcom's Tanzu advisory TNZ-2026-1107 says several Tanzu products ship affected Java runtimes and lists released fixes: Java Buildpack 5.5.0 and 5.5.1, Ruby Buildpack 1.10.104, Tanzu OpenJDK 17.0.21.1+5, 21.0.13.1+5 and 25.0.5.1+5 and Foundation Core 3.1.19, 3.3.10 and 11.0.3, where the identity service and CredHub carry an affected Java 25 runtime that Tanzu has not yet confirmed from the bill of materials; it names -XX:-UseBASE64Intrinsics as the preferred workaround ([Broadcom, 2026-11-19](https://support.broadcom.com/web/ecx/support-content-notification/-/external/content/SecurityAdvisories/0/39639)). Palo Alto Networks lists fixed builds of Privilege Threat Analytics, Remote Access Connector and the Secure Access HTML5 Gateway, says PAN-OS is not affected, offers no workaround and is not aware of any malicious exploitation ([Palo Alto Networks, 2026-11-20](https://security.paloaltonetworks.com/CVE-2026-114938)). None of these statuses changes the exploitation picture above.
