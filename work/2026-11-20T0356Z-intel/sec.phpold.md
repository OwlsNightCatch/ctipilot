PHP released 8.5.13, 8.4.28, 8.3.37 and 8.2.36 on 2026-11-19 ([PHP, 2026-11-19](https://www.php.net/ChangeLog-8.php)). They fix CVE-2026-115560, the third path that the October releases left open, and disable session upload progress by default, so the interim advice to keep it off now applies only to hosts that have not updated; where upload progress is explicitly enabled, every reader and writer of the session store must still use one session.serialize_handler ([PHP, 2026-11-19](https://github.com/php/php-src/security/advisories/GHSA-658j-r8rw-q6mx)). PHP also calls CVE-2026-129481, a use-after-free of a stale session filename that affects PHP 8.3 and later, an incomplete fix for CVE-2026-109619, and CVE-2026-129182, for PHP 8.5 only, covers further scenarios after the 8.5.12 fix, and the 2026-11-19 builds carry both fixes ([PHP, 2026-11-19](https://github.com/php/php-src/security/advisories/GHSA-g3vh-838c-65v7); [PHP, 2026-11-19](https://github.com/php/php-src/security/advisories/GHSA-2fjv-p558-g82m)). The same release fixes an unauthenticated PHP-FPM request-smuggling flaw, CVE-2026-129289, that needs a front end reusing FastCGI backend connections ([PHP, 2026-11-19](https://github.com/php/php-src/security/advisories/GHSA-qc49-hpvq-g2w6)).
