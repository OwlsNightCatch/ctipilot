The same Perforce advisory fixed a second flaw, CVE-2026-115732, an authorization bypass in the certificate-name matching of Puppet's authorization library, scored CVSS 4.0 9.0 by the CNA and 9.5 by OpenVox: a CA-signed certificate whose name extends or shortens an authorised host name is authorised as that host ([ENISA EUVD, 2026-11-03](https://euvdservices.enisa.europa.eu/api/enisaid?id=EUVD-2026-116493)). Neodyme's example is that an attacker who got a certificate for `evil.target.lab.local` can authenticate as `target.lab.local`, then fetch that host's catalog, which can carry configuration files with database credentials and API tokens, push spoofed facts and add exported resources ([Neodyme, 2026-11-03](https://neodyme.io/en/blog/puppet_rce/)). Where the CA autosigns, such a certificate can be requested for a name that does not exist yet, and OpenVox says autosign is not the default but is common in real deployments ([OpenVox, 2026-11-03](https://github.com/OpenVoxProject/trapperkeeper-authorization/security/advisories/GHSA-q4hm-33rc-572g)); NCSC.ch adds that in Puppet Enterprise the bypass also enables CA administration and remote command execution on managed nodes ([NCSC.ch, 2026-11-19](https://security-hub.ncsc.admin.ch/#/posts/13204)).

The fix is in the same Puppet Enterprise builds, in Puppet Core 9.1.3 and 8.22.2 and, for OpenVox Server and OpenVoxDB, in 9.2.0 and 8.18.0 ([SecurityWeek, 2026-11-18](https://www.securityweek.com/critical-perforce-puppet-rce-exploited-in-attacks/); [OpenVox, 2026-11-03](https://github.com/OpenVoxProject/trapperkeeper-authorization/security/advisories/GHSA-q4hm-33rc-572g)). CISA's catalog entry covers only CVE-2026-115731 ([CISA, 2026-11-17](https://www.cisa.gov/news-events/alerts/2026/11/17/cisa-adds-one-known-exploited-vulnerability-catalog)); NCSC.ch labels the pair actively exploited with a proof of concept available, and the Reddit intrusion report it rests on describes a CVE-2026-115731 intrusion, so exploitation of CVE-2026-115732 itself is not established ([NCSC.ch, 2026-11-19](https://security-hub.ncsc.admin.ch/#/posts/13204); [The Hacker News, 2026-11-18](https://thehackernews.com/2026/11/hackers-exploiting-critical-puppet-rce.html)). NCSC.ch's temporary measures are to disable certificate autosigning, enforce strong request validation, audit the issued certificates for colliding names and review the CA configuration for signs of compromise.
