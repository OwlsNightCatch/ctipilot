## What is Ruby2Shell?

CVE-2026-132825, known as Ruby2Shell, is a vulnerability in Ruby, a programming language runtime used to build and run web applications. It sits in the code that changes the case of a string, for example turning it to uppercase, when that text uses a single-byte encoding such as ISO-8859-1 or Windows-1252. Converting certain characters can write one byte past the end of a memory buffer that Ruby allocated for the result.

An attacker who can get such a string into an affected application may be able to use that one-byte overwrite as a starting point to run commands on the server where Ruby is running. Reaching that outcome takes further work specific to each application, but the vulnerability gives an attacker a foothold in memory that the application did not intend to expose.

## How did Ruby2Shell come to light?

Researchers at Veria Labs found the vulnerability and named it Ruby2Shell, echoing the earlier php2shell naming, according to heise online. Ruby published its security announcement and released fixed versions on November 18, 2026, and the CVE record, CVE-2026-132825, followed on November 19, 2026.

## Which Ruby versions are affected?

|---|---|---|
| Ruby 3.3 branch | Before 3.3.14 | 3.3.14 | 
| Ruby 3.4 branch | 3.4.0 before 3.4.13 | 3.4.13 | 
| Ruby 4.0 branch | 4.0.0 before 4.0.10 | 4.0.10 | 
| Ruby 3.2 and earlier | 3.2 and earlier | Not yet available | 

- The application must process text in a single-byte encoding such as ISO-8859-1 or Windows-1252, rather than Ruby’s default UTF-8.
- The application must run a function that changes the case of a string, such as converting it to uppercase, on text an attacker controls.
- Ruby applications built with Rails or with Sinatra in its classic style are affected in their default configuration.

Rails applications and Sinatra applications running in their default configuration face the earliest exposure, along with any Ruby application that changes the case of external text in a single-byte encoding.

## How do I fix Ruby2Shell?

Apply the fix by updating Ruby to 4.0.10, 3.4.13, or 3.3.14, depending on the branch in use, since the vulnerability lives in the interpreter itself. Updating application gems or frameworks alone does not fix it. No workaround has been published, so systems on Ruby 3.2 or earlier should move to a supported release line.

1. Identify every Ruby interpreter version running on application servers, background workers, and container images.
2. Update affected systems to Ruby 4.0.10, 3.4.13, or 3.3.14, matching the branch in use.
3. Rebuild container images and restart application servers and workers after the update.
4. Move any system running Ruby 3.2 or earlier to a supported release line, since no fix exists for it.
5. Review application code for functions that change the case of text coming from outside the application.

## Is Ruby2Shell related to earlier vulnerabilities?

Ruby fixed three different bugs in its regular expression engine in October 2026, which were linked to vulnerabilities in GitLab that compiled patterns from attacker-controlled text. Those earlier bugs are unrelated to the case-conversion issue behind CVE-2026-132825, which involves no regular expressions at all.
