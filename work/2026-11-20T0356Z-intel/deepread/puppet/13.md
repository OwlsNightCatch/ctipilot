<p dir="auto">The zip-like code in match-domain will stop at the shorter hostname entry and compare the zipped values without a length  comparison. This means that a cert issued for evil.target.lab.local will match target.lab.local. With autosign enabled (which is not  default, but common in real world deployments), this will lead to the following attack scenario:</p>
<ul dir="auto">
<li>Attacker does CSR to puppet with evil.somehost.company.tld. As this host ist not registered yet, a cert for client auth will be issued</li>
<li>Attacker uses the cert for evil.somehost.company.tld to impersonate somehost.company.tld, e.g
<ul dir="auto">
<li>Grab puppet catalog with provisioned secrets</li>
<li>Push fake facts / software versions to the puppet master</li>
</ul>
</li>
</ul>
