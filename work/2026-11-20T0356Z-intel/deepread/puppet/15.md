# PE 2026.0.1

On this page**:**

Released November 2026

Puppet Enterprise (PE) 2026.0.1 delivers security, platform support, and reliability improvements, including stricter authorization rule matching, enhanced protection of Forge authorization tokens, support for Oracle Linux 10 x86\_64 agents, and improvements to cloud database, backup, and orchestration operations. This release also includes fixes for multiple security vulnerabilities.

## Puppet Enterprise<sup>®</sup> lifecycle update

Starting in August 2026, Puppet Enterprise transitioned its software support model from Long-Term Support (LTS) and Short-Term Support (STS) to the Latest and Latest-1 model. This change applies to both PE and PE Advanced. To learn more, see [Puppet Enterprise Platform Support Lifecycle](https://www.puppet.com/products/puppet-enterprise/support-lifecycle).

- Puppet Enterprise (PE) 2026 is our leading-edge PE release stream (also referred to as Latest).
- For important information about upgrading to PE 2026, see [Upgrade Puppet Enterprise](https://help.puppet.com/upgrading_pe.htm).

- If you're on PE 2025, your release series is designated Latest-1 and continues to receive security updates, defect fixes, and technical support. Release notes and other information are available in the [PE 2025 documentation.](https://help.puppet.com/pe/2025.11/topics/puppet-enterprise.htm)

- If you're on PE 2023.8, the final release series under Puppet Enterprise's legacy Long-Term Support (LTS) model,  you're currently in the overlap support period, which ends on February 27, 2027. You'll find release notes and other information in the [2023.8 documentation](https://help.puppet.com/pe/2023.8/topics/puppet-enterprise.htm).
- Customers running releases that have reached end of maintenance and support (EOMS) are encouraged to upgrade to a currently supported Puppet Enterprise release.

## Enhancements

**Authorization rules now use stricter certificate name matching**

Authorization rules in `auth.conf` now match certificate names more strictly. Rules that specify a hostname match only certificates with that exact name. Wildcard rules such as `*.example.com` now match only names under `example.com` and no longer match `example.com` itself. If you rely on a wildcard rule to allow the bare domain, add a separate rule for that domain name.

## Platform support

**Agent platforms added**

This release adds support for the Puppet agent on the following operating system platforms:

- Oracle Linux 10 x86\_64

## Resolved issues

**Cloud database installs no longer grant CONNECT access to PUBLIC**

In PE 2025.12.0 and 2026.0, cloud database deployments could leave `CONNECT` privileges granted to `PUBLIC` on most PE databases. This allowed other roles on the same database instance to establish connections to those databases. PE now revokes `CONNECT` access from `PUBLIC` for cloud database deployments, aligning cloud database behavior with local installations. This issue is resolved in PE 2025.12.1 and 2026.0.1. **\[PE-47115\]**

Database connection permissions now converge correctly on migrated Cloud SQL deployments

In PE 2025.12.0 and 2026.0, Puppet runs on deployments migrated from local PostgreSQL to Google Cloud SQL could repeatedly report changes because database connection permissions were not applied correctly for some PE databases. As a result, the deployment might never reach a converged state. This issue is resolved in PE 2025.12.1 and 2026.0.1. **\[PE-47136\]**

**pe-bolt-server now validates upload file paths**

In previous releases, the `pe-bolt-server` upload file handler did not sufficiently validate file paths supplied in upload requests. PE now validates upload paths to ensure uploaded files remain within the intended job cache directory. This issue is resolved in PE 2025.12.1 and 2026.0.1. **\[PE-47314\]**

**Daily log rotation no longer interrupts running plans**

In previous PE versions, daily log rotation could restart the `pe-plan-runner` service while a plan was running. This caused orchestrated plans to abort before completion and could affect infrastructure workflows such as replica upgrades. This issue is resolved in PE 2026.0.1, 2025.12.1 and 2023.8.13 **\[PE-47319\]**

**Certificate-only restores no longer cause CA inconsistencies on database-backed deployments**

In PE 2026.0 and 2025.12.0, using `puppet-backup restore --scope=certs` on a primary configured to use the database CA backend could leave the restored CA files out of sync with the CA data stored in the pe-ca database. As a result, SSL communication and configuration operations could fail. This issue is resolved in PE 2026.0.1 and 2025.12.1 **\[PE-47558\]**

**CD4PE jobs no longer fail with Puppet agent 9.1.1**

In PE 2026.0.0, `cd4pe_jobs` module version 1.7.5 could fail when running jobs with Puppet agent 9.1.1 due to a missing dependency. As a result, repository and script payloads could fail to decompress, causing job execution to fail with an `uninitialized constant GZipHelper::FileUtils` error. This issue is resolved in PE 2026.0.1, 2025.12.1 and 2023.8.13. **\[PE-47501\]**

**Updated trust stores remove revoked certificate authorities**

PE now includes updated certificate trust stores that remove the compromised eMudhra intermediate CA certificates from the bundled trust chain. In addition, PE components that use the Go runtime have been updated to incorporate the latest certificate validation protections. These changes are included in PE 2026.0.1, 2025.12.1, and 2023.8.13. **\[PE-47591\]**

**Backups now work with password-authenticated external PostgreSQL databases**

In PE 2025.12.0 and 2026.0, `puppet-backup create` could fail on installations that use an external PostgreSQL server with password authentication (`puppet_enterprise::database_cert_auth: false`). Database passwords were no longer available through PuppetDB, causing backup operations that include databases to fail authentication. PE now retrieves database credentials from a secure local source, allowing backups to complete successfully on affected installations. This issue is resolved in PE   2026.0.1 and 2025.12.1. **\[PE-47131\]**

**Code Manager** Forge **authorization tokens are now protected**

In previous releases, a Code Manager Forge authorization token could be exposed in agent output, reports, and PuppetDB. Puppet Enterprise now handles Forge authorization tokens as sensitive values, preventing them from being displayed in these locations. In addition, the `/etc/puppetlabs/r10k/r10k.yaml` file is no longer world-readable by default. This issue is resolved in PE 2026.0.1, 2025.12.1, and 2023.8.13. **\[PE-47972\]**
