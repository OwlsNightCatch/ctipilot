    ### Summary

Flawed hostname ACL check allows attackers to impersonate puppet clients with enabled autosign and allows puppet catalog downloads for arbitrary hosts.

### Details

ACL checks for authorized endpoints like GET /puppet/v3/catalog/target.lab.local are processed at the puppetmaster

```
(schema/defn ^:private match-domain? :- schema/Bool
  "Checks that name matches the given ace"
  [{:keys [value match]} :- ACE
   to-match :- schema/Str]
  (let [match-split-domain (split-domain to-match)]
    (if (= :regex match)
      (boolean (re-find (re-pattern value) to-match)) ;; zips the two reversed-segment lists and stops at the SHORTER one, then requires every zipped pair to be equal. No length comparison
      (every? (fn [[a b]] (= a b)) (map vector value match-split-domain)))))
```
The zip-like code in match-domain will stop at the shorter hostname entry and compare the zipped values without a length  comparison. This means that a cert issued for evil.target.lab.local will match target.lab.local. With autosign enabled (which is not  default, but common in real world deployments), this will lead to the following attack scenario:

- Attacker does CSR to puppet with evil.somehost.company.tld. As this host ist not registered yet, a cert for client auth will be issued
- Attacker uses the cert for evil.somehost.company.tld to impersonate somehost.company.tld, e.g
  - Grab puppet catalog with provisioned secrets
  - Push fake facts / software versions to the puppet master

### Proof of concept

- Create CSR for host with openssl
- Send CSR to `/puppet-ca/v1/certificate_request/<certname>`
- Retrieve certificate from `/puppet-ca/v1/certificate/<certname>`
- Use client authentication to download catalog of impersonated host via `/puppet/v3/catalog/<certname>?environment=<puppet_env>`

### Impact

access data from other nodes
