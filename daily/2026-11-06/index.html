    HIGHNATOB2

    Exposed application credentials: Microsoft sees an agentic framework search GitHub for OAuth and cloud application secrets and then sign in as the applications from 2026-10-28, and Todyl sees an operator use MSP applications to reach 27 organisations, government clients among them

    Microsoft reports that since August 2026 threat actors have used the agentic offensive framework ARTEX to submit large volumes of queries to public GitHub for secrets (Microsoft Threat Intelligence, 2026-11-05). As early as 2026-10-28 it saw successful service-principal sign-ins from two IP addresses, one a Tor exit node that may carry unrelated activity, across dozens of applications in several tenants, including a vendor-owned multitenant application whose credential was compromised at the source and used to reach multiple downstream tenants (Microsoft Threat Intelligence, 2026-11-05). Microsoft states that a similar campaign involving the same addresses was also reported by Todyl (Microsoft Threat Intelligence, 2026-11-05).

    Todyl, from its managed-detection telemetry, describes one operator who since 2026-11-01 has signed in to MSPs' Microsoft 365 and Azure environments as their own applications with stolen credentials that are still valid: about 45 app registrations at roughly 18 organisations were targeted, more than 33 authenticated, and 27 organisations were reached, among them the MSPs' downstream clients in government (Todyl, 2026-11-03). For nearly every credential the operator requests an Azure Resource Manager token, then a Key Vault token, and within minutes applications that had never been used start authenticating; MSP multitenant and delegated-admin apps and Partner Center tokens reach client tenants, one app sweeping 15 client tenants in about 10-second loops (Todyl, 2026-11-03). Todyl says no Microsoft vulnerability is involved, that it saw no persistence and does not know how the credentials were obtained, and that several seed secrets had only ever been used from staff devices and office networks, which points to a file store or live backend rather than configurations crawled from the internet (Todyl, 2026-11-03). After its detections fired on 2026-11-03 the operator switched to spoofed browser user agents and replayed users' refresh tokens, all blocked by Conditional Access (Todyl, 2026-11-03).

    Exposure
    Any Entra tenant, an MSP's or a customer's, that holds app registrations with client secrets, above all multitenant, delegated-admin and Partner Center applications and Azure DevOps service connections, security-tool integration apps among those abused (Todyl, 2026-11-03); Conditional Access for workload identities needs the Workload ID Premium licence and covers only single-tenant apps (Microsoft Threat Intelligence, 2026-11-05).
    Detection
    In Entra service-principal and non-interactive sign-in logs, an invalid-secret or expired-secret error for an application followed by a success, one address authenticating as service principals in several unrelated tenants within 24 hours, an Azure Resource Manager token followed at once by a Key Vault token and then by previously unused apps authenticating, and failed service-principal sign-ins from hosting space that never succeed, which success-only logic misses (Todyl, 2026-11-03). In Azure DevOps auditing, personal access token creation and first use, federated service connections and pipeline edits (Microsoft Threat Intelligence, 2026-11-05).

    Triage: the invalid-secret and expired-secret errors alone only show that someone holds an old or wrong credential for the app; Microsoft treats a failure followed by a success as the urgent case (Microsoft Threat Intelligence, 2026-11-05).

    Defender takeaway
    Inventory the client secrets on app registrations and hunt the sign-in pattern above in every tenant you run or manage, MSP-managed communal tenants included; on an affected app remove every client secret, certificate and federated credential, including those the actor added, and rotate what any Key Vault it could read holds, because tokens already issued stay valid until expiry (Microsoft Threat Intelligence, 2026-11-05).

    NOTABLENATOB3

    Seqrite: reverse engineering of two Qilin builds shows the October 2026 variant adding a vCenter and ESXi spreading engine, Restart Manager lock release, a Safe Mode reboot loop and ransom notes printed to office printers

    Seqrite's reverse engineering of a March 2026 and an October 2026 Qilin (Agenda) sample finds that the Rust code was reworked into a modular workspace of 22 internal crates, that the command line grew from 6 to 42 switches, and that the October build carries subsystems the baseline lacked (Seqrite Labs, 2026-11-03). It uses the Windows Restart Manager API to shut down the processes that lock SQL Server, Exchange and virtual-machine disk files, instead of the brute-force process termination of the March sample, so that the files can be encrypted (Seqrite Labs, 2026-11-03). An embedded PowerShell engine, started with --spread-vcenter, authenticates to vCenter, disables HA and DRS, extracts the ESXi host addresses, opens SSH and SCP sessions, uploads Linux ransomware payloads to /tmp on the hosts and runs esxcli to power off virtual machines and encrypt .vmdk volumes (Seqrite Labs, 2026-11-03).

    The build also installs the RSAT Active Directory module itself with DISM before enumerating computers, embeds 32-bit and 64-bit PsExec to spread over the ADMIN$ and C$ shares with harvested credentials, and sets a Safe Mode boot with bcdedit plus an AutoAdminLogon registry value so that it reboots into Safe Mode, where EDR drivers do not load (Seqrite Labs, 2026-11-03). A raw-printing module scans local subnets for TCP port 9100 and sends cleartext ransom notes to office printers, and the October binary masquerades as resmon.exe with a forged Microsoft code-signing overlay (Seqrite Labs, 2026-11-03). Seqrite lists healthcare, manufacturing, education and technology as the victim sectors in its telemetry (Seqrite Labs, 2026-11-03).

    Exposure
    Windows estates with a vCenter and ESXi hosts that a domain-joined host can reach over the network and SSH, since the spreading engine needs a vCenter login and SSH to the hosts; Seqrite names no initial-access route.
    Detection
    In vCenter audit events, HA or DRS being disabled on a cluster followed by SSH sessions to ESXi hosts and esxcli activity; in process-creation and registry telemetry, bcdedit setting a Safe Mode boot and a Winlogon AutoAdminLogon change outside a change window, DISM installing the RSAT Active Directory component on a host that never had it, and rstrtmgr.dll loaded by a process that is not an installer; in network telemetry, one host sending to TCP 9100 on many hosts of a subnet; and an executable named resmon.exe outside System32 (Seqrite Labs, 2026-11-03).

    Triage: the Restart Manager and a DISM-installed RSAT component are normal in patching and administration, so each is weak alone; the combination with the print fan-out, the Safe Mode change and the vCenter actions is the signal.

    Defender takeaway
    Treat HA or DRS being turned off in vCenter, followed by SSH sessions to ESXi hosts, as an incident, and alert on a Safe Mode boot configured by bcdedit outside change windows, which Seqrite names as a detection point (Seqrite Labs, 2026-11-03).

    NOTABLENATOB2

    Kaspersky reconstructs an intrusion through SharePoint ToolShell, attributed to Storm-2603 with moderate confidence, whose implant lived only inside w3wp.exe: an ASP.NET VirtualPathProvider memory shell with a suo5 tunnel, then Velociraptor, several tunnelling mechanisms and Warlock's AV killer

    Kaspersky's retrospective analysis of a December intrusion at a customer's on-premises SharePoint server found activity consistent with Storm-2603, with the access and control layer held entirely inside the IIS worker process w3wp.exe and nothing written to disk (Kaspersky, 2026-11-05). On December 20 a single request to a SharePoint administrative endpoint tied to the ToolPane component fingerprinted the host for ToolShell (CVE-2025-53770); the full exploit chain ran on December 24 against the same endpoint, and the gap kept the probe from being correlated with it (Kaspersky, 2026-11-05). The payload was loaded into the ASP.NET runtime and lost when the application pool recycled or IIS restarted (Kaspersky, 2026-11-05).

    The memory shell registers a custom VirtualPathProvider through a non-public method of the ASP.NET HostingEnvironment class, subverts trust controls so that the registration works even in a precompiled application, intercepts requests at the GetCacheKey() hook and stays dormant unless a specific User-Agent header arrives (Kaspersky, 2026-11-05). It speaks a custom XOR-obfuscated binary protocol, and the open-source suo5 tool proxies traffic so connections from the command server reach arbitrary hosts inside the network through the SharePoint server (Kaspersky, 2026-11-05). It reaches SYSTEM by named-pipe token impersonation adapted from EfsPotato and creates administrative accounts through native SAM RPC calls (Kaspersky, 2026-11-05).

    Shortly after the injection w3wp.exe started msiexec.exe to install a remote MSI that was Velociraptor 0.73.4.0, vulnerable to CVE-2025-6264, which the actor used for persistence, discovery, data collection and payload execution and to deploy Zoho Assist unattended access, a VS Code CLI tunnel, Cloudflare Tunnel and a reverse proxy, so access no longer depended on the IIS process (Kaspersky, 2026-11-05). The actor then uploaded a vulnerable driver that is used to terminate EDR products and sideloaded a DLL that Kaspersky identified as Warlock ransomware's AV killer, possibly meant to use that driver; Kaspersky's endpoint product blocked the ransomware process (Kaspersky, 2026-11-05).

    Exposure
    An internet-reachable on-premises SharePoint Server on which ToolShell (CVE-2025-53770 and CVE-2025-53771) is exploitable (Kaspersky, 2026-11-05).
    Detection
    In CLR loader telemetry, a dynamically compiled App_Web_toolpane assembly and a Microsoft.GeneratedCode assembly loading in the same application domain after a ToolPane request; in the IIS-Configuration ETW provider, events 25 and 47 for a path without the file-change-monitor events 17, 18, 19 and 21 that a real file produces, checked against an allow-list of legitimate VirtualPathProvider implementations; and memory inspection of w3wp.exe (Kaspersky, 2026-11-05).

    Triage: App_Web_* assemblies come from ordinary ASP.NET page compilation and Microsoft.GeneratedCode from legitimate XmlSerializer use, so neither is a signal alone; the signal is the pair in one application domain right after a ToolPane request, and any VirtualPathProvider that is not on the application's inventory (Kaspersky, 2026-11-05). The December 20 probe came from infrastructure associated with ONYPHE, an attack-surface discovery platform whose vulnerability checks use non-intrusive probes, so a probe alone looks like a benign scanner; Kaspersky's retrospective analysis established the probe as the initial phase of the intrusion that followed on the same endpoint (Kaspersky, 2026-11-05).

    Defender takeaway
    On a SharePoint host that shows a code-execution exploit, contain the host, hunt the persistence that was installed afterwards, and rotate credentials and the exposed ASP.NET MachineKey; removing the initial shell or known indicators is not enough (Kaspersky, 2026-11-05). Hunt for VirtualPathProvider implants with the ETW pattern above on SharePoint farms that were exposed to ToolShell.

    NOTABLECVE-2026-116779exploitedNATOA2

    CVE-2026-116779, FreeSWITCH 1.11.2 and earlier: one inbound SIP MESSAGE can select the api chat proto and run FreeSWITCH API commands, the vendor says exploitation has been observed, and 1.11.3 fixes it (CVSS 3.1 9.8)

    SignalWire's advisory GHSA-mg63-h38w-8p9p describes CVE-2026-116779: FreeSWITCH's sofia_presence_handle_sip_i_message() splits the To user of an inbound SIP MESSAGE on + and treats the left half as a chat proto name, the mod_dptools module registers an api chat interface that hands its address to switch_api_execute(), and a peer that can deliver a MESSAGE to a profile therefore selects which FreeSWITCH API command the server runs (SignalWire, 2026-10-28). The impact is command execution with the privileges of the FreeSWITCH process, including arbitrary operating-system commands, disclosure of configuration and credentials and full call control, and where mod_lua is loaded, as the stock configuration does, inline Lua is a second route (SignalWire, 2026-10-28). The advisory scores it CVSS 3.1 9.8, lists 1.11.2 and earlier as affected and 1.11.3 as patched, and states that exploitation of this path has been observed in the wild without naming an actor or a victim (SignalWire, 2026-10-28). BSI CERT-Bund rated its advisory on the flaw critical and lists versions before 1.11.3 as affected (BSI CERT-Bund, 2026-11-05).

    The default posture is exposed: chat handling is on unless a profile sets enable-chat=false, the stock vanilla configuration leaves it on for the internal and external profiles, and the inbound ACL does not cover MESSAGE; where MESSAGE authentication is enforced (the default from 1.10.7) any one account on the profile is enough, and installations that still carry the sample directory user default, which has no password, need no account of their own (SignalWire, 2026-10-28). The fix is a per-profile enable-chat-api-proto parameter that is off unless set, so the route is closed by default and a MESSAGE that selects the proto is answered with 403 and logged with the source and the requested command (SignalWire, 2026-10-28). auth-messages alone does not close the path, and disable_system_api_commands=true removes the system API but leaves the route to every other registered API, module loading and call origination included (SignalWire, 2026-10-28).

    Exposure
    A FreeSWITCH of version 1.11.2 or earlier with a SIP profile that accepts inbound MESSAGE from a peer that can reach it, which is the default configuration (SignalWire, 2026-10-28).
    Detection
    SIP signalling logs, or packet capture at the session border controller, for MESSAGE requests whose To user carries a + with api as the left half, in any letter case; after the upgrade the 403 and the log line with the source and the requested command mark attempts (SignalWire, 2026-10-28). The mechanism also implies child processes such as a shell or a downloader started by the FreeSWITCH process, and, where an instance was reachable before the fix, changes to its Lua scripts, dialplan or loaded modules.
    Defender takeaway
    Upgrade to 1.11.3, or until then set enable-chat=false on every profile that does not need inbound SIP chat and remove directory users that have no password; on an instance that was reachable by SIP peers, treat its configuration and the credentials it holds as disclosed, because the vendor says exploitation has been observed (SignalWire, 2026-10-28).

    NOTABLECVE-2026-123158updatedNATOA2

    CVE-2026-123158, OpenSSH Portable before 10.6p2 (*sshole): on Linux with musl libc and no PAM, a password of 257 to 1,024 bytes logs in to accounts whose password field is *; NCSC Switzerland issued an advisory (CVSS 3.1 8.1)

    Portable OpenSSH 10.6p2 carries what its release notes call a critical security workaround for Linux systems that use the musl libc with PAM disabled (OpenSSH, 2026-11-05). NCSC Switzerland says remote, unauthenticated attackers can bypass SSH password authentication over the network and gain access, and rated the exploitation status unknown (NCSC Switzerland, 2026-11-05). OX Security explains the mechanism: musl's crypt() refuses inputs over 256 bytes and returns the string * when it fails, * is also what /etc/shadow holds for an account with no valid password, and OpenSSH, whose 2016 user-enumeration countermeasure can hash a password with settings taken from another account, reads the two matching values as a successful login (OX Security, 2026-11-05). OX gives the conditions: sshd on musl without PAM (Alpine's openssh-server by default), password logins enabled, an account whose password field is * (key-only users, LDAP users, root on Alpine) and at least one other account on the host with a real password; accounts that hold !, glibc systems, PAM setups, Dropbear and OpenBSD are not affected, and OX scores the flaw CVSS 3.1 8.1 (OX Security, 2026-11-05). On Alpine's official AWS and Azure images the passwordless account is the default alpine user, which can run doas without a password, so the bypass chains to root (OX Security, 2026-11-05); Alpine says those tiny-cloud images are safe on first boot and exploitable once any $6$ hash exists, and that cloud-init images, which write PasswordAuthentication no, are not affected (Alpine Linux, 2026-11-05).

    The OpenSSH developers do not consider the root cause to lie in OpenSSH (heise online, 2026-11-05), and NCSC Switzerland adds that other software with similar authentication paths may be affected (NCSC Switzerland, 2026-11-05). Alpine pushed the fix to every branch back to 3.16 (OX Security, 2026-11-05); on release day other distributions and many OpenSSH download servers still offered 10.6p1 (heise online, 2026-11-05).

    Exposure
    Sshd on a musl-based Linux system built without PAM, which NCSC Switzerland lists as Alpine, KISS, Sabotage, OpenWrt, Morpheus and other musl distributions that do not use PAM for password authentication, with password logins enabled (NCSC Switzerland, 2026-11-05) and, per OX Security, an account whose /etc/shadow password field is * (OX Security, 2026-11-05). Containers that do not run an OpenSSH server are not affected (OX Security, 2026-11-05).
    Detection
    OX Security advises searching /var/log/messages for Accepted password for on an account that has no password (alpine, root, key-only users) and treating the machine as compromised if one is found (OX Security, 2026-11-05). The mechanism implies the same event in any sshd authentication log; no source publishes an indicator beyond that.

    Triage: an accepted password login is normal for an account with a real hash; the same event for an account whose password field is * has no benign explanation, because such an account cannot match any password.

    Defender takeaway
    Install OpenSSH 10.6p2 or the distribution's fixed package on every musl-based host that runs sshd and restart sshd, because updating the package alone does not replace the SSH server that is already running, and rebuild container and cloud images from a fixed base (OX Security, 2026-11-05); until then set PasswordAuthentication no and restart sshd, as NCSC Switzerland advises (NCSC Switzerland, 2026-11-05). Review the accepted password logins for key-only accounts on every musl host that allowed password logins before patching, now that exploitation attempts are reported.

    NOTABLENATOB2

    Microsoft Email Threat Landscape Q3 2026: tenant and user overrides delivered spoofed business-service mail that failed authentication, SVG attachments return as CAPTCHA-phishing carriers, and Teams impersonators move to ordinary personal names

    Microsoft Threat Intelligence's report on Q3 2026 draws four points that matter to a Microsoft 365 defender (Microsoft Threat Intelligence, 2026-11-05). First, malicious messages that spoof the sender domains of business services, such as document-signing and survey platforms, were often delivered because tenant- or user-level overrides applied, even after the messages failed email authentication and were identified as malicious: in September overrides applied to 63% of messages with a recorded security outcome, most of them tenant-level (Microsoft Threat Intelligence, 2026-11-05). Microsoft says the figures do not show that recipients opened the messages and that an overly broad exception made for a legitimate workflow can weaken protection against messages impersonating it (Microsoft Threat Intelligence, 2026-11-05).

    Second, CAPTCHA-gated phishing recovered while QR-code phishing kept falling, with SVG attachments central to the recovery: they carried 65% of CAPTCHA-gated attacks in August and 49% in September (Microsoft Threat Intelligence, 2026-11-05). Third, in Teams, ordinary personal-name display names rose from 46% of the observed July sample to 88% in September while explicit help-desk identities fell from 17% to 2%; Microsoft notes a personal name can accompany a help-desk claim while the account address keeps technical wording, and that more targeted attempts used domains resembling the victim organisation's (Microsoft Threat Intelligence, 2026-11-05). Fourth, an August campaign against legal organisations sent a Word document with a personalised QR code that led to a device-code phishing page and the genuine Microsoft device sign-in portal; completing the sign-in would have transferred a valid session token that gave persistent access without exposing the password or re-triggering MFA (Microsoft Threat Intelligence, 2026-11-05).

    Exposure
    A Microsoft 365 tenant that has tenant- or user-level allow or override entries covering the sender domains of widely used business services, since a message that fails authentication and is detected as malicious can still be delivered when such an override applies.
    Detection
    In mail-flow and message-trace telemetry, delivered messages that claim a business service's domain but fail SPF, DKIM and DMARC, together with the override that applied; in mail-gateway logs, SVG attachments that lead to a CAPTCHA page; in Teams audit, first-contact chats and calls from external tenants whose display name is a personal name but whose account address carries help-desk or service wording; in sign-in logs, device-code flow sign-ins.
    Defender takeaway
    Review the tenant and user overrides in your mail protection for entries that cover well-known service sender domains, because the override, not the detection, decided delivery; Microsoft's own advice is to check its recommended settings for Exchange Online Protection and Defender for Office 365 (Microsoft Threat Intelligence, 2026-11-05).

No source names the controller make, the access route or a maintenance provider in the Swiss cases; Keystone-SDA notes that operators can supervise cooling plants centrally over the internet and that the butcher apparently has such an installation, which is the agency's inference and not the owner's statement (Keystone-SDA via swissinfo.ch, 2026-11-05). Blutspende SRK Schweiz told Keystone-SDA that no attacks on Swiss blood-donation services are known to date (SRF, 2026-11-05).

    On the same day CISA, the FBI, HHS, USDA and DOT published a joint fact sheet on malicious cyber activity against industrial refrigeration and cold-chain monitoring systems worldwide: the actors may exploit vulnerabilities or weaknesses in unpatched or internet-accessible controllers to remotely alter settings and force units into continuous heating and defrost cycles, through authentication bypass, arbitrary code injection or weak configurations, with loss of visibility into current temperatures as a further effect (CISA, 2026-11-05).     watchTowr Labs published the full chain on 2026-11-05 and a detection tool: one unauthenticated request to the Email Security Gateway's login handler reaches the backup-restore function, a secret that is hard-coded in the product lets an attacker build a valid archive, and the restored timezone value reaches the root command injection, so exploitation needs no account; Barracuda changed its own advisory the same day to say authentication is not required for CVE-2026-116606.     watchTowr Labs published the full chain on 2026-11-05 after comparing firmware 9.4.0.027 with 9.4.0.029 (watchTowr Labs, 2026-11-05). In the login handler a failed password-change attempt returns the login-screen role instead of ending the request, so one unauthenticated POST to /cgi-mod/index.cgi that submits mismatching new and retyped passwords with a backup upload reaches the backup-restore function (watchTowr Labs, 2026-11-05). The restore accepts a backup whose checksum matches, and the checksum is built from the file bytes and a secret that is hard-coded in the product, so an attacker can build a valid archive (watchTowr Labs, 2026-11-05). A restored system_timezone value then reaches an unescaped shell call that runs as root (watchTowr Labs, 2026-11-05). watchTowr shares a Detection Artefact Generator so that owners can test their own appliances, and its post does not claim exploitation in the wild (watchTowr Labs, 2026-11-05). Its README describes a tool that takes a target URL and a command, builds a backup, uploads it to the target and attempts to check whether the target is vulnerable (watchTowr Labs README, 2026-11-03).

    Barracuda changed its advisory the same day, 2026-11-05 at 2:30pm EST: the Authentication Required field for CVE-2026-116606 now reads No (Administrative UI Access Required), and the advisory says authentication is not required to exploit it but the administrative user interface must be accessible to the attacker (Barracuda, 2026-11-05). The advisory's entry for CVE-2026-111560 still reads Yes (Administrative Access) (Barracuda, 2026-11-05).
