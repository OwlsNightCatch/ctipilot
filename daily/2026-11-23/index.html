    Operation ShadowCloud: Kaspersky's GitDoor and GraphDoor backdoors hide command and control in GitHub, Microsoft Graph with SharePoint, and Ably against government networks in Asia and Africa, delivered through an abused MeshCentral agent and DLL sideloading

    Kaspersky GReAT describes Operation ShadowCloud, an intrusion set identified in early 2026 that abuses the legitimate MeshAgent utility to drop two new backdoors, with victims in Asia and Africa primarily in the government sector (Kaspersky, 2026-11-17). The entry point is unknown: the first observed step is a MeshCentral agent launched inside a Taiwanese organisation, with evidence pointing to reuse of a prior infection on the network (Kaspersky, 2026-11-17). Through the agent the operators drop a legitimate binary, a malicious loader DLL and an encrypted payload file named config.ini, so the legitimate program loads the loader when it starts; hosts include a Sandboxie launcher, an OpenJDK launcher, a Python application and Sysinternals ZoomIt started as a service (Kaspersky, 2026-11-17). Sophos, which tracks the Sandboxie sideloading as BRONZE SANDCASTLE and which Kaspersky says covered a fragment of this campaign (Kaspersky, 2026-11-17), saw victims between August 2025 and August 2026 in the Philippines, Taiwan, Afghanistan, Namibia and likely the Republic of Korea (Sophos, 2026-10-20).

    GitDoor uses GitHub as its command channel: it opens and labels an issue through the GitHub API, writes victim data to a private repository and reads commands and plug-ins from a public one, authenticating with a personal access token (Kaspersky, 2026-11-17). GraphDoor requests a token for an attacker-registered application with the client-credentials grant from Microsoft's sign-in endpoint, then writes encrypted data to files named like JavaScript source maps in a SharePoint document library through Microsoft Graph (Kaspersky, 2026-11-17). Both download plug-ins on demand and run shellcode in memory, among it Mimikatz and a browser-cookie stealer, with plug-ins for keylogging, screen capture and proxying through a modified Erfrp client or Ably (Kaspersky, 2026-11-17; Kaspersky, 2026-11-17). Kaspersky says it lacks sufficient information to attribute the activity and reports overlaps with the Chinese-speaking groups FamousSparrow and CopperTurtle, which on several victim systems shared staging directories with GitDoor (Kaspersky, 2026-11-17).

    Exposure
    Windows servers and workstations in networks that let non-browser processes reach GitHub, Microsoft's sign-in and Graph endpoints and Ably over HTTPS, and where a MeshCentral agent is not a tool the organisation deploys (Kaspersky, 2026-11-17; Kaspersky, 2026-11-17).
    Detection
    In endpoint inventory and process telemetry, MeshCentral agent processes and services that IT did not deploy, and a legitimate program (a Sandboxie start binary, an OpenJDK launcher, a Python host, ZoomIt) loading a DLL from the folder where an encrypted config.ini sits, as in the first instance Kaspersky shows, in system32 (Kaspersky, 2026-11-17). In network and identity telemetry, a non-browser process requesting an app-only token from Microsoft's sign-in endpoint and then writing files through Microsoft Graph to a SharePoint site outside your tenant, and a process other than a git client or CI runner calling the GitHub API to open issues, label them and write repository contents with a personal access token (Kaspersky, 2026-11-17; Kaspersky, 2026-11-17).

    Triage: MeshCentral is legitimate software, so the agent alone is not the signal; the signal is an agent no administrator deployed that drops a legitimate binary, a DLL and an encrypted config.ini side by side (Kaspersky, 2026-11-17).

    Defender takeaway
    Hunt now for MeshCentral agents nobody deployed and for that binary, DLL and config.ini triad, and baseline which processes on servers and workstations legitimately call GitHub, Microsoft Graph and Ably, because both backdoors hide their command channel in that traffic and Kaspersky found the entry point unknown (Kaspersky, 2026-11-17).

    NOTABLEexploitedNATOA2

    GL.iNet GoodCloud: an exploited cloud remote-management flaw installed malware on routers and Comet KVMs; the cloud fix does not clean infected devices, the vendor's firmware is the clean-up, and RemoteToHome finds that clean-up partial

    GL.iNet says it identified on 2026-11-20 a vulnerability in its cloud remote-management services that an unauthorized party exploited to access some GL.iNet routers and KVM devices and install malicious software; the cloud-side fix blocks new infections but does not remove malware from devices already infected (GL.iNet, 2026-11-20). BleepingComputer names the service as GoodCloud and reports that GL.iNet has not said how the flaw worked or how many customers are affected (BleepingComputer, 2026-11-22).

    BleepingComputer's analysis of the installer script found that it replaces the netstat utility with a script that hides the attacker's server from connection listings (BleepingComputer, 2026-11-22). RemoteToHome Consulting, which manages many of these routers, reads the entry point as the router's GoodCloud client passing a value from a cloud message to the shell as root without checking it, and says GL.iNet has not confirmed that reading; on GL-AXT1800 and GL-MT6000 units it opened a root reverse shell (RemoteToHome, 2026-11-23). It also finds an older persistent backdoor that GL.iNet's check does not detect and that may not be tied to the November attacks, and BleepingComputer reports malicious files with December 2025 timestamps, so infection may predate 2026-11-20 (RemoteToHome, 2026-11-23; BleepingComputer, 2026-11-22).

    GL.iNet lists stable security firmware for each exact model, routers from 4.7.14 to 4.11.1, and says it removes the identified malware without a factory reset and with settings kept (GL.iNet, 2026-11-20); the Comet KVM builds are 1.10.3 and, for the RMQ1, 1.8.7 (RemoteToHome, 2026-11-23). RemoteToHome reports that the clean-up is one short script that does not examine the settings an upgrade keeps, and advises reinstalling with Keep Settings switched off for any device that shows a sign (RemoteToHome, 2026-11-23). GL.iNet's own notice says its quick checks may not detect every affected device (GL.iNet, 2026-11-20).

    Exposure
    The GL.iNet router and Comet KVM models on the vendor's list; RemoteToHome's check applies to devices that had the cloud service switched on (RemoteToHome, 2026-11-23). GL.iNet says an unlisted model is not necessarily unaffected (GL.iNet, 2026-11-20).
    Detection
    On the device, a running process whose command line mimics the cron daemon with an argument pointing at a hidden file in /tmp is GL.iNet's published check (crond -i /tmp/.log, found with ps | grep tmp over SSH or in the LuCI process list) (GL.iNet, 2026-11-20). RemoteToHome did not find that process on any router it examined although other signs were present, and lists instead outbound nc sessions running an interactive shell and, surviving a restart, an empty state file in /etc dated 2026-11-20 or later on a router that does not use AstroWarp (RemoteToHome, 2026-11-23).
    Defender takeaway
    Find every GL.iNet router and KVM your organisation or its remote and branch users run, check each one and capture the process list, connections and firewall rules before any restart or upgrade, because some traces exist only in memory and GL.iNet says to install the firmware even when its checks find nothing, then install the security firmware for the exact model and treat any device with a sign as compromised: reinstall with settings discarded, and rotate every key, password and VPN profile stored on it, removing its peers on the server side, because RemoteToHome says cleaning or reinstalling does not take back what a root shell could read (RemoteToHome, 2026-11-23). For a KVM, also examine the computer it controls, which GL.iNet is still assessing (GL.iNet, 2026-11-20).

    NOTABLECVE-2026-125396NATOB2

    CVE-2026-125396, Ghostscript before 10.08.0 (Upload2Shell): a font-loader use-after-free breaks the -dSAFER sandbox, and pwn.ai reaches it from an anonymous print job, a viewed Roundcube attachment and public WordPress upload forms; fixed since 2026-09-08, no exploitation reported (CVSS 4.0 8.5)

    Artifex fixed CVE-2026-125396 in Ghostscript 10.08.0 on 2026-09-08 (The Hacker News, 2026-11-22). The CVE record says the .putgstringcopy procedure in the font loader calls the privileged .forceput operator without checking operand types, so a crafted PostScript or PDF document triggers a type error, recovers .forceput through a custom error handler and causes a use-after-free across save and restore that executes arbitrary code; VulnCheck scores it CVSS 4.0 8.5 with a local attack vector (VulnCheck, 2026-11-09). pwn.ai's writeup of 2026-11-21 shows the flaw is reachable from the network because applications pass untrusted files to Ghostscript indirectly, through ImageMagick, Pillow, libvips or a print filter, even when the file is named like an image or a PDF (pwn.ai, 2026-11-21; The Hacker News, 2026-11-22).

    pwn.ai ran a command as the rendering account through an anonymous IPP print job to a shared CUPS queue on Debian 13 (as the lp user), through an emailed attachment declared as a JPEG but holding PostScript that a Roundcube 1.7.2 user only had to view, with a permissive ImageMagick delegate required (as www-data), and through public WordPress upload forms in Forminator, a public PDF field storing to the Media Library, and in Essential Addons for Elementor, a public registration widget with an upload field (pwn.ai, 2026-11-21). WordPress closed its own upload path in 7.0.4 on 2026-08-12 under CVE-2026-65640, a different point in the same chain (The Hacker News, 2026-11-22). No source reports exploitation, and the one published proof-of-concept file shows only the core memory trick and fails on 10.08.0 (The Hacker News, 2026-11-22).

    Debian's tracker lists fixed packages for bookworm (10.0.0~dfsg-11+deb12u9), trixie (10.05.1~dfsg-1+deb13u2) and unstable (Debian Security Tracker, 2026-11-23). pwn.ai records Ubuntu fixes for seven releases in USN-8949-1 of 2026-10-21, a notice that predates the CVE assignment and carries no CVE number, and, as of 2026-11-12, Amazon Linux fixes pending and several SUSE branches affected or in progress (pwn.ai, 2026-11-21). Updating the host does not update a separate copy of Ghostscript bundled inside a container image or an application (The Hacker News, 2026-11-22).

    Exposure
    Ghostscript before 10.08.0, or a distribution package without the backport, on a host that renders untrusted files: a mail server that thumbnails attachments, a CUPS server with a shared queue that takes jobs without credentials, or a web server with public upload forms that build image previews (pwn.ai, 2026-11-21). Read the package version, and note that a distribution backport can fix the flaw under an older version number (pwn.ai, 2026-11-21).
    Detection
    A shell or other unexpected child process of the Ghostscript renderer running as the web-service or print account is the sign of success, since the proof ran its command through Ghostscript's pipe device (pwn.ai, 2026-11-21). Delivery looks like a mail attachment or upload whose declared type or extension (image/jpeg, .jpg, .png, .pdf) holds PostScript, or an anonymous Print-Job request to a shared CUPS queue (pwn.ai, 2026-11-21). In one test an AppArmor profile stopped the compromised interpreter from starting a shell (The Hacker News, 2026-11-22).
    Defender takeaway
    Update Ghostscript wherever untrusted files reach it, mail, print and upload servers first and bundled container copies included; until then require authentication on shared print queues and limit the file types image processors accept (The Hacker News, 2026-11-22).

    nginx.org lists ten flaws fixed in nginx 1.31.9 and 1.30.7, five more than the five above, and Fortinet's FG-IR-26-279 lists the same ten (nginx.org, 2026-11-18; Fortinet PSIRT, 2026-11-20).
