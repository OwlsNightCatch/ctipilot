    NOTABLECVE-2025-61624exploitedNATOB2

    PEERSTITCH: a memory-resident FortiGate implant installed through the FortiOS CLI path traversal CVE-2025-61624, which Fortinet lists as exploited and leaves unfixed on FortiOS 7.2, 7.0 and 6.4, after a FortiManager compromise exposed the configurations of 500+ firewalls

    Unit 42 investigated a September 2024 intrusion at a telecommunications organization, tracked as cluster CL-STA-0954, that began with CVE-2024-47575 against a centralized FortiManager appliance: the attackers registered a rogue virtual FortiGate, then exfiltrated an archive with the running configurations, cryptographic material and database files of more than 500 managed FortiGate firewalls (Unit 42, 2026-10-14). Unit 42 recovered the configurations' reversible-ciphertext credentials by brute force; the attackers later logged in over SSL VPN with legitimate credentials and pushed packet-capture settings to downstream firewalls (Unit 42, 2026-10-14).

    For root they used CVE-2025-61624, a path traversal in the FortiOS CLI system.auto-script engine that lets an authenticated administrative account read and write arbitrary files as root (Unit 42, 2026-10-14). That installed PEERSTITCH, an ARM64 injector that attaches with ptrace to the logging daemon miglogd and the IPsec daemon iked, allocates a 16 KB read-write-execute region, NOP-patches three fixed offsets and links the daemons through /proc memory so that tagged VPN sessions skip default FortiOS validation; it leaves no persistent binary on disk, opens no listening port and makes no outbound connection of its own (Unit 42, 2026-10-14). Command and control ran through the firewall's own Apache mod_md ACME module, whose DNS-01 challenge handler executes Node.js with parameters from an attacker-run ACME server and so opens a reverse shell (Unit 42, 2026-10-14).

    Fortinet's advisory FG-IR-26-122 of 2026-04-14 covers the CLI path traversal in FortiOS, FortiPAM, FortiProxy and FortiSwitchManager, lists it as known exploited, and for FortiOS gives fixes only in 7.6.5 and 7.4.10, telling users of 7.2, 7.0 and 6.4 to migrate to a fixed release (Fortinet, 2026-04-14).

    Exposure
    FortiOS on 7.2, 7.0 or 6.4, which have no fixed build, or on 7.6.0 to 7.6.4 and 7.4.0 to 7.4.9, with administrators who can reach the CLI (Fortinet, 2026-04-14); and a FortiManager below 7.6.1, 7.4.5, 7.2.8, 7.0.13, 6.4.15 or 6.2.13 that is reachable on TCP 541 from untrusted networks, where the intrusion began (Fortinet, 2024-10-23; Unit 42, 2026-10-14).
    Detection
    Management-plane audit records of the FortiManager (device registrations, archive creation, TCP 541 sessions from outside the management network); FortiGate administrator and VPN logs for SSL VPN logins with valid credentials from new external addresses and for administrator accounts that match nobody in the estate, such as an unexpected FortiGateCloud account; gaps in forwarded syslog, because the actors stop the logging daemons before running scripts; and unexplained packet-capture settings (Unit 42, 2026-10-14). Unit 42's hunting guidance adds the memory maps of miglogd and iked (anonymous 16,384-byte rwxp regions), text-segment integrity at three fixed offsets, cross-process open and write on /proc/<pid>/mem, signal-11 crashes of miglogd, iked or syslogd in the crash log, and configuration revisions holding auto-script objects with ../ in the name (Unit 42, 2026-10-14).

    Triage: legitimate FortiManager work also creates and deletes auto-scripts and adds devices; the report's signals are ../ in an auto-script name, a device registered from outside the management network, and accounts that match no administrator or tenant the organization created.

    Defender takeaway
    Plan the move off FortiOS 7.2, 7.0 and 6.4, where Fortinet offers no fix for an exploited root escalation (Fortinet, 2026-04-14), and limit who can reach the administrative CLI meanwhile; after any suspected FortiManager compromise treat every managed device's credentials and certificates as compromised and rotate them, because the stolen trust material stays valid until it is rotated (Unit 42, 2026-10-14).

    NOTABLENATOB2

    CL-UNK-1211: an AI-assisted intrusion set against government Linux web and mail servers persists through PHP auto_prepend_file, steals sudo passwords with a fake prompt and reads mail stores, and tries to pass as a red-team exercise

    Unit 42 reports a campaign it tracks as CL-UNK-1211 (UNK: affiliation undetermined) against government entities and state-affiliated infrastructure between October 2025 and April 2026, concentrating on Linux servers for persistent access and intelligence collection (Unit 42, 2026-10-15). It names no victim or country and does not say how the web shells were first placed; the recovered tools include a custom Go scanner for CVE-2025-55182 (React2Shell) (Unit 42, 2026-10-15). The scripts carry conversational, step-by-step comments in the style of an AI model, which Unit 42 reads as LLM-generated code or an AI agent's work, an inference rather than a confirmed finding (Unit 42, 2026-10-15).

    On the hosts, the attackers ran PHP web shells under the php-fpm parent process and rewrote auto_prepend_file in every PHP configuration under /etc/php/ and /opt/plesk/php/, so a planted file runs first (Unit 42, 2026-10-15). They replaced a .bashrc with a copy that, in one instance, aliases sudo to a fake password prompt that logs the input, searched configuration and history files for credentials, escalated with LinPEAS and the public PwnKit exploit (CVE-2021-4034), left root-SUID shells under hidden names and injected an SSH key into authorized_keys (Unit 42, 2026-10-15). They moved laterally with sshpass and hard-coded credentials and through an MSSQL double hop using xp_cmdshell, and kept access with SysGoRAT, a Go trojan that takes commands over WebSocket, plus the revsocks and pysoxy proxies and GSocket's gs-netcat, which ran from /dev/shm under a fake kernel-thread process name (Unit 42, 2026-10-15). On government mail servers they enumerated /var/qmail/mailnames/, counted mails in Maildir folders to pick targets and searched mail headers for social-media messages; they tried to exfiltrate database dumps over netcat and to public file-hosting platforms, to delete authentication, history, mail and system logs and to kill endpoint security processes, timestomped scripts with touch -t, and planted a red-team marker string and a pentest-style password to pass as an authorised exercise (Unit 42, 2026-10-15).

    Exposure
    Linux web and mail hosting estates of government or state-affiliated bodies, in particular Plesk-managed PHP stacks and their /var/qmail/mailnames/ mail directories, which the attackers enumerated and searched; the report does not say how the attackers got in (Unit 42, 2026-10-15).
    Detection
    From the described behaviour: file-integrity monitoring on PHP configuration directories for any auto_prepend_file that points outside the application tree; shells or interpreters spawned by php-fpm or web server workers; writes to shell startup files, authorized_keys and any new sudo alias; PHP or web-server access to the mail store; new systemd units, five-minute cron entries and hidden-name SUID-root binaries; outbound WebSocket, GSocket or file-hosting connections from servers; touch -t changes, bursts of deleted history and mail logs, and pkill sequences that name EDR agents.

    Triage: Plesk or PHP hardening can legitimately set auto_prepend_file and administrators do define sudo aliases; the report supports these discriminators: a prepended file with a vendor-like name outside the application tree, an alias that prompts for and logs the password, a log file named after another product, and red-team marker strings that no change record explains.

    Defender takeaway
    Audit every PHP configuration for auto_prepend_file, privileged accounts' startup files for a sudo alias and authorized_keys for unknown keys, and the file system for root-SUID binaries under hidden names; ship authentication, mail and web logs off-host so local log cleanup cannot erase them; patch PwnKit and keep Linux EDR self-protection alerting.

    NOTABLENATOB2

    AdFection: Citizen Lab and Confiant document zero-click Candiru spyware delivered through targeted online ads from the ad-tech firm Discover-Tech, with ad impressions on defence-ministry, armed-forces and NATO networks

    Citizen Lab reports that in 2024 and 2025 at least 45 devices at the news network Al Jazeera were targeted in zero-click attacks that it links with high confidence to Candiru spyware delivered through ads bought by Discover-Tech, an Israeli firm that presents itself as an ad company (Citizen Lab, 2026-10-15). An ad carries a script tag that calls Discover-Tech's ad-decision server with the user's cookie or mobile advertising identifier; the server decides, apparently from the source address and the identifiers, whether the device is eligible, and returns JavaScript only if so and a zero-byte response otherwise, which keeps malicious code and pointers to it out of what ad vendors can inspect (Citizen Lab, 2026-10-15). In Al Jazeera's network logs an infected device first contacted Discover-Tech infrastructure, which indicates an ad impression, then a Candiru validator server that checks the device, and finally a Candiru command-and-control server; a Windows implant that Al Jazeera isolated from a compromised device and Citizen Lab analysed persists through COM hijacking (Citizen Lab, 2026-10-15). Confiant, working from ad-delivery telemetry from April to September 2026, describes a cloaked payload that fingerprints the device and opens an encrypted channel, and found a hand-off to Candiru-attributed infrastructure, with Belgium by far the most targeted country at 56 percent of the global hits in the period; it has not captured a full exploit chain (Confiant, 2026-10-15).

    Citizen Lab's analysis of four billion Discover-Tech bidding records shows ads on almost 200,000 websites and apps in four months, including on devices in networks of defence ministries, armed forces, national cyber agencies and intergovernmental organizations such as NATO; an impression alone does not prove targeting or infection (Citizen Lab, 2026-10-15). Google, IAB Europe, Beeswax, Vungle (Liftoff) and Eskimi disconnected Discover-Tech after the disclosure (Citizen Lab, 2026-10-15).

    Exposure
    Any device that renders third-party ads in a browser or an app, on staff whose phones or workstations an espionage buyer would want, such as defence, security and diplomatic staff; no source reports an infection in Switzerland, and neither report mentions it (Citizen Lab, 2026-10-15).
    Detection
    In per-device web-proxy, DNS and egress logs the reported signature is contact with Discover-Tech infrastructure, which marks an ad impression, followed by a connection to a validator server and finally to a command-and-control server, the sequence seen in Al Jazeera's network logs (Citizen Lab, 2026-10-15). Confiant adds that the ad-delivered SDK resolves an operator-chosen domain over DNS-over-HTTPS and reaches it by raw IP, so it never appears as a plaintext DNS query or connection hostname and stays invisible to DNS-based monitoring and blocklists (Confiant, 2026-10-15). On a Windows endpoint, the implant Citizen Lab analysed persists through COM hijacking, so a new COM registration that points at an unfamiliar DLL is the artifact to look for.

    Triage: ordinary ad tags also call identifier-bearing endpoints and sync user IDs; the reported discriminators are the eligibility gating, with an empty reply for ineligible devices and code only for chosen ones, and the validator-then-command-and-control sequence (Citizen Lab, 2026-10-15).

    Defender takeaway
    The delivery is zero-click and needs no user action, and Citizen Lab says there is currently no consistently safe way to expose users and networks to targeted ads; its control is to block online advertising at the organization's gateway and on work-issued and edge devices (Citizen Lab, 2026-10-15).

    CVE-2026-102764, BeyondTrust Remote Support: an unauthenticated file-operation flaw exploited as a zero-day since late August by a suspected China-nexus actor that left a web shell and boot-time sudo persistence (CVSS 4.0 9.3)

    BeyondTrust's advisory BT26-05 of 2026-10-15 fixes CVE-2026-102764, an improper origin validation (CWE-290) in an internal messaging component of Remote Support that lets a remote attacker perform file operations on the appliance without authenticating; every version up to 26.2.3 is affected (BeyondTrust, 2026-10-15). Google's Threat Intelligence Group found in an incident response that ARMORY CASTLE, a suspected PRC-nexus espionage actor it formerly tracked as UNC5221, exploited the flaw as a zero-day in late August 2026 (GTIG, 2026-10-15); BeyondTrust dates the exploitation of one hosted instance and one self-hosted appliance to 2026-08-29 (BeyondTrust, 2026-10-15). GTIG warns that ARMORY CASTLE and others have historically exploited broadly once a flaw is public (GTIG, 2026-10-15); BeyondTrust lists government among the actor's documented targets (BeyondTrust, 2026-10-15).

    After the exploit GTIG saw SAWFLY, a lightweight PHP web shell that evaluates attacker-supplied code as the appliance's unprivileged site account; the actor then made a root-owned SUID copy of the system shell, tried to dump the appliance's native secrets vault, and persisted through a boot-time script that adds a passwordless-sudo line to the sudoers template, so the escalation survives reboot and configuration reset (GTIG, 2026-10-15). It deleted appliance logs throughout, raised an account's Jump Item and Team permissions from No Access to Administrator, pulled software inventories from users' desktops through the built-in file transfer, and exposed BARECLAW, a custom SOCKS5-over-WebSocket tunneler, by editing the HAProxy configuration (GTIG, 2026-10-15).

    Exposure
    Self-hosted Remote Support appliances on any version up to 26.2.3 without the BT26-05-RS patch; the advisory says to apply the patch manually unless the instance is subscribed to automatic updates in its /appliance interface, and a build older than 24.3.1 must be upgraded first (BeyondTrust, 2026-10-15), which closes the hole but does not undo earlier exposure (GTIG, 2026-10-15). SaaS tenants were patched by 2026-10-09 (BeyondTrust, 2026-10-15); BeyondTrust patched Privileged Remote Access too, which shares the code, though it found no way to exploit it (BeyondTrust, 2026-10-15).
    Detection
    The actor deletes on-appliance logs, so use other copies: forwarded syslog for user changes that raise a Jump Item or Team role to Administrator and for account or API-account changes without a change ticket; authentication logs for administrative /login success from residential-broadband or commercial-VPN address space; reverse-proxy or WAF logs for unknown .php paths and WebSocket upgrades from non-support addresses; file transfers by accounts whose roles changed (GTIG, 2026-10-15). Patching does not evict the actor, so GTIG advises redeploying any appliance of confirmed or unknown status from a clean, fully patched image and then rotating credentials in dependency order, from the appliance administrators to anything typed into a support session (GTIG, 2026-10-15).

    Triage: a known administrator changing Jump Item roles or signing in from a new network under a change ticket is routine; BeyondTrust's signals are privileged sessions from residential or VPN addresses tied to no administrator or ticket (BeyondTrust, 2026-10-15).

    Defender takeaway
    Patch every self-hosted appliance now, then treat each one that was internet-reachable on an affected build since late August as potentially compromised until reviewed, and redeploy from a clean image any whose status is confirmed or unknown (GTIG, 2026-10-15); BeyondTrust adds that the built-in triage tool of its third-party detection platform closed the sensors' privilege-escalation alerts as false positives, and that it is working with the vendor so that automated triage cannot close high-severity signals on its own (BeyondTrust, 2026-10-15).

    NOTABLECVE-2026-108097 +1NATOA2

    CVE-2026-108097, Drupal core (SA-CORE-2026-014): a critical Field UI code-execution flaw reachable through contributed modules, at least one without login; fixed in 11.4.10, 11.3.19 and 10.6.19, with no fix for end-of-life branches (Drupal risk 19/25)

    The Drupal Security Team's advisory SA-CORE-2026-014 of 2026-10-14 rates CVE-2026-108097 Critical, 19 out of 25 on Drupal's own scale, a remote code execution flaw in the core Field UI module: the vulnerability is not directly exploitable with core alone, but multiple serious exploit paths exist with contributed modules and at least one known path needs no authentication (Drupal Security Team, 2026-10-14). The advisory names no module that opens a path; The Hacker News reads the mechanism from the fix, where Field UI's table element ran whatever PHP callable each row carried in its #region_callback property through call_user_func_array with no check, bypassing the renderer's rule against untrusted callbacks, and 11.4.10 no longer calls it (The Hacker News, 2026-10-15).

    Fixed releases are Drupal 11.4.10, 11.3.19 and 10.6.19; 11.2.x and below, 10.5.x and below, and Drupal 8 and 9 are end of life and get no fix, which The Hacker News counts at 28.5 percent of the sites reporting a core version in the week of 2026-10-04 (The Hacker News, 2026-10-15). The advisory records no public exploit at publication, but the Security Team's pre-announcement of 2026-10-12 told sites to reserve time "because exploits might be developed within hours or days", and in May Drupal reported exploit attempts within two days of a core SQL injection advisory that CISA then added to its Known Exploited Vulnerabilities catalog (The Hacker News, 2026-10-15). The contributed Entity List module has its own critical code-execution advisory, SA-CONTRIB-2026-218, under the same conditions, at least one known path needing no authentication, and 3.0.10 fixes it (Drupal Security Team, 2026-10-14); the flaw is CVE-2026-108099, and updating core does not update the module (The Hacker News, 2026-10-15).

    Exposure
    Drupal core on 10.6.x below 10.6.19, 11.3.x below 11.3.19 or 11.4.x below 11.4.10, or on an end-of-life branch from 8.9 to 11.2, with the Field UI module installed (the Standard install profile installs it) and a contributed module or custom code that exposes the vulnerable functionality, which the advisory does not name; Drupal Steward, a web application firewall service run by Acquia, Pantheon, Ironstar and Skpr, blocks some known vectors but not every one (The Hacker News, 2026-10-15).
    Detection
    The advisory publishes no exploit artifact. The result of the flaw is PHP code running as the web server's user, so as an inference from that, watch web access logs for unusual requests to routes that contributed modules provide, PHP worker process lineage for shells, curl or interpreters spawned by the web server, and new or modified PHP files under the web root and the Drupal files directory. An exposed site updated only after the fix was public needs that file-integrity review in addition to the update.
    Defender takeaway
    Update core to the fixed release of its branch now, internet-facing sites first, because the flaw's mechanism is readable from the public fix and Drupal itself warned that exploits could follow within hours or days; where a site cannot be updated at once, uninstall Field UI, which removes the field management and display admin pages until the update (The Hacker News, 2026-10-15). Custom code that set #region_callback on a field_ui_table row stops working after the update, so test the manage fields and manage display pages (The Hacker News, 2026-10-15).
