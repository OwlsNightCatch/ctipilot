    ARTEX against AWS: Datadog sees agent sessions open with anonymous S3 reads, search CloudWatch Logs for secrets with stolen long-term IAM keys, and self-register in public Cognito user pools to obtain AWS credentials

    Datadog Security Labs reports that in October 2026 operators of ARTEX, the agentic penetration-testing framework Microsoft ties to Storm-0940, worked against several AWS environments with a focus on financial data, and that every session it reviewed opened with unauthenticated S3 reads, which CloudTrail records with a userIdentity type of AWSAccount and an accountId of anonymous, calling GetObject, ListObjects and similar read APIs (Datadog Security Labs, 2026-11-09). Where S3 hosted a web front end, the agent read build manifests and runtime configuration, and it requested objects named like placeholders just before bursts of key guesses (Datadog Security Labs, 2026-11-09), the habit Wiz saw as a request for a path that should not exist before each fuzzing run (Wiz Research, 2026-10-22).

    With a valid long-term IAM access key, the agent's most frequent call was CloudWatch Logs FilterLogEvents, always with a limit of 1,000 events: it first searched log text for the names of cryptocurrency firms, hedge funds and invoicing terms and, in a later session on 2026-10-20, for storage links, internal addresses, database references, passwords and AKIA-style access keys (Datadog Security Labs, 2026-11-09).

    Without a key, the agent self-registered in a public Cognito user pool, iterating against a PreSignUp Lambda that checked a tenant domain, then ran InitiateAuth, RespondToAuthChallenge, GetUser and GetTokensFromRefreshToken and traded the tokens for short-term AWS credentials, which CloudTrail shows under the CognitoIdentityCredentials role session name; some SignUp calls named the tool in the user agent (Datadog Security Labs, 2026-11-09). It then tried read-only discovery calls such as ListBuckets, ListSecrets, DescribeParameters, ListTopics, DescribeLogGroups, GetRestApis, DescribeRepositories and ListFunctions, all of which failed because the identity pool's authenticated role was narrow (Datadog Security Labs, 2026-11-09).

    Datadog found hundreds of internet-exposed ARTEX consoles, often in Mandarin, and says the distributions it analysed do not appear to carry a cloud methodology of their own, so the post-exploitation playbook depends on the model in use; some versions block .gov, .gov.cn, .edu and .edu.cn targets by default (Datadog Security Labs, 2026-11-09).

    Exposure
    AWS accounts with long-term IAM access keys that may have leaked, applications whose public Cognito user pools allow self-registration with identity pools that vend AWS credentials to authenticated users, and S3 buckets that serve web front ends without authentication.
    Detection
    In CloudTrail and S3 access logs, anonymous read bursts that include requests for placeholder-named objects; FilterLogEvents calls with a fixed limit of 1,000 from a long-term user key; Cognito SignUp spikes with PreSignUp failures, followed by CognitoIdentityCredentials sessions issuing broad read-only discovery calls that end in access-denied errors; and instance-role credentials used from an address outside AWS, which Datadog lists among the unusual patterns to hunt (Datadog Security Labs, 2026-11-09).

    Triage: FilterLogEvents is a routine call for log tooling and engineers; the discriminator is a long-term user key searching log text for credentials, internal addresses or company names at a constant page limit, from an address that key does not normally use.

    Defender takeaway
    Check which Cognito user pools allow open self-registration and what their identity pools' authenticated roles can read, rotate long-term IAM keys found in code or logs, and hunt CloudTrail for the sequences above; a narrow authenticated role is what stopped the Cognito path in the case Datadog describes.

    The Gentlemen affiliate: an SSL-VPN account without MFA, a Windows Server 2003 host and a dormant local administrator gave Domain Admin in under an hour; the GPO locker most likely lost a replication race, so antivirus was disabled estate-wide but only one host was encrypted (Ransom-ISAC)

    Ransom-ISAC reconstructs an early-August 2026 intrusion into a small company by a Gentlemen ransomware affiliate from forensic images of two domain controllers, event logs of 41 hosts and firewall logs (Ransom-ISAC, 2026-11-13). Entry was an SSL-VPN account without MFA that succeeded on the first attempt from an unusual country; neither egress address appears in any earlier failed login, so the credential was most likely held beforehand. Within the hour the actor ran an anonymous SMB sweep, three Kerberoast-style service-ticket requests (the KDC logged an RC4 and DES downgrade against an AES-only account) and hundreds of failed SMB logons against a domain controller, then used a dormant, weak-password local administrator on an end-of-life Windows Server 2003 SQL host that allowed null sessions. A Domain Admin session opened on the domain controller less than an hour after the first login; Ransom-ISAC could not prove how and says the credentials were most likely taken from that host. The actor then pushed a Rust credential harvester, which takes the DPAPI domain backup key, and EtherRAT, a Node.js implant that reads its command address from an Ethereum smart contract and never reached it; data left through the VPN tunnel over about two days of a weekend (Ransom-ISAC, 2026-11-13).

    The locker, run on a domain controller in domain-wide mode, built a GPO linked enforced at the domain root and the Domain Controllers container, with eight registry values that disable antivirus and a Preferences scheduled task in SYSVOL. The call that declares the Preferences extension reached a domain controller the GPO had not replicated to, the script suppressed the error and no client read the task: antivirus was off estate-wide but the locker ran on one host, which wiped its logs (Ransom-ISAC, 2026-11-13).

    Exposure
    An SSL-VPN gateway with accounts that lack MFA, and any end-of-life host reachable from the VPN address pool that allows null sessions or keeps dormant local administrators.
    Detection
    In KDC and authentication logs, RC4 or DES advertised against an AES-only account, bursts of SMB logon failures from one client (expired-password answers show valid credentials) and null-session logons with random sixteen-character workstation names followed by a dormant local account's logon on a legacy host; in directory change records, a new GPO linked enforced at the domain root or a Preferences task file written into SYSVOL outside the management console; on servers, a Run value named like a browser updater, node.exe fed its script on standard input by a node.exe parent, resolution of three or more public Ethereum RPC providers and antivirus preference changes that disable real-time monitoring (Ransom-ISAC, 2026-11-13).

    Triage: scanners and inventory tools also sweep SMB anonymously and legacy applications use null sessions (the finding is a dormant account logging on right after); developers resolve Ethereum RPC providers, so scope that rule to servers; administrators edit GPOs, so correlate with the change calendar (Ransom-ISAC, 2026-11-13).

    Defender takeaway
    Ransom-ISAC concludes that the actor needed one credential without MFA and one end-of-life server to reach Domain Admin (Ransom-ISAC, 2026-11-13), so MFA on every SSL-VPN account and retiring or isolating the legacy host with its dormant local administrator each remove a link; Ransom-ISAC advises that a GPO of this shape found in a domain be unlinked and deleted, with its Preferences task file, before hosts are cleaned or credentials rotated (Ransom-ISAC, 2026-11-13).

    ScreenConnect: Huntress finds 2,223 fake guest sessions named after crypto exchanges on 118 self-hosted servers, enrolled from 2026-11-03 and, in its leading hypothesis, bait for technicians whose clients predate 26.6.5; it saw no malicious use and no overlap with SCKit

    Huntress counted 2,223 fake guest sessions on 118 self-hosted ScreenConnect servers across 109 MSP and organisation accounts, enrolled between 2026-11-03 and 2026-11-13: always-online "computers" named after crypto exchanges (an exchange word joined to a role word) with a trading-desktop thumbnail (Huntress, 2026-11-14). An MSP asked about them on 2026-11-12; its own server showed no web shells, suspicious child processes or new accounts, and the first Access installer Huntress examined was publicly downloadable, which ScreenConnect allows without authentication by design, and a guest client needs the server's relay address, which is embedded in that server's guest installer, to register. Huntress saw no malicious activity from the sessions: technicians who opened them mostly stayed under 30 seconds, and in one case a technician used the send-text feature, which ScreenConnect does not log, so Huntress treated it as a possible credential exposure. On 29 servers with complete history the operator revisited every 151 seconds to keep the sessions online (Huntress, 2026-11-14).

    Huntress's leading hypothesis, which it has not observed, is bait: a technician who connects with a client older than 26.6.5 would let a malicious guest use the file-transfer flaw CVE-2026-84869 to run a file on the technician's workstation, often the MSP's most privileged machine; it cannot rule out capturing what a technician types, and it found no overlap with the published SCKit indicators (Huntress, 2026-11-14). It considers the public suggestion that the sessions are a malware sandbox detonating installers unlikely.

    Exposure
    A self-hosted ScreenConnect server whose Access guest installer is public or leaked, and every technician host client older than 26.6.5; server session history shows client versions (Huntress, 2026-11-14).
    Detection
    In the server session database, new guest sessions with ClientType 1 (Windows), an empty guest public key, empty company or site fields and crypto-site thumbnails (guest version 25.3.4.9288 is context, not unique on its own); in web or relay logs, many new Access guests from one external address in a short window; on technician workstations, ScreenConnect.WindowsClient.exe starting cmd.exe, powershell.exe, wscript.exe or msiexec.exe on a file under a Documents Temp folder, which Huntress calls the host-side shape of CVE-2026-84869 exploitation. A fake alone shows reachability, not exposure: compare technician-side with guest-side events (Huntress, 2026-11-14).

    Triage: a malware-analysis sandbox detonating a ScreenConnect installer also creates guest sessions; per Huntress, a sandbox session sends a key and JPEG screenshots of the analysis VM, while these send no key, reuse seven screenshot families and randomise hardware and OS details (Huntress, 2026-11-14).

    Defender takeaway
    Upgrade technician host clients to 26.6.5 or later, keep Access installer links private and rebuild leaked ones, restrict installer and web access where supported, bar technicians from joining sessions they cannot tie to a customer, and move unfamiliar sessions into a group technicians do not browse; in Huntress's hypothesis the target is a technician client below 26.6.5 (Huntress, 2026-11-14).

    PolinRider: a North Korea-linked loader reaches developers through force-pushed forged commits in at least 7,609 GitHub repositories, hijacked npm releases and a fake employer's take-home test, and reads its server address from an Ethereum wallet

    Apiiro calls PolinRider a North Korea-linked worm and found it in at least 7,609 GitHub repositories owned by 2,330 accounts, mostly developers' own (Apiiro, 2026-11-09). Three routes, none relying on an npm install script. Forged commits: with stolen GitHub access the worm force-pushes a copy of a commit the owner already made, with the same author, message and date, plus a loader hidden after hundreds of spaces in a build configuration file; in 94% of 9,990 injection pushes the copy claims to be more than an hour older than the push, so git log shows an old commit under the owner's name. Cloning runs nothing; building the project or running its dev, build or lint scripts loads the file, and in the newest wave opening the folder in VS Code is enough (Apiiro, 2026-11-09). Hijacked npm releases: Sonatype found concealed loaders in 12 releases across 10 hijacked packages with no install or postinstall hook, so disabling install scripts does not help (Sonatype, 2026-11-04). A fake employer: JFrog traced AccuraSoftHire, a decoy recruiter with ID-verified LinkedIn recruiters and job ads, whose take-home loads a look-alike npm package and whose scripted camera check fails and hands the candidate a command that installs the same loader (JFrog, 2026-11-09); StepSecurity says taking its site down, as had happened by 2026-11-13, does not end the operation (StepSecurity, 2026-11-13).

    The loader reads the latest outbound transaction of a hard-coded Ethereum wallet and decodes two IPv4 addresses from its recipient field (Apiiro, 2026-11-09), then fetches XOR-encoded JavaScript over plain HTTP on port 443, so blocking one server changes nothing; the wallet in the hijacked npm releases also appears in GitGuardian's GhostAction report, which Sonatype says does not establish a shared operator (Sonatype, 2026-11-04). Cleanup does not hold: 1,949 repositories were infected again after being publicly listed, and where owners cleaned up the stolen access often still worked; Apiiro counts roughly 2,300 developers reached (Apiiro, 2026-11-09).

    Exposure
    Any developer machine, CI runner or coding agent that builds or opens a checkout the worm reached, installs one of the hijacked npm packages, or runs a take-home from an unverified recruiter. Apiiro's checks are a semicolon followed by 200 or more spaces on any branch, a .vscode/tasks.json task with runOn set to folderOpen that runs node, and force-pushes in the GitHub Activity view whose commit is dated days before the push (Apiiro, 2026-11-09).
    Detection
    In process telemetry, a detached node child with no console started from a build script, editor or package entrypoint; in egress telemetry, build hosts and CI runners resolving public blockchain RPC endpoints and then making plain HTTP requests on port 443 to a bare IP address; in GitHub audit telemetry, force-pushes whose replacement commit repeats the replaced commit's author and message (Apiiro, 2026-11-09; Sonatype, 2026-11-04).

    Triage: blockchain developers legitimately call public RPC endpoints; the discriminator is a build or lint process in a project with no Web3 purpose doing so and then spawning a detached node child (Apiiro, 2026-11-09).

    Defender takeaway
    Treat a machine or runner that built an infected checkout as compromised and rotate what it could reach, because the stolen access, not the file, reinfects; run take-home tests from unknown recruiters only in a throwaway virtual machine with no tokens or keys, and block public blockchain RPC from CI runners (Apiiro, 2026-11-09; JFrog, 2026-11-09).
