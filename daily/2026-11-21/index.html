    Webworm's NtMonitor: Rapid7 finds a custom rebuild of the SoftEther VPN Bridge that removes the open-source tool's detection fingerprints (rebranded metadata, renamed handshake endpoints, a custom handshake watermark, an embedded resource archive and an encrypted configuration), attributed with moderate confidence to the China-aligned actor that targets European governments

    Rapid7 analysed what it believes is a so-far unknown custom tool, a modified build of SoftEther VPN Bridge version 4.44 (build 9807) that it attributes to Webworm with moderate confidence (Rapid7, 2026-11-19). Webworm is the China-aligned actor that ESET reported in May 2026 moving to European government targets and to dual-use tools such as SoftEther (ESET Research, 2026-05-20). The rebuild keeps the bridge function, which cascades a remote network into the victim's local network, and removes the fingerprints: the PE metadata and internal strings are rebranded as a network-monitoring product (inconsistently, since the service name and many registry paths still say SoftEther), the HTTP handshake endpoints get update-style names, the handshake watermark becomes a truncated PNG header so stock SoftEther peers cannot connect and the stock watermark cannot fingerprint the build, the resource archive that normally sits beside the executable is embedded in it as a PE resource, and the configuration is stored under a new name in a custom-encrypted format (Rapid7, 2026-11-19). Rapid7 found no backdoor or other added capability, concludes the actor puts stealth above capability, and says only one antivirus vendor detected the sample although it has been public since January (Rapid7, 2026-11-19).

    Exposure
    Windows hosts in government networks that Webworm has already compromised; Rapid7 says that in every configuration it holds the VPN is set to bridge a remote network into the local one (Rapid7, 2026-11-19).
    Detection
    Rapid7's most reliable network detection, where TLS traffic can be inspected, is a POST request to an update-themed CGI path with a JPEG content type whose body starts with a PNG file header; on hosts, look for a SoftEther VPN Bridge service that was not installed by the organisation, in particular one whose binary carries its resource archive inside itself, and for firewall rules added by such a service (Rapid7, 2026-11-19). Rapid7 calls the branding the easiest change for the actor to make next and says the endpoints and watermark can be swapped out trivially, so behaviour that is intrinsic to SoftEther matters more than any one string (Rapid7, 2026-11-19).
    Defender takeaway
    Government networks in Europe should treat any unmanaged SoftEther VPN Bridge, however it is named, as a persistence mechanism that bridges an outside network into theirs, and learn the tool's intrinsic behaviour, as Rapid7 recommends for the government sector (Rapid7, 2026-11-19).

    CVE-2026-129448, Apache Roller 4.0.0 to 6.1.5: an unauthenticated request to the XML-RPC endpoint deserializes attacker-controlled objects before authentication and runs code on the server; Apache says it is being exploited, CISA lists it, fixed in 6.1.6 (CVSS 3.1 9.8)

    Apache's announcement of 2026-11-17 assigns CVE-2026-129448 (CVSS 3.1 9.8) to Apache Roller 4.0.0 through 6.1.4 and says "This issue is being actively exploited" (Apache via oss-security, 2026-11-17). It is the same vulnerability as CVE-2026-82384, which Apache disclosed on 2026-09-25 for 6.1.5 only (Apache via oss-security, 2026-09-25). Roller's XML-RPC endpoint accepts vendor extension types and deserializes them before authenticating the requester (Apache via oss-security, 2026-11-17); the servlet is mapped unconditionally, so the request is parsed even when the XML-RPC feature is switched off and no non-default configuration is needed (Apache via oss-security, 2026-09-25). CISA added CVE-2026-129448 to its Known Exploited Vulnerabilities catalog on 2026-11-20 (CISA, 2026-11-20), and Apache has not said who is exploiting it or how many servers are compromised (BleepingComputer, 2026-11-18). Roller 6.1.6 or later disables the extension types and rejects XML-RPC requests when the feature is off, and the project's downloads page offers 6.1.7 as the best available release (Apache via oss-security, 2026-11-17; Apache Roller, 2026-11-21).

    Exposure
    Any Apache Roller from 4.0.0 to 6.1.5 whose /roller-services/xmlrpc path is reachable, including sites where XML-RPC was switched off in the administration interface; the checks are the deployed version and the enabledForExtensions setting in WEB-INF/web.xml, both of which Apache names (Apache via oss-security, 2026-11-17). Roller is a niche Java group-blogging server with a much smaller market share than mainstream blogging platforms (BleepingComputer, 2026-11-18).
    Detection
    Web access and reverse-proxy logs for POST requests to /roller-services/xmlrpc from unfamiliar sources, and child processes started by the Java application server's account, since the flaw runs attacker-chosen code; Apache's announcement names no indicator and no post-compromise check, and an upgrade does not undo an earlier compromise (Apache via oss-security, 2026-11-17).
    Defender takeaway
    Upgrade to 6.1.6 or later now; where that waits, Apache's interim steps are setting enabledForExtensions to false in WEB-INF/web.xml or removing the /roller-services/xmlrpc servlet mapping, then restarting (Apache via oss-security, 2026-11-17). Treat an exposed instance on an older release as possibly compromised, because Apache and CISA report exploitation (CISA, 2026-11-20).

    03Research, reports & policy1 item

    NOTABLENATOB3

    Cleared Windows event logs are not empty: Arctic Wolf shows that clearing an EVTX log truncates it after the first 64 KB cluster and leaves the earlier records in that chunk's free space, where standard forensic tools do not parse or flag them, and recovered a ransomware encryptor's command line this way

    Arctic Wolf's incident responders report that clearing a Windows event log does not wipe the underlying EVTX file (Arctic Wolf, 2026-11-20). On clearing, Windows truncates the file after the first 64 KB cluster and resets the first and last record numbers, but that first chunk keeps its earlier records in free space until enough new events fill it (Arctic Wolf, 2026-11-20). In a ransomware case the encryptor needed a password argument to run, and Arctic Wolf found its full command line inside the allocated System.EVTX of a domain controller, stamped about three hours before the final clear and absent from the parsed output of Event Viewer, EvtxECmd and Magnet AXIOM; another log held a netscan execution record and an attacker hostname that survived the same way (Arctic Wolf, 2026-11-20). In a second case a PowerShell log held 44 records of which one was allocated, all of them the same command that clears every log, which shows repeated clearing (Arctic Wolf, 2026-11-20). Arctic Wolf identified no forensic tool that flags records left in the slack space after a clear, and records come back with some template-held fields missing (Arctic Wolf, 2026-11-20).

    Detection
    The clearing itself is the alertable event, since Arctic Wolf notes that it often triggers EDR or IDS alerting and is frequently what exposes an attack in progress; the recovery step is forensic: when a log shows as cleared, acquire the EVTX file and carve its first chunk for records with earlier timestamps and lower record identifiers than the allocated ones (Arctic Wolf, 2026-11-20).
    Defender takeaway
    Do not treat a cleared log as empty; preserve the EVTX files of affected hosts promptly, because new events overwrite the free space once they fill the first 64 KB, and search the whole file, not only the parsed events, for the encryptor's command line, tool names and hostnames (Arctic Wolf, 2026-11-20).
