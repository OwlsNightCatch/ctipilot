    ROUTINECVE-2026-44088updatedNATOA2

    CVE-2026-44088: SzafirHost, KIR's qualified e-signature helper, verifies a JAR's signature and loads its classes from different parts of the file (fixed in 1.2.1)

    CERT Polska coordinated the disclosure of CVE-2026-44088 in SzafirHost from Krajowa Izba Rozliczeniowa (KIR) on 2026-05-15: SzafirHost verifies the signature of a downloaded JAR file with JarInputStream, which reads from the beginning of the file, but loads classes with JarFile/URLClassLoader, which reads the ZIP Central Directory from the end (CERT Polska, 2026-05-15). An attacker who combines a genuine signed JAR with a malicious ZIP file therefore passes verification while the malicious class is loaded, which CERT Polska says can lead to remote code execution; all versions before 1.2.1 are affected and version 1.2.1 fixes the flaw (CERT Polska, 2026-05-15). ENISA's EUVD carries CERT-PL's CVSS 4.0 base score of 8.6, with a network attack vector, no privileges and active user interaction (ENISA EUVD-2026-30512). SzafirHost is the application that, with KIR's browser plugin and Java, signs documents and tax declarations with a qualified signature; accounting software prompts users to install the plugin and SzafirHost at the first signing attempt (wFirma help centre). CERT Polska does not say how a malicious JAR would reach SzafirHost, and no source reports exploitation.

    Exposure
    Workstations that sign with KIR Szafir qualified certificates through SzafirHost earlier than version 1.2.1 (CERT Polska, 2026-05-15; wFirma help centre).
    Defender takeaway
    Update SzafirHost to version 1.2.1 or later on every workstation that signs with Szafir certificates (CERT Polska, 2026-05-15). Swiss bodies are not drawn in through signature recognition: without a mutual recognition agreement between Switzerland and the EU, a foreign qualified signature is not equivalent to a qualified signature under Swiss law (BAKOM), so only organizations that sign within Poland's qualified-signature ecosystem have a decision to make.

    NOTABLECVE-2026-47100exploitedupdatedNATOB2

    FunnelKit Funnel Builder for WooCommerce: unauthenticated settings write (CVE-2026-47100) exploited to plant card skimmers on checkout pages, fixed in version 3.15.0.3

    Sansec reported on 2026-05-14 that it was tracking active attacks against Funnel Builder by FunnelKit, a checkout and upsell plugin used on 40,000+ WooCommerce stores, in which all versions before 3.15.0.3 let unauthenticated attackers inject arbitrary JavaScript into every checkout page (Sansec, 2026-05-14). The plugin's public checkout endpoint lets a request pick which internal method to run without checking the caller's permissions or restricting the methods, so an unauthenticated request can reach the method that writes the plugin's global settings, and whatever sits in the External Scripts setting is printed onto every Funnel Builder checkout page (Sansec, 2026-05-14). In at least one case Sansec found a payload posing as a Google Tag Manager loader beside the store's legitimate marketing tags: at page load it decodes a base64 string and loads that external script, which opens a WebSocket to the attacker's server and receives a skimmer tailored to the store that steals card numbers, CVVs, billing addresses and other personal details at checkout (Sansec, 2026-05-14). The flaw is tracked as CVE-2026-47100 and rated 8.7 in CVSS 4.0 (Sansec, 2026-05-14; ENISA EUVD-2026-30936).

    FunnelKit shipped version 3.15.0.3 on 2026-05-14 (BleepingComputer, 2026-05-15), released the fix within 36 hours of the first report, pushed it to older release branches through WordPress.org so many stores updated without manual action, and DNS-blocked the attacker domains it knew (Sansec, 2026-05-14). In a statement added to The Hacker News report on 2026-05-31, FunnelKit said the exploitation path had been closed and that of more than 1,300 sites it monitored in the nine days after disclosure, three showed signs of compromise before its mitigations took effect (The Hacker News, 2026-05-16).

    Exposure
    WooCommerce stores running Funnel Builder before version 3.15.0.3 that did not take the update; stores on 3.15.0.3 or later, including those updated automatically through WordPress.org, are not vulnerable (The Hacker News, 2026-05-16).
    Detection
    In the plugin's Settings > Checkout > External Scripts, entries the store did not add (Sansec, 2026-05-14); in browser-side telemetry of checkout pages, scripts loaded from unfamiliar hosts and WebSocket connections to them (Sansec, 2026-05-14). Updating does not remove a planted script, which is why FunnelKit asks customers to review that setting and remove anything unfamiliar after updating (Sansec, 2026-05-14).

    Triage: Sansec calls skimmers dressed as analytics tags a recurring Magecart pattern, because reviewers skip familiar tracking code; the planted loader names Google Analytics but at page load decodes a base64 string and loads its script from another host (Sansec, 2026-05-14).

    Defender takeaway
    Confirm that every WooCommerce store with Funnel Builder runs version 3.15.0.3 or later and clean its External Scripts setting as FunnelKit advises (Sansec, 2026-05-14). Stores without Funnel Builder have no decision to make.

    CERT Polska coordinated the disclosure of three vulnerabilities in DHTMLX software on 2026-05-15, reported by Łukasz Jaworski and Tomasz Holeksa of Pentest Limited (CERT Polska, 2026-05-15). In CVE-2026-41553 the PDF Export Module used by DHTMLX Gantt and Scheduler does not sanitize its data parameter, so an unauthenticated attacker can inject JavaScript that Node.js processes and executes, which can lead to server compromise; CVE-2026-41552 in the same module and CVE-2026-7182 in Diagram's export module (through the src attribute) lack HTML sanitization, so a crafted payload can include local files from the server in the generated PDF (CERT Polska, 2026-05-15). ENISA's EUVD carries CERT-PL's CVSS 4.0 scores of 10.0 for CVE-2026-41553 and 9.2 for each file-read flaw, all with a network vector, no privileges and no user interaction (ENISA EUVD-2026-30537; ENISA EUVD-2026-30538; ENISA EUVD-2026-30539). PDF Export Module version 0.7.6 fixes CVE-2026-41552 and CVE-2026-41553 and Diagram version 1.1.1 fixes CVE-2026-7182 (CERT Polska, 2026-05-15), and EUVD lists the module from 0.3.3 and Diagram from 1.0.0 as affected below those releases (ENISA EUVD-2026-30537; ENISA EUVD-2026-30539); DHTMLX's changelog for release 0.7.6 records fixed remote code execution and file read vulnerabilities (DHTMLX PDF Export Module changelog). No source reports exploitation.

    Exposure
    Self-hosted DHTMLX PDF Export Module services from release 0.3.3 and earlier than 0.7.6 that back Gantt or Scheduler exports, and Diagram export modules from 1.0.0 and earlier than 1.1.1, wherever an attacker can send requests to the export service (CERT Polska, 2026-05-15; ENISA EUVD-2026-30537; ENISA EUVD-2026-30539).
    Detection
    In process telemetry on the export host, the Node.js export service spawning shells or other child processes, and in its request logs, export requests whose data parameter carries script rather than chart data (CERT Polska, 2026-05-15). A service that ran exposed before 0.7.6 needs a compromise check after the upgrade, since anything an attacker ran or left on the host survives it.
    Defender takeaway
    Upgrade the PDF Export Module to version 0.7.6 or later and Diagram to 1.1.1 or later (CERT Polska, 2026-05-15). Organizations that do not self-host DHTMLX export services have no decision to make.

    Kaspersky: Kimsuky adds Rust-based HelloDoor and httpMalice to its PebbleDash toolkit and takes over hosts through VSCode tunnels and DWAgent

    Kaspersky's report covers Kimsuky (also APT43, Ruby Sleet) campaigns whose droppers it detected between August 2025 and February 2026: spear-phishing emails deliver compressed attachments disguised as documents, with lure names carrying a document extension before .jse or .pif (Kaspersky Securelist, 2026-05-14). JSE droppers decode at least two Base64 blobs with JScript into a location such as C:\ProgramData, open the lure, then decode the payload a second time with certutil from a hidden PowerShell window and run it through regsvr32 or rundll32, while the SCR and PIF droppers decrypt theirs with XOR (Kaspersky Securelist, 2026-05-14). HelloDoor, a Rust DLL backdoor first seen in August 2025 that Kaspersky judges early-stage, persists through an HKCU Run value that launches regsvr32 and talks to a C2 hosted through TryCloudflare, which makes the infrastructure behind it hard to trace; httpMalice (version 1.9 over HTTP or HTTPS, version 1.8 over the Dropbox API) persists as a service when elevated and through an HKCU Run value otherwise, profiles the host, captures the screen, uploads archived directories and encrypts its traffic with ChaCha20 (Kaspersky Securelist, 2026-05-14). MemLoad runs anti-VM checks and reconnaissance, persists through scheduled tasks that run regsvr32 on its DLL every minute, and reflectively loads the RC4-encrypted httpTroy backdoor in memory for long-term access and exfiltration; the AppleSeed Spy variant collects documents, screenshots, keystrokes and the GPKI certificate directory (Kaspersky Securelist, 2026-05-14).

    For post-exploitation the group downloads the legitimate VSCode CLI, unpacks it into C:\Users\Public and runs code.exe tunnel, completing the GitHub device-code authorization with its own account so the host then talks to Microsoft-owned servers, or installs DWAgent from C:\ProgramData with a configuration linked to its own account; it also tunnels through Ngrok, and some samples are signed with certificates stolen from South Korean organizations (Kaspersky Securelist, 2026-05-14). Targets are mainly South Korean public and private entities, and PebbleDash victims also include Brazilian defense organizations and a German defense firm (Kaspersky Securelist, 2026-05-14).

    Exposure
    South Korean government bodies, AppleSeed's most frequent target, and defense, military and medical organizations, PebbleDash's focus, including defense firms abroad as in Brazil and Germany (Kaspersky Securelist, 2026-05-14).
    Detection
    In process-creation telemetry, a script host running a .jse attachment that spawns a hidden PowerShell calling certutil to decode a file, followed by regsvr32 /s or rundll32 on a file in C:\ProgramData or the temp folder; in persistence artifacts, HKCU Run values or per-minute scheduled tasks named after browser checks that run regsvr32 on a DLL, and a new service whose command runs rundll32 (Kaspersky Securelist, 2026-05-14). For the tunnel path, code.exe running a tunnel from C:\Users\Public after a GitHub device-code login, and DWAgent services installed from C:\ProgramData by a dropper (Kaspersky Securelist, 2026-05-14).

    Triage: VSCode Remote Tunnels and DWAgent are legitimate remote-access tools; in Kimsuky's use the VSCode CLI is unpacked into C:\Users\Public and started by a script dropper or installer rather than by the user, and DWAgent arrives with a preset configuration from a dropper that unpacks it into C:\ProgramData (Kaspersky Securelist, 2026-05-14).

    Defender takeaway
    Where VSCode Remote Tunnels and DWAgent are not sanctioned, alert on tunnel creation and on DWAgent service installs, because both give the attacker access that bypasses detection built for malware C2 channels (Kaspersky Securelist, 2026-05-14). Organizations in Kimsuky's target set should hunt for the dropper chain and the tunnel path described above.

    Pwn2Own Berlin 2026 results: 47 zero-days and $1,298,250 awarded, DEVCORE Master of Pwn, AI coding agents and inference tools exploited

    Pwn2Own Berlin 2026, ZDI's second Berlin contest after the inaugural 2025 event, ran at OffensiveCon from 14 to 16 May (Zero Day Initiative, 2026-03-12) (BleepingComputer, 2026-05-15). For 2026 ZDI split its AI category into AI Databases, Coding Agents, Local Inferences and NVIDIA (Zero Day Initiative, 2026-03-12). Targets ran fully patched in their default configurations (Zero Day Initiative, contest rules), and vendors have 90 days to patch after the zero-days are disclosed at the contest (BleepingComputer, 2026-05-15). Before it began, Hackread wrote that it had reportedly run out of space and that some researchers turned away were releasing their findings instead (Hackread, 2026-05-12).
