    tcherber: Cyderes finds an access broker's Go toolkit with VPN clients for FortiGate and SonicWall that, once a tunnel is up, maps internal routes and sweeps Active Directory over LDAP; a credential file mixes default guest, admin and test logins with organisation-specific passwords (more than 500 FortiGate entries) and connection logs show root-level tunnels into multiple victims in May and June 2026

    Cyderes' Howler Cell identified a database holding more than 500 FortiGate VPN credential entries and VPN connection records showing successful root-level tunnels into multiple victim environments during May and June 2026 (Cyderes, 2026-11-17). The recovered Go toolkit wraps OpenConnect with --protocol=fortinet for FortiGate, with a 30-second reconnect loop that keeps the tunnel up, and NetExtender for SonicWall, whose wrapper probes seven login URL paths and ten page patterns to find the authentication domain (Cyderes, 2026-11-17). The credential file mixes default guest, admin and test logins with organisation-specific passwords, which Cyderes reads as both brute-force harvesting and credential-dump sourcing; the broker's forum advert claims the access came from brute-forcing and an "exploit toolkit", which Cyderes relays without confirming (Cyderes, 2026-11-17).

    The orchestrator launches the FortiGate client in the background with a 20-second stabilization delay, maps internal subnets and gateways from the established tunnel, and runs an LDAP module that enumerates users, groups, domain structure and domain controllers; port scanning, SMB reconnaissance and credential validation sit in separate tools that the operator runs by hand (Cyderes, 2026-11-17). Cyderes assesses a Russian-speaking operator working as both an initial access broker and a malware-as-a-service provider, with operations ongoing as of September 2026, and notes that the handle comes from a build-path username that one machine or several could share (Cyderes, 2026-11-17). VMRay independently links the same build path to Zer0day Stealer and ENIGMA Locker and calls the same developer the likely author of an HVNC remote-control sample, without mentioning VPN access brokerage (VMRay, 2026-09-01).

    Exposure
    A FortiGate or SonicWall VPN gateway reachable from the internet that accepts a VPN account with a default or guessed password, or a password that appears in a credential dump; Cyderes names no vulnerability or firmware version and does not discuss multi-factor authentication (Cyderes, 2026-11-17).
    Detection
    VPN gateway logs for successful logins by default-named accounts and for repeated reconnect attempts from one source about every 30 seconds, the interval of the FortiGate client's retry loop; after the tunnel is up, route parsing and a broad LDAP enumeration of users, groups and domain controllers from an address in the VPN pool follow from the toolkit's orchestrator (Cyderes, 2026-11-17).
    Defender takeaway
    Audit VPN credentials on FortiGate and SonicWall appliances, which is Cyderes' own recommendation, and treat default-named accounts and dumped passwords as the entry the toolkit relies on (Cyderes, 2026-11-17).

    NOTABLENATOB2

    CyberPower PowerPanel Business as a SYSTEM script channel on a domain controller: Symantec traces ntds.dit extraction with ntdsutil ifm and esentutl /vss and a side-loaded implant to scripts that the UPS-management service ppbed.exe runs as SYSTEM; Symantec does not say how the console was reached and no actor is named

    Symantec analysed an intrusion in which the attacker used CyberPower PowerPanel Business (PPB), software that manages UPS devices, as the execution channel on a Windows domain controller (Symantec, 2026-11-18). Scripts placed in the product's extcmd folder and staged first under temp\profile\extcmd, are run by the PPB service ppbed.exe as SYSTEM, so the commands of the chain have ppbed.exe as their ancestor and the lineage runs ppbed.exe, cmd.exe, powershell.exe and then the implant (Symantec, 2026-11-18). The attacker pushed the scripts to the PPB web service endpoint /local/rest/v1/file/upload on TCP port 3052, worked hands-on, iterating scripts until ntds.dit was exported with ntdsutil ifm and esentutl /vss, and then side-loaded the implant, an old trusted executable paired with an unknown DLL in a user-profile path (Symantec, 2026-11-18). The channel is a documented product function: CyberPower describes user-programmable command executions for event actions (CyberPower, 2026-11-19), and Symantec notes the attacker did not use power events to trigger them (Symantec, 2026-11-18).

    Symantec does not say how the attacker reached the console; public advisories or stolen administrator credentials could give that access, and it names no actor, victim sector or product version (Symantec, 2026-11-18). CISA's 2024 advisory lists PowerPanel Business 4.9.0 and prior as affected by weaknesses fixed in version 4.10.1 or later, which Symantec does not cite (CISA, 2024-05-02).

    Exposure
    Every host that runs PPB, a domain controller above all, whose web service on TCP 3052 a hostile network or a compromised administrator account can reach; Symantec says to audit the extcmd and temp\profile\extcmd paths of every PPB host against the product defaults (Symantec, 2026-11-18).
    Detection
    Process-creation lineage with ppbed.exe as the ancestor of cmd.exe or powershell.exe, every script staged under extcmd, whatever its name, certutil downloads and decodes, curl downloads and powershell -ep bypass loading .NET code in memory, inbound requests to TCP 3052 from addresses that do not administer the UPS, and on a domain controller ntdsutil, esentutl and new shadow copies; an unexpected DLL next to a trusted binary in a user-profile path marks the side-loaded implant (Symantec, 2026-11-18).

    Triage: the activity looks like a power-management product launching cmd.exe, which defenders may dismiss as a routine power-related recovery process; scripts or event-to-command assignments that no administrator configured, children that are not shutdown or notification routines (which follows from the mechanism) and the absence of a preceding power event separate it from benign use (Symantec, 2026-11-18).

    Defender takeaway
    Treat PPB hosts as privileged execution surfaces: restrict TCP port 3052 to named administrator hosts, change the default administrator password and keep PPB patched, since CISA names 4.10.1 as the fixed build for its 2024 advisory (Symantec, 2026-11-18; CISA, 2024-05-02); where the techniques Symantec lists are found, assume Active Directory credentials are exposed and plan a krbtgt reset and wider credential rotation (Symantec, 2026-11-18).

    HIGHCVE-2026-90817exploitedNATOB1

    CVE-2026-90817, REDCap 13.3.0 up to 16.0.48 LTS, 17.3.9 LTS and 17.4.3 Standard: an unauthenticated chain from a public survey request through the Data Import controller to code execution on the server, exploited as of 2026-10-07 for cryptocurrency mining and listed by CISA; fixed in 16.0.49 LTS, 17.3.10 LTS and 17.4.4 Standard (CVSS 3.1 9.8)

    Securifera, which found the flaw, describes a chain of five faults in REDCap, the research-data platform from Vanderbilt University. The public survey handler checks the passthrough value in two forms, so a double-encoded value reaches the root index.php dispatcher while the route restriction is skipped; the project user-rights object is built before the respondent identity exists, so the public context receives the Data Import privilege and the POST CSRF check is skipped because NOAUTH is defined; the Data Import commit path trusts the posted file name as a local path or PHP stream; the byte-order-mark cleanup writes changed bytes back to the same stream, which turns a CSV cleanup into an arbitrary overwrite; and a compiled-template cache file is then rendered as PHP through a route that works without a login (Securifera, 2026-09-27). An attacker needs only a valid survey hash, with no account, project membership, session cookie, role or CSRF token (Securifera, 2026-09-27); Securifera's repository publishes a proof of concept (Securifera repository, 2026-10-01).

    Unit 42's note of 2026-10-07 reports active exploitation: an unauthenticated POST to a public survey URL stages a transient Blade-template web shell under the temp cache, run by php-fpm with the web server's permissions, which executes a Base64 bash cradle entirely in memory and pipes a payload disguised as a JPEG into bash (Unit 42, 2026-10-07). The chain deploys Monero miners, run with randomized syslog-themed process names, with at least four live workers; persistence is a modified crontab, an RSA public key appended to the authorized_keys of every accessible profile and an edited ~/.profile, and the attackers unset HISTFILE and purge the bash history (Unit 42, 2026-10-07). CISA added the flaw to its Known Exploited Vulnerabilities catalog on 2026-11-18 on evidence of active exploitation it does not describe (CISA, 2026-11-18).

    Google's GTIG reported in June 2026 that the PRC-nexus cluster UNC6508 had exploited internet-facing REDCap servers of North American academic and medical organisations (Google GTIG, 2026-06-15). REDCap 13.3.0 through 16.0.48 LTS, 17.3.9 LTS and 17.4.3 Standard are vulnerable (Pentest-Tools, 2026-10-23); the CVE record names 16.0.49 LTS, 17.3.10 LTS and 17.4.4 Standard as the upgrade targets (OpenCVE, 2026-09-20).

    Exposure
    Any REDCap server from 13.3.0 to the builds above that serves a public survey; the attack needs a valid survey hash (Securifera, 2026-09-27).
    Detection
    Web access logs for POSTs to public survey URLs with a double percent-encoded passthrough and a Data Import route (Unit 42, 2026-10-07) and, where a WAF or proxy logs request bodies, a php:// stream in the file-name field (Securifera, 2026-09-27); transient Blade-template files under the web temp cache, a web-server worker or php-fpm spawning bash, and miner processes started under syslog-style names (Unit 42, 2026-10-07). Securifera's proof of concept deletes its injected cache so that REDCap regenerates a clean copy, so a clean cache does not prove the server was not hit (Securifera, 2026-09-27).

    Triage: the survey flow is supposed to allow only the PDF route (PdfController:index), so a public survey request that reaches the Data Import controller or carries a stream wrapper in the file-name field is not benign (Securifera, 2026-09-27).

    Defender takeaway
    Upgrade now and check crontabs, authorized_keys, ~/.profile and processes on any server that was reachable on an older build, because an upgrade removes none of the persistence Unit 42 lists (Unit 42, 2026-10-07).

    HIGHCVE-2026-123007 +10updatedNATOA1

    NGINX nginx2root: five unauthenticated memory-corruption flaws (CVE-2026-123007 and CVE-2026-123633 in HTTP/2, CVE-2026-121810 in HTTP/3, CVE-2026-123634 in the resolver, CVE-2026-113425 in the mail proxy) can lead to code execution as the worker process; fixed in nginx 1.31.9 and 1.30.7 and NGINX Plus 37.3.0.1 and 37.0.8.1, Rapid7 proof of concept public, no exploitation reported (CVSS 4.0 9.2)

    F5 and the nginx project published the nginx2root fixes (nginx.org, 2026-11-18); CERT-EU counts five vulnerabilities, all able to lead to unauthenticated code execution with the privileges of the NGINX worker process (CERT-EU, 2026-11-18). CVE-2026-123007 is an HTTP/2 flow-control overflow: cancelling queued response data makes nginx use an invalid length when copying a later response (Rapid7, 2026-11-18), and Wiz demonstrated code execution on nginx serving ordinary static files (Wiz Research, 2026-11-18).

    Rapid7 published a working proof of concept for CVE-2026-123007 against nginx 1.31.8; the exploit needs about 128 GB of HTTP/2 traffic and likely fails with concurrent clients (Rapid7, 2026-11-18; Rapid7 repository, 2026-11-18). CERT-EU reports no exploitation in the wild and NCSC.ch rates exploitation unknown with a proof of concept available (CERT-EU, 2026-11-18; NCSC.ch, 2026-11-18).

    The memory-corruption fixes are in nginx 1.31.9 and 1.30.7 (nginx.org, 2026-11-18); nginx 1.31.10 and 1.30.8 of 2026-11-23 add a fix for CPU exhaustion when ssl_early_data is on (CVE-2026-132779, affecting 1.21.4 to 1.31.9 per nginx.org, 2026-11-27), as do NGINX Plus 37.3.1.1 and 37.0.9.1 (nginx.org, 2026-11-23; nginx.org, 2026-11-23; F5 NGINX Plus release notes, 2026-11-23). CERT.at lists NGINX Plus 37.3.0.1 and 37.0.8.1 as fixing four of the five (CVE-2026-123007, CVE-2026-121810, CVE-2026-123633 and CVE-2026-113425); it also says 37.2.0.1 and 37.0.7.1 already carry the fix for CVE-2026-123633 but stay affected by CVE-2026-123007 and CVE-2026-121810, and NGINX Plus R33 to R36 have no update (translated from German) (CERT.at, 2026-11-18).

    Exposure
    An nginx build from the first affected release of each flaw (1.9.5, 1.19.7, 0.6.18, 1.25.0 and 0.5.33) up to 1.31.8 whose configuration uses the feature: an HTTP/2 or HTTP/3 listener, the resolver with variable proxy_pass destinations plus mirror or SSI, or the mail proxy with auth_http (nginx.org, 2026-11-18; Xint, 2026-11-18). A distribution backport can fix a flaw without changing the version nginx -v reports (Xint, 2026-11-18). Veeam Software Appliance and Infrastructure Appliance 13.1 are affected by the two HTTP/2 flaws and cannot disable HTTP/2; Veeam ships the fix through Veeam Updater (Veeam, 2026-11-25). GitLab's Linux package and Docker images carry nginx 1.31.9 from 19.6.2, 19.5.9 and 19.4.11 (GitLab, 2026-11-25).
    Detection
    Process-creation or audit telemetry for any program started by the worker's user, since a normal nginx worker runs no external programs and that is the clearest sign of success; worker exits and core dumps in the error log mark attempts, not successes (Xint, 2026-11-18; CERT-EU, 2026-11-18).

    Triage: a large upload is a legitimate cause of an inbound-heavy connection and workers crash for unrelated reasons, so a program started by the worker is the discriminator, not the traffic shape alone (Xint, 2026-11-18).

    Defender takeaway
    Update and restart nginx, because a configuration reload does not replace the running executable; disabling HTTP/2 on exposed listeners blocks only the two HTTP/2 flaws (Xint, 2026-11-18) and, if it stays on elsewhere, leaves connection pressure (Unit 42, 2026-11-24), and Xint gives interim measures for the others: a fixed upstream group in place of request-time DNS lookups for CVE-2026-123634, no QUIC listeners for CVE-2026-121810 and bound or firewalled mail listeners for CVE-2026-113425 (Xint, 2026-11-18). An empty execution-audit result after the update cannot rule out an earlier compromise, and Xint chained CVE-2026-123007 with a separate Linux kernel SCTP flaw, unpatched when it published, to reach root on the host and escape a Docker container; hosts that do not use SCTP can block the module from loading (Xint, 2026-11-18).

In the module's PreRequestHandlerExecute step, once the CSRF cookie and the CSRF form field are both non-empty, it deserializes the form field with a parameterless ObjectStateFormatter, which performs no MAC, signature, encryption or machineKey validation and enforces no SerializationBinder restrictions, so a crafted serialized .NET object in that field runs code in the IIS worker process, w3wp.exe; one POST with no prior authentication or valid CSRF token suffices (Mandiant, 2026-11-18).

    The module runs before the page lifecycle, so any anonymously reachable .aspx page, or any page that relies on application-level session checks inside Page_Load, is reachable unless it opts out through ISuppressCsrfCheck or the SuppressCsrfCheck attribute; pipeline-level authentication rules run earlier and keep anonymous requests away from pages they protect (Mandiant, 2026-11-18). After the sink the module raises its own error, so the response is HTTP 302 when customErrors is active and HTTP 500 when its mode is Off, and recompiled or customised copies keep the sink under different file hashes (Mandiant, 2026-11-18). Mandiant states that active exploitation in the wild has been observed, names no actor, and says Google's FLARE team completed the root-cause analysis during an incident-response investigation on 2026-11-04 (Mandiant, 2026-11-18); the ENISA record scores the flaw CVSS 4.0 9.3 (ENISA EUVD, 2026-11-19).

    Exposure
    An ASP.NET WebForms application whose Web.config registers Idunno.AntiCsrf.AntiCsrfModule under httpModules or modules, or whose bin directory holds Idunno.AntiCsrf.dll; Mandiant says to search by name, not by hash (Mandiant, 2026-11-18).
    Detection
    IIS logs for anomalous POST requests to .aspx endpoints that return 302 or 500 with elevated request size (cs-bytes, where logged), carrying the module's default cookie __CSRFCOOKIE and form field __CSRFTOKEN, and process-creation telemetry for children of w3wp.exe, which follows from code execution in the worker; if the csrfSettings section is omitted from Web.config, a setter bug overwrites the fallback form field name with RaiseException, so the default field name is not a reliable hunting key on every deployment (Mandiant, 2026-11-18).

    Triage: the module's own tokens are a GUID cookie and a short serialized GUID in the form field, so a cookie that is not a GUID, or a large Base64 value in the CSRF form field, is not legitimate token traffic (Mandiant, 2026-11-18).

    Defender takeaway
    Remove the module and its DLL and replace it with a supported anti-forgery mechanism, since no patch exists; on environments with evidence of exploitation, Mandiant says to rotate all secrets stored in Web.config and applicationHost.config, machineKey and encryption keys and database credentials included, and to inspect the web roots for unauthorized files (Mandiant, 2026-11-18).
