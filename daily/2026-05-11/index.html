    SMS-blaster smishing in Switzerland: fake base stations push phones onto 2G and send spoofed texts past operator filters

    BACS reported on 2025-09-09 that numerous fake parking-fine texts were reaching people in western Switzerland who had recently been in the places mentioned, and that one recipient's phone switched from 4G to 2G just before the message arrived, pointing to an SMS blaster (BACS, 2025-09-09). The device builds on IMSI-catcher technology: it poses as the best available mobile mast within a radius of 500 to 1,000 metres, forces connecting phones onto the outdated 2G standard and sends texts with forged sender information directly to the handset, bypassing the operator's SMS filters (BACS, 2025-09-09). In November 2025 Basel-Landschaft police arrested a suspect who had an SMS blaster in his car (SRF, 2025-11-13). On 2026-05-07 the awareness portal ebas.ch warned that the scam is establishing itself in Switzerland, with texts posing as authorities, banks or courier services that link to fake websites collecting credit card data or e-banking credentials and are adapted to the location, such as a parking fine where many cars are parked (ebas.ch, 2026-05-07).

    Exposure
    Any phone in range that still connects to 2G, which includes many modern smartphones; only SMS is affected, not services such as WhatsApp, Signal or Telegram (ebas.ch, 2026-05-07).
    Detection
    Handset network state as users report it: the phone drops from 4G to 2G shortly before the scam text arrives and returns to 4G immediately afterwards (BACS, 2025-09-09); the sender number is spoofed and cannot be verified or blocked (BACS, 2025-09-09).
    Defender takeaway
    On managed Android devices at API level 34 (Android 14) or later, a device owner or the owner of an organisation-owned managed profile can block 2G for the whole device with the DISALLOW_CELLULAR_2G restriction, and emergency calls still use 2G (Android Developers); iPhones cannot disable 2G directly, only through Lockdown Mode, which also limits other functions (ebas.ch, 2026-05-07).

    NOTABLECVE-2025-69690 +1updatedNATOB2

    BSI lists two authenticated pfSense CE code-execution flaws as critical: CVE-2025-69690 (CE 2.7.2) and CVE-2025-69691 (CE 2.8.0), disputed by Netgate

    BSI listed two Netgate pfSense Community Edition (CE) vulnerabilities in its advisory WID-SEC-2026-1435, released on 2026-05-08 (22:00 UTC on 2026-05-07), with severity critical: an attacker can exploit them to execute arbitrary code with administrator rights (BSI WID-SEC-W-2026-1435). Both come from a researcher's Full Disclosure post of 2026-02-16 (Full Disclosure, 2026-02-16). CVE-2025-69690 affects pfSense CE 2.7.2: the configuration restore mechanism calls unserialize() on user-controlled data, so a crafted backup file carrying a serialized PHP object injects commands through its post_reboot_commands property, and they run through mwexec() as root (Full Disclosure, 2026-02-16). CVE-2025-69691 affects pfSense CE 2.8.0: the XMLRPC API method pfsense.exec_php runs arbitrary PHP code as root (Full Disclosure, 2026-02-16). The researcher scores them 8.8 and 9.9 under CVSS 3.1 (Full Disclosure, 2026-02-16), and ENISA's EUVD records 9.1 and 9.9 (EUVD-2025-209738; EUVD-2025-209739).

    According to the researcher, Netgate was notified on 2025-12-02, acknowledged the reports, classified both as expected behaviour for authenticated administrators and indicated that no patches would be issued (Full Disclosure, 2026-02-16); the CVE records note that the supplier disputes them because the functions are only available to administrators, who are intentionally allowed to execute PHP code (EUVD-2025-209739). BSI's advisory names only pfSense CE 2.7.2 and CE 2.8.0 and references a public proof of concept (BSI WID-SEC-W-2026-1435).

    Exposure
    PfSense CE 2.7.2 (CVE-2025-69690) and CE 2.8.0 (CVE-2025-69691) (BSI WID-SEC-W-2026-1435), for anyone who can log in as administrator; the researcher notes the XMLRPC endpoint is enabled by default over HTTPS with Basic Authentication and that default administrator credentials are widely deployed (Full Disclosure, 2026-02-16).
    Detection
    Firewall web and XMLRPC access logs: calls to the pfsense.exec_php method and configuration restores nobody scheduled, both made with administrator credentials (Full Disclosure, 2026-02-16).
    Defender takeaway
    No patch is coming, so the decision is about the precondition: replace default administrator credentials and keep the management interface and XMLRPC off networks an attacker can reach; with that in place the flaws give nothing beyond what an administrator can already do, which is the supplier's position (EUVD-2025-209739).

    ROUTINECVE-2026-6722 +2updatedNATOA2

    CVE-2026-6722: PHP SOAP extension use-after-free in the ref_map deduplication can lead to code execution, fixed in PHP 8.2.31 to 8.5.6

    PHP 8.2.31, 8.3.31, 8.4.21 and 8.5.6, released on 2026-05-07, fix three flaws in the SOAP extension (php.watch, 2026-05-07) (PHP 8 ChangeLog). The serious one, CVE-2026-6722, is a use-after-free: ext-soap remembers decoded PHP objects in SOAP_GLOBAL(ref_map) for id/href deduplication without holding a reference, so an apache:Map with a duplicate key and an empty value frees an object while the map still points to it, and a later href reuses the freed memory, which PHP's advisory says can lead to remote code execution (PHP, GHSA-85c2-q967-79q5). The advisory includes a reproducer (PHP, GHSA-85c2-q967-79q5). PHP rates it High in that advisory, and the CVE record PHP published as the numbering authority scores it 9.5 under CVSS 4.0, with high attack complexity and attack requirements present (ENISA EUVD, EUVD-2026-28966).

    The two companion flaws are narrower. CVE-2026-7261 is a use-after-free when a header handler returns false or throws while the server uses SOAP_PERSISTENCE_SESSION (PHP, GHSA-m33r-qmcv-p97q); CVE-2026-7262 is a NULL pointer dereference in the apache:Map decoder when the server has a typemap configured, a denial of service that PHP's advisory scores 6.3 under CVSS 4.0 (PHP, GHSA-hmxp-6pc4-f3vv); its CVE record scores 2.9, the same base vector with the threat metric for a public proof of concept added (ENISA EUVD, EUVD-2026-28971). No source reports exploitation.

    Exposure
    A SoapServer reachable by untrusted clients on PHP below 8.2.31, 8.3.31, 8.4.21 or 8.5.6 (PHP, GHSA-85c2-q967-79q5).
    Defender takeaway
    A patch-cycle upgrade for PHP hosts that expose SOAP endpoints; the use-after-free is triggered by a crafted envelope (PHP, GHSA-85c2-q967-79q5).

    CVE-2026-43284 / CVE-2026-43500 Linux Dirty Frag: deterministic page-cache write to root through xfrm-ESP and RxRPC, public exploit, fixes released

    First published 2026-05-09 · open finding →

    Update11 May 2026 05:00 UTCrun 2026-05-11-migratedcvesevidenceregionssourcesbody

    Dirty Frag Linux LPE now confirmed exploited in the wild; Microsoft Threat Intelligence reports "limited in-the-wild activity" involving su privilege escalation after SSH initial access (Microsoft Security Blog, 2026-05-08). Red Hat published RHSB-2026-003 with backports rolling out (Red Hat, updated 2026-05-09); NCSC.ch issued a Swiss federal advisory (NCSC-CH Security Hub post 12547, 2026-05-08).

    Microsoft's Defender Security Research Team reported on 2026-05-08 "limited in-the-wild activity where privilege escalation involving ‘su’ is observed, and which may be indicative of techniques associated with either “Dirty Frag” or “Copy Fail”": an external connection gained SSH access, spawned a shell and ran an ELF binary that immediately escalated through su (Microsoft Security Blog, 2026-05-08). Microsoft does not say which flaw the binary used.

    Red Hat's bulletin RHSB-2026-003 lists the Dirty Frag CVEs, states that CVE-2026-43500 does not affect Red Hat products, and gives user.max_user_namespaces=0 as a targeted mitigation alongside blocking the ESP modules (Red Hat RHSB-2026-003). NCSC.ch's Security Hub post 12547 of 2026-05-08 noted a public proof of concept and advised temporarily blacklisting esp4, esp6 and rxrpc (NCSC-CH advisory 12547, 2026-05-08), and Belgium's CCB issued a parallel advisory (CCB Belgium, 2026-05-08).

    The mainline fixes are f4c50a4034e6 for the ESP flaw and aa54b1d27fe0 for the RxRPC flaw (V4bel, 2026-05-07). Microsoft warns that modifications made before mitigation may persist in cached file content even after the vulnerable modules are disabled (Microsoft Security Blog, 2026-05-08). On Ubuntu systems where AppArmor blocks unprivileged user namespaces, the ESP path cannot be triggered, while the RxRPC path needs no namespace (V4bel, 2026-05-07). Blocking rxrpc breaks AFS and other RxRPC uses, so for those hosts the kernel update is the fix (Ubuntu, 2026-05-08).
