    GhostFrame: Recorded Future's Insikt Group finds an ESXi post-exploitation framework (vmhostd-core implant, VM control panel, VMkatz credential theft) used by TAG-218, whose activity overlaps Settra ransomware and which targeted SonicWall, Palo Alto Networks and Fortinet VPN appliances in the US and Europe

    Insikt Group describes GhostFrame, a previously undocumented command-and-control and post-exploitation framework for compromised VMware ESXi hosts, which it saw used by TAG-218, a group "whose operations overlap with Settra ransomware" (Recorded Future, 2026-11-10). Operators must already hold root on the host: the implant, an ELF named vmhostd-core generated from a web operator panel, does not exploit a vulnerability to gain access (Recorded Future, 2026-11-10). It copies itself to /opt/vmhostd-core, edits the ESXi boot script /etc/rc.local.d/local.sh and runs /sbin/auto-backup.sh to keep the change across reboots, masquerades as vmhostd (resembling VMware's vmware-hostd), and about every five seconds disables the ESXi firewall and the execInstalledOnly control that restricts execution of unsigned binaries, so an administrator who re-enables them is undone (Recorded Future, 2026-11-10). Its command channel opens simultaneous TCP connections to one address on ports 53, 2222, 3389, 4444, 8443 and 9443, keeps the first that succeeds and retries after a random delay of 5 to 12 seconds, which Insikt notes is a network detection opportunity; the implant is mainly an in-memory shellcode loader with a reverse-shell fallback.

    From the hypervisor the panel can list registered VMs, change power state, create or delete snapshots, enable VNC on a guest, run a SOCKS5 proxy for pivoting, intercept ESXi logins, and run the open-source VMkatz against VM memory snapshots, virtual disks or whole datastores to recover NTLM hashes, Kerberos tickets, SAM and LSA secrets and NTDS.dit data without running anything inside the guest (Recorded Future, 2026-11-10). Insikt ties TAG-218's victim-facing servers to VPN-appliance targeting across the US and Europe between late August and October 2026, "predominantly SonicWall, Palo Alto Networks, and Fortinet devices", and says four of those organisations later appeared on the Settra leak site; it assesses that other financially motivated actors are highly likely to adopt the framework, which is an assessment, not an observation (Recorded Future, 2026-11-10). Unit 42 independently reports that after CVE-2026-0257 exploitation attackers pivot from the VPN gateway directly to the virtualization layer (Palo Alto Networks Unit 42, 2026-10-20).

    Exposure
    ESXi hosts whose root credentials, SSH or shell, or vCenter are reachable after an edge compromise; no ESXi vulnerability is involved, so patching ESXi does not address it, and an estate that runs both a SonicWall, Palo Alto Networks or Fortinet VPN appliance and ESXi without isolated hypervisor management is in the pattern Insikt describes.
    Detection
    In ESXi file-integrity and shell-audit telemetry, changes to local.sh, a process masquerading as the host daemon or an unexpected executable under /opt, and repeated firewall-off and execInstalledOnly resets; in network telemetry, six near-simultaneous SYNs from the hypervisor management address to one destination on those ports, and any outbound command-style traffic from a hypervisor at all; in vCenter and ESXi logs, snapshot creation or deletion, VNC enablement and power-state changes outside change windows; in datastore telemetry, reads of VM memory-snapshot and virtual-disk files by an identity that is not the backup service.

    Triage: administrators legitimately edit local.sh, create snapshots and use VNC; the discriminators are a firewall-off and execInstalledOnly loop, a binary under /opt named vmhostd where the genuine daemon is vmware-hostd, and snapshot-file reads by a non-backup account.

    Defender takeaway
    Treat a VPN-appliance compromise as a possible hypervisor compromise and check the ESXi persistence files and the execInstalledOnly state before declaring the incident closed; restrict ESXi and vCenter management to dedicated administration hosts.

    NOTABLENATOB2

    Turla's Cereal toolset turns a compromised on-premises Exchange server into the command channel and mail collector at Kazakh and Romanian government bodies, with no attacker infrastructure and no new transport agent registered (ESET)

    ESET found a previously undocumented .NET toolset, Cereal, on a Kazakh government organisation's Exchange server on 2025-11-28 and, after tuning its detections, on a Romanian government organisation's Exchange server compromised from 2025-12-23; in Romania the mail-collection module was configured to identify messages to or from NATO and EU institutional addresses (ESET Research, 2026-11-10). ESET attributes Cereal to Turla with high confidence, on the concurrent use of another component publicly linked to Turla and conceptual similarity to older Turla malware, and could not determine the initial access method, although it considers a vulnerability exploit possible because the servers are reachable from the internet (ESET Research, 2026-11-10).

    The command channel is the victim's own Exchange server. CerealNeuron runs on the compromised server and passively waits for requests on web paths made to look like Outlook Web Access, Autodiscover and ActiveSync traffic; a correctly encrypted request is treated as a command and a bad one gets a normal-looking Exchange error page, and ESET found no operator-controlled server and could not identify ingress addresses (ESET Research, 2026-11-10). CerealHermit is a network-less variant that reads encrypted command files from disk, and each task runs as a small .NET assembly inside a CerealRunner (mailbox retrieval, Active Directory and WMI queries, LSA secrets extraction, file operations) (ESET Research, 2026-11-10). CerealLoader, the only component written to disk in recognisable .NET form, abuses .NET VTable fixups so native code runs before managed code and is placed where trusted processes load it: the System32 wbem directory (ncobjapi.dll, wbemcomn.dll, loaded by WMI) and the .NET native image cache (ESET Research, 2026-11-10). CerealBox, injected into EdgeTransport.exe, wraps the handlers of transport agents already loaded, so "no new agent appears anywhere in Exchange's configuration"; it keeps messages with .doc, .docx or .pdf attachments that match hard-coded sender, recipient, subject or attachment-name lists and stages them compressed and encrypted on disk for exfiltration through CerealNeuron (ESET Research, 2026-11-10).

    Exposure
    Any organisation that runs Microsoft Exchange on premises with a role reachable from the internet; ESET names no vulnerable version, so exposure is the deployment model.
    Detection
    File-integrity telemetry on the Exchange host for DLLs in the System32 wbem directory and .NET native image cache files that do not match the Microsoft originals; module telemetry for non-Microsoft assemblies loaded into EdgeTransport.exe while Get-TransportAgent lists nothing new; web-server logs for requests to the Outlook Web Access, Autodiscover and ActiveSync look-alike paths from clients with no matching mailbox flow, whose encrypted bodies return a generic error page; and Exchange Web Services mailbox retrievals made from the server's own context. With no external C2 and no known entry vector, the check is a compromise assessment of every internet-facing Exchange server.

    Triage: third-party anti-spam, data-loss-prevention and archiving products also inject into the transport service, but they are vendor-signed and appear in the transport-agent configuration, which CerealBox does not; the native image cache regenerates legitimately after .NET updates, so a changed timestamp alone is weak, while a file that does not match the Microsoft binary is the signal.

    Defender takeaway
    Treat internet-facing Exchange servers as top-tier assets with endpoint detection and restricted egress, baseline the wbem directory and the native image cache, and run the compromise assessment now, because network-only detection will not find a channel that rides the victim's own web paths.

    CopperDragon: Check Point ties three China-nexus intrusion sets to one Sparrow-framework supplier, among them SilentDelivery watering holes on government, shipping, IT and research sites that show a fake Chrome certificate warning (Czech Republic, Germany and France in its telemetry)

    Check Point Research's year-long investigation groups three intrusion sets under one malware-supply entity it calls CopperDragon, a possible "digital quartermaster" for China-nexus actors that use the cross-platform Sparrow framework (FamousSparrow and Earth Estries among them); Check Point itself cautions that the use of the same backdoor or C2 infrastructure "does not necessarily mean" the same actor ran two intrusions, so this is a hypothesis (Check Point Research, 2026-11-10).

    SilentDelivery, active since early 2026 against Europe and Asia, is the set nearest the constituency. Compromised government, shipping, IT and research websites, one through cross-site scripting in an unsanitised input field, carry obfuscated JavaScript that fingerprints the visitor and replaces the page with a language-localised fake Google Chrome SSL warning urging a "Certificate Fix" utility; the MSI, served from compromised cloud storage buckets, installs the new SquadC backdoor or a SparrowDoor variant (Check Point Research, 2026-11-10). SquadC can be set to run only while a browser process is alive, persists through a Run key named WindowsUpdateAssist, and offers file operations, command execution and screenshots. A second route is a spear-phishing RAR whose LNK abuses ftp.exe, with the same C2 (Check Point Research, 2026-11-10). Positive Technologies independently documented the same fake-certificate chain, with victims in Taiwan, Germany, Indonesia and the Czech Republic (Positive Technologies, 2026-08-21).

    The other two sets show what follows an intrusion. OceanGate in Asia starts from an exploited internet-facing Linux server and moves through trojanised ssh and sshd binaries that log passwords, a Linux backdoor that can load a kernel rootkit, FRP and Chisel tunnels, a hidden local administrator account and an LSA security-package credential interceptor; recent SparrowDoor builds embed the WinDivert driver to share a service port such as 443. DarkWire against Latin American telecom and government bodies uses DLL sideloading of uncommon executables, SoftEther VPN renamed to system-process names, DNS MX tunnelling and WMI lateral movement (Check Point Research, 2026-11-10). No Swiss victim is named.

    Exposure
    Staff of public bodies, shipping, IT and research organisations who browse peer websites, web teams whose sites accept unsanitised input, and Windows endpoints that let a standard user run an MSI from a browser download.
    Detection
    In endpoint telemetry, a browser followed by msiexec running an installer named like a certificate repair utility and a new Run key value with an update-themed name; in module-load telemetry, DLL sideloading by rarely abused executables, and the WinDivert driver loaded by a process that is not a VPN or firewall product; in account telemetry, a new local administrator account; on Linux, ssh and sshd binaries that differ from the package-manager copy and frpc or chisel binaries; in DNS, MX-query volume from servers that send no mail.

    Triage: WinDivert is legitimate in VPN and firewall products, so the signal is a parent that is a sideloaded DLL or backdoor rather than the vendor's signed service; SoftEther is legitimate software, but not under a system-process name in a non-system path; a genuine Chrome SSL warning is never cleared by installing an MSI.

    Defender takeaway
    Treat a browser page that offers a "certificate fix" installer as an incident trigger and stop standard users running MSI installers from a browser download; web teams of government and research sites should check for injected third-party script and input-handling flaws, because a compromised site becomes a delivery vehicle for its peers.

    Qubole: an attacker used IAM credentials from a vendor-associated AWS account to assume dormant cross-account integration roles in dozens of customer accounts, then harvested secrets and validated Entra ID and Okta client credentials (Wiz and Sentra, 14 to 26 October)

    Wiz, working with Sentra and Mandiant, observed a threat actor using IAM credentials from an AWS account associated with Qubole, a big-data platform, between 2026-10-14 and 2026-10-26 (Wiz, 2026-11-09). The actor used two Qubole IAM users to call sts:AssumeRole on the cross-account integration roles that customers had created to trust Qubole's account; "every AssumeRole request we attributed to the threat actor included an External ID, and every one succeeded", most of the roles were otherwise not in use, and the traffic came from a rented hosting server and commercial VPN exits, not the AWS infrastructure where legitimate platform traffic originates (Wiz, 2026-11-09; Sentra, 2026-11-09).

    Inside each account the actor enumerated resources, read Lambda function configuration, Secrets Manager and Systems Manager Parameter Store, ran TruffleHog to test AWS access keys, Entra ID service-principal client secrets and Okta client credentials it found, and then downloaded S3 data opportunistically, in some cases whole buckets in one session (Wiz, 2026-11-09). Wiz found no tie to other reported activity and judges the targeting opportunistic; how the Qubole IAM users were compromised is not stated. Sentra writes that dozens of Qubole customers were impacted, and BleepingComputer could not find a public Qubole announcement (Sentra, 2026-11-09; BleepingComputer, 2026-11-10). No Swiss or public-sector victim is named, but the exposure is shared by any account that gave a data or analytics vendor a cross-account role and left it in place.

    Exposure
    Any AWS account holding an IAM role whose trust policy lets a Qubole account, or any other vendor account, assume it, including roles left from integrations that ended; the roles' trust policies and last-used data show them, and Wiz publishes the vendor account identifier, the two principals and the attacker address ranges for a CloudTrail hunt back to 2026-10-01 (Wiz, 2026-11-09).
    Detection
    In cloud control-plane audit logs, AssumeRole events into integration roles whose calling identity is the vendor account but whose source address is not AWS infrastructure, and session names with a consistent attacker-chosen prefix; GetCallerIdentity calls from many keys within seconds and Entra ID or Okta sign-ins by service principals or clients right after, as the actor validates credentials; ListSecrets, GetSecretValue, Parameter Store and Lambda configuration reads in bursts. Object reads are absent from CloudTrail management events, so S3 data events or server access logs must be on, and Wiz says missing logs left responders unable to see what was read (Wiz, 2026-11-09).

    Triage: legitimate vendor traffic comes from the vendor's own AWS infrastructure; the correct External ID does not discriminate, because it is logged in plaintext and often stored by the vendor, while a vendor role assumed from a consumer VPN or a hosting provider the vendor has never used is the high-signal case.

    Defender takeaway
    Inventory third-party trust relationships, delete the roles of ended integrations, narrow each trusted principal to the vendor's specific principal and add a source-address or endpoint condition, which Wiz says alone would have blocked every observed assumption; after an incident, revoke the issued role sessions and rotate every secret, parameter, Lambda variable and identity-provider credential the role could read.

    CVE-2026-124194, Microsoft Outlook: opening a crafted message file makes Outlook reach an attacker-chosen network location without the usual warning and disclose authentication information; exploited as a zero-day, fixed in the November 2026 updates and listed by CISA (CVSS 3.1 6.5)

    Microsoft's November 2026 Patch Tuesday fixes CVE-2026-124194, an Outlook spoofing flaw (CWE-356, the product does not warn the user of an unsafe action) scored CVSS 3.1 6.5, which the Security Update Guide marks as exploited and not publicly disclosed (Microsoft, 2026-11-10). Microsoft's FAQ says an unauthenticated attacker sends a crafted message file and convinces the user to open it, whereupon Outlook may connect to an attacker-controlled network location without showing the usual external-content warning, "potentially disclosing authentication information that could be used to impersonate the user"; the Preview Pane is not an attack vector, so the file has to be opened (Microsoft, 2026-11-10). CISA added the flaw to its Known Exploited Vulnerabilities catalog on 2026-11-10 (CISA, 2026-11-10), and BleepingComputer counts it as the one actively exploited zero-day of this Patch Tuesday (BleepingComputer, 2026-11-10). The affected products are Outlook in Microsoft 365 Apps for Enterprise, Office LTSC 2024 (fixed in 16.0.17932.21140) and Office LTSC 2021 (fixed in 16.0.14334.21048); Microsoft 365 Apps take the fix through the Office security-update channel (ENISA EUVD, 2026-11-10). BleepingComputer calls it an NTLM credential disclosure flaw: opening the attachment makes Windows connect to an attacker-controlled share and expose the user's NTLMv2 hash, which can be captured and cracked offline (BleepingComputer, 2026-11-10). No source names the actor or the victims.

    Exposure
    Every Outlook desktop below those builds; the build shows under File, Office Account, and the delivery path is mail or a download that carries a message file, which the user must open.
    Detection
    Outbound connections to non-corporate addresses over SMB (TCP 445), WebDAV or HTTPS from OUTLOOK.EXE or from the user's session shortly after a message-file attachment is opened, authentication events carrying the user's identity toward an external address, and mail-gateway logs for message-file attachments from unknown senders. Because the credential material may already have been captured before the patch, the check also covers the weeks before it. The disclosed material is the user's NTLMv2 hash, which can be cracked offline or used to impersonate the user, so also watch for later logons by the account from unfamiliar hosts.

    Triage: Outlook legitimately contacts SharePoint, OneDrive and corporate file servers; the discriminator is an external, non-corporate destination preceded by the opening of a message file.

    Defender takeaway
    Install the November Office update now rather than in the normal cycle, because the flaw is exploited and a patched machine still leaves earlier captured credentials valid; reset the accounts of users whose Outlook reached an external destination.
