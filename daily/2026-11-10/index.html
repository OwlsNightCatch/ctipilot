    An independent researcher published what Huntress counts as 33 critical flaws in the N-central appliance, chaining into four exploits, and N-able took its hosted environments offline on 2026-11-09 (Huntress, 2026-11-09); the chain BleepingComputer calls most critical abuses an unauthenticated XML external entity flaw to steal a trusted local session and run commands as the service user (BleepingComputer, 2026-11-09).

    On 2026-11-10 N-able released N-central 2026.4 Hotfix 2, build 2026.4.1.26, "a critical security update", for which Huntress lists seven CVE ids (N-able, 2026-11-10; Huntress, 2026-11-10; N-able CNA record, 2026-11-10; N-able CNA record, 2026-11-10). N-able reported scanning for that set but no successful exploitation (Huntress, 2026-11-10), and none of the seven is in CISA's catalog (Tenable, 2026-11-12).

    On 2026-11-12 the researcher published a second set. 4EverAble2Shell is unauthenticated command execution as root that requires the Legacy API to be enabled, per BleepingComputer; it chains CVE-2026-90436, an Apache Axis 1.x deserialization flaw for which Apache does not expect a fix, with a root escalation in N-central's maintenance helper (BleepingComputer, 2026-11-12; Apache Axis project, 2026-11-06; Huntback, 2026-11-12). Huntback counts at least 21 servers, 19 of them on Hotfix 2, in North America, South Africa and Europe but not Switzerland, and Previdian's honeypot recorded attempts at the chain (Huntback, 2026-11-12; Previdian, 2026-11-12). Agent2Shell is a set of more than ten issues in how the server talks to Windows Agents and Probes, two chains of which let an unauthenticated attacker who can reach the server run commands as SYSTEM on managed endpoints; N-able confirmed it also requires the non-default Legacy API (The Hacker News, 2026-11-12; Huntress, 2026-11-13). N-able has published indicators of compromise for customers that have not disabled the Legacy API, has no fix for the new claims and plans a follow-up hotfix (Huntress, 2026-11-13; Tenable, 2026-11-12).

    Exposure
    An on-premises N-central server, yours or an IT provider's: below build 2026.4.1.26 for the first set, and any build up to Hotfix 2 for the second when the Legacy API, off by default, is on and reachable (Huntress, 2026-11-13). A compromised server reaches the systems N-central manages (Field Effect, 2026-11-09).
    Detection
    In N-central's authentication and audit logs from 2026-11-08 onward, unexpected logins, new administrator accounts and changes to stored credentials or API integrations; on managed endpoints, unscheduled software deployments, scripts and remote-control sessions (Huntress, 2026-11-09; Field Effect, 2026-11-09). For 4EverAble2Shell, Huntback names POST requests to the Axis endpoint /dms/services/ServerUI, a symlink at the N-central flag file path, a systemd unit or cron entry relaunching a miner and a hidden miner directory under /tmp or /var/tmp (Huntback, 2026-11-12). Huntress's Agent2Shell indicators come from static analysis of the proof of concept, not attacks seen: SYSTEM PowerShell with an encoded command spawned by the Agent, where PowerShell as an Agent child is common and the command is what matters (Huntress, 2026-11-13).
    Defender takeaway
    Upgrade on-premises servers to Hotfix 2, then Agents and Probes, and confirm the Legacy API is disabled and not internet-reachable, because Hotfix 2 does not fix 4EverAble2Shell and 19 of the 21 compromised servers already ran it (Huntback, 2026-11-12); treat a hit as a full compromise, ask each IT provider managing your endpoints through N-central whether it runs a server on premises and has upgraded it, and rotate the administrator, service and integration credentials the platform holds where activity looks unauthorised (Field Effect, 2026-11-09).

    CVE-2026-120017, CVE-2026-89126, CVE-2026-76964 and CVE-2026-89103, SAP NetWeaver AS ABAP, Web Dispatcher and Gateway: four unauthenticated network flaws rated CVSS 10.0 and fixed on SAP's November 2026 Patch Day; Onapsis, which found three of them, says a working exploit exists and has seen no attacks

    SAP's November Patch Day of 2026-11-10 fixes four flaws that SAP scores CVSS 3.1 10.0, each reachable over the network without privileges or user interaction and with changed scope. In the SAML2 service provider of NetWeaver AS ABAP and the ABAP Platform, an unauthenticated attacker could submit crafted data, under certain configurations, to bypass authentication and impersonate arbitrary users, privileged accounts included (CVE-2026-120017, note 3849308) (ENISA EUVD, 2026-11-10). SAP Web Dispatcher and the Internet Communication Manager of NetWeaver AS ABAP share a memory corruption that could allow arbitrary code execution (CVE-2026-89126, note 3778556; CVE-2026-76964, note 3778530) (ENISA EUVD, 2026-11-10; ENISA EUVD, 2026-11-10), and SAP Gateway activates its default access control list with high privileges, so an external attacker is treated as an internal application server (CVE-2026-89103, note 3798345) (ENISA EUVD, 2026-11-10).

    Onapsis, which found and reported the Web Dispatcher, ICM and Gateway flaws, names the first pair ICM2SHELL: a memory corruption in the shared kernel code that reassembles fragmented WebSocket messages, reachable on the HTTP or HTTPS port with no credentials, and "WebSocket support is enabled by default, whether or not it is used" (Onapsis, 2026-11-10). Onapsis provided SAP a working unauthenticated code-execution exploit that runs commands as the system's <sid>adm user, a single connection crashes the process on every kernel it tested, and it has not observed attacks; NCSC Switzerland lists the exploitation status as unknown (Onapsis, 2026-11-10; NCSC Switzerland, 2026-11-10). It affects ABAP systems on kernel 7.40 or higher and every Web Dispatcher, the one in SAP HANA XS included; AS Java alone and kernel 7.22 are not affected, and kernels out of maintenance may get no fix. The fixed patch levels are 7.53 PL 1616 or 1617, 7.54 PL 710, 7.77 PL 914, 7.93 PL 401 or 420, 9.16 PL 111, 9.18 PL 37 and 9.20 PL 11 or 13 (Onapsis, 2026-11-10).

    ProxyGate lets an unauthenticated attacker with network access run operating system commands as <sid>adm on the Gateway, and its exploitability depends on the proxy access list: a permissive prxyinfo file, or none with gw/acl_mode_proxy at its default of 0, leaves the system exposed, so "neither a version check nor patching alone tells you whether you are safe"; on most releases SAP's fix combines the kernel patch with gw/acl_mode_proxy = 1, and Onapsis lists the minimum patch level for each kernel release, for example 7.53 PL 1625 and 7.54 PL 718 (Onapsis, 2026-11-10).

    Exposure
    A system that runs one of the components and lets an untrusted network reach its Web Dispatcher, Internet Communication Manager, Gateway or SAML2 endpoint; the SAML2 flaw applies under certain configurations of the SAML 2.0 service provider (ENISA EUVD, 2026-11-10).
    Detection
    Onapsis expects every exploitation attempt against ICM2SHELL to crash the ICM or Web Dispatcher at least once, so unexpected restarts of either process outside maintenance deserve investigation; requests with status 101 in the ICM or Web Dispatcher HTTP log show whether WebSocket is in use before anyone considers disabling it (Onapsis, 2026-11-10). The sources name no indicator for the SAML2 flaw or the Gateway.
    Defender takeaway
    Patch internet-facing Web Dispatchers and Internet Communication Managers first and every application server and Web Dispatcher after them, set gw/acl_mode_proxy to 1 on every Gateway, and apply note 3849308 where the SAML2 service provider runs; Onapsis calls the notes the only complete fix.

    NOTABLENATOB2

    BluePhishing: Proofpoint's proof of concept turns a consent link for a third-party Entra agent blueprint into tenant initial access, with an agent-creation permission that Proofpoint says cannot be revoked

    Proofpoint presents BluePhishing, a proof of concept that extends OAuth consent phishing to Microsoft Entra Agent ID. The attacker builds an agent blueprint, the agent analogue of an app registration, in their own tenant with a client secret and permissions set to be inherited, sets its sign-in audience to work across tenants (a setting the Entra portal does not expose, so it takes Microsoft Graph, PowerShell or a manifest edit), and sends the victim a one-time consent link (Proofpoint, 2026-11-09). When a victim consents, a blueprint principal appears in the victim tenant with the AgentIdentity.CreateAsManager permission, which Proofpoint says cannot be revoked from the principal; the attacker then obtains an app-only Graph token for the victim tenant and creates agent identities, up to 250 per blueprint, that inherit the consented permissions (Proofpoint, 2026-11-09). Creating one needs the victim's tenant ID and the object ID of a sponsor user, both obtainable through documented unauthenticated lookups, and Proofpoint's tests used the Graph permissions User.Read.All and Group.Read.All (Proofpoint, 2026-11-09). Proofpoint, citing Microsoft's documentation, says inherited permissions are not visible in the Entra portal or in Microsoft Graph, which limits auditing what an agent identity can do; in its tests silent inheritance appeared only for delegated permissions, those granted through user consent (Proofpoint, 2026-11-09).

    Proofpoint has identified no in-the-wild activity and says agent consent controls are less mature and less widely deployed than app consent controls; it adds that Microsoft 365 Message Center item MC1506733 says default Entra users will be able to create agent blueprints from November 2026 (Proofpoint, 2026-11-09).

    Exposure
    A Microsoft Entra tenant whose users or administrators can be led to approve a consent link; Proofpoint says the user consent settings that limit third-party app consent also extend to agent blueprints and their agent identities (Proofpoint, 2026-11-09).
    Detection
    Proofpoint says agent and blueprint events surface in the Entra audit log as app consent operations do, the creation of an agent identity blueprint as "Add application" and the creation of an agent identity as "Add service principal", and that the blueprint ID is the same in every tenant that consents to it, so a known malicious blueprint can be searched for across tenants (Proofpoint, 2026-11-09).
    Defender takeaway
    Review the tenant's user consent settings and permission classifications before the November 2026 default lets default Entra users create agent blueprints, and look in the audit log for blueprint and agent-identity creations that nobody in IT made; no attacks have been reported, so this is a hardening decision, not an incident response.
