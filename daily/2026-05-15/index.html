    FrostyNeighbor (Ghostwriter, UNC1151): since March 2026, geofenced PDF lures deliver a JavaScript PicassoLoader and Cobalt Strike to Ukrainian government organisations

    ESET attributes new activity since March 2026 to FrostyNeighbor, also known as Ghostwriter, UNC1151, UAC-0057, TA445, PUSHCHA or Storm-0257, a long-running cyberespionage group apparently aligned with the interests of Belarus, using links in spearphishing PDFs to target governmental organisations in Ukraine (ESET, 2026-05-14). In ESET's telemetry the group's Ukrainian targeting focuses on military, defence and government, while its victimology in Poland and Lithuania is broader, spanning industry and manufacturing, healthcare and pharmaceuticals, logistics and many governmental organisations (ESET, 2026-05-14).

    The lure is a blurred PDF impersonating Ukrtelecom whose download button leads to the group's delivery server; visitors outside Ukraine receive a benign PDF of the same name, while Ukrainian IP addresses receive a RAR archive holding a JavaScript first stage that shows a decoy, re-runs itself, drops a base64-embedded JavaScript PicassoLoader and builds a scheduled task from an XML template the C2 serves as a fake JPG (ESET, 2026-05-14). PicassoLoader collects the username, computer name, OS version, boot time, current time and running processes, posts them over HTTPS every 10 minutes and evaluates any response longer than 100 bytes (ESET, 2026-05-14). Operators very likely decide by hand whether the victim is of interest; if so, the C2 returns a third-stage dropper that copies rundll32.exe into %ProgramData% under another name, writes the base64-decoded Cobalt Strike beacon DLL beside it, and registers in the HKCU Run key a LNK that starts the copied rundll32 with the DLL's export (ESET, 2026-05-14).

    Exposure
    Governmental organisations in Ukraine are the targets of this chain; the payload is delivered only after server-side checks of the user agent and IP address and a manual operator decision, so a request from outside Ukraine sees only the benign PDF (ESET, 2026-05-14).
    Detection
    In process telemetry, a JavaScript file from a RAR archive that relaunches itself, followed by scheduled-task creation from a downloaded XML template; in network telemetry, a script process posting to the same HTTPS endpoint every 10 minutes; in persistence telemetry, an HKCU Run entry pointing at a LNK in %ProgramData% that starts a renamed copy of rundll32.exe loading a DLL from the same directory (ESET, 2026-05-14).

    Triage: rundll32.exe is a normal Windows binary when it runs from the system directory; a copy of it under a different name in %ProgramData%, which ESET says is very likely meant to bypass detection rules, is the signal (ESET, 2026-05-14).

    Defender takeaway
    Because delivery is geofenced and operator-gated, a clean verdict on an Ukrtelecom-themed lure link from a sandbox outside Ukraine proves nothing; hunt on the host artefacts above instead (ESET, 2026-05-14). The Hacker News reports the same chain (The Hacker News, 2026-05-14).

    Datadog analyses TeamPCP's open-sourced Shai-Hulud framework: credential and runner-memory theft, IDE and Claude Code hook persistence, OIDC npm publishing and a wipe-on-revocation daemon

    On 2026-05-12 a GitHub repository appeared with what Datadog Security Labs assesses as the complete source code of the Shai-Hulud offensive framework attributed to TeamPCP; its README reads "Love - TeamPCP" and "Change keys and C2 as needed", its commits are authored as TeamPCP_OSS, and GitHub removed it shortly after publication, though not before it was forked several times (Datadog Security Labs, 2026-05-13). Datadog maps the source directly to compiled payloads seen in the wild, including those of the TanStack and UiPath compromises, and finds 19 of the 22 TeamPCP techniques described in earlier reporting implemented in it (Datadog Security Labs, 2026-05-13).

    The modular TypeScript and Bun toolkit exits on systems with a Russian locale, then reads OS-specific lists of more than 100 sensitive file paths, runs gh auth token and captures the process environment, and in GitHub Actions on Linux feeds a script to sudo python3 that reads the Runner.Worker process memory for values marked secret; further providers walk the AWS credential chain including instance and container metadata, read every Kubernetes secret in every namespace and enumerate Vault (Datadog Security Labs, 2026-05-13). Data leaves AES-256-GCM encrypted over HTTPS to a campaign domain, with a fallback domain found through signed GitHub commits and, failing that, new public GitHub repositories used as dead-drops (Datadog Security Labs, 2026-05-13). Stolen GitHub tokens are used to commit VS Code folder-open tasks and Claude Code SessionStart hooks to every branch of the victim's repositories, stolen npm tokens to republish the victim's packages with a preinstall loader, and, in a release workflow it was hardcoded to target, the workflow's OIDC token to publish a poisoned package with genuine Sigstore provenance; where it attaches a stolen token it installs a LaunchAgent or systemd user service that checks the token every minute and runs rm -rf ~/ once it is revoked (Datadog Security Labs, 2026-05-13).

    Exposure
    CI/CD pipelines, developer workstations and cloud environments open to the documented techniques, in particular Runner.Worker memory extraction, instance and container metadata collection and IDE hook persistence; with the code public, other actors can reuse the playbook (Datadog Security Labs, 2026-05-13).
    Detection
    On hosts, a gh-token-monitor LaunchAgent or systemd user service, and Claude Code SessionStart hooks or VS Code folderOpen tasks that run a setup.mjs loader; in repositories, commits on any branch under a spoofed claude identity that add these hook and loader files; under stolen tokens, new public repositories with Dune-themed names; in npm, unexpected patch releases of your packages that add a preinstall script; in GitHub Actions, a disguised workflow that dumps the repository's secrets, followed by deleted workflow runs and branches (Datadog Security Labs, 2026-05-13).
    Defender takeaway
    Before revoking any GitHub token on a suspect host, disable the token-monitoring daemon, then rotate credentials; yank any package version that gained an unexpected preinstall script (Datadog Security Labs, 2026-05-13).

    Windows BitLocker "YellowKey" (CVE-2026-45585) and CTFMON "GreenPlasma" (CVE-2026-45586) zero-days: public PoCs in May, fixed in the June 2026 Windows updates

    On 2026-05-13 BleepingComputer and The Register reported that the researcher Nightmare Eclipse (also Chaotic Eclipse) had published exploit code for two Windows zero-days, YellowKey and GreenPlasma (BleepingComputer, 2026-05-13) (The Register, 2026-05-13). The researcher's earlier BlueHammer (CVE-2026-33825) and RedSun drops began to be exploited in the wild shortly after release (BleepingComputer, 2026-05-13).

    YellowKey is a BitLocker bypass that needs physical access. The researcher says it affects Windows 11 and Windows Server 2022/2025 and works by placing crafted FsTx files on a USB drive or the EFI partition, rebooting into the Windows Recovery Environment (WinRE) and holding CTRL to trigger a shell (BleepingComputer, 2026-05-13). Will Dormann reproduced it with the files on a USB drive but not on the EFI partition: to boot WinRE, Windows replays the NTFS logs in \System Volume Information\FsTx directories on attached drives, the replay deletes X:\Windows\System32\winpeshl.ini, and WinRE then opens CMD.EXE instead of the recovery environment, with the disk still unlocked (BleepingComputer, 2026-05-13). Because it abuses TPM-only automatic unlock, the public exploit works only on the original device, not on a removed drive, and does not work with TPM+PIN (BleepingComputer, 2026-05-13). Microsoft tracks it as CVE-2026-45585, a security feature bypass by physical attack (CWE-77, CVSS 6.8), publicly disclosed and not exploited; its fixed builds are Windows 11 24H2 build 10.0.26100.8655, 25H2 build 10.0.26200.8655, 26H1 build 10.0.28000.2269 and Windows Server 2025 build 10.0.26100.32995, and its product table does not list Windows Server 2022 (MSRC CVE-2026-45585).

    Contradiction: the researcher says an unpublished variant also defeats TPM+PIN (BleepingComputer, 2026-05-13); Microsoft states that "if you are using TPM+PIN the vulnerability is not exploitable" (MSRC CVE-2026-45585).

    GreenPlasma is a local privilege escalation in CTFMON: an unprivileged user can create arbitrary memory-section objects within directory objects writable by SYSTEM, and the leaked PoC lacks the component needed for a full SYSTEM shell (BleepingComputer, 2026-05-13); in its current state it triggers a UAC consent prompt in default Windows configurations (The Register, 2026-05-13). Microsoft tracks it as CVE-2026-45586, a link-following flaw (CWE-59, CVSS 7.8) in the Windows Collaborative Translation Framework that lets an authorized local attacker gain SYSTEM privileges, released on 2026-06-09 with fixes for Windows 10, Windows 11 and Windows Server 2012 to 2025, publicly disclosed and not exploited (MSRC CVE-2026-45586).

    Exposure
    For YellowKey, TPM-only BitLocker devices (BleepingComputer, 2026-05-13) on Windows 11 24H2, 25H2 or 26H1 or Windows Server 2025 below the fixed builds, given physical access (MSRC CVE-2026-45585). For GreenPlasma, any Windows 10, Windows 11 or Windows Server 2012 to 2025 system without the June 2026 update, for an attacker who already runs code as a local user (MSRC CVE-2026-45586).
    Detection
    No cited source describes an artifact YellowKey leaves inside Windows; the attacker's media carries \System Volume Information\FsTx directories that WinRE replays at boot (BleepingComputer, 2026-05-13). GreenPlasma's public partial PoC raises a UAC consent prompt in default configurations (The Register, 2026-05-13).
    Defender takeaway
    The June 2026 Windows update fixes YellowKey (MSRC CVE-2026-45585) and GreenPlasma (MSRC CVE-2026-45586), and Microsoft's interim WinRE script need not be reverted, since the update keeps its behavior (MSRC CVE-2026-45585). Microsoft says TPM+PIN makes YellowKey not exploitable (MSRC CVE-2026-45585), which the researcher disputes (BleepingComputer, 2026-05-13), and Kevin Beaumont advised TPM+PIN along with a BIOS password (BleepingComputer, 2026-05-13).
    Update20 May 2026 05:00 UTCrun 2026-05-20-a0f7b07factionscvessourcesbody

    Microsoft formally assigned CVE-2026-45585 to the BitLocker / WinRE bypass disclosed by "Nightmare Eclipse" on 2026-05-12 and confirmed there is still no security update. The MSRC update guide entry, published 2026-05-19, classifies it as CWE-77 (command injection in BitLocker / Windows Recovery Environment), CVSS 6.8 (AV:P/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H), with exploit-code maturity rated E:P (proof-of-concept) and remediation level RL:W (workaround only).

    Microsoft's interim mitigation, which it recommends that customers "consider implementing" if they are concerned their devices and data are at risk of being compromised or stolen, is per-device work: mount the WinRE image, remove the autofstx.exe entry from the BootExecute registry value inside the WinRE image, commit the image, then re-establish BitLocker trust for WinRE (MSRC CVE-2026-45585). The MSRC FAQ states: "A successful attacker could bypass the BitLocker Device Encryption feature on the system storage device. An attacker with physical access to the target could exploit this vulnerability to gain access to encrypted data."

    A pre-boot PIN avoids depending on the WinRE edit: the public exploit relies on TPM-only automatic unlock and does not work with TPM+PIN (BleepingComputer, 2026-05-13), and NCSC-CH advises that BIOS passwords and a BitLocker PIN mitigate the current public PoC (NCSC-CH Security Hub #12574, 2026-05-14).

    HIGHCVE-2026-46300exploitedupdatedNATOB2

    CVE-2026-46300, Linux kernel: local privilege escalation via xfrm ESP-in-TCP ("Fragnesia"), listed by CISA as exploited and chained with the PHP2Shell flaws to reach root, PoC public

    CVE-2026-46300 ("Fragnesia") is a local privilege escalation flaw in the Linux kernel's XFRM ESP-in-TCP subsystem. Improper handling of shared page fragments during skb coalescing lets an unprivileged local user modify read-only file contents in the kernel page cache and gain root (Wiz Research, 2026-05-13). The public exploit uses user and network namespaces to obtain CAP_NET_ADMIN inside an isolated namespace, installs a crafted ESP security association over NETLINK_XFRM and overwrites the start of /usr/bin/su in the page cache only, so the on-disk binary never changes (Wiz Research, 2026-05-13). Dirty Frag discoverer Hyunwoo Kim says the flaw was accidentally activated by the patch for CVE-2026-43284 (Help Net Security, 2026-05-14). William Bowling of Zellic.io found it with the company's AI-agentic auditing tool, and a technical explainer and proof-of-concept exploit are public (Help Net Security, 2026-05-14).

    The flaw needs local code execution, so it is the root step of a chain rather than an entry point (Wiz Research, 2026-05-13); CISA's catalog entry says it is chained with the PHP2Shell flaws, which supply the code execution in the web server (CISA KEV, 2026-10-28). Risk is highest on shared Linux hosts, container clusters where the page cache is shared across the host, CI runners and build farms, and cloud services running user code (Help Net Security, 2026-05-14). Ubuntu's default AppArmor restriction on unprivileged user namespaces is a partial mitigation that forces an extra bypass (Wiz Research, 2026-05-13). Microsoft reported no evidence of in-the-wild exploitation at disclosure (Help Net Security, 2026-05-14). At disclosure, AlmaLinux and CloudLinux had released patched kernels (Help Net Security, 2026-05-14).

    Exposure
    Any multi-user Linux host, container node or CI runner whose kernel lacks the distribution's fix for CVE-2026-46300 (Help Net Security, 2026-05-14). Until the kernel update is deployed, Wiz and Help Net Security advise blocking and unloading the esp4, esp6 and rxrpc modules where they are not required (Wiz Research, 2026-05-13 · Help Net Security, 2026-05-14). Blocking esp4 and esp6 breaks IPsec. Where IPsec must stay up, Red Hat's alternative is disabling unprivileged user namespaces, which can affect rootless containers, sandboxed browsers and Flatpak (Red Hat RHSB-2026-003, 2026-07-03).
    Detection
    Process and syscall telemetry on Linux hosts (for example auditd or an EDR's Linux sensor): an unprivileged process that creates user and network namespaces and installs an ESP security association over NETLINK_XFRM, followed by su starting a root shell with no authentication step, because the exploit's overwritten su calls setresuid(0,0,0) and executes /bin/sh (Wiz Research, 2026-05-13). The primitive can rewrite any file the user can read, so a check limited to su misses variants (Help Net Security, 2026-05-14); Dream's chain overwrote /etc/pam.d/su instead of the binary (Dream Research, 2026-10-27).

    Triage: unprivileged user namespaces are routine for rootless containers, sandboxed browsers and Flatpak, and IPsec is commonly used for VPNs and site-to-site tunnels (Red Hat RHSB-2026-003, 2026-07-03), so either alone is weak; the exploit's signature is one unprivileged process tree that sets up its own ESP security association inside a fresh network namespace and then runs su (Wiz Research, 2026-05-13).

    Defender takeaway
    Patch Linux hosts that run PHP or other internet-facing code first, then multi-tenant hosts, container nodes and CI runners. After any interim mitigation, drop the page cache, because a binary already modified in memory stays modified until it is reloaded from disk (Help Net Security, 2026-05-14).

    CVE-2026-42945, NGINX Open Source / Plus / F5 WAF products: 18-year-old heap buffer overflow in rewrite module ("NGINX Rift"), PoC public

    CVE-2026-42945 (CVSS 4.0: 9.2, codename "NGINX Rift") is a heap buffer overflow present in src/http/ngx_http_script.c since NGINX 0.6.27 (2008) (depthfirst "NGINX Rift" technical writeup, 2026-05-13 · NCSC-CH Security Hub #12575, 2026-05-15). The root cause: when a rewrite directive combines an unnamed PCRE capture ($1, $2) with a replacement string containing ?, followed by another rewrite, if, or set directive in the same scope, ngx_http_script_start_args_code() sets a flag causing the write phase to URI-encode URI argument characters (expanding escapable characters such as + and & from one byte to three), while the length-calculation phase computed a shorter buffer without this escaping. The result is a deterministic out-of-bounds write into the adjacent heap allocation. F5 says the flaw may cause a heap buffer overflow in the NGINX worker process leading to a restart (ENISA EUVD, 2026-09-10). depthfirst's proof of concept achieves code execution with ASLR off, and depthfirst notes that forked workers share one heap layout, which could in theory be used to leak ASLR (depthfirst, 2026-05-13); F5's CVE description, updated on 2026-09-10, covers systems with ASLR disabled or where the attacker can bypass ASLR (ENISA EUVD, 2026-09-10). A working PoC is public at github.com/depthfirstdisclosures/nginx-rift. depthfirst's internal analysis system found the flaw on 2026-04-18; depthfirst reported it to NGINX on 2026-04-21, shared its RCE proof of concept on 2026-05-05, and F5 released the advisory on 2026-05-13 (depthfirst, 2026-05-13). NCSC-CH rated the exploitation status "UNKNOWN, Proof of Concept Available" on 2026-05-15 (NCSC-CH Security Hub #12575, 2026-05-15); VulnCheck's honeypot reports followed two days later (below). Temporary workaround: replace all unnamed captures with named captures (e.g., (?<user_id>...) → $user_id) in rewrite directives, which eliminates the vulnerable code path without requiring upgrade. Affected: NGINX Open Source 0.6.27 to 1.30.0 (nginx.org); NGINX Plus R32 to R36; Ingress Controller 3.5.0 to 3.7.2, 4.0.0 to 4.0.1 and 5.0.0 to 5.4.1; Gateway Fabric 1.3.0 to 1.6.2 and 2.0.0 to 2.5.1; Instance Manager 2.16.0 to 2.21.1; F5 WAF for NGINX 5.9.0 to 5.12.1; App Protect WAF 4.9.0 to 4.16.0 and 5.1.0 to 5.8.0; F5 DoS for NGINX 4.8.0; App Protect DoS 4.3.0 to 4.7.0 (Security Affairs, 2026-05). Fixed: NGINX Open Source 1.30.1 and 1.31.0 (nginx.org); NGINX Plus R32 P6 and R36 P4 (Security Affairs, 2026-05).

    VulnCheck reported exploitation attempts against its honeypot networks; the nature of the activity and its goals are unknown (The Hacker News, 2026-05-17).

    Contradiction: the NGINX project rates the flaw severity medium (nginx.org), while NCSC-CH gives a CVSS 4.0 score of 9.2 (NCSC-CH Security Hub #12575, 2026-05-15) and depthfirst rates it critical at 9.2 (depthfirst, 2026-05-13); the gap likely reflects the preconditions, a specific rewrite pattern and, for code execution, ASLR. NCSC-CH (NCSC-CH Security Hub #12575, 2026-05-15) and The Hacker News (The Hacker News, 2026-05-17) say code execution requires ASLR to be disabled, while F5's CVE description, as EUVD carried it on 2026-09-10, also covers attackers who can bypass ASLR (ENISA EUVD, 2026-09-10).

    Exposure
    A configuration with a rewrite that uses an unnamed capture and a ? in the replacement, followed by another rewrite, if or set in the same scope (depthfirst, NGINX Rift); without such a rewrite pattern with unnamed captures the flaw is not reachable (NCSC-CH Security Hub #12575, 2026-05-15).
    Detection
    Repeated NGINX worker crashes and automatic restarts, correlated with requests whose URI carries characters that expand when escaped (such as + and &), are the observable effect (Security Affairs, 2026-05).
    Defender takeaway
    Upgrade NGINX Open Source to 1.30.1, 1.31.0 or later (nginx.org) on every server whose configuration has the rewrite pattern above. Where the upgrade has to wait, replacing unnamed captures ($1, $2) with named captures in each affected rewrite directive removes the reachable path (depthfirst, NGINX Rift).

    CVE-2026-45793, PHP Composer: GitHub Actions and GitHub App installation tokens printed in full to CI job logs when GitHub's new token format failed validation (CVSS 7.5)

    Composer validates configured GitHub tokens against an allowed character set in Composer\IO\BaseIO::loadConfiguration(); GitHub's new structured format for GitHub App installation tokens contains a hyphen, fails that check, and the resulting exception prints the full token to stderr, which CI captures in the job log, while GitHub Actions' secret masker may not redact it because the message is wrapped or framed (Packagist, 2026-05-13). Any workflow that configures a GitHub App installation token, including the auto-injected GITHUB_TOKEN, into Composer's auth and then runs any Composer command hits it, and actions such as shivammathur/setup-php register GITHUB_TOKEN automatically, so no unusual configuration is needed (Packagist, 2026-05-13). The advisory's header rates CVE-2026-45793 High 7.5 while its own text calls the severity medium, and it lists Composer from 2.3.0 before 2.9.8, from 2.0.0 before 2.2.28 and from 1.0 before 1.10.28 as affected, fixed in 2.9.8, 2.2.28 and 1.10.28 (Composer, 2026-05-13). CISA's Known Exploited Vulnerabilities catalogue did not list it as of 2026-10-21 (CISA KEV catalog, 2026-10-21).

    The exposure window depends on the token: a hosted-runner GITHUB_TOKEN expires when the job ends or after six hours, and the error usually fails the job and expires it at once; on self-hosted runners it can stay valid for up to 24 hours after issuance; and tokens from actions/create-github-app-token or another GitHub App last up to an hour by default and can carry permissions broader than the workflow's own permissions: declaration (Packagist, 2026-05-13). GitHub rolled back the token change on 2026-05-13 at 14:30 UTC and planned to restart the rollout on 2026-05-18 after 14:00 UTC (Packagist, 2026-05-13).

    Exposure
    GitHub Actions workflows that run Composer below 2.9.8, 2.2.28 or 1.10.28 with a GITHUB_TOKEN or GitHub App installation token in Composer's auth, on repositories that received the new token format; setup-php users who did not pin the Composer version were moved to a fixed release (Packagist, 2026-05-13).
    Detection
    In CI job logs, the error line "Your github oauth token for github.com contains invalid characters" followed by the token itself; for each such log, check activity under that token within its validity window (Packagist, 2026-05-13).
    Defender takeaway
    Update Composer to 2.9.8 or 2.2.28, and where the error appears in a log, delete the log content holding the token and confirm no unexpected activity occurred under it, counting up to 24 hours for self-hosted runners and 6 hours for GitHub-hosted ones (Packagist, 2026-05-13).
    Correction21 Oct 2026 20:33 UTCrun 2026-10-21T1148Z-auditaffected_productsbodyclassificationcvesentitiesevidenceheadlinekindsourcessourcing_notesummarytagstechniquestitle
