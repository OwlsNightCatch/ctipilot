    Ghost CMS CVE-2026-26980: Content API SQL injection mass-exploited to steal Admin API keys and turn 700+ sites into ClickFix lures

    CVE-2026-26980 is an unauthenticated SQL injection in the Ghost CMS Content API, present from 3.24.0 to 6.19.0, fixed in 6.19.1 and rated CVSS 9.4 on Ghost's advisory; because it gives access to a site's API keys, Ghost recommends reviewing staff users and rotating keys after upgrading (Ghost, GHSA-w52v-v783-gw97). There is no application-level workaround, since the Content API key is public by design; a reverse proxy or WAF rule blocking Content API requests whose filter contains slug:[ (or slug%3A%5B) is the temporary mitigation (Ghost, GHSA-w52v-v783-gw97). The fix shipped in February, but many sites did not install it (BleepingComputer, 2026-05-24).

    XLab detected the campaign on 2026-05-07, confirmed 156 victim domains by 2026-05-10 and more than 700 in its enumeration of 2026-05-17, when it also found a second attack group; the two groups sometimes replace each other's code on the same site (XLab, 2026-05-21). XLab names Harvard University, Oxford University and Auburn University among the well-known sites affected, and its victim table is 48.1% personal blogs or independent sites (XLab, 2026-05-21); BleepingComputer adds DuckDuckGo and describes the mix as university portals, AI/SaaS companies, media outlets, fintech firms, security sites and personal blogs (BleepingComputer, 2026-05-24).

    The attackers used the SQL injection to read each site's Admin API key, which has management permissions over articles, themes and users, then called the Admin API (PUT /ghost/api/admin/posts/:id/) to append a JavaScript loader to articles in bulk (XLab, 2026-05-21). The loader fetches a cloaking script, which XLab traces to the commercial Adspect service, that fingerprints each browser and shows only visitors it judges to be real victims a forged Cloudflare "Verify you are human" page in an iframe (XLab, 2026-05-21). While the page silently downloads an archive, it tells the visitor to press WIN+R and paste a command that moves the archive to %TEMP%, extracts it with tar and starts the batch file inside it minimized; the batch file runs hidden PowerShell that downloads a DLL and starts one of its exported functions through rundll32 (XLab, 2026-05-21). From 2026-05-16 the DLL fetched a stealer, an Electron application that persists through Electron's login-item API and polls its server every 30 seconds for JavaScript or executables to run (XLab, 2026-05-21). BleepingComputer also lists DLL loaders and JavaScript droppers among the payloads (BleepingComputer, 2026-05-24).

    Exposure
    Any Ghost site running 3.24.0 to 6.19.0; the running Ghost version is the test (Ghost, GHSA-w52v-v783-gw97).
    Detection
    On the site, PUT /ghost/api/admin/posts/:id/ requests from unfamiliar sources or in bulk within a short period, Admin API keys nobody created, and extra <script> tags in post bodies, Code Injection settings or theme files (XLab, 2026-05-21). On endpoints, a Run-dialog command that moves an archive out of the Downloads folder, extracts it with tar and starts a batch file, followed by hidden PowerShell and rundll32 loading a freshly downloaded DLL (XLab, 2026-05-21).
    Defender takeaway
    An upgrade does not undo the compromise: after moving to 6.19.1 or later, rotate the Admin API key, Content API key, administrator password and sessions, review staff accounts, and remove injected scripts at the database level, not just in the editor (Ghost, GHSA-w52v-v783-gw97) (XLab, 2026-05-21). XLab advises keeping at least 30 days of Admin API call logs so a compromise can be traced back (XLab, 2026-05-21).

    "Underminr": a multi-tenant-CDN domain-fronting variant that blinds DNS-layer filtering

    ADAMnetworks disclosed Underminr, a structural evolution of domain fronting that abuses the shared-IP, multi-tenant architecture of modern CDN edges rather than a single-CDN misconfiguration (ADAMnetworks, 2026-05-21). Classic domain fronting (overriding the HTTP Host header behind a permitted SNI) was largely closed by the major CDNs in 2021–2022 by enforcing SNI/Host consistency. Underminr instead presents the SNI and HTTP Host of a legitimate, allow-listed domain hosted on a shared edge while forcing the request to the IP of a different tenant (the attacker's origin) on the same edge, exploiting the fact that the CDN's internal tenant routing is decoupled from the network-visible Host/SNI (SecurityWeek, 2026-05-23). As SecurityWeek frames it, "the detection gap appears when DNS decisions, edge IPs, SNI, Host headers, and CDN tenant routing are not correlated." No CVE was assigned; this is an architectural property of shared-edge multi-tenancy, not a software bug. SecurityWeek reports roughly 88 million domains on shared infrastructure are potentially in scope, with US, UK and Canadian infrastructure most affected; the technique does not require compromising the legitimate domain, only co-tenancy on the same edge IP range.

    Why it matters to us: this maps to ATT&CK T1090.004 (Proxy: Domain Fronting) and is squarely a C2 / exfiltration-evasion concern for the many CH/EU public-sector networks whose egress control leans on DNS-layer filtering (DNS RPZ, recursive-resolver allow-lists) or that treat a CDN's published IP range as a proxy for the actual destination, both of which Underminr defeats, because the FQDN legitimately resolves to the shared edge IP and edge-terminated TLS inspection never sees the origin-routing decision. Defenders should stop treating DNS/domain allow-listing as a sufficient egress control on its own; correlate SNI, Host, the resolved edge IP and (where available) CDN tenant identity per flow, and prefer per-flow identity verification (ZTNA) over perimeter-DNS-filter trust. Specific vulnerable CDN providers are not named in the public reporting.
