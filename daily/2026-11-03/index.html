    Patchstack reports that default WordPress installs reach the Brotli decoder without authentication through the xmlrpc.php pingback and the operating system's libbrotli, shown to crash a worker but not to execute code; WordPress hosts need a patched libbrotli package, which the official WordPress image did not yet carry.

    Patchstack reports that WordPress ships no Brotli of its own but links the operating system's libbrotli through libcurl, so one unauthenticated POST to xmlrpc.php can take down a PHP worker on a stock install: the pingback method makes WordPress fetch an attacker-named URL and decode the Brotli reply (Patchstack, 2026-10-30). A laboratory demonstration killed a worker or pinned it at full CPU, its author says no code execution is included, and Patchstack says no public chain aims at PHP; the fix is a patched libbrotli package, and the official wordpress:latest image still carried a vulnerable one when Patchstack wrote (Patchstack, 2026-10-30).
