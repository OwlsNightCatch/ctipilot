    NOTABLECVE-2026-85097exploitedupdatedNATOB2

    CVE-2026-85097, Bricksforge for WordPress: an unauthenticated upload in the Pro Forms module writes attacker PHP into the uploads directory, exploited since 7 October; fixed in 3.1.8.10 and 4.0.0, with a related upload fix in 4.0.1 (CVSS 9.8)

    Bricksforge's Pro Forms module checks a file's type when it is first uploaded but trusts the file metadata the client sends when the form is submitted, in particular the url field of the temporaryFileUploads parameter (Patchstack, 2026-10-08). An attacker obtains a nonce from the unauthenticated bricksforge_regenerate_nonce AJAX endpoint, uploads a GIF/PHP polyglot that passes the type check, then submits a form whose file path names that image and whose url ends in a PHP extension; the plugin writes the image's content to the PHP path and one request to it executes the code (Patchstack, 2026-10-08). Versions up to and including 3.1.8.9 are affected (Patchstack, 2026-10-08). The vendor's changelog, revised after the disclosure, states that the flaw was fixed in 3.1.8.10 and in 4.0.0, and lists a related security fix in the same Pro Forms upload area in 4.0.1 of 2026-10-08 (Bricksforge, 2026-10-13); Patchstack also names 3.1.8.10 (Patchstack, 2026-10-08). Dr. Web credits Wordfence with a CVSS score of 9.8 and Patchstack with 10.0 (Dr. Web, 2026-10-09).

    Patchstack's telemetry first recorded exploitation attempts on 2026-10-07 at 21:47 UTC, from 63 distinct source addresses, and it calls the activity automated without attributing it (Patchstack, 2026-10-08). Patchstack describes exploitation attempts and says an attacker with execution can deploy web shells, modify site content, read data and persist (Patchstack, 2026-10-08). It counts about 6,000 active installations (Dr. Web, 2026-10-09), Previdian lists it as exploited in the wild and links public proof-of-concept code (Previdian, 2026-10-08), and the flaw is not in CISA's KEV catalog (Dr. Web, 2026-10-09).

    Exposure
    WordPress sites running Bricksforge versions up to and including 3.1.8.9 (Patchstack, 2026-10-08) with the Pro Forms module active, including sites whose forms have no upload field (Bricksforge, 2026-10-13). Patchstack and Dr. Web bound the affected range at 3.1.8.9 (Dr. Web, 2026-10-09); the vendor states that 4.0.0 already carries the fix, while the related upload issue fixed in 4.0.1 affects every site with Pro Forms active, and the changelog names no 3.x build for that second fix (Bricksforge, 2026-10-13). Bricksforge is not in the wordpress.org plugin directory, so no public version statistics exist, and updates come with an annual licence, so a site with a lapsed licence may not receive the fix (Dr. Web, 2026-10-09).
    Detection
    In web server and WordPress access logs, POST requests to /wp-json/bricksforge/v1/form_submit or to admin-ajax with the bricksforge_form_submit action that carry a temporaryFileUploads value pairing an image path with a PHP-extension destination, preceded by a call to the nonce endpoint and repeated with changing extensions, case or encodings, from 2026-10-07 onward; in file-integrity and endpoint telemetry, new PHP files in the WordPress uploads tree, the plugin's temporary upload folder first, and web requests to them (Patchstack, 2026-10-08). Patchstack says a site that ran a vulnerable version without protection should have its historical logs and the host reviewed for unexpected PHP files, unusual application activity and unauthorized changes (Patchstack, 2026-10-08); Dr. Web adds a check of the user list for unknown administrator accounts (Dr. Web, 2026-10-09).
    Defender takeaway
    Update every Bricksforge site to 4.0.1 or later now, since the vendor lists the related Pro Forms upload fix only there; a 3.x site needs at least 3.1.8.10 (Bricksforge, 2026-10-13); where that is not possible, deactivate Pro Forms or the plugin and block PHP execution in the uploads directory (Dr. Web, 2026-10-09). On a site that was reachable and unpatched since 2026-10-07, run the log and file search above, and if code turns up restore from a backup older than 2026-10-07 and change all passwords (Dr. Web, 2026-10-09).

    Bricksforge has revised its changelog: CVE-2026-85097 itself "was fixed earlier in 3.1.8.10 and in 4.0.0", and the 4.0.1 release of 2026-10-08 fixes a related issue in the same Pro Forms upload area that affects every site with Pro Forms active, including forms without upload fields (Bricksforge, 2026-10-13). The same changelog lists no 3.x build for that second fix, so a site on 3.1.8.10 is protected against the exploited flaw but not shown as covered for the related one; 4.0.1 or later carries both (Bricksforge, 2026-10-13). Version 4.0.2 of 2026-10-13 stops the upload check introduced in 4.0.1 from rejecting about one normal image in sixty and tightens access checks on the plugin's REST endpoints (Bricksforge, 2026-10-13). Previdian now lists the flaw as exploited in the wild, based on third-party reporting, and links public proof-of-concept code (Previdian, 2026-10-08).
