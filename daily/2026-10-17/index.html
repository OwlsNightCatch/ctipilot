    HIGHNATOB1

    AOMEI Backupper and AnyViewer update files tampered with for five to ten minutes at a time between April and July 2026 to push the CROSSROAD downloader and the SHINYROAD backdoor, with Switzerland among 11 countries GTIG names

    GTIG and Mandiant report that a cluster they track as UNC7017 repeatedly altered two configuration files on AOMEI Technology's update servers between April and July 2026, each time for five to ten minutes before restoring the genuine content; GTIG confirmed three windows and says more probably went unseen (GTIG, 2026-10-16). ManageEngine's Threat Analysis Lab (METAL) writes "There was no CVE, no memory corruption, and no unpatched component." (METAL, 2026-10-16).

    The client polls down_html.ini (update archive address and MD5 checksum) and Notifycfg.ini (what to display and run); during a window the actor pointed the first at an attacker-controlled ZIP with a matching checksum and padded the second with more than 35,000 lines of dummy sections, so the client started the unpacked downloader from its html directory, and GTIG describes the same flow for AnyViewer (GTIG, 2026-10-16). METAL's EDR recorded the chain on Backupper 8.3.0 (METAL, 2026-10-16).

    The downloader, CROSSROAD, stops in some branches when the host geolocates to China (GTIG, 2026-10-16) and, METAL adds, when specific endpoint security agents are present (METAL, 2026-10-16). It registers a scheduled task that runs a signed Radmin binary every three hours; that binary loads an attacker-built DLL by search-order hijacking, which registers an in-process COM server running the SHINYROAD backdoor as encrypted PocketPy bytecode (GTIG, 2026-10-16). On some hosts GTIG later saw the Adaptix C2 agent, disguised as Nitro PDF tooling and started by hidden PowerShell through a second scheduled task (GTIG, 2026-10-16). The 20 July window also pointed a popup at a remote WebDAV path through an invisible window, which can leak the user's NetNTLMv2 response (GTIG, 2026-10-16).

    GTIG's telemetry shows affected IT-services, telecommunications and higher-education organizations in 11 countries including Switzerland and calls the targeting opportunistic; AOMEI told Mandiant on 2026-07-29 that it had taken corrective action (GTIG, 2026-10-16). AOMEI's Backupper release notes through 8.5.0 list no change to update verification as of 2026-10-17 (AOMEI Technology, 2026-10-09).

    Exposure
    Windows hosts running AOMEI Backupper or AnyViewer that polled for updates during an unseen window between April and July 2026; server-side repair does not clean a host that already ran the downloader (GTIG, 2026-10-16).
    Detection
    In process telemetry, an executable written into the Tmphtml or html folders and started by the notification process, and a signed Radmin binary loading an unexpected DLL (GTIG, 2026-10-16); METAL adds dllhost.exe hosting a COM component registered from a non-standard path (METAL, 2026-10-16). Also scheduled tasks named RadminComponentRuntime or NitroRuntime, and outbound SMB (TCP 445) and WebDAV to external addresses; hunt the whole April to July span and preserve the cached update files in the Tmphtml folder (GTIG, 2026-10-16).

    Triage: do not validate an alert by fetching AOMEI's update address now: the files revert within minutes and the genuine content served then has led analysts to dismiss real detections; the Nitro PDF camouflage can make alerts read as isolated user downloads, so trace each one's parent process back to the updater (GTIG, 2026-10-16). Radmin is legitimate software, so provenance discriminates: METAL's EDR recorded the updater's unsigned child process installing it (METAL, 2026-10-16).

    Defender takeaway
    Hunt every Windows host that runs AOMEI Backupper or AnyViewer for these artifacts even though AOMEI says its servers are repaired, treat a match as a compromised host, and block outbound SMB and WebDAV to external addresses, which GTIG advises against NTLM credential coercion (GTIG, 2026-10-16).

    CVE-2026-82078 / CVE-2026-81578, PaperCut NG/MF: an Apache Tapestry request-routing confusion chains an unauthenticated config rewrite to arbitrary code execution, exploited before a patch existed

    First published 2026-08-29 · open finding →

    Update17 Oct 2026 03:38 UTCrun 2026-10-17T0256Z-inteltitlesummaryregionstechniquescvessourcesevidencesourcing_noteactionsbody

    Hunt.io recovered the attacker's open directories (2026-10-15) and reports a second route to code execution through PaperCut's XML-RPC API that does not use the Tapestry bypass and works when the API allowlist is too permissive or no explicit token is set, a cron-kept reverse SOCKS tunnel, an offline LSA-secret playbook and 45 victims with live internal pivots, Switzerland among the countries listed. Hunt.io does not report the XML-RPC route used against a victim; PaperCut's documentation names the token and allowlist settings that close it. PaperCut's September bulletin, revised 2026-10-13, now lists CVE-2026-82077 as fixed in 24.1.10 and names 24.1.11 as the v24 build.

    Hunt.io found three open directories on one attacker host and reconstructs the operator's toolkit from the files in them; it says the recovered material aligns with GreyNoise's published account of the AI-driven campaign (Hunt.io, 2026-10-15). The operator's notes record a second route to code execution that does not use the Tapestry bypass: PaperCut's XML-RPC API at /rpc/api/xmlrpc accepts api.setConfigValue when its network allowlist is too permissive or no explicit API token is configured, because the handler then falls back to the built-in admin password as the token, and the same user-lookup settings are then rewritten (Hunt.io, 2026-10-15). Hunt.io says an instance already hardened against the Tapestry bypass is not necessarily protected against this one if its XML-RPC API is exposed with weak access controls (Hunt.io, 2026-10-15); it does not report the route used against a victim. PaperCut's documentation says the API's authentication token should be defined in the advanced config key auth.webservices.auth-token and that the address allowlist can be set in the admin interface or through auth.webservices.allowed-addresses (PaperCut Software, 2026-01-30).

    The files also show what follows a compromise. A Linux kit keeps a chisel reverse SOCKS5 client alive through cron entries (periodic and at reboot) and a watchdog script that checks the process (Hunt.io, 2026-10-15). The Windows playbook exports the SECURITY and SYSTEM registry hives from a compromised host to recover LSA secrets, the domain machine account's password among them, offline (Hunt.io, 2026-10-15). The scale comes from the actor's own files: a reconnaissance pool of 1,005 hosts in at least 45 countries (800 confirmed vulnerable and 205 flagged from version fingerprinting), 2,165 logged attempts, 46 Active Directory domains packaged as victim data and 45 targets with a live reverse SOCKS5 pivot at the time of capture (Hunt.io, 2026-10-15). Switzerland is among the countries listed for those 45 targets, with no sector or organisation named, and Hunt.io says it shared its findings and the victim data with the national CERTs of the affected countries (Hunt.io, 2026-10-15).

    PaperCut's September security bulletin, last updated 2026-10-13, now lists CVE-2026-82077 as fixed in 24.1.10 on the 24.x branch as well as in 26.0.5 and 25.0.13, and recommends 26.0.5, 25.0.13 or 24.1.11 or later (PaperCut Software, 2026-09-24).

    First published 2026-10-14 · open finding →

    Update17 Oct 2026 03:36 UTCrun 2026-10-17T0256Z-intelsummarysourcesevidenceactionsbody

    Microsoft's Exchange Team now gives a workaround for the instability that the October 2026 Windows Server updates can cause on Exchange servers: it advises against uninstalling them and says setting the registry value EpmapSavedContextCap to 65536 and rebooting has solved the cases it assisted. It adds that DAG members losing quorum are among the reported symptoms and that the Exchange security updates are not the cause.

    Microsoft's Exchange Team has published guidance for Exchange servers that become unstable after the October 2026 Windows Server updates. Since 2026-10-13 it has seen reports of OWA failing with MapiExceptionMdbOffline (hr=0x80004005, ec=1142; event ID 1006 in the Application log), mail queues growing during the day, DAG members unable to reach quorum and a reboot helping only temporarily; Exchange 2016, 2019 and Subscription Edition can all be affected (Microsoft Exchange Team, 2026-10-17). It says the issues are not related to installing the October 2026 Exchange security updates and that any Exchange version running on an affected Windows build can be hit; KB5126646 (Windows Server 2025), KB5126655 (2022), KB5126651 (2019) and KB5126868 (2016) can cause the failures after some time, and the impact varies with Exchange load, so some servers may never see a problem (Microsoft Exchange Team, 2026-10-17).

    Microsoft's recommendation is not to uninstall the October 2026 Windows Server updates and, from an elevated command prompt on the Exchange server, to set the registry value EpmapSavedContextCap (REG_DWORD) under HKLM\SOFTWARE\Microsoft\Rpc to 65536, reboot, monitor, and raise the limit if the problem recurs; it says this has solved the customer cases it has assisted (Microsoft Exchange Team, 2026-10-17).
