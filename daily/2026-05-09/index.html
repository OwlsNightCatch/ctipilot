    Berlin court orders Apobank to refund EUR 218,000 lost to a letter, QR-code and phone scam that enrolled the attackers' own device

    Landgericht Berlin II ruled on 2026-04-22 (38 O 293/25) that Apobank may not refuse to refund about EUR 218,000 on grounds of gross negligence: a bank-branded letter asked the customer to register a new security procedure, its QR code led to a cloned banking portal, a caller posing as the bank guided her through the process, and photographing a QR code let the attackers enrol their own device; the judgment is not yet final and the customer bears only the EUR 50 statutory share (Borncity, 2026-05-09). Beyond the holding, the chamber remarked that the login and the attackers' new-device registration came from entirely different IP addresses and providers and that the bank did not block this discrepancy automatically (heise online, 2026-05-08).

    Contradiction: Borncity has a QR code in the letter leading to the manipulated page (Borncity, 2026-05-09), while heise reports that the customer was asked to set up two-factor authentication during her usual login through her browser's favourites bar (heise online, 2026-05-08).

    Defender takeaway
    The attack's decisive step was a device enrolment authorised by the victim, so the control point is the enrolment itself: a new authenticator registered from a network or provider different from the session that requested it deserves a hold and an out-of-band confirmation (heise online, 2026-05-08).

    DAEMON Tools Lite supply-chain compromise: signed installers deliver a profiler worldwide, with a backdoor and QUIC RAT reserved for a dozen targets in Russia, Belarus and Thailand

    Kaspersky found that DAEMON Tools installers distributed from the product's legitimate website and signed with the developer's certificates had been trojanised from 2026-04-08: in versions 12.5.0.2421 to 12.5.0.2434 the helper binaries DTHelper.exe, DiscSoftBusServiceLite.exe and DTShellHlp.exe, signed by AVB Disc Soft, were compromised, and version 12.6.0.2445 no longer contains the malicious behaviour (Kaspersky Securelist, 2026-05-05). At startup the trojanised binaries activate a backdoor that sends GET requests to a domain typosquatting the vendor's download site; when the server replies with a shell command, it runs through cmd.exe, which in the observed cases ran PowerShell to download an executable into C:\Windows\Temp and execute it, the first payload being a .NET information collector (Kaspersky Securelist, 2026-05-05). Kaspersky saw several thousand infection attempts in more than 100 countries, 10% of the affected systems belonging to organizations, and most received only the information collector (Kaspersky Securelist, 2026-05-05). A minimalistic backdoor reached about a dozen machines of government, scientific, manufacturing and retail organizations in Russia, Belarus and Thailand, and was used to deploy QUIC RAT against one organization, an educational institution in Russia; QUIC RAT supports HTTP, UDP, TCP, WSS, QUIC, DNS and HTTP/3 for command and control and can inject payloads into notepad.exe and conhost.exe (Kaspersky Securelist, 2026-05-05). Chinese strings in the collector may imply a Chinese-speaking actor, but Kaspersky does not attribute the compromise, and whether the intent is espionage or big-game hunting is unclear (Kaspersky Securelist, 2026-05-05). The developer says only the free Lite edition was affected (The Record, 2026-05-06).

    Exposure
    Endpoints that installed or updated DAEMON Tools Lite to a version from 12.5.0.2421 to 12.5.0.2434 from 2026-04-08 onward (Kaspersky Securelist, 2026-05-05).
    Detection
    In DNS and proxy telemetry, a DAEMON Tools binary beaconing at startup to a lookalike of the vendor's download domain is the earliest signal; in process telemetry, the same binary spawning cmd.exe and then PowerShell that downloads a file into C:\Windows\Temp and executes it follows when the server issues a command (Kaspersky Securelist, 2026-05-05). Injection into notepad.exe or conhost.exe shortly after such a chain points to QUIC RAT (Kaspersky Securelist, 2026-05-05).
    Defender takeaway
    A validly signed installer from the vendor's own site was the delivery vehicle, so code-signing trust did not help; inventory DAEMON Tools Lite installations, upgrade or remove them, and hunt the helper-to-PowerShell chain on any host that ran an affected version (Kaspersky Securelist, 2026-05-05).

    NCSC-CH's Security Hub post 12551 of 2026-05-08 lists six CVEs in the SEPPmail Secure E-Mail Gateway, scored from 6.9 to 9.3, with exploitation status unknown and vendor patches available since 2026-04-24 (NCSC-CH, 2026-05-08). SEPPmail's 15.0.4 release notes say test endpoints intended only for development had been left active in the beta GINA v2 web interface and are now removed (SEPPmail release notes). CVE-2026-44128 (9.3) is unauthenticated remote code execution through a parameter passed to Perl eval() and was already fixed in 15.0.2.1 (NCSC-CH, 2026-05-08) (InfoGuard Labs, 2026-05-18); CVE-2026-44126 (9.2), an insecure deserialization, was fixed in 15.0.3 (InfoGuard Labs, 2026-05-18), while NCSC-CH's advisory says the vulnerabilities were fixed in 15.0.4 (NCSC-CH, 2026-05-08); CVE-2026-44125 (9.3, missing authorization on GINA v2 endpoints), CVE-2026-44127 (8.8, file inclusion and arbitrary file deletion), CVE-2026-44129 (8.3, server-side template injection) and CVE-2026-7864 (6.9, exposure of sensitive information) were fixed in 15.0.4 (InfoGuard Labs, 2026-05-18); the scores are NCSC-CH's (NCSC-CH, 2026-05-08). The appliance is OpenBSD-based with Perl web applications, and self-registration, enabled by default, gives an attacker an authenticated session (InfoGuard Labs, 2026-05-18).

    Exposure
    SEPPmail appliances on a release older than 15.0.4 with the GINA v2 interface exposed; GINA v2 has to be explicitly activated in the system settings, which is how to tell whether its flaws apply (InfoGuard Labs, 2026-05-18). InfoGuard describes SEPPmail as widely used in the DACH region and counts several thousand public instances on Censys (InfoGuard Labs, 2026-05-18).
    Detection
    Internet requests to /v1/file.app, whose JSON body carries the path traversal in its file field (visible where a WAF or reverse proxy logs request bodies), and on the appliance a changed /etc/syslog.conf or an unexpected process started by syslogd after the 15-minute log-rotation reload, the chain InfoGuard uses for CVE-2026-2743 (InfoGuard Labs, 2026-05-18); an appliance that ran an affected build exposed to the internet needs that check after patching.
    Defender takeaway
    The GINA interface is internet-facing by design, so every appliance should run the current 15.0.x release, and an appliance that ran an affected build with GINA v2 exposed warrants a compromise check rather than a patch alone.

    HIGHCVE-2026-43284 +1updatedNATOB2

    CVE-2026-43284 / CVE-2026-43500 Linux Dirty Frag: deterministic page-cache write to root through xfrm-ESP and RxRPC, public exploit, fixes released

    Researcher Hyunwoo Kim (V4bel) published "Dirty Frag" on 2026-05-07, after the embargo had been broken by external factors and before patches or CVE ids existed (V4bel, 2026-05-07). It is two page-cache write flaws: CVE-2026-43284 in the xfrm-ESP (IPsec) receive path, in the kernel since 2017 and fixed in mainline commit f4c50a4034e6, and CVE-2026-43500 in RxRPC, in the kernel since 2023 and fixed in mainline commit aa54b1d27fe0 (V4bel, 2026-05-07). In both, a page-cache page planted with splice() sits in a fragment of a network buffer and the receiving code decrypts it in place, writing into the cached copy of a file: the ESP variant stores 4 attacker-chosen bytes per trigger into a setuid binary such as su, and the RxRPC variant stores 8 bytes whose value the attacker brute-forces through the session key, aimed at /etc/passwd; the result is deterministic root without a race window (V4bel write-up, 2026-05-07). The ESP variant needs the privilege to create a user namespace, which Ubuntu sometimes blocks through AppArmor; the RxRPC variant needs no namespace but depends on the rxrpc module, which most distributions do not ship and Ubuntu loads by default (V4bel, 2026-05-07). The kernel.org CNA scores CVE-2026-43284 CVSS 8.8, and NVD and CISA score CVE-2026-43500 7.8 (Ubuntu, 2026-05-08). Microsoft reports limited in-the-wild privilege escalation involving su that "may be indicative of techniques associated with either" Dirty Frag or Copy Fail: an SSH session ran an ELF binary that escalated through su, then edited a GLPI LDAP authentication file and deleted and read web session files (Microsoft Security Blog, 2026-05-08). Copy Fail is the earlier CVE-2026-31431 (Microsoft Security Blog, 2026-05-08).

    The researcher tested the exploit on Ubuntu 24.04.4, RHEL 10.1, openSUSE Tumbleweed, CentOS Stream 10, AlmaLinux 10 and Fedora 44 (V4bel, 2026-05-07). Ubuntu publishes fixed kernels for every supported release from 18.04 to 26.04 (Ubuntu, 2026-05-08), and Red Hat states that fixes are released for all affected products and that CVE-2026-43500 does not affect Red Hat products (Red Hat RHSB-2026-003). Where a fix cannot be applied, NCSC-CH advises blocking or removing the esp4, esp6 and rxrpc modules (NCSC-CH advisory 12547, 2026-05-08), which affects IPsec and AFS where they are in use (Ubuntu, 2026-05-08); on RHEL, user.max_user_namespaces=0 blocks the ESP path (Red Hat RHSB-2026-003).

    Exposure
    Linux hosts on kernels without their distribution's fix where a local user can run code; the ESP path needs the privilege to create a user namespace, and the RxRPC path needs the rxrpc module, which Ubuntu loads by default (V4bel, 2026-05-07).
    Defender takeaway
    Install the distribution kernel update, which makes the module mitigations unnecessary (Ubuntu, 2026-05-08); where it cannot be installed yet, disabling unprivileged user namespaces is the mitigation Red Hat gives for its affected kernels (Red Hat RHSB-2026-003).
    Detection
    The write modifies the page cache in RAM (V4bel write-up, 2026-05-07) while the file on disk never changes (Aikido Security, 2026-09-04), so file-write watches do not fire. Look instead for setuid binaries such as su executed from an unprivileged shell and returning root without an authentication event, for esp4, esp6 or rxrpc module loads on hosts that use neither IPsec nor AFS, and, after an incident, for differences between cached and on-disk file contents. Microsoft notes that malicious modifications may persist in cached file content after the vulnerable modules are disabled, and suggests validating critical files and considering clearing the page cache (Microsoft Security Blog, 2026-05-08).

    CVE-2026-42208: LiteLLM Proxy pre-authentication SQL injection in API-key verification, first exploitation attempt 36 hours after the advisory, CISA KEV-listed (CVSS 4.0 9.3)

    LiteLLM's advisory GHSA-r75f-5x8p-qvmc, published on 2026-04-20, describes a SQL injection in the proxy's API-key verification: the caller-supplied value was not passed to the database as a separate parameter, and the flaw is fixed in 1.83.7 (LiteLLM, 2026-04-20). Bishop Fox confirmed that versions 1.81.16 through 1.83.6 are exploitable without credentials from any LLM API route, through the Authorization: Bearer value reaching PrismaClient.get_data(); the response is always the same HTTP 401, so exploitation runs over a time-based blind channel using PostgreSQL's pg_sleep() (Bishop Fox, 2026-05-06). On a stock Docker Compose deployment with the Postgres sidecar, the application database user is a superuser, which raises the impact beyond reading metadata (Bishop Fox, 2026-05-06). Virtual keys are stored as SHA-256 hashes, but the provider credentials are stored for use (Bishop Fox, 2026-05-06) (Sysdig, 2026-04-27).

    Sysdig observed the first exploitation attempt 36 hours and seven minutes after the advisory reached the global database, with queries against LiteLLM_VerificationToken (virtual keys, including the master key), litellm_credentials (stored upstream provider credentials) and litellm_config (Sysdig, 2026-04-27). Sysdig saw no follow-through: no authenticated calls with exfiltrated keys, no virtual-key minting through /key/generate and no reuse of provider credentials, so its finding is the speed and precision of the enumeration rather than a confirmed compromise; it still advises treating any internet-facing instance on a vulnerable version as compromised (Sysdig, 2026-04-27). CISA added the flaw to its Known Exploited Vulnerabilities catalog on 2026-05-08 (CISA KEV catalog, 2026-05-08). The published workaround, general_settings.disable_error_logs: true, closes only one of the two code paths that reach the vulnerable query (Bishop Fox, 2026-05-06).

    Exposure
    LiteLLM Proxy 1.81.16 through 1.83.6 with the default PostgreSQL backend, reachable by untrusted clients (Bishop Fox, 2026-05-06).
    Detection
    In proxy access logs, HTTP 401 responses to LLM API routes that take several seconds instead of under 100 milliseconds, from bearer values that are not sk- virtual keys, and proxy log errors stating that a virtual key was expected to start with sk- (Bishop Fox, 2026-05-06). LiteLLM provides a helper to review PostgreSQL query history for the injection (LiteLLM, 2026-04-29).
    Defender takeaway
    Upgrading stops new extraction but not the use of keys already taken: any instance exposed during the window needs its stored provider credentials rotated (Sysdig, 2026-04-27).

    CVE-2026-31431 Copy Fail: Linux kernel AF_ALG page-cache write gives any local user root on mainstream distributions, public exploit, CISA KEV-listed (CVSS 7.8)

Microsoft reports limited in-the-wild privilege escalation involving su that may be associated with either Dirty Frag or Copy Fail (Microsoft Security Blog, 2026-05-08).

    Exposure
    Any Linux host where an attacker can run code as an unprivileged local user, including inside a container sharing the host kernel, on a kernel without the fix (Xint, 2026-04-29).
    Detection
    File-integrity tools comparing on-disk checksums miss the corruption, because the on-disk file is unchanged and only the page cache is modified (Xint, 2026-04-29). The escalation shows up as an unprivileged process opening AF_ALG sockets and calling splice(), followed by a setuid binary such as su granting root without a matching authentication event; after patching, look back for root shells spawned from su by unexpected accounts since late April (Xint, 2026-04-29) (Microsoft Security Blog, 2026-05-08).
    Defender takeaway
    A public, distribution-portable root exploit for local users puts every multi-user, container or web-facing Linux host on the patch-now list; where a fixed kernel cannot be deployed immediately, blocking AF_ALG socket creation with seccomp or blacklisting algif_aead closes the path (Xint, 2026-04-29).     DENIC .de DNSSEC outage: a faulty key rollover made all .de domains unresolvable for validating resolvers for more than three hours on 5 May 2026

    During a routine, scheduled DNSSEC key rollover on the evening of 2026-05-05, DENIC distributed signatures for the .de zone that validating resolvers could not verify, so they treated responses for all .de domains as bogus (DENIC, 2026-05-06). DENIC dates the incident from 21:57, began distributing a correct zone at 00:08 and had fully restored normal operation by 01:15 on 2026-05-06, giving no time zone; read as CEST, that is 19:57 to 23:15 UTC (DENIC, 2026-05-06); Cloudflare saw SERVFAILs from about 19:30 UTC and rolled out its own mitigation at 22:17 UTC through an existing override rule, having no native negative trust anchor mechanism (Cloudflare, 2026-05-06); heise gives 21:43 for the first disruption, which read as CEST is 19:43 UTC (heise online, 2026-05-08), so the three sources give three onsets. DENIC's analysis traces the fault to in-house code around its hardware security modules in the third-generation signing system it put into operation in April 2026: instead of one key pair stored on three HSMs, the software generated three different key pairs, one per HSM, and only one of them matched the pre-published DNSKEY (DENIC analysis, 2026-05-08). Because signatures over NSEC3 records were also unverifiable, even second-level domains without DNSSEC failed to resolve, and DENIC's three permanent validation tools detected the anomaly but their alerts were not processed correctly (DENIC analysis, 2026-05-08). DENIC's final report of 2026-06-11 confirms that initial analysis, rules out any compromise of the signing system and any malfunction of Knot or the HSMs, and explains that the test environment, a single HSM at one location, did not fully execute the rollover-agent code, which misbehaves only when several HSMs are connected (DENIC final report, 2026-06-11).

    Defender takeaway
    A TLD-side DNSSEC failure looks the same as an attack to a validating resolver; operators of validating resolvers should have a tested way to mark a broken TLD as insecure and should rely on serve-stale to absorb the first hours, as Cloudflare did (Cloudflare, 2026-05-06).
