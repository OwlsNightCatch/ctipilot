    Belgium's CCB warns that attackers abused Microsoft Entra ID SMS first-factor sign-in (phone number and one-time code, no password) to compromise several Belgian organisations; turning off 'Use for sign-in' is the priority step

    The Belgian Centre for Cybersecurity (CCB) warned on 2026-11-10 that a trusted partner had observed successful attacks against multiple Belgian organisations in which attackers abused Microsoft Entra ID SMS as a first factor, the sign-in mode in which a phone number and a one-time code replace the password (CCB, 2026-11-10). The warning gives no victim count, sector, actor, date range or attack chain, and it does not say how the codes were obtained; its only statement on the factor itself is that SMS and voice can be phished, intercepted or SIM-swapped (CCB, 2026-11-10). No other source reports the Belgian attacks. Microsoft describes the method as designed for frontline workers, advises enabling it only for them, and says it is different from SMS as a multifactor method, which needs a username and password (Microsoft Learn, 2026-10-30). Microsoft is disabling first-factor sign-in in tenants with no such traffic in the previous 30 days (Microsoft Learn, 2026-10-30) and retires its own SMS and voice delivery on 2027-02-01 for all users except Global Administrators and external users, who follow on 2027-07-01; a customer-configured telephony provider can keep the methods working (Microsoft Learn, 2026-09-23).

    Exposure
    An Entra tenant whose SMS authentication method policy has first-factor sign-in turned on for any user or group; the CCB's path is Authentication methods, SMS, "Use for sign-in", and the Authentication methods activity report shows who actually uses it (CCB, 2026-11-10). Microsoft's how-to calls the same setting "Enable first factor sign-in" and says that leaving it unchecked limits SMS to multifactor authentication and self-service password reset (Microsoft Learn, 2026-10-30).
    Detection
    In Entra sign-in logs, look for successful sign-ins that used SMS as the authentication method; in audit logs, for phone-number or authentication-method changes; then for unusual locations or devices and follow-on mailbox rules or application consents, reviewing as far back as log retention allows (CCB, 2026-11-10).
    Defender takeaway
    Disable SMS first-factor sign-in now for everyone who has an alternative and restrict it to the smallest group where it must stay, as the CCB advises; remove SMS and voice for privileged accounts only after each has a working phishing-resistant method, and avoid a blind switch-off, which can lock users out or leave them with a password alone (CCB, 2026-11-10). Microsoft's own clearing reaches only tenants with no first-factor SMS sign-in traffic in the previous 30 days (Microsoft Learn, 2026-10-30), so a tenant that uses the method stays exposed until it acts.

    On 2026-11-11 Huntress observed an operator using access to several cloud-hosted ScreenConnect panels to run commands as SYSTEM on groups of managed endpoints through the Run Command feature, hitting at least 288 hosts at 48 organisations within 90 minutes (Huntress, 2026-11-11). Each host installed an attacker-controlled second client and fetched SCKit, a 16-file toolkit delivered encrypted that sets the legitimate client to manual start so the attacker's copy replaces it and runs a per-host executable from a scheduled task (Huntress, 2026-11-11). A second wave on 2026-11-13 hit 205 hosts at 41 organisations with no follow-on executions observed (Huntress, 2026-11-13), and Blackpoint says it appears to target on-premises instances where mitigations are still pending (Blackpoint, 2026-11-13).

    Huntress's later update says the activity seems related to RMM+, a third-party extension that bypasses ScreenConnect's accounts, roles and MFA: versions 1.0.31 and 1.0.32 accepted a blank access key when an administrator had never set one (Huntress, 2026-11-11). ConnectWise, as CNA, published CVE-2026-127063 (CVSS 4.0 9.3) saying the extension uses a static API secret by default; it names no fixed version, removed the extension from cloud-hosted instances and tells on-premises customers to disable it and not reinstall it (ConnectWise, 2026-11-12).

    Microsoft describes the technician stage: RelayTrap, a replacement client compiled on the endpoint with the .NET C# compiler and designed to deliver a payload to the technician who connects, and browser-access code that searches Chrome, Edge and Opera profiles for cookies named .ASPXAUTH, with a component designed to queue payloads through the console's Shared Toolbox (Microsoft, 2026-11-13). ConnectWise says clients 26.6.5 and later block the transfer, and Microsoft adds that a cloud-console update does not update technician clients (Microsoft, 2026-11-13); Huntress and Blackpoint saw no successful technician compromise (Huntress, 2026-11-11; Blackpoint, 2026-11-13).

    Exposure
    A ScreenConnect instance whose panel can run commands on managed endpoints, run by the organisation or an IT provider; an RMM+ extension at any version, since ConnectWise's record names a static default secret, with versions 1.0.31 and 1.0.32 and a blank key as the condition Huntress describes; a technician host client older than 26.6.5; an endpoint with a second client service pointing at a foreign relay.
    Detection
    ScreenConnect instance audit logs, Run Command and Toolbox history for mass executions nobody started and RMM+ requests with no matching login (Huntress, 2026-11-11), and file-transfer-and-run events (event ID 201, per Blackpoint) (Blackpoint, 2026-11-13); process-creation telemetry with the ScreenConnect client service as parent of cmd, PowerShell or msiexec, curl or PowerShell downloads followed by a silent msiexec install (the Sophos pattern) (Sophos, 2026-11-11), a scheduled-task PowerShell watcher that compiles an executable with the .NET compiler (Microsoft, 2026-11-13), and a client service named like a Windows component (Huntress, 2026-11-13).
    Defender takeaway
    Treat Run Command or Toolbox executions you did not start as a compromise; disable RMM+ and the four other extensions the first notice named, update every technician host client to 26.6.5 or later, rotate ScreenConnect credentials and revoke active sessions and the browser and identity-provider sessions the toolkit could steal, and keep hosts and technician workstations out of service until the rogue client and persistence are gone (Huntress, 2026-11-11; Microsoft, 2026-11-13). Removing the rogue client alone leaves the persistence and the web sessions, and the cleanup script found in the kit must not be used (Microsoft, 2026-11-13).

    GSocket on compromised Linux web servers: Microsoft sees several unrelated actors install the open-source relay client after exploiting an internet-facing web application, so access outlives the patch; no inbound listener, no attacker-hosted infrastructure

    Microsoft observed several unrelated threat actors deploy GSocket, an open-source remote access tool, on Linux servers after exploiting an internet-facing web application, and says it kept access after the exploited vulnerabilities were remediated (Microsoft, 2026-11-11). The chain starts with command execution as a child of the web server or application runtime, where curl fetches an installation script that bash runs; the script profiles the host, picks a client matching the architecture, stages it as a hidden, executable file in a writable or memory-backed path such as /dev/shm and opens encrypted outbound command and control through the Global Socket Relay Network (Microsoft, 2026-11-11). The client is then disguised with kernel-thread-like process names (bash exec -a), persisted through cron, systemd units, shell profiles, watchdogs and redundant copies, and the staging files are removed (Microsoft, 2026-11-11). In a few incidents the actors afterwards attempted the Linux kernel flaw CVE-2026-43284, known as Dirty Frag, to reach root; Microsoft gives no success statement and no affected or fixed versions (Microsoft, 2026-11-11).

    Both the compromised host and the operator connect outbound to the public relay, so the host needs no inbound listener, inbound firewall rules do not see the traffic and a shared secret, not an address, pairs the endpoints, which lets the operator reconnect later from any compatible client; Microsoft therefore says that blocking an address or domain is unlikely to cut off access, while egress filtering and outbound monitoring can see it (Microsoft, 2026-11-11). Microsoft's telemetry is concentrated on web applications and hosting; education and research and technology and telecommunications were the largest shares of affected organisations, which Microsoft says reflect exposure more likely than deliberate sector selection (Microsoft, 2026-11-11).

    Exposure
    Any Linux web, CMS or hosting server whose internet-facing application was exploited, patched or not, in the months before the patch; Microsoft says the same persistence problem applies when initial access came through remote access services or cloud shell sessions.
    Detection
    Process-creation telemetry with parent lineage, where a web-server or application-runtime process starts curl and then bash, followed by a long-lived process whose name imitates a kernel thread but whose executable sits in a hidden or memory-backed path; file events in /dev/shm and /tmp; new cron entries and systemd units with plausible service names created in the same window as the download; shell startup file changes; and long-lived outbound sessions to a public relay from servers that have no reason to initiate them. After patching, remove the client, its persistence and staged files, and verify that the outbound relay connections stopped, because persistence is layered and stopping the process alone does not remove access (Microsoft, 2026-11-11).

    Triage: Microsoft notes that the same relay model also serves legitimate remote administration, and says a match must be judged on process ancestry, execution context, persistence changes and related network activity; a client started from a web-service process tree, from a writable or memory-backed path and under a kernel-thread-like name is the pattern it describes (Microsoft, 2026-11-11).

    Defender takeaway
    Treat every Linux web server whose application was exploited as possibly holding a relay client, not only web shells, and hunt it on the host after patching; Microsoft's hardening steps are deny-by-default egress with monitoring of relay connections, non-executable mounts for temporary and memory-backed directories, and a review of cron entries, systemd units and shell startup files.

    Plone security fix of 2026-11-10: a chain of missing security declarations and opened modules lets an anonymous visitor run code on the server in every supported Plone version and back to 4.3; a working proof of concept exists, no CVE ids yet, no exploitation reported

    The Plone and Zope security team says the fixes it released on 2026-11-10 close a chain of several issues that together let an anonymous visitor run code on the server, in all supported Plone versions (6.0, 6.1 and 6.2) and in older ones back to at least 4.3 (Plone Security Team, 2026-11-10). The anonymous entry point is Products.CMFEditions: the conditional modifiers in portal_modifier had no security declarations, so an anonymous visitor could change a modifier's TALES condition and then run it, and the condition is also evaluated when an editor saves versioned content (Plone Security Team, 2026-11-10). Products.CMFPlone, Products.MimetypesRegistry and plone.batching opened whole modules to restricted code, which let TALES expressions and Python scripts escape the sandbox and reach modules such as os, and plone.restapi opened the json module (Plone Security Team, 2026-11-10). The CMFEditions advisory rates its flaw 9.8 with no privileges required and states that a working proof of concept exists; the team says details are public and that with current AI tools it may not take long to turn them into a working exploit, and no source reports exploitation (Plone, 2026-11-10; Plone Security Team, 2026-11-10).

    The fixed packages are CMFPlone 6.2.3, 6.1.6 and 6.0.16 with the helper package versions the announcement lists, or the hotfix Products.PloneHotfix20261110, which covers Plone 4.3 to 6.2, and all Zope instances must be restarted afterwards (Plone Security Team, 2026-11-10). The team's pre-announcement of 2026-11-02 already gave the workaround, to block any URL containing portal_modifier at the web server at any path depth, which only helps if Zope's own port cannot be reached directly; the team advises keeping it after updating (Plone Security Team, 2026-11-02). After the fix, restricted code can import only the names Plone itself needs from the closed modules, so custom scripts that import others now get an Unauthorized error (Plone Security Team, 2026-11-10).

    Exposure
    Any Plone site reachable by anonymous visitors, on a version below the fixed packages; no source states a non-default setting that the anonymous path needs, and Plone 5.2 and older are out of security support, with the fix released as an exception.
    Detection
    Web-server access logs for anonymous requests whose path contains portal_modifier; and the stored state, which survives the update: a changed modifier condition stays in the database, so as Manager open @@check-modifier-conditions on the site root, or read the hotfix's startup log line that reports modified versioning conditions, and treat the server as compromised if a condition is not recognised, although defaults have changed over time so a difference alone is not an attack (Plone Security Team, 2026-11-10).
    Defender takeaway
    Update or install the hotfix and restart now on every internet-facing Plone site, keep the portal_modifier block in place, and run the modifier-condition check afterwards, because the fix does not remove a condition an anonymous request already stored.

    CVE-2026-119618, Apache HTTP Server 2.4.55 to 2.4.70: a race in mod_http2 assign_headers() corrupts heap memory and leads to remote code execution on servers with HTTP/2 enabled; fixed in 2.4.71, Red Hat calls it unauthenticated and claims public exploit research, no exploitation reported

    Apache HTTP Server 2.4.71, released on 2026-11-11, fixes CVE-2026-119618, a race in mod_http2's assign_headers() that the project rates critical and says can lead to remote code execution, in versions 2.4.55 through 2.4.70 (Apache HTTP Server project, 2026-11-11). The project publishes no CVSS score; Red Hat scores it CVSS 3.1 9.8 and says it allows unauthenticated remote code execution, with a worker thread writing into memory owned by the connection thread through a shared lock-free allocator (Red Hat Product Security, 2026-11-11). Red Hat states that only servers with HTTP/2 (h2 or h2c) enabled through the Protocols directive are affected and that HTTP/1.1-only servers are not (Red Hat Product Security, 2026-11-11); the project's own page is silent on that prerequisite (Apache HTTP Server project, 2026-11-11).

    On exploitation the sources differ. Wiz wrote at its publication that no exploit was available and no exploitation in the wild was reported (Wiz, 2026-11-11), while Red Hat says public research has demonstrated a reliable exploit against a default-configured server with mod_http2 enabled, without linking it (Red Hat Product Security, 2026-11-11). A researcher has since posted a test setup that reports memory corruption and Apache child-process crashes on 2.4.70, and Wordfence says it does not demonstrate remote command execution (Wordfence, 2026-11-12). No source reports attacks, and the project's advisory carries no exploitation or workaround statement (Apache HTTP Server project, 2026-11-11). Wiz advises disabling HTTP/2 temporarily as the interim measure (Wiz, 2026-11-11).

    The upstream fix is 2.4.71. The project lists standalone mod_h2 releases from GitHub, 2.0.8 through 2.0.42, as affected and names no fixed standalone release (Apache HTTP Server project, 2026-11-11). Red Hat shipped mod_http2 errata for RHEL 9 (mod_http2-2.0.26-7.el9_9.1) and RHEL 10 (mod_http2-2.0.29-5.el10_3.1) on 2026-11-11, rates them Important (Red Hat, 2026-11-11; Red Hat, 2026-11-11), says the packages allocate each HTTP/2 stream from a separate allocator, which makes exploitation substantially more complex, and lists RHEL 8 and earlier as not affected (Red Hat Product Security, 2026-11-11); Debian's tracker lists apache2 2.4.71-1~deb12u1 for bookworm (DLA-4902-1) and 2.4.71-1~deb13u1 for trixie (DSA-6620-1) as fixed while forky is still vulnerable (Debian Security Tracker, 2026-11-13), Ubuntu's USN-9090-1 fixes 22.04 LTS to 26.10, and 20.04 LTS through ESM (Ubuntu, 2026-11-12), Alpine 3.21 to 3.24 ship 2.4.71-r0 (Alpine Linux, 2026-11-13) and SUSE lists the issue as pending (SUSE, 2026-11-13).

    Exposure
    An Apache HTTP Server 2.4.55 to 2.4.70, or a distribution mod_http2 build without the vendor's fix, that has the mod_http2 module loaded and h2 or h2c in a Protocols directive for the server or a virtual host; the loaded modules and the Protocols directives of the configuration show it, and the distribution advisory, not the upstream version string, shows whether a backported fix is installed.
    Detection
    Neither the project nor Red Hat publishes indicators of compromise; the researcher's test shows the corruption as httpd child-process crashes inside the allocator and HTTP/2 stream code (researcher repository, 2026-11-12), so watch for child crashes in the error log; shells or interpreters started by an httpd worker are an inference from the flaw class, not a source statement.
    Defender takeaway
    Update internet-facing servers that serve HTTP/2 to 2.4.71 or the distribution's fixed package and restart, and where no fix is available yet remove h2 and h2c from Protocols until it is, because Red Hat describes an unauthenticated path and a public exploit while the project describes neither.
