    k0t: Group-IB and NyxLab describe a probable access broker that mass-exploits FortiWeb and PAN-OS GlobalProtect, brute-forces FortiGate and decrypts stolen FortiGate configurations offline with the default key, with victims later listed by Qilin and The Gentlemen

    Group-IB and NyxLab describe a campaign by an operator they track as k0t (Group-IB lists CryptoFeel as a potential alias, and Scrooge as a likely collaborator and possible alias) that enumerates internet-facing VPN and firewall appliances in bulk and attacks the product directly, chiefly Fortinet firewalls and Palo Alto GlobalProtect portals (Group-IB, 2026-10-21). A custom script exploits CVE-2025-64446 against FortiWeb, a relative path traversal that lets an unauthenticated attacker run administrative commands, or brute-forces exposed Fortinet devices as a fallback (Group-IB, 2026-10-21; CISA KEV, 2026-10-21). Against PAN-OS it exploits CVE-2026-0257, the GlobalProtect authentication bypass, with a forged authentication-override cookie (Group-IB, 2026-10-21). On a compromised FortiGate the tool downloads the configuration and decrypts its secrets locally with the default FortiOS key, the weakness tracked as CVE-2019-6693, recovering LDAP and Active Directory bind and, Group-IB says, administrator credentials, although Fortinet's advisory excludes the administrator's password and says FIPS-CC devices are not impacted; unless private-data-encryption is set, the device falls back to that known key (Group-IB, 2026-10-21; Fortinet, 2019-11-19).

    After access the operators work by hand with NetExec, Impacket, Kerbrute, relayed PetitPotam and Mimikatz, keep access through OpenConnect, MeshCentral agents, AdaptixC2, Atera and AnyDesk, and exfiltrate with Rclone to Wasabi and MEGA (Group-IB, 2026-10-21). Group-IB sees victim overlap with the Qilin and The Gentlemen leak sites and assesses the operators are probably initial-access brokers, but says no relationship is confirmed, and it found indications of a possible connection with the FortiBleed cluster alongside negligible overlap in the compromised credentials (Group-IB, 2026-10-21). CISA lists all three CVEs in KEV, with ransomware use marked known for CVE-2026-0257 and CVE-2019-6693 (CISA KEV, 2026-10-21).

    Exposure
    Internet-reachable FortiGate administrator and VPN logins, FortiWeb up to 8.0.1, 7.6.4, 7.4.9, 7.2.11 or 7.0.11 on its branch (Fortinet, 2025-11-14), and PAN-OS GlobalProtect portals and gateways below the per-branch fixed builds (Palo Alto Networks, 2026-05-13); every FortiGate except FIPS-CC models is exposed to the offline decryption step once its configuration has been downloaded unless private-data-encryption, available from FortiOS 5.6.11, 6.0.7 and 6.2.1 and off by default, is enabled with an operator-defined key, which Fortinet warns can cause install errors and split-brain on FortiManager-managed or HA FortiGates until FortiManager 6.2.7 and FortiGate 6.2.6, 6.4.4 or 6.6.0 and later (Group-IB, 2026-10-21; Fortinet, 2019-11-19).
    Detection
    On edge appliances, unexpected local administrator creation, configuration exports, trusted-host changes, repeated authentication failures, lockout-and-retry patterns and administration from unusual source addresses; on directory infrastructure, the NetExec, Impacket and relay pattern against domain controllers; on endpoints, remote-management agents and dual-use tools without an approved owner. The decryption leaves no trace on the appliance, so a patched or cleaned device may already have yielded its secrets (Group-IB, 2026-10-21). After upgrading FortiWeb, Fortinet advises reviewing configuration and logs for unexpected changes and unauthorised administrator accounts, and until then disabling HTTP and HTTPS on internet-facing interfaces (Fortinet, 2025-11-14).

    Triage: OpenConnect, MeshCentral, Atera, AnyDesk and Rclone are legitimate tools, so Group-IB advises judging execution context, installation source, operator account, destination and timing rather than tool names (Group-IB, 2026-10-21).

    Defender takeaway
    Enable private-data-encryption with an operator-defined key on every FortiGate and rotate the directory and administrator secrets stored in any configuration that may have left the device, because patching or rebuilding does not undo a copy already decrypted; Group-IB also advises investigating lockout events and raising the lockout time against brute force (Group-IB, 2026-10-21).

    ARTEX: Microsoft reports Storm-0940, a China-state aligned actor, running an open-source multi-agent LLM penetration-testing framework against hundreds of organizations, with privileged cloud access in under three hours in some cases, and Expel sees the same infrastructure abuse Okta self-service registration

    Microsoft Threat Intelligence reports that as early as September 2026 Storm-0940, a China-state aligned actor active since 2021, used the agentic penetration-testing framework ARTEX to automate attacks on hundreds of organizations across many industries, government and military among them (Microsoft, 2026-10-21). ARTEX is an open-source multi-agent LLM system that can use any AI model and runs a penetration test from reconnaissance to exfiltration with little human involvement (Microsoft, 2026-10-21). Microsoft says ARTEX accelerated the abuse of compromised applications already granted access to Microsoft 365 tenants (Microsoft, 2026-10-21), and Expel adds that it is not a vulnerability and only speeds up familiar techniques such as password spraying and OAuth-application abuse (Expel, 2026-10-21); most targeting failed, yet several cases went from first targeting to privileged cloud access in under three hours (Microsoft, 2026-10-21). Microsoft assesses the same actor was behind the ConnectWise Cloud Backup application-credential abuse (Microsoft, 2026-10-21).

    Expel saw Storm-0940 infrastructure scan a customer and, from 2026-10-13, abuse its Okta self-service registration with no ConnectWise application involved: the attacker created five accounts of its own, enrolled Okta Verify on three of them about a minute after activation, made 50 single sign-on logins with more than 100 OAuth tokens issued and ran a password spray that Okta ThreatInsight blocked (Expel, 2026-10-21). Expel says the shared source address is its only link to Storm-0940, the activity alone does not prove ARTEX was used, and it had not seen the technique reported before (Expel, 2026-10-21). Other actors use it: CrowdStrike analysed an unnamed, probably Chinese-speaking and financially motivated actor that ran ARTEX against South Korean financial institutions from late September (CrowdStrike, 2026-10-07), and Recorded Future, which tracks that activity as TAG-217, says use of ARTEX and other AI penetration-testing tools is not limited to it (Recorded Future, 2026-10-16).

    Wiz Research independently reports that throughout October 2026 it tracked an actor using ARTEX-associated tooling, overlapping with Storm-0940, against IT and software vendors, focused on identity providers (Okta, Entra, Cognito) and Microsoft 365 integrations, and says that most attempts failed and that none of the techniques is novel (Wiz, 2026-10-22). It describes a consistent sequence: downloading JavaScript bundles, exposed source maps, runtime configuration and OpenAPI documents, then calling internal API routes by name minutes later; fabricated authorization codes and malformed state values against Microsoft OAuth callbacks; unsigned JWTs tried against more than 60 SSO route variants in two minutes; and account-recovery, sign-up and Cognito calls such as InitiateAuth, ForgotPassword and ResendConfirmationCode (Wiz, 2026-10-22). Its password sprays against Entra and Okta hit hundreds of users, mainly software engineers, in bursts of 20 to 60 minutes with a unique user agent per burst, a median gap of one second between attempts and new source addresses within minutes of a block (Wiz, 2026-10-22).

    Exposure
    Any tenant that relies on password sign-in or grants OAuth consent to applications, and any Okta org with self-service registration enabled; not using ConnectWise does not exclude exposure (Expel, 2026-10-21).
    Detection
    In the authentication logs of every identity provider in use, bursts of failed logons and lockouts spread over many accounts; in the Okta system log, newly self-registered accounts that enrol Okta Verify and start single sign-on within minutes; and in the Entra audit log, credentials or certificates added to applications that nobody on your team created and any application that assigns itself a directory role (Microsoft, 2026-10-21; Expel, 2026-10-21). A clean audit log is not proof of no access, because Microsoft Graph directory reads leave no Entra audit record (Expel, 2026-10-21). In web access logs of an application exposed to the same actor, Wiz points to source-map and OpenAPI downloads followed minutes later by calls to internal routes that appear only in those files, and to sign-in telemetry showing a new user agent for each burst of attempts at a one-second cadence (Wiz, 2026-10-22).

    Triage: Python and curl user agents match common legitimate automation, so Expel treats them as supporting evidence only, and a Python user agent on an application that normally calls Microsoft Graph with a .NET SDK is the anomaly (Expel, 2026-10-21).

    Defender takeaway
    Expel's reading is that the framework adds speed, not a new vulnerability, so the levers are the identity controls it runs into: least privilege on multi-tenant application permissions and consent grants, alerting on credential additions and privileged role assignments by applications, and a review of self-registered Okta accounts since 2026-10-13 (Microsoft, 2026-10-21; Expel, 2026-10-21).

    LiteLLM 1.107.0: the PyPI wheels and the official Docker images carried a credential stealer and a dormant remote-code loader that Python starts at every launch, published through the maintainers' own release workflow with stolen developer tokens

    Socket reports that LiteLLM 1.107.0, an open-source LLM gateway, carries malicious Python startup files in all seven wheels, and that Upwind found the same payload in the published images (Socket, 2026-10-21). A startup hook and a second startup module in the Python library directory run at every Python start without the application importing LiteLLM: the first collects cloud, Kubernetes, CI, registry and database credentials, SSH, GPG and TLS private keys, browser stores, AI-tool credential files, environment variables and, where configured, the credentials saved in a LiteLLM proxy database; the second forks a detached loader that polls a file in a GitHub repository for a domain and would execute Python downloaded from it with no signature or hash check, though at 13:01 UTC the pointer returned an empty body, which stops the loader before its download stage (Socket, 2026-10-21).

    The payload is not in the git tag: a packaging setting in an untagged commit pulls it into the wheel, and the container build provenance records a source repository named Berri-AI/litellm, one hyphen away from BerriAI/litellm (Socket, 2026-10-21). The maintainers' root-cause post of 2026-10-23, which they call the canonical account and which corrects assumptions in their earlier status updates, traces the chain to a configuration file committed on 2026-05-27 to a public repository with the master key of an experimental internal agent service; the commit was force-pushed over but the key was never revoked (LiteLLM, 2026-10-23). On 2026-10-10 the attacker used that key against the service's API, which returned the GitHub CLI OAuth token of an organization owner, not a service account and not scoped down, and from then on the attacker held owner-level access to every repository; such CLI tokens are post-2FA and exempt from GitHub's re-authentication for sensitive actions (LiteLLM, 2026-10-23). With it the attacker pushed throwaway branches whose workflows posted CI secrets to an external capture endpoint, yielding the CLI tokens of two maintainers, and deleted the workflow runs minutes later (LiteLLM, 2026-10-23). Socket found secret-exfiltration workflows running in the repository on 2026-10-10 from its Actions performance metrics, eleven days before the release attack, says it has not established how the attacker first obtained access and does not claim that the 2026-10-10 theft produced the access used on 2026-10-21, while LiteLLM says its audit logs tie the token stolen on 2026-10-10 to the approval of the release (Socket, 2026-10-23). On 2026-10-21 a push to the private release-orchestration repository with a maintainer's token was rejected by branch protection, and the owner's token then overrode it so that the build could be pointed at the look-alike repository; the owner's token dispatched the staging build, a second maintainer's token approved the production gate, a third maintainer's token deleted the run records, and the owner's token force-pushed the history clean, after the maintainers had relaxed the release rule earlier that week so that any two engineers could trigger and approve a release (LiteLLM, 2026-10-23). LiteLLM distributes an embargoed release for a vulnerability whose disclosure is scheduled for 2026-10-27 to enterprise customers through a private registry (LiteLLM, 2026-10-21). PyPI quarantined 1.107.0 and the images were pulled the same day (Aikido, 2026-10-21; LiteLLM, 2026-10-21).

    Exposure
    An environment that installed litellm 1.107.0 from PyPI between 11:39 and 13:23 UTC on 2026-10-21, or pulled the v1.107.0, latest, main-latest or main-stable tag of the official images from GHCR (until about 13:51 UTC) or Docker Hub (until 14:20 UTC); lockfiles, caches, build logs and running image digests show which (Socket, 2026-10-21; LiteLLM, 2026-10-21).
    Detection
    In the cloud audit logs of every account the host could reach, a caller-identity check followed by a Bedrock model listing and IAM enumeration, made with an instance-role credential harvested from CI runners or Kubernetes nodes from an address outside your estate, which Wiz saw from 16:20 UTC on 2026-10-21 (Wiz, 2026-10-21); on hosts, startup hooks and sitecustomize modules in a Python library directory that your tooling did not install, a detached Python process holding a lock file, and an encrypted archive posted to a path labelled as a health check (Socket, 2026-10-21). In the GitHub organization audit log, short-lived throwaway branches that add a single workflow file, workflow runs deleted minutes after they ran, and branch-protection and force-push-block overrides made with an owner's token; the log records a hash of the token behind each action, which tied the stolen maintainer token to the release approval (LiteLLM, 2026-10-23). Starting Python or pip in an affected environment can run the payload again, and removing the package directory does not remove the startup files or stop a running loader (Socket, 2026-10-21).
    Defender takeaway
    Rotate every credential the host could reach (LiteLLM, 2026-10-21), because removing the package does not remove the startup files (Socket, 2026-10-21) and stolen cloud credentials were in use within hours (Wiz, 2026-10-21); rebuild from a reviewed release and pin container digests (Socket, 2026-10-21), and move to 1.106.2 or an explicit earlier version as the maintainers advise (LiteLLM, 2026-10-21). For your own pipelines, the root cause was a key that was removed from a public repository's history but never revoked, and an organization owner's CLI token held by an automation service; the maintainers call it an illustration of the risk of failing to rotate a potentially exposed key (LiteLLM, 2026-10-23).

    Cisco's advisory of 2026-10-21 fixes CVE-2026-76466 (CVSS 3.1 9.8, network, no privileges, no user interaction) in the database service of Expressway-C and Expressway-E, virtual and appliance: an unauthenticated remote attacker with network access can run operating-system commands as root (Cisco PSIRT, 2026-10-21).     The same day Cisco ships two further hardening releases whose worst classes are exploitable over the network without authentication. For Emergency Responder, Prime Collaboration Deployment, Unified CM, Unified CM IM&P, Unified CM SME and Unity Connection, regardless of device configuration, the worst classes score 9.8 (CVE-2026-76473, improper control of a resource through its lifetime, and CVE-2026-76474, improper authentication); release 15 is fixed in 15SU5 and release 14 must migrate (Cisco PSIRT, 2026-10-21).     NOTABLECVE-2026-110264updatedNATOA2

    CVE-2026-110264, GitLab CE/EE: an unauthenticated code-execution flaw in the Org-mode renderer's regular-expression handling, fixed in 19.5.1, 19.4.3 and 19.3.6 and backported to four older lines (CVSS 10.0)

    GitLab's ad-hoc critical patch release of 2026-10-21 fixes CVE-2026-110264 (CVSS 3.1 10.0), an integer overflow while compiling a specially crafted regular expression that could let an unauthenticated user execute code on the GitLab server (GitLab, 2026-10-21). GitLab's detection write-ups place the flaw in the rendering of Org-mode files: the org-ruby gem builds a regular expression from a custom TODO keyword in a .org file, a keyword with more than 32,767 repeats makes the Onigmo engine write out of bounds when it matches, and with heap grooming that becomes command execution as the git user (GitLab security, 2026-10-21). The attack needs no authentication, only one public project that can hold the .org payload (GitLab security, 2026-10-21). Affected are all versions from 7.0 before 18.11.13, 19.0 before 19.0.10, 19.1 before 19.1.9, 19.2 before 19.2.9, 19.3 before 19.3.6, 19.4 before 19.4.3 and 19.5 before 19.5.1; GitLab.com is already patched, and GitLab Dedicated tenants on 19.3.5-internal0, 19.4.2-internal0 or later need no action (GitLab, 2026-10-21). The builds 19.4.2, 19.3.5 and 19.2.8 from GitLab's earlier regular-expression fixes do not contain this fix (GitLab security, 2026-10-21). GitLab does not state that the flaw is exploited, and its patch notes and detection pages mention no public proof of concept (GitLab, 2026-10-21). The bug is in Ruby's Onigmo regular-expression engine: the Ruby project released 4.0.9, 3.4.12 and 3.3.13 on 2026-10-23 with the fix, the release of 4.0.8 lacks the fix for this flaw, and GitLab fixed its own servers by patching the Ruby it ships (Ruby, 2026-10-23).

    Exposure
    Self-managed GitLab CE and EE on the versions above; the vulnerable path is reached when GitLab renders a .org file, so an instance with public projects, or one where untrusted users can create them, is the exposed shape, and until patching GitLab advises reducing public visibility (GitLab security, 2026-10-21). A Ruby application outside GitLab is exposed to the same bug when it compiles a regular expression from a string an attacker controls, through Regexp.new, Regexp.union, Regexp.compile or interpolation into a regexp literal; applications that only use patterns written by their own developers are not affected (Ruby, 2026-10-23).
    Detection
    GitLab's two detections key on, first, five or more render timeouts from the Org-mode renderer on .org files from one client within 30 minutes in the Rails exceptions log, with the request that actually crashes a worker visible only as a 502 on the .org blob route in the Workhorse log, and second, a native Ruby crash report in the Puma error log whose backtrace runs through org-ruby or Onigmo frames (GitLab security, 2026-10-21). In repository content, scan each suspect checkout for .org files with an oversized TODO-keyword line, and in the Rails request log look for editor preview requests whose file_path ends in .org while the URL names another file type, which forces the Org renderer (GitLab security, 2026-10-21). A successful exploit is quiet and does not reliably crash, so the absence of a hit never clears an instance (GitLab security, 2026-10-21). On an exposed, unpatched instance, hunt for unexpected child processes of Puma, new files owned by git in the temporary directory, outbound connections and changed crontabs or SSH keys for the git user, and treat the secrets, CI/CD variables, runner tokens and access tokens the git user can read as at risk (GitLab security, 2026-10-21).

    Triage: a reader of documentation .org files renders each file once and quickly, while an attack produces a burst of timeouts from one client over a few minutes (GitLab security, 2026-10-21); a worker crash with no accompanying render burst from one client is more likely a benign parser bug than an attack (GitLab security, 2026-10-21).

    Defender takeaway
