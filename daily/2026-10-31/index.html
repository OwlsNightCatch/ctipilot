    NOTABLENATOB2

    Teams help-desk impersonation to domain-controller identity: Microsoft traces two intrusions from a Quick Assist session to AD CS ESC1 certificates with DCSync, and to PetitPotam relayed to ESC8 Web Enrollment

    Microsoft Threat Intelligence describes two human-operated intrusions, not attributed to any threat actor, that began with an external Teams contact (across the broader activity Microsoft saw organisation-themed tenant names and support-style display names) who persuaded a user to open Quick Assist and read out the connection code; the activity did not exploit a Teams vulnerability. In the session the operator placed an archive in Downloads, extracted it into a newly created KB-prefixed folder under the user profile and started the payload with a portable Python, JavaScript or Java runtime, which ran host and network discovery and assessed AD CS (Microsoft Threat Intelligence, 2026-10-30).

    In the first case a certificate template open to ESC1, where the requester supplies the identity, produced certificates for three privileged accounts, and about 90 minutes later for eight more after a second wave against 16 users; DCSync began within seconds of obtaining one privileged certificate. Defender's automated disruption blocked more than 1,000 SMB attempts, but a privileged account excluded from automated response stayed usable, reached a file server and ran a renamed Rclone that copied a share to an external SFTP destination (Microsoft Threat Intelligence, 2026-10-30). In the second case the operator used PetitPotam to make a domain controller authenticate to the attacker's host, relayed that NTLM authentication to an AD CS Web Enrollment endpoint, obtained a certificate from the Domain Controller template and used it for PKINIT to get a ticket-granting ticket for the controller's account; Defender raised ESC8 alerts and the customer isolated the workstation (Microsoft Threat Intelligence, 2026-10-30).

    Exposure
    A forest with an enterprise CA whose authentication-capable templates accept requester-supplied identity with broad enrollment rights (ESC1), or whose Web Enrollment or Certificate Enrollment Web Service endpoints lack HTTPS and Extended Protection (ESC8), where Teams accepts external chats and calls and users can start Quick Assist; Defender for Identity's AD CS posture assessments, or an inventory of /certsrv endpoints and template permissions, shows the first two (Microsoft Threat Intelligence, 2026-10-30).
    Detection
    New external Teams contacts from help-desk-themed tenants; in process telemetry, a portable runtime started from a freshly created KB-prefixed folder under the user profile after a remote-support session; in CA records, certificate requests and issuances correlated by requester, subject alternative name and template with the first authentication using the certificate; and a domain controller account authenticating to Web Enrollment from a device that is not that controller, which Microsoft calls a strong pivot (Microsoft Threat Intelligence, 2026-10-30). After containment, revoke the unauthorized certificates and assess issued Kerberos tickets separately; a password reset and a reimage of the first workstation leave both in place.

    Triage: a help-desk Quick Assist session is routine; what separates this one is an external-tenant initiator with no matching ticket and an interpreter runtime launched from a newly created user-writable folder rather than a managed install path.

    Defender takeaway
    Require HTTPS and Extended Protection on every enrollment web endpoint, drop the ones nobody needs, review authentication-capable templates and require approval where enrollment is broad, and enable the Certification Services audit subcategory and CA audit filter; limit Teams external access and restrict remote-support tools to approved ones. Treat a containment exclusion as an incident decision with a manual compensating step, because in the first case the one excluded privileged account was the route to the file server (Microsoft Threat Intelligence, 2026-10-30).

    NOTABLENATOB1

    Cursor marketplace: a tampered Claude Code extension (versions 2.1.312 and 2.1.313) planted an SSH key, a reverse tunnel and persistence for about eleven hours on 2026-10-29; uninstalling it does not remove the persistence

    Between about 2:27am PT and 1:35pm PT on 2026-10-29 (09:27 to 20:35 UTC) a maliciously modified copy of Anthropic's Claude Code extension, versions 2.1.312 and 2.1.313 for macOS and Windows, was served from the Cursor VS Code Extension Marketplace; Cursor removed it, shut the marketplace down briefly, rotated its keys, rebuilt it and had the hosting provider take the attacker's server offline (Cursor, 2026-10-29). Anthropic told Microsoft its systems were not compromised and that it did not build the package, and Microsoft confirms the packages were never published to the Visual Studio Marketplace or npm (Microsoft Threat Intelligence, 2026-10-30). How the attacker published under Anthropic's name is not disclosed in any source read. Cursor estimates up to 5,000 affected users (Sophos X-Ops, 2026-10-30).

    The injected loader runs when the extension module loads. It reports host and user data (hostname, username, operating system, home and working directories, the configured Git email, environment-variable names and public IP address), appends an attacker-controlled SSH public key to authorized_keys, tries to enable the local SSH service and open a reverse SSH tunnel, and installs persistence outside the extension: a LaunchAgent on macOS, and on Windows a scheduled task that asks to run as SYSTEM with a Startup-folder fallback, with background scripts retrying the tunnel about every 60 seconds (Cursor, 2026-10-29). Microsoft's analysis adds a user crontab entry for Linux (Microsoft Threat Intelligence, 2026-10-30). Because of coding errors the step that enables SSH fails unless Cursor was started with administrator privileges, so on most hosts the attacker could not log in through the tunnel, but the key, the persistence and the host report still happened (Cursor, 2026-10-29).

    Exposure
    Any macOS or Windows host on which Cursor installed or auto-updated Anthropic.claude-code 2.1.312 or 2.1.313 inside the window; the code also carries Linux routines though Cursor names only macOS and Windows packages (heise online, 2026-10-30). Extension-install telemetry shows the version. NCSC Switzerland carried the incident on 2026-10-30 but places the backdoored extension on Open VSX and says Anthropic pulled versions from npm and the VS Code marketplace (NCSC Switzerland, 2026-10-30); Microsoft says the packages never reached the Visual Studio Marketplace or npm, and Cursor and Phorion name the Cursor marketplace, so the entry follows them.
    Detection
    In process-creation telemetry, an editor's extension host starting ssh or autossh with remote port forwarding and no command; in file-write telemetry, an editor process modifying authorized_keys; and, shortly after an extension update, a new LaunchAgent, scheduled task, Startup-folder script or @reboot crontab entry named after system-monitoring components. Phorion advises matching the attacker key's fingerprint rather than the comment string it carries (Phorion, 2026-10-30). Removing the extension does not remove the persistence scripts, which keep running (Cursor, 2026-10-29).

    Triage: a running SSH process is not proof the attacker got in, since both ends must allow the connection (Microsoft Threat Intelligence, 2026-10-30); administrators run tunnels too, and what separates this one is an editor extension as the parent process and persistence written to user-writable locations rather than a managed service.

    Defender takeaway
    Treat a host that ran either version as backdoored whether or not the tunnel connected: remove the key, the persistence and the tunnel processes, rebuild where compromise cannot be excluded, and rotate credentials reachable from it. heise reports a cleaned release, with 2.1.314 as the minimum to install (heise online, 2026-10-30).

    CVE-2026-84295, Progress WS_FTP Server: an unauthenticated remote authentication flaw can expose administrative credentials (CVSS 10.0), with two more unauthenticated flaws, fixed in 2025.0.4 and 2024.0.7; no exploitation found

    Progress, as CNA, published CVE-2026-84295 on 2026-10-29: improper authentication in WS_FTP Server on Windows that "could allow an unauthenticated remote attacker to access sensitive information, including administrative credentials"; its CVSS 3.1 vector is network, low complexity, no privileges and no user interaction, scored 10.0, and the record names no component or endpoint (ENISA EUVD, 2026-10-29). Two further flaws carry an unauthenticated vector with high attack complexity: CVE-2026-90865, an OS command injection that could allow command execution with elevated privileges under certain configurations (9.0) (ENISA EUVD, 2026-10-29), and CVE-2026-90867, improper access control in the Web Admin console that could expose administrative functionality to remote authentication attempts (8.1) (ENISA EUVD, 2026-10-29). CSIRT Italia counts 6 critical and 3 high flaws in the release, of types including authentication bypass, remote code execution and arbitrary file read and write (CSIRT Italia, 2026-10-30).

    The record for CVE-2026-84295 names versions before 2024.0.6 and 2025.0.3 as affected (ENISA EUVD, 2026-10-29), and the records for the other two name versions before 2024.0.7 and 2025.0.4 (ENISA EUVD, 2026-10-29), so 2024.0.7 or 2025.0.4 is the build to reach. CSIRT Italia lists 2025.0.3 (10.0.3) and 2024.0.6 (9.0.6) and earlier as affected and says that for unsupported versions the vendor will not release a workaround or patch (translated from Italian) (CSIRT Italia, 2026-10-30). No source reports exploitation: CISA's catalog holds no 2026 WS_FTP flaw, although CVE-2023-40044 in the same product has been listed since 2023-10-05 with known ransomware use (CISA KEV catalog, 2026-10-30).

    Progress's bulletin, as listed by heise, carries fifteen CVEs, six of them critical (heise online, 2026-11-02). Besides the three above: CVE-2026-90868, an OS command injection that could allow arbitrary command execution under certain configurations (9.9) (GitHub Advisory Database, 2026-10-29); CVE-2026-90866, a path traversal by a delegated Host Administrator, potentially enabling remote code execution (9.1) (GitHub Advisory Database, 2026-10-29); CVE-2026-90864, a path traversal that lets a delegated Host Administrator reach data beyond their permitted scope (9.1) (GitHub Advisory Database, 2026-10-29); and CVE-2026-90863, missing authorization in the administrative interface (9.1) (GitHub Advisory Database, 2026-10-29). NCSC Switzerland describes the exposed administrator credentials as the start of a chain: command injection under certain configurations (CVE-2026-90868, CVE-2026-90865) or a scope escape (CVE-2026-90863, CVE-2026-90866) leads to a complete compromise of the server, and it lists exploitation as unknown (NCSC Switzerland, 2026-11-02). Builds 2024.0.7 and 2025.0.4 have been available since 2026-10-01 (heise online, 2026-11-02).

    Exposure
    Any WS_FTP Server on Windows below 2024.0.7 or 2025.0.4; CSIRT Italia describes it as a secure file-transfer server used within organisations and with external partners, so instances reachable from partner or public networks come first (CSIRT Italia, 2026-10-30). The records name no component for the authentication flaw, so no configuration is known to make an instance safe.
    Detection
    No source publishes an indicator. For an instance that was reachable before the fix, the records to review are the web-server logs of the Web Admin console and the file-transfer server's own logons for administrator access from unfamiliar addresses, and process creation by the service or its web worker, since CVE-2026-90865 is command execution (an inference from the described flaw).
    Defender takeaway
    Upgrade to 2024.0.7 or 2025.0.4, partner-facing instances first, and rotate the administrator credentials afterwards, because the upgrade does not change credentials an attacker already read; take an instance on an unsupported branch off the network or migrate it.

    NOTABLECVE-2026-98432updatedNATOB2

    CVE-2026-98432, Linux kernel IPv4 TCP: a use-after-free in connection setup, present since 4.4, has an Anthropic-built remote root exploit against MPTCP listeners that CloudLinux could not reproduce; Citrix XenServer, XCP-ng, MikroTik, Red Hat, Debian, CIQ and Amazon Linux have fixes, Ubuntu's are in progress and WatchGuard and Fortinet have none for their products (CVSS 9.8)

    The Linux kernel CVE team published CVE-2026-98432 on 2026-10-15: a use-after-free in the IPv4 TCP connection setup path, introduced in Linux 4.4 and fixed upstream in 6.12.113, 6.18.56, 7.2.10 and 7.3-rc7 (Linux kernel CVE team, 2026-10-15). An unauthenticated peer starts it by sending TCP SYN packets that carry IPv4 options, and a retransmitted SYN can then touch the freed option memory (CIQ, 2026-10-30).

    Anthropic wrote on 2026-10-27 that Claude produced an exploit that gives a remote attacker root on a Linux server with a multipath TCP (MPTCP) listener (Anthropic, 2026-10-27), but CloudLinux's kernel team could not reproduce the claim (CloudLinux, 2026-11-02). The Go team says the bug is not specific to MPTCP (Go team, 2026-10-29). Akamai is not aware of a public working exploit and says disabling MPTCP alone does not prevent exploitation (Akamai, 2026-11-02), whereas Vates, XCP-ng and WatchGuard say a public exploit exists or circulates (XCP-ng, 2026-11-04; Vates, 2026-11-04; WatchGuard, 2026-11-03). No source reports attacks, and NCSC-NL judges large-scale abuse unlikely given the exploit's complexity (translated from Dutch) (NCSC-NL, 2026-10-30).

    Severity is disputed: the CNA scores it 9.8, upstream 8.1 with high attack complexity (CIQ, 2026-10-30). Debian's security kernels are fixed (Debian Security Tracker, 2026-11-03); Red Hat has fixed RHEL 8, 9 and 10 (Red Hat, 2026-11-03); CIQ has patched kernels (CIQ, 2026-11-01); AWS has fixed Amazon Linux 2 and 2023 kernels (AWS, 2026-11-02); Ubuntu 22.04 to 26.10 are still marked vulnerable with work in progress in a tracker last updated 2026-11-04 (Canonical, 2026-11-04). Citrix rates its XenServer 8.4 and 9 bulletin Critical and has fixed its appliances (Citrix, 2026-11-03). XCP-ng released a kernel fix (XCP-ng, 2026-11-04; Vates, 2026-11-04), and MikroTik's RouterOS 7.25.1 and 7.24.6 changelogs list the CVE (MikroTik, 2026-11-02; MikroTik, 2026-10-30). WatchGuard lists Fireware OS, AP and Dimension as potentially affected with no fix (WatchGuard, 2026-11-03); Fortinet's advisory lists FortiOS, FortiProxy, FortiManager, FortiAnalyzer, FortiWeb and FortiAuthenticator among the products under investigation and names no fixed build (Fortinet, 2026-11-02).

    Exposure
    A Linux host on a kernel below the fixed builds that accepts IPv4 TCP connections from an attacker; the demonstrated exploit needs an MPTCP listener, which sudo ss -M -l -n -p -e lists and which Go programs enable on Linux listen sockets by default since Go 1.24 unless the multipathtcp GODEBUG setting or a per-socket option overrides it (Akamai, 2026-11-02; Go team, 2026-10-29). CIQ's testing found that setting net.mptcp.enabled to 0 leaves the plain-TCP path reachable (CIQ, 2026-10-30), and Akamai reports a similar flaw when request-socket migration is on, as sudo sysctl net.ipv4.tcp_migrate_req or a BPF reuseport migration program shows (Akamai, 2026-11-02).
    Detection
    No source publishes an indicator. Because the trigger is a SYN packet with IP options (CIQ, 2026-10-30) and a lost race only fails the handshake, so the attacker can retry (Anthropic, 2026-10-27), repeated option-bearing SYNs from one source toward a listener in firewall or flow telemetry are the pattern the mechanism implies (an inference).
    Defender takeaway
    Install the distribution kernel and reboot as soon as it ships and confirm the running version afterwards; Ubuntu's were not out on 2026-11-04. Until then, drop IPv4 TCP packets whose header carries IP options before the TCP stack sees them, tested first on one non-production host because it also drops legitimate option-bearing traffic; disabling MPTCP alone does not remove the path (CIQ, 2026-10-30).
