    NOTABLENATOB2

    A fake WatchGuard VPN download site captures the SSL VPN server, login and password in the browser and then serves the genuine signed installer, leaving no malicious file for endpoint tools to flag

    Huntress's SOC investigated an incident on 2026-10-07 in which an administrator at a managed service provider searched Bing for a WatchGuard VPN download with a typo in the query and clicked through the standard Bing result redirect to a lookalike site titled "WatchGuard Firebox VPN Client", which Huntress classes as search-engine poisoning rather than malvertising (Huntress, 2026-10-13). Choosing any download option opens a pop-up asking for Server, Login and Password; one unobfuscated JavaScript file of about 150 lines posts the typed values as JSON to a separate collector domain, tagged as the first or second attempt, and always rejects the first submission with an "incorrect data" message so that the victim types again or tries a second set of credentials (Huntress, 2026-10-13). Only after the second submission does the page fetch the real WatchGuard Mobile VPN with SSL installer from WatchGuard's own CDN, an Authenticode-signed file whose digest Huntress recomputed and found unmodified, so there is no trojanized installer or malicious DLL for endpoint defenses to flag (Huntress, 2026-10-13). The victim's browser history showed no download in the observed window, so Huntress judges the user probably did not finish both rounds but may have typed credentials in the first, and Managed Defender flagged the incident 21 seconds after the lookalike domain loaded (Huntress, 2026-10-13). Both domains were registered within the previous two months, few reputation engines flagged either as of 2026-10-08, and the lure domain was offline by 2026-10-13 (Huntress, 2026-10-13). Huntress places the iteration in a campaign that WatchGuard's Secplicity team described in January 2026 as lookalike download sites for WatchGuard, F5, Fortinet, SonicWall and Sophos clients, and that Microsoft tied in March 2026 to a financially motivated actor it tracks as Storm-2561; the new element is that the fake client is gone from the middle (Huntress, 2026-10-13).

    Exposure
    Administrators and users who find an SSL VPN client through a web search, as an administrator at a managed service provider did here; the lure here impersonates WatchGuard, and Huntress describes the same campaign against clients of five vendors (Huntress, 2026-10-13). The credentials of any VPN account typed into such a page, and the gateway address with them, are in the attacker's hands.
    Detection
    No malicious file or process reaches the endpoint, so the signal is in web proxy and DNS telemetry (a visit that arrives from a search-result redirect to a domain that is not the vendor's, followed by a JSON POST to a second, recently registered domain; Huntress's Managed Defender did flag the browsing activity) and in VPN gateway authentication logs; Huntress advises watching for SSL VPN logins from hosting providers, unfamiliar ASNs and countries where the account has never connected (Huntress, 2026-10-13).

    Triage: a genuine VPN client also asks for server, login and password, but only inside the installed client at connect time; a browser form that collects the three values before any installer has run, on a domain that is not the vendor's, is the signal.

    Defender takeaway
    If a user typed VPN credentials into a page found through search, reset every affected account and treat the VPN endpoint those credentials belong to as known to the attacker; enforce multi-factor authentication on the VPN, and publish and bookmark the official client download links in internal documentation so staff do not search for them (Huntress, 2026-10-13).

    CVE-2026-76519, Cisco Secure Email Gateway: one crafted email attachment writes files and runs commands as root, exploited in the wild and listed in CISA KEV (CVSS 9.8)

    Cisco's advisory of 2026-10-14 describes CVE-2026-76519, a relative path traversal in the Advanced Malware Protection feature of Cisco Secure Email Gateway: improper handling of email attachments when the file reputation service is enabled lets an unauthenticated remote attacker who sends a crafted attachment through the device write arbitrary files on the underlying operating system and run commands as root, and Cisco rates it CVSS 3.1 9.8 (Cisco PSIRT, 2026-10-14). Cisco states that in October 2026 its PSIRT became aware of active exploitation, and that it has directly contacted Cisco Secure Email Cloud customers on whose devices indicators of possible compromise were identified (Cisco PSIRT, 2026-10-14); CISA added the flaw to its Known Exploited Vulnerabilities catalog the same day (CISA, 2026-10-14). Cisco gives no workaround; the fix is distributed through the Content Scanner Tools package for every supported AsyncOS release and needs no software upgrade or restart, and it is also in AsyncOS 15.5.5-014 and 16.5.0-780, while release 16.0 must migrate to a fixed release (Cisco PSIRT, 2026-10-14). It is the second exploited root-level flaw in this product in about four weeks: BleepingComputer notes that last month Cisco warned of CVE-2026-76461, which also lets unauthenticated remote attackers run commands as root (BleepingComputer, 2026-10-14).

    Exposure
    A physical or virtual Cisco Secure Email Gateway is exposed when both conditions hold: the File Reputation service is enabled and assigned to a mail policy (web interface, Mail Policies, Incoming or Outgoing Mail Policies, Advanced Malware Protection, "Enable File Reputation" ticked), and the Content Scanner Tools version, shown by the contentscannerstatus command, is earlier than 25.3.0.5525; Secure Email and Web Manager and Secure Web Appliance are not affected, and Cisco Secure Email Cloud Gateway customers need take no action (Cisco PSIRT, 2026-10-14). The attack arrives as an email attachment passing through the appliance, so exposure does not depend on its management interface being reachable (Cisco PSIRT, 2026-10-14).
    Detection
    Start with the appliance's own logs: Cisco's self-check is grep "System Security" system_logs on each cluster member, which returns "Suspected compromise indicator was found", "Security scan did not complete" or "No compromise indicator was found" (Cisco PSIRT, 2026-10-14). Cisco warns that an attacker with root may remove or hide evidence, so it also recommends cross-checking network and firewall logs outside the device for unexpected uploads from the appliance to external addresses or downloads from malicious addresses (Cisco PSIRT, 2026-10-14); that is egress telemetry from the gateway's own addresses.
    Defender takeaway
    Confirm Content Scanner Tools 25.3.0.5525 or later on every gateway today, since automatic updates deliver it and only gateways with updates disabled need the manual update, and run the log check on every one; for a virtual appliance with a compromise indicator, Cisco says to keep forensic data before upgrading, because upgrading a compromised instance destroys it, then deploy a new virtual machine on a fixed release, rebuild the configuration without importing an old file and renew credentials and cryptographic material (a physical appliance goes to Cisco TAC), and strongly recommends restoring every member of a cluster that contains a compromised appliance, since the cluster's SSH private keys could be accessed (Cisco PSIRT, 2026-10-14).

    HIGHCVE-2026-110447exploitedNATOA2

    CVE-2026-110447, Collabora Online Built-in CODE Server (Nextcloud richdocumentscode app): an unauthenticated command injection in proxy.php, exploited in the wild to plant PHP web shells, fixed in 26.4.303 (CVSS 4.0 9.2)

    Collabora's own advisory, published 2026-10-14, says users of Nextcloud with the Collabora Online Built-in CODE Server app (richdocumentscode) can be vulnerable through proxy.php: a request can run an operating system command as the web server user, the attack works only while the built-in CODE server is not running (after a restart, an upgrade or a crash), and disabling the app is not sufficient, it must be upgraded to 26.4.303 or later or removed (Collabora Online security advisory, 2026-10-14). Users of end-of-life Nextcloud 29 or older should upgrade Nextcloud or remove the app, standalone Collabora Online servers are not affected, and the fix for CVE-2025-66208 does not prevent this flaw (Collabora Online security advisory, 2026-10-14). The GitHub Advisory Database record for CVE-2026-110447 says it was exploited in the wild in September and October 2026 (GitHub Advisory Database, 2026-10-14). Field reports came first: on 2026-09-11 a hoster reported on the app's issue tracker that several Nextcloud servers running richdocumentscode 26.4.302 had been compromised since the previous day through requests to proxy.php that carried shell command substitution and an encoded path traversal, with base64 payloads decoded and run through a shell to create PHP web shells in the app directory; on one server the attacker then searched for password-manager databases and cryptocurrency-wallet files, and the reviewed requests showed no archiving or upload commands (issue 354, 2026-09-11). Other administrators report the same compromise, one noticing it because Nextcloud's integrity check failed on an unexpected PHP file (issue 354, 2026-09-11). A reply on the issue says the flaw affects only the Development Edition in the Built-in CODE Server mode that downloads a local AppImage, and a later one that leftover web-shell files must be removed after upgrading (issue 354, 2026-09-11). A Nextcloud forum post of 2026-10-03 told users to update, saying that as far as the poster knew no CVE existed (Nextcloud community forum, 2026-10-03).

    Exposure
    A Nextcloud server with the "Collabora Online - Built-in CODE Server" app at 26.4.302 or older, including one patched for CVE-2025-66208; a restart, an upgrade or a crash that stops the built-in CODE server opens the window, and deactivating the app does not close it (Collabora Online security advisory, 2026-10-14).
    Detection
    In web access logs, requests to the app's proxy.php whose path carries $( command substitution and an encoded ..; in file telemetry, unexpected PHP files in the app directory, which Nextcloud's integrity check flagged on a compromised server; in process telemetry, the web server account starting a shell that decodes base64 and calls out with curl or wget to an external service (issue 354, 2026-09-11). The web shell survives the update, so the post-patch check is the same file and process search, and the reporter says secrets available to the web server account must be treated as potentially affected (issue 354, 2026-09-11).
    Defender takeaway
    Update the app to 26.4.303 or remove it on every Nextcloud server that has it, because disabling it does not stop the request, and on Nextcloud 29 or older upgrade Nextcloud or remove the app (Collabora Online security advisory, 2026-10-14); then search for dropped PHP files and the request pattern back to at least early September 2026, and on a hit rotate whatever the web server account can read (issue 354, 2026-09-11).

    HIGHCVE-2026-0322exploitedupdatedNATOA2

    CVE-2026-0322, Palo Alto Networks PAN-OS: code injection in the management interface gives an authenticated attacker root, exploited in very limited attacks and listed in CISA KEV (CVSS-B 8.6)

    Palo Alto Networks' advisory of 2026-10-14 describes CVE-2026-0322, a code injection (CWE-94) in the management interface of PAN-OS that lets an authenticated attacker with network access run arbitrary code as root on PA-Series and VM-Series firewalls and on Panorama (virtual and M-Series); Cloud NGFW and Prisma Access are not affected and no special configuration is needed to be affected (Palo Alto Networks PSIRT, 2026-10-14). The advisory is tagged as attacked and says very limited exploitation has been observed targeting the management interface (Palo Alto Networks PSIRT, 2026-10-14), and CISA added the flaw to its Known Exploited Vulnerabilities catalog the same day (CISA, 2026-10-14). Palo Alto scores it CVSS-B 8.6 with a suggested urgency of highest, says the risk is highest when the management interface is reachable from the internet, and scores it 8.5 when access is restricted to a single jump box (Palo Alto Networks PSIRT, 2026-10-14). It lists no workaround; Threat Prevention IDs 510046 and 510047 give limited coverage and only when management traffic is routed through a data-plane interface and decrypted, and Palo Alto warns that variations of the attack may not be detected (Palo Alto Networks PSIRT, 2026-10-14). Fixes ship per train; a unit on 11.2.14 or 11.2.15 had no fixed build when the advisory appeared, and 11.2.16, the fix for those two releases, was published on 2026-10-15 (Palo Alto Networks PSIRT, 2026-10-14). The advisory does not say how the attackers obtained the credentials the flaw requires, when exploitation began or who is behind it, and BleepingComputer says it asked Palo Alto when exploitation began, who is behind the attacks and whether attackers compromised firewalls or used them to reach internal networks (BleepingComputer, 2026-10-14).

    Exposure
    Any PA-Series or VM-Series firewall or Panorama (virtual or M-Series) on PAN-OS 10.2, 11.1, 11.2, 12.1 or 12.2 below the fixed build of its train, with no configuration needed; the exposure is greatest where the management interface accepts connections from outside trusted internal addresses (Palo Alto Networks PSIRT, 2026-10-14). BleepingComputer reads the advisory as requiring existing credentials and network access to the management interface (BleepingComputer, 2026-10-14).
    Detection
    Look at authentication and administrator-change records on the management interface, and at inbound connections to the management address in upstream firewall or provider logs, for logins from unfamiliar sources; Palo Alto's advisory FAQ lists three source addresses associated with the limited exploit attempts to compare against (Palo Alto Networks PSIRT, 2026-10-14). Root code execution means an upgrade does not evict an attacker who is already in, and the advisory gives no file or process artifact, so a device that was reachable from untrusted networks before the fix needs a compromise assessment as well as the patch.
    Defender takeaway
    Take the management interface off every network but trusted internal addresses, with a jump box as the tightest setting Palo Alto describes, and upgrade to the fixed build of each train; units on 11.2.14 and 11.2.15 upgrade to 11.2.16, which Palo Alto published on 2026-10-15 (Palo Alto Networks PSIRT, 2026-10-14).
