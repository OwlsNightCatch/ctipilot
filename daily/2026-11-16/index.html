    ARTEX: Microsoft reports Storm-0940, a China-state aligned actor, running an open-source multi-agent LLM penetration-testing framework against hundreds of organizations, with privileged cloud access in under three hours in some cases, and Expel sees the same infrastructure abuse Okta self-service registration

    First published 2026-10-22 · open finding →

    Update16 Nov 2026 04:29 UTCrun 2026-11-16T0356Z-intelheadlinesummarytechniquessourcessourcing_note

    The FBI's FLASH of 2026-11-13 says a variety of actors have used ARTEX since at least August against sectors including government, with more than 1,600 exposed consoles in early November. It lists the observed steps (cloud-trust and vendor-credential pivots, Kudu abuse, Active Directory credential theft, exfiltration preparation), the telemetry to check and the attack-surface hardening it recommends.

    The FBI's FLASH of 2026-11-13 (TLP:CLEAR) adds a US authority's account of ARTEX use. It says a variety of malicious actors have used the framework since at least August 2026 against organisations in financial services, government, technology, defense, semiconductor, energy, healthcare, manufacturing, telecommunications and legal services, with some intrusions reaching privileged access in under three hours (FBI, 2026-11-13). The original repository was withdrawn on 2026-10-08, but forks, archived copies and a commercial version keep the framework available, and researchers identified more than 1,600 publicly exposed ARTEX consoles in early November (FBI, 2026-11-13). The FBI says ARTEX excels at finding and exploiting peripheral systems that get less security attention: partner and supplier portals, mobile backends, employee applications, legacy services and third-party integrations (FBI, 2026-11-13).

    The FBI's table of observed activity lists these further steps. Initial access came through unsigned SAML assertions, XXE, SSRF, anonymous file upload, hard-coded administrator passwords in single-page-application JavaScript bundles, stolen VPN configurations and leaked credentials, cross-account cloud trust abused from an external partner tenant, and compromised third-party vendor credentials used across trusted B2B federation. Persistence used JSP and PHP web shells (one route was MySQL log poisoning), Kudu administrative APIs to run commands, and credentials added to existing OAuth applications. For privilege escalation and internal discovery the agents used Kerberoasting, DCSync, resource-based constrained delegation abuse and a cloud metadata query through XXE, ran iterative PowerShell enumeration against domain controllers (over 110,000 Active Directory objects), read LAPS passwords and inventoried Windows hosts without a particular EDR sensor; attempted lateral movement to domain controllers by pass-the-ticket, WinRM, Kerberos relay and pass-the-hash was blocked by endpoint protection. Theft preparation used database queries, mass blob reads, custom boot scripts via EC2 instances and new 100 GB volumes, with command output sent to rotating webhook endpoints, and command and control ran through residential proxies, Tor, Chisel and SoftEther (FBI, 2026-11-13).

    Telemetry the FBI lists: unexpected outbound calls to LLM API endpoints (to be read alongside other suspicious activity), high-frequency sequential enumeration against login and search endpoints, Azure Resource Manager deployment-validation dry runs across many resource types, IAM permission tests with DryRun flags and sub-second test blob writes and deletes, credential additions to applications and service principals in the Entra audit log, and .aspx or .jsp files in unexpected web-application paths (FBI, 2026-11-13). Its recommendations: inventory every internet-facing application including the peripheral ones named above, restrict Kudu/SCM endpoints, cloud administration, hypervisor and backup interfaces to trusted networks or dedicated administrative paths, and disable basic publishing authentication where it is not required. For every Microsoft 365 tenant where an affected ConnectWise application is or was authorised, it asks for a review by application ID of activity from at least 2026-10-01 and says not to delete the enterprise application before evidence is preserved (FBI, 2026-11-13).
