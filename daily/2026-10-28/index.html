    NOTABLENATOB2

    DeadTag: re-registered domains of defunct analytics and advertising tags redirect visitors of thousands of sites, among them to a page that serves the Coruna and DarkSword iPhone exploit kits, which compromise a vulnerable device when the page opens

    Report URI and iVerify describe a campaign they name DeadTag: attackers buy the expired domains behind old analytics and advertising tags that thousands of websites still load, so every page that still carries the tag runs the operator's script without the site owner changing or noticing anything, and the operator sells the visitors those tags bring in (Report URI, 2026-10-22). Report URI has identified more than 660 re-registered domains still embedded on thousands of sites and cautiously estimates 135 million visits a month (Report URI, 2026-10-22). The script is about 2 KB, does nothing for search engines, scanners and other bots, asks the operator's server what to do with each visitor and redirects the chosen ones, and Report URI found that the operator stopped answering when it probed from data-centre addresses or returned too often from residential ones; destinations include scam pages, a fake VPN pop-up and, for iPhones, a page that serves two exploit kits (Report URI, 2026-10-22).

    One chain ends at a fake prediction-market page that picks the kit by the visitor's iOS version, Coruna for iOS 13 to 17.2.1 and a modified "P7" variant of DarkSword for iOS 18.4 to 18.7; both attack the browser itself, so opening the page is enough to compromise a vulnerable device, and the spyware they install steals keychain passwords, crypto-wallet app data and device and account information and reports to one server; Report URI notes that Coruna and DarkSword are separate exploit kits that have been seen in different campaigns, and that here both send their stolen data to the same server, which it reads as one operator running both (Report URI, 2026-10-22). iVerify reads DeadTag as mostly focused on European domains rather than .com (iVerify, 2026-10-21), and saw the P7 variant reach an employee's device at a customer organisation through a malicious Instagram ad while the employee was scrolling in the app (iVerify, 2026-10-21). The kit operator does not rely on DeadTag alone: Report URI found DarkSword loaders on hundreds of online shops on one e-commerce platform, PrestaShop (Report URI, 2026-10-22).

    Exposure
    Any public website that still loads a script from a third-party domain whose provider no longer operates it, where the browser fetches nothing useful and the page looks normal, and any iPhone on iOS 13 to 17.2.1 or 18.4 to 18.7 that opens such a page (Report URI, 2026-10-22).
    Detection
    Inventory the external script references of each public site and flag any whose domain has been re-registered or no longer belongs to its provider; Report URI recommends script monitoring that shows when a new script or domain appears on a page, and a Content Security Policy that controls which domains a site may load code from (Report URI, 2026-10-22). A security scanner usually sees only an empty response from the malicious script, because the operator answers only selected visitors.
    Defender takeaway
    Remove dead third-party tags from every site you run, enforce a Content Security Policy and keep iPhones on the current iOS, with Lockdown Mode for people who may be targeted; for an iPhone that may have opened an affected page, Report URI advises restarting it, changing the passwords stored in its keychain and moving crypto assets to a new wallet (Report URI, 2026-10-22).

    CVE-2026-48356 (PolyShell), Adobe Commerce and Magento Open Source: an unauthenticated file upload attacked since March 2026, fixed for supported lines in July, and listed by CISA as exploited on 2026-10-27

    Sansec named the flaw PolyShell: a missing validation in Magento's REST API that lets unauthenticated attackers upload executable files to a store, using a polyglot (code disguised as an image) to pass the image check (Sansec, 2026-03-17). It reports that its Shield service has blocked exploitation attempts against 79.5% of the Magento stores it protects since 2026-03-16, with first attacks observed on 2026-03-19, and that the vulnerable code has existed since the first Magento 2 release (Sansec, 2026-03-17). On 2026-03-30 a mass wave uploaded webshells, spread backdoor scripts across several directories and injected a JavaScript loader into the CMS pages of 471 stores within one hour (Sansec, 2026-03-30).

    Sansec dates a fix in Magento 2.4.9 to 2026-05-12, without a backport to the supported 2.4.8 and 2.4.7 lines, and the backport to those lines to 2026-07-14, in bulletin APSB26-73 (Sansec, 2026-03-17). That bulletin rates the flaw Critical at CVSS 3.1 9.6, lists 2.4.9 among the affected versions, names the 2026-jul builds, 2.4.9-2026-jul included, as the fix for Adobe Commerce and Magento Open Source, and still says Adobe is not aware of any exploits in the wild (Adobe, 2026-07-14). CISA added CVE-2026-48356 to its Known Exploited Vulnerabilities catalog on 2026-10-27 on evidence of active exploitation and gives no detail (CISA, 2026-10-27; CISA KEV, 2026-10-27). Sansec's research of 2026-10-24 shows the operator behind the March wave still active: its newest loader domain, registered on 2026-10-06, sits in the CMS blocks of 83 stores, 60 of which already carried an earlier loader, and one of them, on Magento 2.4.7-p1, still lacks APSB26-73 and holds PolyShell webshells disguised as images (Sansec, 2026-10-24).

    Exposure
    Every Magento Open Source and Adobe Commerce store without the 2026-jul fix, 2.4.9 included (Adobe, 2026-07-14); the anonymous guest-cart item routes need no credentials, and the upload becomes code execution on stock nginx for the oldest 2.x lines, on any non-stock nginx that hands every .php file to the PHP handler, and on Magento before 2.3.5 running on Apache without the engine switch set for that directory (Sansec, 2026-03-17).
    Detection
    Sansec calls any .php, .phtml or .phar file in the custom-options upload directory a strong indicator of compromise, and the uploaded file stays on disk even where execution is blocked (Sansec, 2026-03-17); also look for requests that add items to guest carts with embedded file data from unfamiliar sources (Sansec, 2026-03-17), script tags in the CMS block table and administrator accounts nobody created (Sansec, 2026-10-24).
    Defender takeaway
    Install the fix now, and treat a store that ran an unpatched build while internet-reachable since March as possibly compromised until its upload directory, CMS blocks and administrator accounts are checked, because an uploaded file stays on disk even where execution is blocked (Sansec, 2026-03-17), so the fix does not remove a shell already written (an inference), and deleting a loader script does not remove the access behind it (Sansec, 2026-10-24).
