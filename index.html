    Cleared Windows event logs are not empty: Arctic Wolf shows that clearing an EVTX log truncates it after the first 64 KB cluster and leaves the earlier records in that chunk's free space, where standard forensic tools do not parse or flag them, and recovered a ransomware encryptor's command line this way

    Arctic Wolf incident responders report that clearing a Windows event log truncates the EVTX file after the first 64 KB cluster and resets the record numbers, but the first chunk keeps its earlier records in its free space. On a domain controller the System log held 104 allocated events after the final clear, yet the encryptor's full command line, stamped about three hours before the clear, sat inside the allocated file, and Event Viewer, EvtxECmd and Magnet AXIOM showed none of it; a PowerShell log in a second case held 44 records of which one was allocated.

    NOTABLENATOB3

    Webworm's NtMonitor: Rapid7 finds a custom rebuild of the SoftEther VPN Bridge that removes the open-source tool's detection fingerprints (rebranded metadata, renamed handshake endpoints, a custom handshake watermark, an embedded resource archive and an encrypted configuration), attributed with moderate confidence to the China-aligned actor that targets European governments

    Rapid7 describes NtMonitor, a Windows build of SoftEther VPN Bridge 4.44 that it attributes with moderate confidence to Webworm, the China-aligned actor that ESET documented moving to European government targets in May 2026. The rebuild keeps SoftEther's function of bridging a remote network into the victim's LAN and strips its fingerprints: branding, handshake paths, the handshake watermark, the separate resource archive and the plain-text configuration are all changed, and Rapid7 found no backdoor or other added capability. Only one antivirus vendor detected the sample on VirusTotal although it has been public since January.

    Hokkaido: resident-register, support-needed and tax data of the cities of Rumoi and Iwamizawa and the town of Shintoku sat on a subcontractor's development PC infected with the K2F information stealer, which GIS Hokkaido links to the NIKKE game launcher; Rumoi's data was still there after its contract ended

    On 2026-11-18 and 2026-11-19 the Hokkaido municipalities Iwamizawa, Rumoi and Shintoku disclosed that data they gave their contractor GIS Hokkaido was stored on a development terminal of its subcontractor Rimgate that the K2F information stealer infected overnight on 2 to 3 November: up to 71,002 resident-register and 4,503 support-needed records for Rumoi, whose personal data was still on the terminal after its contract ended, 6,001 resident-register and 986 evacuation-support records for Shintoku, and fixed-asset-tax land and building data for Iwamizawa. GIS Hokkaido told ITmedia that the PC launcher of the game NIKKE is involved and would not say whether Rimgate staff ran the game on the work PC; no leak or misuse is confirmed, and none of the data contains the national My Number.

    CVE-2026-129448, Apache Roller 4.0.0 to 6.1.5: an unauthenticated request to the XML-RPC endpoint deserializes attacker-controlled objects before authentication and runs code on the server; Apache says it is being exploited, CISA lists it, fixed in 6.1.6 (CVSS 3.1 9.8)

    Apache's announcement of 2026-11-17 assigns CVE-2026-129448 (CVSS 3.1 9.8) to Apache Roller 4.0.0 through 6.1.4, the same flaw it disclosed as CVE-2026-82384 for 6.1.5 in September: the XML-RPC endpoint deserializes vendor extension types before authenticating the requester, which gives an unauthenticated attacker code execution. Apache states the flaw is being actively exploited and CISA listed it on 2026-11-20, while neither describes the attacks; Roller 6.1.6 or later fixes it, and switching XML-RPC off in the administration interface does not help on older releases.

    Action items (9)

    Do-now tasks recorded on the findings in this window. Each one links the finding it comes from.

    • On every x86-64 host with an AVX-512 VBMI processor that runs Java 17, 21, 25 or 27, update the JDK to 17.0.21.1, 21.0.13.1, 25.0.5.1 or 27.0.1.1 (Oracle builds; other distributions use their own build numbers) or 8u513-perf, then restart the Java processes and rebuild containers, internet-reachable applications and the identity, build and artifact servers Calif names (Keycloak, Jira, Confluence, Artifactory, Jenkins, PingFederate) first; where that waits, start the JVM with -XX:-UseBASE64Intrinsics, or with -XX:UseAVX=2 on x86-64 hosts only.
      FindingCVE-2026-114938→
    • Find every Danfoss AK-SM and AK-SC, Copeland xweb and Dixell xweb refrigeration controller, and any other refrigeration controller with a remote management interface because not every second-wave site's vendor is confirmed, in facilities you own or that a contractor manages for you and take its management interface off the internet now, restoring access only through a secure VPN or protected network (filtering to the contractor's source addresses is an emergency stop-gap, and CERT-FR asks you to check your insurance conditions before cutting the contractor's data uplink); an end-of-life unit that gets no fixes needs replacing, because a factory reset leaves it vulnerable and probably compromised again.
      FindingCVE-2026-129713 +1→
    • On every such controller that was reachable from the internet, check the whole configuration, defrost ranges, alarm thresholds and notification recipients included, against the intended one, verify the actual temperatures and test that alarms reach staff; for a Danfoss unit that may have been taken over, restart it or otherwise factory-reset it, restore access only through a secure VPN or protected network and reconfigure it for service, then update its firmware, set the security level to Strict and replace the default and any weak passwords, which do not close the six unpatched AK-SM 800A flaws that Midnight Blue and CCB report, so the interface stays off the internet; change all credentials where compromise is suspected and check the devices attached to the controllers, as BSI advises; and on every Copeland or Dixell XWEB unit confirm the factory Admin password was changed and give each contractor a named account with an expiry date.
      FindingCVE-2026-129713 +1→
    • On every PAN-OS firewall and Panorama with the HTTP/2 option enabled, upgrade to 12.2.4-h3, 12.1.10-h6 or 11.2.16-h3 or later (12.1.7-h15, 11.2.10-h19 and 11.2.13-h6 are listed with a 2026-11-23 ETA) or disable HTTP/2, because Palo Alto Networks lists CVE-2026-123007 and CVE-2026-123633 as affecting them with that option on.
      FindingCVE-2026-123007 +4→
    • Update every internet-facing nginx to 1.31.9 or 1.30.7 (NGINX Plus to 37.3.0.1 or 37.0.8.1) and restart the process, because a reload does not replace the running executable; where the update waits, disable HTTP/2 on exposed listeners, which blocks only CVE-2026-123007 and CVE-2026-123633, since five unauthenticated flaws reach code execution as the worker and Rapid7's proof of concept for one of them is public.
      FindingCVE-2026-123007 +4→
    • Upgrade every clustered Cisco Expressway-C and Expressway-E to X15.5.20 now (X14 and earlier has no fix and must migrate) and, until it is in, limit TCP 4371 to 4372 to the cluster peers' addresses as F6 advises, because CISA lists CVE-2026-76466 as exploited and F6 saw two internet-reachable nodes compromised soon after a public proof of concept appeared.
      FindingCVE-2026-76466 +4→
    • On every clustered Expressway that was reachable before the upgrade, search erlang.log for a nodeup record naming wombat@127.0.0.1 and check for scanning, SMB, SQL Server and WinRM traffic that starts on the Expressway or its cluster peers, treating a hit as a root compromise, because an upgrade does not evict an attacker who already holds root.
      FindingCVE-2026-76466 +4→
    • On every SAP NetWeaver AS Java with Enterprise Portal (EP-BASIS or EP-RUNTIME 7.50), confirm that SAP Security Note 3660969 is implemented and apply it where it is not, internet-reachable portals first, because CISA lists CVE-2025-42884 as exploited a year after the fix.
      FindingCVE-2025-42884→
    • Upgrade every Apache Roller to 6.1.6 or later (6.1.7 is the project's best available release) and, where that waits, set enabledForExtensions to false in WEB-INF/web.xml or remove the /roller-services/xmlrpc servlet mapping and restart; treat any internet-reachable instance on an older release as possibly compromised, because Apache and CISA report exploitation and the request is deserialized before authentication.
      FindingCVE-2026-129448 +1→
