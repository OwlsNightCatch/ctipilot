    Defender insights

    What each entry about Synology DiskStation Manager (DSM) tells a defender to do, newest first.

    2026-11-19HIGHnginx2root: five unauthenticated flaws reach worker RCE, Rapid7 PoC public; update to 1.31.10, 1.30.8, Plus 37.3.1.1

    Defender takeaway

    Update and restart nginx, because a configuration reload does not replace the running executable; disabling HTTP/2 on exposed listeners blocks only the two HTTP/2 flaws (Xint, 2026-11-18) and, if it stays on elsewhere, leaves connection pressure (Unit 42, 2026-11-24), and Xint gives interim measures for the others: a fixed upstream group in place of request-time DNS lookups for CVE-2026-123634, no QUIC listeners for CVE-2026-121810 and bound or firewalled mail listeners for CVE-2026-113425 (Xint, 2026-11-18). An empty execution-audit result after the update cannot rule out an earlier compromise, and Xint chained CVE-2026-123007 with a separate Linux kernel SCTP flaw, unpatched when it published, to reach root on the host and escape a Docker container; hosts that do not use SCTP can block the module from loading (Xint, 2026-11-18).

    Exposure · triage · detection
    Exposure

    An nginx build from the first affected release of each flaw (1.9.5, 1.19.7, 0.6.18, 1.25.0 and 0.5.33) up to 1.31.8 whose configuration uses the feature: an HTTP/2 or HTTP/3 listener, the resolver with variable proxy_pass destinations plus mirror or SSI, or the mail proxy with auth_http (nginx.org, 2026-11-18; Xint, 2026-11-18). A distribution backport can fix a flaw without changing the version nginx -v reports (Xint, 2026-11-18). Veeam Software Appliance and Infrastructure Appliance 13.1 are affected by the two HTTP/2 flaws and cannot disable HTTP/2; Veeam ships the fix through Veeam Updater (Veeam, 2026-11-25). GitLab's Linux package and Docker images carry nginx 1.31.9 from 19.6.2, 19.5.9 and 19.4.11 (GitLab, 2026-11-25).

    Triage

    A large upload is a legitimate cause of an inbound-heavy connection and workers crash for unrelated reasons, so a program started by the worker is the discriminator, not the traffic shape alone (Xint, 2026-11-18).

    Detection

    Process-creation or audit telemetry for any program started by the worker's user, since a normal nginx worker runs no external programs and that is the clearest sign of success; worker exits and core dumps in the error log mark attempts, not successes (Xint, 2026-11-18; CERT-EU, 2026-11-18).

    Detection

    Encrypted shares show as a burst of renames to the .L0CK3D extension with a read-me3.txt note created in every encrypted directory; 360 says the ransomware skips 27 system directories and encrypts each file with its own ChaCha8 key kept under RSA-2048 (360, 2026-10-29). For the September flaws, which need network access to the DSM management interface (NCSC Switzerland, 2026-09-21), file reads or writes outside a session's own storage scope, or unauthenticated requests to the SCGI and login endpoints from outside the administrative source range, are the sharpest signal (an inference from the flaw classes).

    HIGHCVE-2026-123007 +10updatedNATOA1

    NGINX nginx2root: five unauthenticated memory-corruption flaws (CVE-2026-123007 and CVE-2026-123633 in HTTP/2, CVE-2026-121810 in HTTP/3, CVE-2026-123634 in the resolver, CVE-2026-113425 in the mail proxy) can lead to code execution as the worker process; fixed in nginx 1.31.9 and 1.30.7 and NGINX Plus 37.3.0.1 and 37.0.8.1, Rapid7 proof of concept public, no exploitation reported (CVSS 4.0 9.2)

    F5 and the nginx project published the nginx2root fixes (nginx.org, 2026-11-18); CERT-EU counts five vulnerabilities, all able to lead to unauthenticated code execution with the privileges of the NGINX worker process (CERT-EU, 2026-11-18). CVE-2026-123007 is an HTTP/2 flow-control overflow: cancelling queued response data makes nginx use an invalid length when copying a later response (Rapid7, 2026-11-18), and Wiz demonstrated code execution on nginx serving ordinary static files (Wiz Research, 2026-11-18).

    Rapid7 published a working proof of concept for CVE-2026-123007 against nginx 1.31.8; the exploit needs about 128 GB of HTTP/2 traffic and likely fails with concurrent clients (Rapid7, 2026-11-18; Rapid7 repository, 2026-11-18). CERT-EU reports no exploitation in the wild and NCSC.ch rates exploitation unknown with a proof of concept available (CERT-EU, 2026-11-18; NCSC.ch, 2026-11-18).

    The memory-corruption fixes are in nginx 1.31.9 and 1.30.7 (nginx.org, 2026-11-18); nginx 1.31.10 and 1.30.8 of 2026-11-23 add a fix for CPU exhaustion when ssl_early_data is on (CVE-2026-132779, affecting 1.21.4 to 1.31.9 per nginx.org, 2026-11-27), as do NGINX Plus 37.3.1.1 and 37.0.9.1 (nginx.org, 2026-11-23; nginx.org, 2026-11-23; F5 NGINX Plus release notes, 2026-11-23). CERT.at lists NGINX Plus 37.3.0.1 and 37.0.8.1 as fixing four of the five (CVE-2026-123007, CVE-2026-121810, CVE-2026-123633 and CVE-2026-113425); it also says 37.2.0.1 and 37.0.7.1 already carry the fix for CVE-2026-123633 but stay affected by CVE-2026-123007 and CVE-2026-121810, and NGINX Plus R33 to R36 have no update (translated from German) (CERT.at, 2026-11-18).

    NOTABLECVE-2026-120382NATOA2

    CVE-2026-120382, Synology DSM OAuth API: an argument injection lets an unauthenticated remote attacker read or write arbitrary files on the NAS (CVSS 3.1 9.8); fixed in DSM 7.4.1-90080-2 and 7.3.2-86009-6, with DSM 7.2.x, 7.1 and BeeStation OS still unfixed

    Synology published Synology-SA-26:21 on 2026-11-19 and revised it on 2026-11-20 to update the fix status for DSM 7.3 and 7.4 (Synology, 2026-11-19). CVE-2026-120382 is an improper neutralization of argument delimiters in a command (CWE-88) in the OAuth API of DiskStation Manager that allows remote attackers to read or write arbitrary files and conduct denial-of-service attacks; Synology rates it Critical at CVSS 3.1 9.8 with network access, low complexity and no privileges or user interaction (Synology, 2026-11-19). DSM 7.4 is fixed in 7.4.1-90080-2 and DSM 7.3 in 7.3.2-86009-6; DSM 7.2.2, 7.2.1, 7.1 and BeeStation OS 1.5 are marked OnGoing, with an upgrade to 7.3.2-86009-6 recommended for the 7.2 lines, while APM, DSM Enterprise and SRM are not affected (Synology, 2026-11-19). The advisory does not mention exploitation. An unauthenticated file write on a network storage appliance warrants action before the regular cycle, because it reaches the data the NAS holds without credentials.

    Exposure
    A NAS on DSM 7.4 below 7.4.1-90080-2, DSM 7.3 below 7.3.2-86009-6, any DSM 7.2.2, 7.2.1 or 7.1, or BeeStation OS 1.5 whose DSM interface untrusted hosts can reach.
    Detection
    In DSM web and reverse-proxy logs, requests to the OAuth API from addresses that do not normally use it, and file changes on the NAS outside administrator activity, which follow from the mechanism; Synology names no indicators.
    Defender takeaway
    Update DSM 7.4 and 7.3 now; where no fix exists, deactivate the OAuth Service package as Synology's mitigation, and for 7.2.x plan the move to 7.3.2-86009-6 (Synology, 2026-11-19).

    HIGHCVE-2026-13684 +4exploitedupdatedNATOA3

    CVE-2026-13684 / CVE-2026-13639, Synology DSM: two unauthenticated CVSS 9.8 flaws (SCGI output-encoding bug, login-logic entropy weakness) allow remote arbitrary file read/write and denial-of-service with no credentials; C3RB3R ransomware is encrypting NAS on outdated DSM and CISA lists the 2024 flaw CVE-2024-10441 as exploited

    Synology disclosed eight CVEs in DiskStation Manager (DSM) on 2026-09-18 (Synology-SA-26:13). Two are unauthenticated and rated CVSS 9.8, CVE-2026-13684 (improper output encoding in the SCGI component) and CVE-2026-13639 (insufficient entropy in the login logic), and each lets a remote attacker with no credentials read or write arbitrary files and cause denial-of-service. Two more need only a low-privileged session: CVE-2026-13673 (8.8, LDAP API) and CVE-2026-6205 (8.1, Upload API). All four are fixed in DSM 7.4-90075, 7.3.2-86009-4, 7.2.2-72806-9 and 7.2.1-69057-12, and Synology lists no mitigation for the unauthenticated pair (Synology PSIRT, 2026-09-18).

    NCSC Switzerland recorded exploitation status as unknown on 2026-09-21 (NCSC Switzerland, 2026-09-21), and CERT-FR relayed the advisory the same day without commenting on exploitation (CERT-FR, 2026-09-21). heise online expected the terse advisory to draw ransomware authors and other criminals quickly, since Synology describes exploitation as very easy (translated from German) (heise online, 2026-09-18).

    Synology said on 2026-10-29 that threat actors are exploiting a vulnerability patched in December 2024 against outdated DSM to encrypt data and extort ransom, naming no CVE and pointing to Synology-SA-24:20 (Synology, 2026-10-29), whose lead flaw, CVE-2024-10441, allows remote code execution without credentials (CVSS 9.8) (Synology PSIRT, 2024-11-05). The same day 360 identified the ransomware as C3RB3R, a Cerber variant, and named CVE-2026-13639 and CVE-2026-13684 as its entry point (translated from Chinese) (360, 2026-10-29). The accounts conflict: CISA's listing of CVE-2024-10441 on 2026-11-18 supports Synology's pointer to SA-24:20 (CISA, 2026-11-18), and no source corroborates 360's naming of the two September flaws. BleepingComputer says the name is borrowed from the 2016 Cerber ransomware-as-a-service operation and reports Shadowserver tracking over 380,000 internet-exposed Synology NAS (BleepingComputer, 2026-11-02).

    Exposure
    Any DSM below the fixed build of its branch in Synology-SA-26:13 (7.4-90075, 7.3.2-86009-4, 7.2.2-72806-9, 7.2.1-69057-12) (Synology PSIRT, 2026-09-18) or Synology-SA-24:20 (7.2.2-72806-1, 7.2.1-69057-6, 7.2-64570-4, 7.1.1-42962-7, 6.2.4-25556-8), the only fixes the two advisories name for DSM 7.1, 7.2 and 6.2 (Synology PSIRT, 2024-11-05), with the DSM management interface reachable over the network (NCSC Switzerland, 2026-09-21).
    Detection
    Encrypted shares show as a burst of renames to the .L0CK3D extension with a read-me3.txt note created in every encrypted directory; 360 says the ransomware skips 27 system directories and encrypts each file with its own ChaCha8 key kept under RSA-2048 (360, 2026-10-29). For the September flaws, which need network access to the DSM management interface (NCSC Switzerland, 2026-09-21), file reads or writes outside a session's own storage scope, or unauthenticated requests to the SCGI and login endpoints from outside the administrative source range, are the sharpest signal (an inference from the flaw classes).
    Defender takeaway
    Update every DSM to the build of its branch now and take internet-facing management interfaces offline first (BleepingComputer, 2026-11-02), since Synology confirms ransomware exploitation of outdated DSM, CISA lists CVE-2024-10441 as exploited (CISA, 2026-11-18) and Synology lists no mitigation for the September flaws; treat a NAS that was reachable on an older build as possibly encrypted or compromised and check its shares for the .L0CK3D extension and read-me3.txt notes before relying on it.
