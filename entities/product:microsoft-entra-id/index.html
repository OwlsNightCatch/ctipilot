    What each entry about Microsoft Entra ID tells a defender to do, newest first.

    2026-11-13NOTABLEHuntress: device-code phishing posing as a Teams booking skips URL reputation checks; hunt Cmsi:Cmsi sign-ins

    Defender takeaway

    Restrict or monitor device-code authentication where it is not needed, enforce phishing-resistant MFA, and investigate unfamiliar device sign-ins from unmanaged devices, new regions or residential proxy networks (Huntress, 2026-11-12).

    Exposure · triage · detection
    Exposure

    A Microsoft 365 tenant that allows the device-code flow for users with no device that needs it, particularly accounts without MFA.

    Triage

    Huntress treats a device-code prompt that follows a link, a booking request or another unexpected interaction as suspicious, and the captured session shows up as a replay from another ASN and region within one session (Huntress, 2026-11-12).

    Detection

    In Entra sign-in logs, a successful device-code authentication shown as Cmsi:Cmsi, programmatic user agents such as python-requests and node afterwards (often only in the non-interactive log), and a change of ASN and region inside the same session ID; in mail and proxy telemetry, a Google share link that redirects to a freshly registered lookalike domain (Huntress, 2026-11-12).

    2026-11-12NOTABLECCB: attackers signed in to Entra ID with an SMS code alone; turn off SMS first-factor sign-in

    Defender takeaway

    Disable SMS first-factor sign-in now for everyone who has an alternative and restrict it to the smallest group where it must stay, as the CCB advises; remove SMS and voice for privileged accounts only after each has a working phishing-resistant method, and avoid a blind switch-off, which can lock users out or leave them with a password alone (CCB, 2026-11-10). Microsoft's own clearing reaches only tenants with no first-factor SMS sign-in traffic in the previous 30 days (Microsoft Learn, 2026-10-30), so a tenant that uses the method stays exposed until it acts.

    Exposure · detection
    Exposure

    An Entra tenant whose SMS authentication method policy has first-factor sign-in turned on for any user or group; the CCB's path is Authentication methods, SMS, "Use for sign-in", and the Authentication methods activity report shows who actually uses it (CCB, 2026-11-10). Microsoft's how-to calls the same setting "Enable first factor sign-in" and says that leaving it unchecked limits SMS to multifactor authentication and self-service password reset (Microsoft Learn, 2026-10-30).

    Detection

    In Entra sign-in logs, look for successful sign-ins that used SMS as the authentication method; in audit logs, for phone-number or authentication-method changes; then for unusual locations or devices and follow-on mailbox rules or application consents, reviewing as far back as log retention allows (CCB, 2026-11-10).

    2026-11-10NOTABLEBluePhishing: consent to a rogue Entra agent blueprint gives tenant access, and default users can soon create blueprints

    Defender takeaway

    Review the tenant's user consent settings and permission classifications before the November 2026 default lets default Entra users create agent blueprints, and look in the audit log for blueprint and agent-identity creations that nobody in IT made; no attacks have been reported, so this is a hardening decision, not an incident response.

    Exposure · detection
    Exposure

    A Microsoft Entra tenant whose users or administrators can be led to approve a consent link; Proofpoint says the user consent settings that limit third-party app consent also extend to agent blueprints and their agent identities (Proofpoint, 2026-11-09).

    Detection

    Proofpoint says agent and blueprint events surface in the Entra audit log as app consent operations do, the creation of an agent identity blueprint as "Add application" and the creation of an agent identity as "Add service principal", and that the blueprint ID is the same in every tenant that consents to it, so a known malicious blueprint can be searched for across tenants (Proofpoint, 2026-11-09).

    2026-10-22NOTABLEMicrosoft: Storm-0940 runs ARTEX at machine speed; Mandiant now sees agent frameworks in incident-response cases

    Defender takeaway

    Expel's reading is that the framework adds speed, not a new vulnerability, so the levers are the identity controls it runs into: least privilege on multi-tenant application permissions and consent grants, alerting on credential additions and privileged role assignments by applications, and a review of self-registered Okta accounts since 2026-10-13 (Microsoft, 2026-10-21; Expel, 2026-10-21).

    Exposure · triage · detection
    Exposure

    Any tenant that relies on password sign-in or grants OAuth consent to applications, and any Okta org with self-service registration enabled; not using ConnectWise does not exclude exposure (Expel, 2026-10-21).

    Triage

    Python and curl user agents match common legitimate automation, so Expel treats them as supporting evidence only, and a Python user agent on an application that normally calls Microsoft Graph with a .NET SDK is the anomaly (Expel, 2026-10-21).

    Detection

    In the authentication logs of every identity provider in use, bursts of failed logons and lockouts spread over many accounts; in the Okta system log, newly self-registered accounts that enrol Okta Verify and start single sign-on within minutes; and in the Entra audit log, credentials or certificates added to applications that nobody on your team created and any application that assigns itself a directory role (Microsoft, 2026-10-21; Expel, 2026-10-21). A clean audit log is not proof of no access, because Microsoft Graph directory reads leave no Entra audit record (Expel, 2026-10-21). In web access logs of an application exposed to the same actor, Wiz points to source-map and OpenAPI downloads followed minutes later by calls to internal routes that appear only in those files, and to sign-in telemetry showing a new user agent for each burst of attempts at a one-second cadence (Wiz, 2026-10-22).

    2026-11-06HIGHEntra app-credential abuse: agents hunt GitHub for secrets, an operator reaches MSP clients, government among them

    Defender takeaway

    Inventory the client secrets on app registrations and hunt the sign-in pattern above in every tenant you run or manage, MSP-managed communal tenants included; on an affected app remove every client secret, certificate and federated credential, including those the actor added, and rotate what any Key Vault it could read holds, because tokens already issued stay valid until expiry (Microsoft Threat Intelligence, 2026-11-05).

    Exposure · triage · detection
    Exposure

    Any Entra tenant, an MSP's or a customer's, that holds app registrations with client secrets, above all multitenant, delegated-admin and Partner Center applications and Azure DevOps service connections, security-tool integration apps among those abused (Todyl, 2026-11-03); Conditional Access for workload identities needs the Workload ID Premium licence and covers only single-tenant apps (Microsoft Threat Intelligence, 2026-11-05).

    Triage

    The invalid-secret and expired-secret errors alone only show that someone holds an old or wrong credential for the app; Microsoft treats a failure followed by a success as the urgent case (Microsoft Threat Intelligence, 2026-11-05).

    Detection

    In Entra service-principal and non-interactive sign-in logs, an invalid-secret or expired-secret error for an application followed by a success, one address authenticating as service principals in several unrelated tenants within 24 hours, an Azure Resource Manager token followed at once by a Key Vault token and then by previously unused apps authenticating, and failed service-principal sign-ins from hosting space that never succeed, which success-only logic misses (Todyl, 2026-11-03). In Azure DevOps auditing, personal access token creation and first use, federated service connections and pipeline edits (Microsoft Threat Intelligence, 2026-11-05).

    2026-11-05HIGHVaud: device-code phishing against Microsoft 365 is running in Romandie; several organisations already affected

    Defender takeaway

    Where the tenant has no documented need for device code flow, Microsoft recommends blocking it with a Conditional Access policy, testing in report-only mode and auditing existing use first (Microsoft Learn, 2026-04-07). Tell users never to enter a Microsoft login code at a third party's request, and that anyone who has entered a code or validated an authentication request must call IT support at once, which is the canton's own instruction (Canton of Vaud, 2026-11-04).

    Exposure · triage · detection
    Exposure

    Any Microsoft 365 tenant whose users can complete the device code flow, which Microsoft describes as meant for devices without local input such as shared devices or digital signage and as a high-risk method that phishing can use (Microsoft Learn, 2026-03-24).

    Triage

    Microsoft documents device code sign-in for shared devices and signage; a device-code sign-in by a user who has no such device, soon after that user received a mailed link, falls outside that use (Microsoft Learn, 2026-03-24).

    Detection

    Mail, web proxy and DNS telemetry for links to workers.dev subdomains of the structure above; in the Entra sign-in logs, device code events found with the authentication protocol filter (Microsoft Learn, 2026-03-24). Microsoft says protocol tracking persists through token refreshes, so later sign-ins in the same session can fall under an authentication-flows policy, and it records an original transfer method property in the activity details of the Conditional Access sign-in logs (Microsoft Learn, 2026-03-24).
