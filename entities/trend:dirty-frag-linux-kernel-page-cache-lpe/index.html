    Dirty Frag / Fragnesia

    trend · trend:dirty-frag-linux-kernel-page-cache-lpe

    Collective name (Red Hat: 'Copy Fail 2') for a family of Linux kernel local-privilege-escalation flaws (CVE-2026-43284, CVE-2026-43500, CVE-2026-46300) in which unmarked shared page-cache fragments surviving TCP-receive coalescing reach in-place modification via the IPsec ESP and RxRPC networking decrypt/verify paths, letting a local attacker corrupt a privileged read-only binary's in-memory copy and gain root; Kubernetes-context proof-of-concept exploits are public and Red Hat confirms RHEL kernels are affected by two of the three CVEs (Wiz Research, 2026-05-08/13; Red Hat RHSB-2026-003; Aikido Security, 2026-09-04).

    What each entry about Dirty Frag / Fragnesia tells a defender to do, newest first.

    2026-10-21CRITICALexploitedPHP2Shell: CISA lists both flaws as exploited after honeypot code execution; update the runtime, not the CMS

    Defender takeaway

    Update the PHP runtime on every internet-facing host today and restart the workers, internet-facing systems first and then internal and embedded installations, and take the management interface of every appliance that embeds PHP off the internet; where an update must wait, CERT-EU advises isolating internet-facing applications from public networks until the fix is applied and verified (CERT-EU, 2026-10-21). The project's interim settings (disable session upload progress, enforce memory_limit=-1 administratively, a low post_max_size, block multipart requests at the proxy where uploads are not needed) reduce only some attack paths, and BACS says a web application firewall alone is not enough (BACS, 2026-10-21; PHP, 2026-10-21). PHP 8.1 and older need a vendor backport, the project's source backports or an upgrade, ASLR is not a safe reason to wait on x86-64 given VulnCheck's exploit, and an update does not remove an attacker who is already in. The October releases do not fix CVE-2026-115560, so keep session upload progress disabled on updated hosts until PHP's next regular release (PHP, 2026-10-23). Because the flaws can disclose worker memory, rotating session secrets, API keys and other credentials that the PHP workers handled is a reasonable step on hosts that were reachable while unpatched.

    Exposure · triage · detection
    Exposure

    Every internet-facing server or container image that runs PHP, and every product, appliance or administration interface that embeds it, internal ones included; BACS stresses that operators often do not know a product uses PHP, and that distribution packages can carry the fix under an unchanged version number, so the running version and the vendor's security information decide (BACS, 2026-10-21). On WordPress the running PHP version is shown under Tools > Site Health > Info > Server (Wordfence, 2026-10-20).

    Triage

    An unexplained outage of a public-sector, university or fire-service website on 2026-10-21 or 2026-10-22 is more likely a precautionary take-down than a denial-of-service attack where the operator says so, as Basel-Stadt, Publica and the Lodur provider each did; the discriminators are the operator's statement and restoration after the update (Canton of Basel-Stadt, 2026-10-21; Publica, 2026-10-21; nau.ch, 2026-10-21).

    Detection

    AWS, as relayed by Inside IT, advises an operator who cannot exclude a compromise to start the investigation at least from 2026-10-17, the date of its earliest honeypot exploit attempt (Inside IT, 2026-10-22); the telemetry is, in web access logs, multipart POST requests to PHP endpoints from unfamiliar sources, including multipart requests that use the upload-progress code path, which VulnCheck's canaries saw scanners send, and an attempt to drop a web shell through a server-side session file, which one canary saw fail (VulnCheck, 2026-10-21); in PHP error logs and process telemetry, worker crashes and fatal errors, and processes started by the web server or PHP worker account, since the code runs with the web worker's privileges (PHP, 2026-10-21), above all a shell started directly by an Apache worker, as in Karimi's honeypots, which CISA also names as the behaviour to watch for (Karimi, 2026-10-24; CISA, 2026-10-26); and in the web root, new or changed files. BACS asks operators to examine logs and systems for unusual requests, crashes, changed files and unexpected processes, and says an update does not remove a compromise that has already happened (BACS, 2026-10-21). ReliaQuest, which reproduced exploitation of CVE-2026-109618 in controlled labs, reports a sequence across the PHP error, Apache access, Apache error and system logs: a POST that returns HTTP 500, PHP memory exhaustion reported "in Unknown on line 0" where an ordinary memory error names the application file and line, heap corruption, and an abort of the Apache worker that handled the request within seconds; each event can be benign alone, the full sequence on the same process is the stronger indication, and linking request to crash needs the process ID in the Apache access log as well as the error log (ReliaQuest, 2026-10-22).

    2026-10-25NOTABLEPublic root exploit for a Linux page-cache write past the Dirty Frag fix; AlmaLinux kernels carry the fix, no CVE yet

    Defender takeaway

    Restrict unprivileged user namespaces where nothing depends on them (Sysdig says user.max_user_namespaces=0 should block the public exploit, untested by TuxCare, and breaks rootless containers and some build tooling), do not rely on Ubuntu's AppArmor restriction, set seccomp RuntimeDefault on Kubernetes pods and install the fixed kernel where your distribution has shipped it; unload ksmbd where unused and keep TCP 445 to trusted networks where it must stay (Sysdig, 2026-10-24).

    Exposure · detection
    Exposure

    A Linux host where a local user or workload can run code and unprivileged user namespaces are on (shared hosting, CI runners, container nodes, login nodes) on the distributions above. For ksmbd, look for the ksmbd module, the ksmbd.mountd daemon and a kernel-owned listener on TCP 445 (Sysdig, 2026-10-24).

    Detection

    The exploit is one unprivileged process that unshares into new user and network namespaces and writes sysctls, brings up an nlmon interface, installs XFRM state over netlink, adds an nftables NFQUEUE rule, attaches a tc pedit action with a redirect and then calls splice() into a socket on the loopback address; Sysdig says nothing legitimate does all of that from one unprivileged process, so syscall-level runtime telemetry sees it (Sysdig, 2026-10-24). The write lands in the page cache, not the file, so a disk-content integrity check does not show it.

    2026-05-15HIGHexploitedCVE-2026-46300 (Fragnesia): CISA lists the Linux kernel root flaw as exploited, chained with PHP2Shell

    Defender takeaway

    Patch Linux hosts that run PHP or other internet-facing code first, then multi-tenant hosts, container nodes and CI runners. After any interim mitigation, drop the page cache, because a binary already modified in memory stays modified until it is reloaded from disk (Help Net Security, 2026-05-14).

    Exposure · triage · detection
    Exposure

    Any multi-user Linux host, container node or CI runner whose kernel lacks the distribution's fix for CVE-2026-46300 (Help Net Security, 2026-05-14). Until the kernel update is deployed, Wiz and Help Net Security advise blocking and unloading the esp4, esp6 and rxrpc modules where they are not required (Wiz Research, 2026-05-13 · Help Net Security, 2026-05-14). Blocking esp4 and esp6 breaks IPsec. Where IPsec must stay up, Red Hat's alternative is disabling unprivileged user namespaces, which can affect rootless containers, sandboxed browsers and Flatpak (Red Hat RHSB-2026-003, 2026-07-03).

    Triage

    Unprivileged user namespaces are routine for rootless containers, sandboxed browsers and Flatpak, and IPsec is commonly used for VPNs and site-to-site tunnels (Red Hat RHSB-2026-003, 2026-07-03), so either alone is weak; the exploit's signature is one unprivileged process tree that sets up its own ESP security association inside a fresh network namespace and then runs su (Wiz Research, 2026-05-13).

    Detection

    Process and syscall telemetry on Linux hosts (for example auditd or an EDR's Linux sensor): an unprivileged process that creates user and network namespaces and installs an ESP security association over NETLINK_XFRM, followed by su starting a root shell with no authentication step, because the exploit's overwritten su calls setresuid(0,0,0) and executes /bin/sh (Wiz Research, 2026-05-13). The primitive can rewrite any file the user can read, so a check limited to su misses variants (Help Net Security, 2026-05-14); Dream's chain overwrote /etc/pam.d/su instead of the binary (Dream Research, 2026-10-27).

    2026-05-09HIGHDirty Frag: two kernel page-cache write flaws give local root; Microsoft saw su escalation that may be it or Copy Fail

    Defender takeaway

    Install the distribution kernel update, which makes the module mitigations unnecessary (Ubuntu, 2026-05-08); where it cannot be installed yet, disabling unprivileged user namespaces is the mitigation Red Hat gives for its affected kernels (Red Hat RHSB-2026-003).

    Exposure · detection
    Exposure

    Linux hosts on kernels without their distribution's fix where a local user can run code; the ESP path needs the privilege to create a user namespace, and the RxRPC path needs the rxrpc module, which Ubuntu loads by default (V4bel, 2026-05-07).

    Detection

    The write modifies the page cache in RAM (V4bel write-up, 2026-05-07) while the file on disk never changes (Aikido Security, 2026-09-04), so file-write watches do not fire. Look instead for setuid binaries such as su executed from an unprivileged shell and returning root without an authentication event, for esp4, esp6 or rxrpc module loads on hosts that use neither IPsec nor AFS, and, after an incident, for differences between cached and on-disk file contents. Microsoft notes that malicious modifications may persist in cached file content after the vulnerable modules are disabled, and suggests validating critical files and considering clearing the page cache (Microsoft Security Blog, 2026-05-08).

    CRITICALCVE-2026-109618 +1exploitedupdatedNATOA1

    CVE-2026-109618 / CVE-2026-109619, PHP (PHP2Shell): two unauthenticated remote-code-execution flaws in the runtime, fixed on 2026-10-21 in 8.5.12, 8.4.27, 8.3.36 and 8.2.35, with attack traffic already observed and no upstream release for 8.1 and older (CVSS 4.0 9.2)

    The PHP project released PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35 on 2026-10-21 to fix two critical vulnerabilities that can allow unauthenticated remote code execution, CVE-2026-109618 and CVE-2026-109619, both CVSS 4.0 9.2, and urges all PHP users to update immediately (PHP, 2026-10-21; PHP, 2026-10-20). CVE-2026-109618 is memory corruption when PHP handles an out-of-memory error: it aborts the request with longjmp() while internal request data is only partly initialised, and request cleanup then treats the invalid data as valid (PHP, 2026-10-21). CVE-2026-109619 is stale global state: request-owned state survives a fatal error after its memory is freed, and a later request on the same worker uses it (PHP, 2026-10-21). Every PHP installation serving web requests is at risk, including PHP-FPM, Apache with mod_php, php-cgi, FrankenPHP and LiteSpeed; the project rates mod_php highest, with a demonstrated exploit where an unauthenticated request can trigger the attack before any application code runs (PHP, 2026-10-21). The confirmed impact is unauthenticated code execution as the web worker account, validated against mod_php with default settings, and for the second flaw against both mod_php and FPM through session upload progress, which is on by default and needs no session_start() call (PHP, 2026-10-21; PHP, 2026-10-21). The advisory for the second flaw also lists heap use-after-free and memory disclosure among the confirmed impacts (PHP, 2026-10-21), and Sansec says the leaked worker memory can hold passwords, session tokens, API keys and TLS private keys from other requests, and files the upload-progress memory disclosure under CVE-2026-109618 where the PHP advisories list it under CVE-2026-109619 (Sansec, 2026-10-21).

    The fixed branches are 8.2 to 8.5; PHP 8.1 and older no longer receive updates, and the project published minimal source backports for 7.4, 8.0 and 8.1 for people who build from source, while distributions and LTS vendors received the patches in advance (PHP, 2026-10-21). Cloudflare says all web servers running PHP 5.4 or later are affected (Cloudflare, 2026-10-21). The fix is in the runtime, so updating WordPress, a plugin or a theme does not change exposure (Wordfence, 2026-10-20). Products that embed PHP are affected through it: Palo Alto Networks lists PAN-OS 12.2, 12.1, 11.2, 11.1 and 10.2 as affected, with all but one of its hotfixes released and 11.1.7-h12 due on 2026-10-30, and notes that the issue applies to PAN-OS software on PA-Series and VM-Series firewalls and on Panorama (Palo Alto Networks, 2026-10-29), and ENISA, the Commission, CERT-EU, Europol EC3 and the CSIRTs network point to NCSC-NL's repository for software that bundles PHP (ENISA, 2026-10-21).

    CISA added both flaws to its Known Exploited Vulnerabilities catalog on 2026-10-26 and revised its alert the same day; the alert names no actor and does not say how CISA learned of the exploitation (CISA, 2026-10-26; CISA KEV, 2026-10-26). The first documented code execution is a honeypot report by Adel Karimi of Perplexity dated 2026-10-24: on three disposable targets running PHP 8.4.26 under single-worker Apache mod_php, 35 execution-stage requests were each followed by a shell started directly by an Apache worker, in a four-stage multipart chain (memory pressure, memory disclosure, more memory pressure, an execution request adjusted to the leaked layout); the chain is consistent with CVE-2026-109618, the records do not establish a CVE-2026-109619 path and no second-stage download was observed (Karimi, 2026-10-24; SecurityWeek, 2026-10-26; BleepingComputer, 2026-10-26). Earlier reports describe scanning and attempts: Cloudflare saw attack traffic against its customers while the flaws were still leaked (Cloudflare, 2026-10-21), watchTowr's honeypots recorded exploitation on 2026-10-21 (watchTowr, 2026-10-21), and VulnCheck's canary hosts recorded scanning from 08:37 UTC that day (VulnCheck, 2026-10-21). VulnCheck says it holds a working exploit for CVE-2026-109618 that, as of 2026-10-26, supports mod_php on PHP 8.2.28 to 8.2.34, 8.3.22 to 8.3.35, 8.4.10 to 8.4.26 and 8.5.10 to 8.5.11 with default settings and display_errors off, and WordPress on default Docker installs (VulnCheck, 2026-10-26). Palo Alto Networks' advisory for both flaws now states that active exploitation has been observed targeting its management interface exposed to the internet, after a copy of 2026-10-27 said very limited exploitation, and names no victim or actor (Palo Alto Networks, 2026-10-28; Palo Alto Networks, 2026-10-27); Dream Research's recovered artifacts, described next, add a detailed account of a production compromise through these CVEs, while Unit 42 retracted on 2026-10-25 its update of 2026-10-23 that had linked an attack on a European government agency to these flaws and says it is unable to confirm that the initial access is associated with them (Unit 42, 2026-10-25), and CrowdStrike, Wordfence and Sophos reported no successful exploitation (CrowdStrike, 2026-10-23; Wordfence, 2026-10-22; Sophos, 2026-10-22). Dream Research describes the chain it recovered: a custom PHP2Shell build tailored to the management web server of one unnamed vendor's firewall software (PHP 8.0.30), combined with the Linux kernel flaw CVE-2026-46300, gave unauthenticated root on 24 internet-facing firewalls and led, through the second of two firewalls of a US government-affiliated organization (the first crashed), to an outbound SSH tunnel, the rooting of the organization's firewall management server and a password-spraying attack on its Active Directory, and CISA's entry for the kernel flaw says the same chaining (Dream Research, 2026-10-27; CISA KEV, 2026-10-28). In Switzerland, SRF reported on 2026-10-26 that TCS Camping is warning about 15,000 customers in connection with the PHP flaw after a data theft at its booking-system supplier Camping.Care, and Blick, citing SRF, writes that the attackers used the two flaws; neither names a CVE (SRF, 2026-10-26; Blick, 2026-10-26).

    PHP posted an informational advisory on 2026-10-23 for a third code-execution path, CVE-2026-115560, that the October releases do not fix: it needs an application that sets session.serialize_handler to php_binary or php_serialize, switches it to php with ini_set() before session_start(), and leaves session upload progress enabled; PHP calls it an unlikely vector, issues no emergency release, suggests session.upload_progress.enabled=0 until the next regular bugfix release and will publish the full advisory then (PHP, 2026-10-23). PHP has not stated affected versions or a severity score for CVE-2026-115560, and no exploitation is reported (The Hacker News, 2026-10-23).

    Assessments of how easy exploitation is diverge. Sansec says an attack needs specific knowledge of the target server and specific conditions on it, that nobody has shown a single request that works against any vulnerable server, as there was for Log4Shell and Shellshock, that a researcher who tested the public proofs of concept found they do not work against a default PHP installation, and that mass exploitation is therefore less likely than it first expected, while it advises updating anyway (Sansec, 2026-10-21). CrowdStrike expects no single universal exploit but says a reliable one is feasible against a specific deployment profile, such as a fixed Docker image, because an attacker can calibrate offsets and heap grooming in advance (CrowdStrike, 2026-10-23), and the SANS Internet Storm Center, reading the public proofs of concept, finds a universal, reliable one-click exploit quite difficult (SANS ISC, 2026-10-23). Red Hat rates CVE-2026-109618 Important (CVSS 3.1 8.1 with high attack complexity, against 9.8 at NVD), says reliable exploitation requires precise heap manipulation and timing, and says its standard Red Hat Enterprise Linux deployments use PHP-FPM, whose workers exit on early initialization failures, so code execution is difficult in practice and typically needs non-default behavior such as parsing a second request body during script execution (Red Hat, 2026-10-21). That sits against VulnCheck's weaponized exploit above, and the advice of the PHP project, BACS, CERT-EU and ENISA to update is unchanged. Vendors of products that embed PHP report as follows: Citrix lists the NetScaler management GUI on every supported version (NetScaler Product Security, 2026-10-22); Cisco lists Expressway, Ultra-Reliable Wireless Backhaul, Duo Access Gateway and ISE Portal Builder, with fixes at 15.5.21, 27.1.1 (November 2026) and 3.2.0 (Cisco PSIRT, 2026-10-28); Fortinet keeps only FortiDDoS, FortiSOAR and FortiSOAR PaaS under investigation (Fortinet PSIRT, 2026-10-26); Splunk lists its products as unaffected or remedied (Splunk, 2026-10-26); Tenable's patch SC-202610.2 updates the bundled PHP in Security Center and Enclave Security to 8.2.35 (Tenable, 2026-10-23; Tenable, 2026-10-23); Siemens lists RUGGEDCOM APE1808 devices running PAN-OS as affected (Siemens ProductCERT, 2026-10-23); and WatchGuard says none of its products are affected (WatchGuard PSIRT, 2026-10-21).

    Exposure
    Every internet-facing server or container image that runs PHP, and every product, appliance or administration interface that embeds it, internal ones included; BACS stresses that operators often do not know a product uses PHP, and that distribution packages can carry the fix under an unchanged version number, so the running version and the vendor's security information decide (BACS, 2026-10-21). On WordPress the running PHP version is shown under Tools > Site Health > Info > Server (Wordfence, 2026-10-20).
    Detection
    AWS, as relayed by Inside IT, advises an operator who cannot exclude a compromise to start the investigation at least from 2026-10-17, the date of its earliest honeypot exploit attempt (Inside IT, 2026-10-22); the telemetry is, in web access logs, multipart POST requests to PHP endpoints from unfamiliar sources, including multipart requests that use the upload-progress code path, which VulnCheck's canaries saw scanners send, and an attempt to drop a web shell through a server-side session file, which one canary saw fail (VulnCheck, 2026-10-21); in PHP error logs and process telemetry, worker crashes and fatal errors, and processes started by the web server or PHP worker account, since the code runs with the web worker's privileges (PHP, 2026-10-21), above all a shell started directly by an Apache worker, as in Karimi's honeypots, which CISA also names as the behaviour to watch for (Karimi, 2026-10-24; CISA, 2026-10-26); and in the web root, new or changed files. BACS asks operators to examine logs and systems for unusual requests, crashes, changed files and unexpected processes, and says an update does not remove a compromise that has already happened (BACS, 2026-10-21). ReliaQuest, which reproduced exploitation of CVE-2026-109618 in controlled labs, reports a sequence across the PHP error, Apache access, Apache error and system logs: a POST that returns HTTP 500, PHP memory exhaustion reported "in Unknown on line 0" where an ordinary memory error names the application file and line, heap corruption, and an abort of the Apache worker that handled the request within seconds; each event can be benign alone, the full sequence on the same process is the stronger indication, and linking request to crash needs the process ID in the Apache access log as well as the error log (ReliaQuest, 2026-10-22).

    Triage: an unexplained outage of a public-sector, university or fire-service website on 2026-10-21 or 2026-10-22 is more likely a precautionary take-down than a denial-of-service attack where the operator says so, as Basel-Stadt, Publica and the Lodur provider each did; the discriminators are the operator's statement and restoration after the update (Canton of Basel-Stadt, 2026-10-21; Publica, 2026-10-21; nau.ch, 2026-10-21).

    Defender takeaway
    Update the PHP runtime on every internet-facing host today and restart the workers, internet-facing systems first and then internal and embedded installations, and take the management interface of every appliance that embeds PHP off the internet; where an update must wait, CERT-EU advises isolating internet-facing applications from public networks until the fix is applied and verified (CERT-EU, 2026-10-21). The project's interim settings (disable session upload progress, enforce memory_limit=-1 administratively, a low post_max_size, block multipart requests at the proxy where uploads are not needed) reduce only some attack paths, and BACS says a web application firewall alone is not enough (BACS, 2026-10-21; PHP, 2026-10-21). PHP 8.1 and older need a vendor backport, the project's source backports or an upgrade, ASLR is not a safe reason to wait on x86-64 given VulnCheck's exploit, and an update does not remove an attacker who is already in. The October releases do not fix CVE-2026-115560, so keep session upload progress disabled on updated hosts until PHP's next regular release (PHP, 2026-10-23). Because the flaws can disclose worker memory, rotating session secrets, API keys and other credentials that the PHP workers handled is a reasonable step on hosts that were reachable while unpatched.

    Linux kernel ZDI-CAN-33367: a public local root exploit for an skb_zerocopy page-cache write that gets past the Dirty Frag fix, with no CVE and no mainline fix, among six reports Trend Micro's ZDI copied to public lists, two of them ksmbd flaws scored CVSS 9.0

    On 2026-10-21 Trend Micro's Zero Day Initiative sent five Linux kernel reports and copied public mailing lists on every one, several with no fix in any released kernel; none of the six reports, the five kernel ones and a ConnMan report, has a CVE (Sysdig, 2026-10-24). ZDI-CAN-33367 matters most: skb_zerocopy() moves shared page-cache pages into a new socket buffer without the marker the Dirty Frag fix added, so IPsec ESP decrypts in place and an unprivileged local user writes attacker bytes into the cached copy of a read-only file, which gives root through a setuid binary or /etc/passwd; the public exploit needs unprivileged user namespaces and networking modules such as nlmon and act_pedit (Sysdig, 2026-10-24). TuxCare reproduced a root shell on AlmaLinux 8 to 10 (Dirty Frag fix installed), CloudLinux 9 and 10, Debian 12 and 13 and Ubuntu 24.04 and 26.04 (AppArmor user-namespace restriction bypassed) (Sysdig, 2026-10-24). A reviewed patch from the netdev list is now in the kernel's networking tree but not in mainline, and a kernel with only the fix for CVE-2026-90049, a bug in the same function, is not covered (Sysdig, 2026-10-24; TuxCare, 2026-10-27). AlmaLinux has put fixed kernels into production (4.18.0-553.178.1.el8_10, 5.14.0-687.60.1.el9_8, 6.12.0-211.69.1.el10_2), and TuxCare's rebootless patch is out for EL9 and EL10, with EL8 ready and Debian and Ubuntu in progress (AlmaLinux, 2026-10-28; TuxCare, 2026-10-27).

    Two reports concern ksmbd, the kernel's own SMB server, not Samba. ZDI-CAN-33774 is a pre-authentication race in the SMB1 or SMB2 handler choice: its public proof of concept leaks 28 bytes of kernel heap per attempt and can crash the kernel, ZDI labels it remote code execution, nothing public shows code execution, and a fix is queued in ksmbd-for-next (Sysdig, 2026-10-24; Phoronix, 2026-10-22). ZDI-CAN-33549 is an SMB Direct integer underflow that needs an RDMA interface, a writable share and an SMB Direct client, and its proof of concept crashes the kernel (Sysdig, 2026-10-24). ZDI scores both 9.0, and Red Hat Enterprise Linux does not include ksmbd by default (The Hacker News, 2026-10-22).

    Exposure
    A Linux host where a local user or workload can run code and unprivileged user namespaces are on (shared hosting, CI runners, container nodes, login nodes) on the distributions above. For ksmbd, look for the ksmbd module, the ksmbd.mountd daemon and a kernel-owned listener on TCP 445 (Sysdig, 2026-10-24).
    Detection
    The exploit is one unprivileged process that unshares into new user and network namespaces and writes sysctls, brings up an nlmon interface, installs XFRM state over netlink, adds an nftables NFQUEUE rule, attaches a tc pedit action with a redirect and then calls splice() into a socket on the loopback address; Sysdig says nothing legitimate does all of that from one unprivileged process, so syscall-level runtime telemetry sees it (Sysdig, 2026-10-24). The write lands in the page cache, not the file, so a disk-content integrity check does not show it.
    Defender takeaway
    Restrict unprivileged user namespaces where nothing depends on them (Sysdig says user.max_user_namespaces=0 should block the public exploit, untested by TuxCare, and breaks rootless containers and some build tooling), do not rely on Ubuntu's AppArmor restriction, set seccomp RuntimeDefault on Kubernetes pods and install the fixed kernel where your distribution has shipped it; unload ksmbd where unused and keep TCP 445 to trusted networks where it must stay (Sysdig, 2026-10-24).

    CVE-2026-46300, Linux kernel: local privilege escalation via xfrm ESP-in-TCP ("Fragnesia"), listed by CISA as exploited and chained with the PHP2Shell flaws to reach root, PoC public

    CVE-2026-46300 ("Fragnesia") is a local privilege escalation flaw in the Linux kernel's XFRM ESP-in-TCP subsystem. Improper handling of shared page fragments during skb coalescing lets an unprivileged local user modify read-only file contents in the kernel page cache and gain root (Wiz Research, 2026-05-13). The public exploit uses user and network namespaces to obtain CAP_NET_ADMIN inside an isolated namespace, installs a crafted ESP security association over NETLINK_XFRM and overwrites the start of /usr/bin/su in the page cache only, so the on-disk binary never changes (Wiz Research, 2026-05-13). Dirty Frag discoverer Hyunwoo Kim says the flaw was accidentally activated by the patch for CVE-2026-43284 (Help Net Security, 2026-05-14). William Bowling of Zellic.io found it with the company's AI-agentic auditing tool, and a technical explainer and proof-of-concept exploit are public (Help Net Security, 2026-05-14).

    The flaw needs local code execution, so it is the root step of a chain rather than an entry point (Wiz Research, 2026-05-13); CISA's catalog entry says it is chained with the PHP2Shell flaws, which supply the code execution in the web server (CISA KEV, 2026-10-28). Risk is highest on shared Linux hosts, container clusters where the page cache is shared across the host, CI runners and build farms, and cloud services running user code (Help Net Security, 2026-05-14). Ubuntu's default AppArmor restriction on unprivileged user namespaces is a partial mitigation that forces an extra bypass (Wiz Research, 2026-05-13). Microsoft reported no evidence of in-the-wild exploitation at disclosure (Help Net Security, 2026-05-14). At disclosure, AlmaLinux and CloudLinux had released patched kernels (Help Net Security, 2026-05-14).

    Exposure
    Any multi-user Linux host, container node or CI runner whose kernel lacks the distribution's fix for CVE-2026-46300 (Help Net Security, 2026-05-14). Until the kernel update is deployed, Wiz and Help Net Security advise blocking and unloading the esp4, esp6 and rxrpc modules where they are not required (Wiz Research, 2026-05-13 · Help Net Security, 2026-05-14). Blocking esp4 and esp6 breaks IPsec. Where IPsec must stay up, Red Hat's alternative is disabling unprivileged user namespaces, which can affect rootless containers, sandboxed browsers and Flatpak (Red Hat RHSB-2026-003, 2026-07-03).
    Detection
    Process and syscall telemetry on Linux hosts (for example auditd or an EDR's Linux sensor): an unprivileged process that creates user and network namespaces and installs an ESP security association over NETLINK_XFRM, followed by su starting a root shell with no authentication step, because the exploit's overwritten su calls setresuid(0,0,0) and executes /bin/sh (Wiz Research, 2026-05-13). The primitive can rewrite any file the user can read, so a check limited to su misses variants (Help Net Security, 2026-05-14); Dream's chain overwrote /etc/pam.d/su instead of the binary (Dream Research, 2026-10-27).

    Triage: unprivileged user namespaces are routine for rootless containers, sandboxed browsers and Flatpak, and IPsec is commonly used for VPNs and site-to-site tunnels (Red Hat RHSB-2026-003, 2026-07-03), so either alone is weak; the exploit's signature is one unprivileged process tree that sets up its own ESP security association inside a fresh network namespace and then runs su (Wiz Research, 2026-05-13).

    Defender takeaway
    Patch Linux hosts that run PHP or other internet-facing code first, then multi-tenant hosts, container nodes and CI runners. After any interim mitigation, drop the page cache, because a binary already modified in memory stays modified until it is reloaded from disk (Help Net Security, 2026-05-14).
