    Dirty Frag / Fragnesia

    trend · trend:dirty-frag-linux-kernel-page-cache-lpe

    Collective name (Red Hat: 'Copy Fail 2') for a family of Linux kernel local-privilege-escalation flaws (CVE-2026-43284, CVE-2026-43500, CVE-2026-46300) in which unmarked shared page-cache fragments surviving TCP-receive coalescing reach in-place modification via the IPsec ESP and RxRPC networking decrypt/verify paths, letting a local attacker corrupt a privileged read-only binary's in-memory copy and gain root; Kubernetes-context proof-of-concept exploits are public and Red Hat confirms RHEL kernels are affected by two of the three CVEs (Wiz Research, 2026-05-08/13; Red Hat RHSB-2026-003; Aikido Security, 2026-09-04).

    Patch multi-tenant Linux hosts first. After any interim mitigation, drop the page cache, because a binary already modified in memory stays modified until it is reloaded from disk (Help Net Security, 2026-05-14).

    Exposure · triage · detection
    Exposure

    Any multi-user Linux host, container node or CI runner whose kernel lacks the distribution's fix for CVE-2026-46300 (Help Net Security, 2026-05-14). Until the kernel update is deployed, Wiz and Help Net Security advise blocking and unloading the esp4, esp6 and rxrpc modules where they are not required (Wiz Research, 2026-05-13 · Help Net Security, 2026-05-14). Blocking esp4 and esp6 breaks IPsec. Where IPsec must stay up, Red Hat's alternative is disabling unprivileged user namespaces, which can affect rootless containers, sandboxed browsers and Flatpak (Red Hat RHSB-2026-003, 2026-07-03).

    Triage

    Unprivileged user namespaces are routine for rootless containers, sandboxed browsers and Flatpak, and IPsec is commonly used for VPNs and site-to-site tunnels (Red Hat RHSB-2026-003, 2026-07-03), so either alone is weak; the exploit's signature is one unprivileged process tree that sets up its own ESP security association inside a fresh network namespace and then runs su (Wiz Research, 2026-05-13).

    Detection

    Process and syscall telemetry on Linux hosts (for example auditd or an EDR's Linux sensor): an unprivileged process that creates user and network namespaces and installs an ESP security association over NETLINK_XFRM, followed by su starting a root shell with no authentication step, because the exploit's overwritten su calls setresuid(0,0,0) and executes /bin/sh (Wiz Research, 2026-05-13). The primitive can rewrite any file the user can read, so a check limited to su misses variants (Help Net Security, 2026-05-14).

    HIGHCVE-2026-43284 +1updatedNATOB2

    CVE-2026-43284 / CVE-2026-43500 Linux Dirty Frag: deterministic page-cache write to root through xfrm-ESP and RxRPC, public exploit, fixes released

    Researcher Hyunwoo Kim (V4bel) published "Dirty Frag" on 2026-05-07, after the embargo had been broken by external factors and before patches or CVE ids existed (V4bel, 2026-05-07). It is two page-cache write flaws: CVE-2026-43284 in the xfrm-ESP (IPsec) receive path, in the kernel since 2017 and fixed in mainline commit f4c50a4034e6, and CVE-2026-43500 in RxRPC, in the kernel since 2023 and fixed in mainline commit aa54b1d27fe0 (V4bel, 2026-05-07). In both, a page-cache page planted with splice() sits in a fragment of a network buffer and the receiving code decrypts it in place, writing into the cached copy of a file: the ESP variant stores 4 attacker-chosen bytes per trigger into a setuid binary such as su, and the RxRPC variant stores 8 bytes whose value the attacker brute-forces through the session key, aimed at /etc/passwd; the result is deterministic root without a race window (V4bel write-up, 2026-05-07). The ESP variant needs the privilege to create a user namespace, which Ubuntu sometimes blocks through AppArmor; the RxRPC variant needs no namespace but depends on the rxrpc module, which most distributions do not ship and Ubuntu loads by default (V4bel, 2026-05-07). The kernel.org CNA scores CVE-2026-43284 CVSS 8.8, and NVD and CISA score CVE-2026-43500 7.8 (Ubuntu, 2026-05-08). Microsoft reports limited in-the-wild privilege escalation involving su that "may be indicative of techniques associated with either" Dirty Frag or Copy Fail: an SSH session ran an ELF binary that escalated through su, then edited a GLPI LDAP authentication file and deleted and read web session files (Microsoft Security Blog, 2026-05-08). Copy Fail is the earlier CVE-2026-31431 (Microsoft Security Blog, 2026-05-08).

    The researcher tested the exploit on Ubuntu 24.04.4, RHEL 10.1, openSUSE Tumbleweed, CentOS Stream 10, AlmaLinux 10 and Fedora 44 (V4bel, 2026-05-07). Ubuntu publishes fixed kernels for every supported release from 18.04 to 26.04 (Ubuntu, 2026-05-08), and Red Hat states that fixes are released for all affected products and that CVE-2026-43500 does not affect Red Hat products (Red Hat RHSB-2026-003). Where a fix cannot be applied, NCSC-CH advises blocking or removing the esp4, esp6 and rxrpc modules (NCSC-CH advisory 12547, 2026-05-08), which affects IPsec and AFS where they are in use (Ubuntu, 2026-05-08); on RHEL, user.max_user_namespaces=0 blocks the ESP path (Red Hat RHSB-2026-003).

    Exposure
    Linux hosts on kernels without their distribution's fix where a local user can run code; the ESP path needs the privilege to create a user namespace, and the RxRPC path needs the rxrpc module, which Ubuntu loads by default (V4bel, 2026-05-07).
    Defender takeaway
    Install the distribution kernel update, which makes the module mitigations unnecessary (Ubuntu, 2026-05-08); where it cannot be installed yet, disabling unprivileged user namespaces is the mitigation Red Hat gives for its affected kernels (Red Hat RHSB-2026-003).
    Detection
    The write modifies the page cache in RAM (V4bel write-up, 2026-05-07) while the file on disk never changes (Aikido Security, 2026-09-04), so file-write watches do not fire. Look instead for setuid binaries such as su executed from an unprivileged shell and returning root without an authentication event, for esp4, esp6 or rxrpc module loads on hosts that use neither IPsec nor AFS, and, after an incident, for differences between cached and on-disk file contents. Microsoft notes that malicious modifications may persist in cached file content after the vulnerable modules are disabled, and suggests validating critical files and considering clearing the page cache (Microsoft Security Blog, 2026-05-08).

    The mainline fixes are f4c50a4034e6 for the ESP flaw and aa54b1d27fe0 for the RxRPC flaw (V4bel, 2026-05-07). On Ubuntu systems where AppArmor blocks unprivileged user namespaces, the ESP path cannot be triggered, while the RxRPC path needs no namespace (V4bel, 2026-05-07). Blocking rxrpc breaks AFS and other RxRPC uses, so for those hosts the kernel update is the fix (Ubuntu, 2026-05-08).

    A related flaw, CVE-2026-46300 ("Fragnesia"), reopens this vulnerability's underlying page-cache-write primitive even on hosts already patched against CVE-2026-43284: a bug from 2013 in the code that merges packet fragments drops the marker that flags a fragment as page-cache-backed, which the original xfrm-ESP fix depends on to decide whether it is safe to decrypt in place (Aikido Security). Public proof-of-concept exploits for this family now target Kubernetes specifically, extending the exposure to container-shared-kernel environments beyond the bare-metal/VM case originally described (Aikido Security).

    NOTABLECVE-2026-46300updatedNATOB2

    CVE-2026-46300, Linux kernel: local privilege escalation via xfrm ESP-in-TCP ("Fragnesia"), PoC public

    CVE-2026-46300 ("Fragnesia") is a local privilege escalation flaw in the Linux kernel's XFRM ESP-in-TCP subsystem. Improper handling of shared page fragments during skb coalescing lets an unprivileged local user modify read-only file contents in the kernel page cache and gain root (Wiz Research, 2026-05-13). The public exploit uses user and network namespaces to obtain CAP_NET_ADMIN inside an isolated namespace, installs a crafted ESP security association over NETLINK_XFRM and overwrites the start of /usr/bin/su in the page cache only, so the on-disk binary never changes (Wiz Research, 2026-05-13). Microsoft's analysts noted that an attacker can modify any file the user can read, including /etc/passwd, not only su (Help Net Security, 2026-05-14). Dirty Frag discoverer Hyunwoo Kim says the flaw was accidentally activated by the patch for CVE-2026-43284 (Help Net Security, 2026-05-14). William Bowling of Zellic.io found it with the company's AI-agentic auditing tool, and a technical explainer and proof-of-concept exploit are public (Help Net Security, 2026-05-14).

    The flaw needs local code execution, so it is a post-compromise root primitive rather than an entry point (Wiz Research, 2026-05-13). Risk is highest on shared Linux hosts, container clusters where the page cache is shared across the host, CI runners and build farms, and cloud services running user code (Help Net Security, 2026-05-14). Ubuntu's default AppArmor restriction on unprivileged user namespaces is a partial mitigation that forces an extra bypass (Wiz Research, 2026-05-13). Microsoft reported no evidence of in-the-wild exploitation at disclosure (Help Net Security, 2026-05-14). At disclosure, AlmaLinux and CloudLinux had released patched kernels (Help Net Security, 2026-05-14).

    Exposure
    Any multi-user Linux host, container node or CI runner whose kernel lacks the distribution's fix for CVE-2026-46300 (Help Net Security, 2026-05-14). Until the kernel update is deployed, Wiz and Help Net Security advise blocking and unloading the esp4, esp6 and rxrpc modules where they are not required (Wiz Research, 2026-05-13 · Help Net Security, 2026-05-14). Blocking esp4 and esp6 breaks IPsec. Where IPsec must stay up, Red Hat's alternative is disabling unprivileged user namespaces, which can affect rootless containers, sandboxed browsers and Flatpak (Red Hat RHSB-2026-003, 2026-07-03).
    Detection
    Process and syscall telemetry on Linux hosts (for example auditd or an EDR's Linux sensor): an unprivileged process that creates user and network namespaces and installs an ESP security association over NETLINK_XFRM, followed by su starting a root shell with no authentication step, because the exploit's overwritten su calls setresuid(0,0,0) and executes /bin/sh (Wiz Research, 2026-05-13). The primitive can rewrite any file the user can read, so a check limited to su misses variants (Help Net Security, 2026-05-14).

    Triage: unprivileged user namespaces are routine for rootless containers, sandboxed browsers and Flatpak, and IPsec is commonly used for VPNs and site-to-site tunnels (Red Hat RHSB-2026-003, 2026-07-03), so either alone is weak; the exploit's signature is one unprivileged process tree that sets up its own ESP security association inside a fresh network namespace and then runs su (Wiz Research, 2026-05-13).

    Defender takeaway
    Patch multi-tenant Linux hosts first. After any interim mitigation, drop the page cache, because a binary already modified in memory stays modified until it is reloaded from disk (Help Net Security, 2026-05-14).

    Red Hat rates CVE-2026-46300 CVSS 7.8 (Red Hat Product Security, 2026-05-13). Red Hat's own security bulletin groups it under the collective "Dirty Frag" name alongside CVE-2026-43284 and CVE-2026-43500, labelling it specifically "Fragnesia (skb coalescing via ESP-in-TCP)": "three vulnerabilities, collectively known as 'Dirty Frag', have been identified in networking subsystems of the Linux kernel, two of which affect Red Hat products" (Red Hat RHSB-2026-003, 2026-07-03). Applicability splits per CVE: "Red Hat says CVE-2026-43500 doesn't affect its products, while CVE-2026-43284 and CVE-2026-46300 do affect supported Red Hat Enterprise Linux kernels and anything built on them" (Aikido Security, 2026-09-04). Any RHEL, OpenShift or RHEL CoreOS estate must therefore confirm the CVE-2026-46300 fix specifically, not only the earlier two. For the Dirty Frag family as a whole (CVE-2026-43284, CVE-2026-43500 and CVE-2026-46300), Aikido writes: "Researchers have already published working proof-of-concept exploits for Kubernetes, and Ubuntu spells out the risk of a container escape"; it names no Kubernetes exploit for CVE-2026-46300 itself (Aikido Security, 2026-09-04). Because containers share the host kernel, a compromised workload that can reach the vulnerable code path (governed by seccomp, pod security and user-namespace settings) can escalate to root on the node (Aikido Security, 2026-09-04). No source states confirmed in-the-wild exploitation of this specific CVE. Microsoft's previously reported limited in-the-wild activity ("privilege escalation involving 'su'") was itself stated as ambiguous between the "Dirty Frag" family and the separate, earlier "Copy Fail" vulnerability (CVE-2026-31431) (Microsoft Security Blog, 2026-05-08). That is not a distinction between the two Dirty Frag CVEs themselves, and not specific evidence of exploitation for CVE-2026-46300.

    Detection
    As an exposure check, compare uname -r against the distribution vendor's fixed package version, not the upstream kernel version string, since backports mean a patched RHEL or Ubuntu host can report an old-looking version (Aikido Security, 2026-09-04). lsmod | grep -E 'esp4|esp6|rxrpc' shows whether the vulnerable code path is loaded, but an empty result is not an all-clear because these modules load on demand (Aikido Security, 2026-09-04). In container and Kubernetes environments, review RuntimeDefault seccomp enforcement, restricted pod policies and unprivileged user-namespace availability, the settings that govern whether a compromised workload can reach this kernel path (Aikido Security, 2026-09-04).
