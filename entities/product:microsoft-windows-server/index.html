    2026-05-30NOTABLEexploitedMicrosoft says its Digital Crimes Unit will keep bringing cases after six leaked Windows zero-days; three fixed in June

    Defender takeaway

    The decision is patch level, not the dispute: three of the researcher's six drops were exploited after release (The Record, 2026-05-29), and the other three are closed by the June 2026 Windows updates (BleepingComputer, 2026-06-10).

    Exposure · detection
    Exposure

    Windows systems without the June 2026 updates: GreenPlasma and MiniPlasma are local privilege escalations open to any logged-on user (MSRC CVE-2026-45586) (MSRC CVE-2020-17103), and YellowKey needs physical access to a BitLocker device not protected by TPM+PIN (Microsoft MSRC).

    Detection

    For MiniPlasma, ThreatLocker advised watching registry-modification telemetry from the EDR for changes under the user hive's Software\Policies\Microsoft\CloudFiles\BlockedApps key and the .DEFAULT\Volatile Environment key (BleepingComputer, 2026-05-17).

    2026-05-15NOTABLELeaked BitLocker bypass "YellowKey" and CTFMON privilege escalation "GreenPlasma" were fixed in the June 2026 updates

    Defender takeaway

    The June 2026 Windows update fixes YellowKey (MSRC CVE-2026-45585) and GreenPlasma (MSRC CVE-2026-45586), and Microsoft's interim WinRE script need not be reverted, since the update keeps its behavior (MSRC CVE-2026-45585). Microsoft says TPM+PIN makes YellowKey not exploitable (MSRC CVE-2026-45585), which the researcher disputes (BleepingComputer, 2026-05-13), and Kevin Beaumont advised TPM+PIN along with a BIOS password (BleepingComputer, 2026-05-13).

    Exposure · detection
    Exposure

    For YellowKey, TPM-only BitLocker devices (BleepingComputer, 2026-05-13) on Windows 11 24H2, 25H2 or 26H1 or Windows Server 2025 below the fixed builds, given physical access (MSRC CVE-2026-45585). For GreenPlasma, any Windows 10, Windows 11 or Windows Server 2012 to 2025 system without the June 2026 update, for an attacker who already runs code as a local user (MSRC CVE-2026-45586).

    Detection

    No cited source describes an artifact YellowKey leaves inside Windows; the attacker's media carries \System Volume Information\FsTx directories that WinRE replays at boot (BleepingComputer, 2026-05-13). GreenPlasma's public partial PoC raises a UAC consent prompt in default configurations (The Register, 2026-05-13).

    2026-10-14HIGHexploitedMicrosoft patches an exploited Windows Shell zero-day that evades Mark of the Web protections on files and links

    Defender takeaway

    Install the October cumulative update now, ahead of the monthly cycle, on endpoints that open mail and web downloads first; because the tag is the control that failed, attachment blocking and mail-gateway detonation remain the compensating layer until the update is deployed, and Rapid7 reports no patch for Windows Server 2012.

    Exposure · triage · detection
    Exposure

    Windows 10, Windows 11 and Windows Server 2012 R2 through 2025 where users open files or links from mail, chat or the web; the fixed build per release is in the CVE record, and Rapid7 reports no patch for Windows Server 2012.

    Triage

    A file a user created or received from a trusted local source also carries no tag; the discriminator is an internet origin (mail, chat or web download) together with the absence of the tag on the opened item.

    Detection

    Microsoft, CISA and Rapid7 name no actor, payload or victims and no source describes the exploit's behavior, so this is a hunt hypothesis that follows from the mechanism: the failed control is the Mark of the Web tag, so there is no warning dialog for a user to report. Look at mail gateway, chat and endpoint file-origin telemetry for internet-origin files, archives and shortcuts that execute without the usual download warning, and at process lineage from explorer.exe into scripting interpreters and living-off-the-land binaries shortly after a mail or browser download.

    2026-09-09HIGHexploitedMicrosoft names two exploited Windows privilege-escalation zero-days, splitting the newest and legacy build lines

    Triage
    Triage

    Both bugs manifest only after an attacker already runs code on the host, so the signal is a privilege transition, not an initial-access event: a low-integrity or AppContainer-sandboxed process acquiring a SYSTEM or higher-integrity token with no legitimate installer or servicing context is the discriminator. Routine software installation and Windows servicing also elevate to SYSTEM, so correlate the token change with a preceding low-privilege, non-installer execution rather than alerting on elevation alone.

    2026-07-31HIGHexploitedThe autonomous agent landed nothing; the operator's hand-driven work took data from three NetScaler targets and ran commands on 11 Marimo servers

    Defender takeaway

    The headline is not that an AI agent ran an attack; it is that the agent's attacks all failed against configuration and the human's did not. For the constituency the practical item is unglamorous: a SAML-IDP-configured NetScaler on an unpatched build leaks session material to anyone who asks, and it has been exploited by more than one unrelated actor since March. The secondary lesson is that the two products the agent chose autonomously, Langflow and n8n, are exactly the kind of self-hosted workflow and AI-orchestration software that spreads through research and public-sector environments without going through an asset inventory, and that in both cases the thing that saved the targets was an authentication setting rather than a patch.

    Latest update · triage · detection
    Latest update · 2026-08-10

    The patch has existed since April, so the practical action is inventory rather than remediation; identify which Windows hosts are actually configured as IKEv2 responders, confirm they took the April 2026 update, and close UDP 500/4500 inbound on the ones that are not. This adds mechanism to a CVE already known to have been reached in a real campaign; it does not change its patch status.

    Triage

    Scanning noise against edge appliances is constant, so volume alone discriminates nothing. Two things separate this from background scanning: the requests target the specific identity-provider paths rather than sweeping the whole surface, and successful reads produce responses that are neither errors nor valid authentication outcomes. On the enumeration side, ordinary vulnerability scanners announce themselves through breadth and user-agent consistency; what Unit 42 describes is narrow, sequenced and selective, a fingerprint pass followed by exploitation of only the matching subset.

    Detection

    For the NetScaler exposure the observable is in the appliance's own web logs: repeated requests to the SAML identity-provider endpoints from a single source, returning responses whose length varies request to request, with no corresponding completed authentication; memory-overread harvesting looks like a failing login loop that never fails cleanly. Follow it with authentication telemetry: a session cookie presented from an address or client fingerprint that never performed the sign-in that minted it is the downstream consequence the operator was working toward. More broadly, the enumeration behaviour Unit 42 describes leaves an approach signature worth hunting on any exposed application, high-volume version-fingerprinting requests from a narrow address set, followed within a short window by a small number of precisely-targeted exploit attempts against just the instances whose version replied in scope.

    In a blog post on 2026-05-27, the Microsoft Security Response Center said the vulnerabilities known as RedSun, UnDefend, BlueHammer, YellowKey, GreenPlasma and MiniPlasma "were not responsibly disclosed" and that uncoordinated disclosures putting proof-of-concept code for unpatched flaws "into the hands of bad actors are never justifiable"; it added that its Digital Crimes Unit "will continue bringing cases against these actors and those that enable their criminal activity" (Microsoft MSRC blog, 2026-05-27).     Contradiction: the outlets read the statement differently. The Record says Microsoft "stopped short of directly threatening legal action" (The Record, 2026-05-29), while heise writes that the company "is threatening lawsuits and the police" (heise Security, 2026-05-29).

    The first three drops, BlueHammer (CVE-2026-33825), UnDefend (CVE-2026-45498) and RedSun (CVE-2026-41091), all disclosed in April, have been exploited in live intrusions and appear on CISA's Known Exploited Vulnerabilities catalogue (The Record, 2026-05-29); UnDefend lets a standard user block Microsoft Defender definition updates (BleepingComputer, 2026-06-10). YellowKey, tracked as CVE-2026-45585, is a BitLocker security feature bypass that needs physical access (Microsoft MSRC). The researcher says MiniPlasma abuses the HsmOsBlockPlaceholderAccess routine of the Cloud Filter driver cldflt.sys, and that it is the flaw Google Project Zero reported in 2020 as CVE-2020-17103, "still present, unpatched"; BleepingComputer's test on a fully patched Windows 11 Pro system with the May 2026 updates opened a SYSTEM command prompt from a standard user account (BleepingComputer, 2026-05-17).

    Microsoft fixed the three May drops on 2026-06-09: GreenPlasma as CVE-2026-45586, a CTFMON elevation of privilege that can give SYSTEM (MSRC CVE-2026-45586), MiniPlasma by re-releasing CVE-2020-17103 with the June 2026 updates (MSRC CVE-2020-17103), and YellowKey in the same Patch Tuesday (BleepingComputer, 2026-06-10).

    NOTABLECVE-2026-45585 +1updatedNATOA1

    Windows BitLocker "YellowKey" (CVE-2026-45585) and CTFMON "GreenPlasma" (CVE-2026-45586) zero-days: public PoCs in May, fixed in the June 2026 Windows updates

    On 2026-05-13 BleepingComputer and The Register reported that the researcher Nightmare Eclipse (also Chaotic Eclipse) had published exploit code for two Windows zero-days, YellowKey and GreenPlasma (BleepingComputer, 2026-05-13) (The Register, 2026-05-13). The researcher's earlier BlueHammer (CVE-2026-33825) and RedSun drops began to be exploited in the wild shortly after release (BleepingComputer, 2026-05-13).

    YellowKey is a BitLocker bypass that needs physical access. The researcher says it affects Windows 11 and Windows Server 2022/2025 and works by placing crafted FsTx files on a USB drive or the EFI partition, rebooting into the Windows Recovery Environment (WinRE) and holding CTRL to trigger a shell (BleepingComputer, 2026-05-13). Will Dormann reproduced it with the files on a USB drive but not on the EFI partition: to boot WinRE, Windows replays the NTFS logs in \System Volume Information\FsTx directories on attached drives, the replay deletes X:\Windows\System32\winpeshl.ini, and WinRE then opens CMD.EXE instead of the recovery environment, with the disk still unlocked (BleepingComputer, 2026-05-13). Because it abuses TPM-only automatic unlock, the public exploit works only on the original device, not on a removed drive, and does not work with TPM+PIN (BleepingComputer, 2026-05-13). Microsoft tracks it as CVE-2026-45585, a security feature bypass by physical attack (CWE-77, CVSS 6.8), publicly disclosed and not exploited; its fixed builds are Windows 11 24H2 build 10.0.26100.8655, 25H2 build 10.0.26200.8655, 26H1 build 10.0.28000.2269 and Windows Server 2025 build 10.0.26100.32995, and its product table does not list Windows Server 2022 (MSRC CVE-2026-45585).

    Contradiction: the researcher says an unpublished variant also defeats TPM+PIN (BleepingComputer, 2026-05-13); Microsoft states that "if you are using TPM+PIN the vulnerability is not exploitable" (MSRC CVE-2026-45585).

    GreenPlasma is a local privilege escalation in CTFMON: an unprivileged user can create arbitrary memory-section objects within directory objects writable by SYSTEM, and the leaked PoC lacks the component needed for a full SYSTEM shell (BleepingComputer, 2026-05-13); in its current state it triggers a UAC consent prompt in default Windows configurations (The Register, 2026-05-13). Microsoft tracks it as CVE-2026-45586, a link-following flaw (CWE-59, CVSS 7.8) in the Windows Collaborative Translation Framework that lets an authorized local attacker gain SYSTEM privileges, released on 2026-06-09 with fixes for Windows 10, Windows 11 and Windows Server 2012 to 2025, publicly disclosed and not exploited (MSRC CVE-2026-45586).

    Exposure
    For YellowKey, TPM-only BitLocker devices (BleepingComputer, 2026-05-13) on Windows 11 24H2, 25H2 or 26H1 or Windows Server 2025 below the fixed builds, given physical access (MSRC CVE-2026-45585). For GreenPlasma, any Windows 10, Windows 11 or Windows Server 2012 to 2025 system without the June 2026 update, for an attacker who already runs code as a local user (MSRC CVE-2026-45586).
    Detection
    No cited source describes an artifact YellowKey leaves inside Windows; the attacker's media carries \System Volume Information\FsTx directories that WinRE replays at boot (BleepingComputer, 2026-05-13). GreenPlasma's public partial PoC raises a UAC consent prompt in default configurations (The Register, 2026-05-13).
    Defender takeaway
    The June 2026 Windows update fixes YellowKey (MSRC CVE-2026-45585) and GreenPlasma (MSRC CVE-2026-45586), and Microsoft's interim WinRE script need not be reverted, since the update keeps its behavior (MSRC CVE-2026-45585). Microsoft says TPM+PIN makes YellowKey not exploitable (MSRC CVE-2026-45585), which the researcher disputes (BleepingComputer, 2026-05-13), and Kevin Beaumont advised TPM+PIN along with a BIOS password (BleepingComputer, 2026-05-13).

    CVE-2026-96951, Windows Shell: a Mark of the Web bypass exploited as a zero-day, fixed in the 2026-10-13 cumulative updates and listed in CISA KEV (CVSS 8.8)

    Microsoft's 2026-10-13 release fixes CVE-2026-96951, a Windows Shell security feature bypass that Microsoft marks as exploited and not publicly disclosed (Microsoft Security Response Center, 2026-10-13); CISA added it to its Known Exploited Vulnerabilities catalog the same day, citing evidence of active exploitation (CISA, 2026-10-13). Microsoft's record gives the root cause as improper neutralization of special elements in a command (command injection, CWE-77) (Microsoft Security Response Center, 2026-10-13). Rapid7 describes the effect as Windows not showing the dialog that says it protected the PC, because the tag that triggers it is bypassed, calls this the second exploited Windows Shell zero-day this year, and says the flaw also affected Outlook.com, patched in a build several weeks ago (Rapid7, 2026-10-13). Rapid7 says Windows Server 2012 receives no patch while Server 2012 R2 does (Rapid7, 2026-10-13), and Microsoft's record lists no Windows Server 2012 product for this flaw (Microsoft Security Response Center, 2026-10-13).

    Exposure
    Windows 10, Windows 11 and Windows Server 2012 R2 through 2025 where users open files or links from mail, chat or the web; the fixed build per release is in the CVE record, and Rapid7 reports no patch for Windows Server 2012.
    Detection
    Microsoft, CISA and Rapid7 name no actor, payload or victims and no source describes the exploit's behavior, so this is a hunt hypothesis that follows from the mechanism: the failed control is the Mark of the Web tag, so there is no warning dialog for a user to report. Look at mail gateway, chat and endpoint file-origin telemetry for internet-origin files, archives and shortcuts that execute without the usual download warning, and at process lineage from explorer.exe into scripting interpreters and living-off-the-land binaries shortly after a mail or browser download.

    Triage: a file a user created or received from a trusted local source also carries no tag; the discriminator is an internet origin (mail, chat or web download) together with the absence of the tag on the opened item.

    Defender takeaway
    Install the October cumulative update now, ahead of the monthly cycle, on endpoints that open mail and web downloads first; because the tag is the control that failed, attachment blocking and mail-gateway detonation remain the compensating layer until the update is deployed, and Rapid7 reports no patch for Windows Server 2012.
