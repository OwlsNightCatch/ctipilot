    2026-10-16NOTABLEDrupal patches a critical Field UI RCE reachable through contributed modules; uninstall field_ui if you cannot update

    Defender takeaway

    Update core to the fixed release of its branch now, internet-facing sites first, because the flaw's mechanism is readable from the public fix and Drupal itself warned that exploits could follow within hours or days; where a site cannot be updated at once, uninstall Field UI, which removes the field management and display admin pages until the update (The Hacker News, 2026-10-15). Custom code that set #region_callback on a field_ui_table row stops working after the update, so test the manage fields and manage display pages (The Hacker News, 2026-10-15).

    Exposure · detection
    Exposure

    Drupal core on 10.6.x below 10.6.19, 11.3.x below 11.3.19 or 11.4.x below 11.4.10, or on an end-of-life branch from 8.9 to 11.2, with the Field UI module installed (the Standard install profile installs it) and a contributed module or custom code that exposes the vulnerable functionality, which the advisory does not name; Drupal Steward, a web application firewall service run by Acquia, Pantheon, Ironstar and Skpr, blocks some known vectors but not every one (The Hacker News, 2026-10-15).

    Detection

    The advisory publishes no exploit artifact. The result of the flaw is PHP code running as the web server's user, so as an inference from that, watch web access logs for unusual requests to routes that contributed modules provide, PHP worker process lineage for shells, curl or interpreters spawned by the web server, and new or modified PHP files under the web root and the Drupal files directory. An exposed site updated only after the fix was public needs that file-integrity review in addition to the update.

    Most of this traffic is automated probing that tests whether a site is vulnerable (Imperva, 2026-05-21); a probe against a MySQL or SQLite site, or one already on a fixed release, is noise, while the same request against an unpatched PostgreSQL site is an attempt that calls for the account review above (Drupal SA-CORE-2026-004).

    NOTABLECVE-2026-108097 +1NATOA2

    CVE-2026-108097, Drupal core (SA-CORE-2026-014): a critical Field UI code-execution flaw reachable through contributed modules, at least one without login; fixed in 11.4.10, 11.3.19 and 10.6.19, with no fix for end-of-life branches (Drupal risk 19/25)

    The Drupal Security Team's advisory SA-CORE-2026-014 of 2026-10-14 rates CVE-2026-108097 Critical, 19 out of 25 on Drupal's own scale, a remote code execution flaw in the core Field UI module: the vulnerability is not directly exploitable with core alone, but multiple serious exploit paths exist with contributed modules and at least one known path needs no authentication (Drupal Security Team, 2026-10-14). The advisory names no module that opens a path; The Hacker News reads the mechanism from the fix, where Field UI's table element ran whatever PHP callable each row carried in its #region_callback property through call_user_func_array with no check, bypassing the renderer's rule against untrusted callbacks, and 11.4.10 no longer calls it (The Hacker News, 2026-10-15).

    Fixed releases are Drupal 11.4.10, 11.3.19 and 10.6.19; 11.2.x and below, 10.5.x and below, and Drupal 8 and 9 are end of life and get no fix, which The Hacker News counts at 28.5 percent of the sites reporting a core version in the week of 2026-10-04 (The Hacker News, 2026-10-15). The advisory records no public exploit at publication, but the Security Team's pre-announcement of 2026-10-12 told sites to reserve time "because exploits might be developed within hours or days", and in May Drupal reported exploit attempts within two days of a core SQL injection advisory that CISA then added to its Known Exploited Vulnerabilities catalog (The Hacker News, 2026-10-15). The contributed Entity List module has its own critical code-execution advisory, SA-CONTRIB-2026-218, under the same conditions, at least one known path needing no authentication, and 3.0.10 fixes it (Drupal Security Team, 2026-10-14); the flaw is CVE-2026-108099, and updating core does not update the module (The Hacker News, 2026-10-15).

    Exposure
    Drupal core on 10.6.x below 10.6.19, 11.3.x below 11.3.19 or 11.4.x below 11.4.10, or on an end-of-life branch from 8.9 to 11.2, with the Field UI module installed (the Standard install profile installs it) and a contributed module or custom code that exposes the vulnerable functionality, which the advisory does not name; Drupal Steward, a web application firewall service run by Acquia, Pantheon, Ironstar and Skpr, blocks some known vectors but not every one (The Hacker News, 2026-10-15).

    The advisory publishes no exploit artifact.     CRITICALCVE-2026-9082exploitedupdatedNATOA1

    CVE-2026-9082: anonymous SQL injection in Drupal core on PostgreSQL, Highly critical, exploited and CISA KEV-listed

    The Drupal Security Team pre-announced a Highly critical core release on 2026-05-18, scored 20 of 25 (AC:None, A:None, E:Theoretical, TD:Uncommon), and urged administrators to reserve the 2026-05-20 window from 17:00 to 21:00 UTC because "exploits might be developed within hours or days" (Drupal PSA-2026-05-18). SA-CORE-2026-004 followed on 2026-05-20 with CVE-2026-9082: a flaw in core's database abstraction API lets an anonymous attacker send specially crafted requests that result in arbitrary SQL injection on sites using PostgreSQL, which can lead to information disclosure and in some cases privilege escalation, remote code execution or other attacks (Drupal SA-CORE-2026-004). Searchlight Cyber traced it to the PostgreSQL entity-query override of the case-insensitive IN operator, which builds SQL placeholder names from the keys of the submitted value array, so attacker-chosen JSON object keys reach the SQL text through two anonymous entry points, the JSON login endpoint and the JSON:API filter syntax (Searchlight Cyber, 2026-05-21). The fixed releases are 11.3.10, 11.2.12, 11.1.10, 10.6.9, 10.5.10 and 10.4.10, and Drupal 9 and 8.9 sites are told to try applying a best-effort patch file by hand (Drupal SA-CORE-2026-004); Drupal 7 is not affected (Drupal PSA-2026-05-18). On 2026-05-22 Drupal raised the risk score to 23 of 25 because exploit attempts were being detected in the wild (Drupal SA-CORE-2026-004), and CISA added the flaw to its Known Exploited Vulnerabilities catalog the same day (CISA KEV catalog, 2026-05-22); the Drupal CNA scores it CVSS 9.8 (ENISA EUVD-2026-31153). By 2026-05-21 Imperva had observed over 15,000 attack attempts against almost 6,000 sites in 65 countries, most of it probing (Imperva, 2026-05-21).

    Exposure
    Drupal core sites on PostgreSQL running a version from 8.9.0 before 10.4.10, 10.5.0 before 10.5.10, 10.6.0 before 10.6.9, 11.0.0 before 11.1.10, 11.2.0 before 11.2.12 or 11.3.0 before 11.3.10 (Drupal SA-CORE-2026-004); on MySQL and SQLite the IN compilation never enters the vulnerable loop (Searchlight Cyber, 2026-05-21). The releases for the supported branches (11.3, 11.2, 10.6 and 10.5) also carry Symfony and Twig security updates, which Drupal highly recommends whether or not the SQL injection affects a site, since exposure to those upstream issues depends on site configuration and contributed modules (Drupal SA-CORE-2026-004).
    Detection
    Web access logs. The observed probes hit JSON:API routes, especially /jsonapi/node/article, with crafted filter parameters using the IN operator, crafted array keys, PostgreSQL pg_sleep timing checks and UNION-style probes, several of them carrying Nuclei-style markers, and Imperva also points to /user/login?_format=json requests (Imperva, 2026-05-21). A successful injection can make all non-public data accessible and let the attacker modify or delete any data (Drupal PSA-2026-05-18) and can escalate privileges (Drupal SA-CORE-2026-004), so patching does not close a past compromise: on a PostgreSQL site that ran an affected version after 2026-05-20, review user accounts and role assignments for changes nobody made.

    Triage: most of this traffic is automated probing that tests whether a site is vulnerable (Imperva, 2026-05-21); a probe against a MySQL or SQLite site, or one already on a fixed release, is noise, while the same request against an unpatched PostgreSQL site is an attempt that calls for the account review above (Drupal SA-CORE-2026-004).

    Defender takeaway
    Every Drupal core site on PostgreSQL that was not on a fixed release by 2026-05-22 is in scope for that review; sites behind the Drupal Steward web application firewall were protected from known attack vectors but Drupal still told them to upgrade (CSO Online, 2026-05-20), and sites on other databases take the release for its Symfony and Twig fixes (Drupal SA-CORE-2026-004).
