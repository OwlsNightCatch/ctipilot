    2026-10-31NOTABLELinux TCP use-after-free: Sophos hotfix and Ubuntu generic kernels out; WatchGuard, Fortinet have no fixed build

    Defender takeaway

    Install the distribution kernel and reboot as soon as it ships and confirm the running version afterwards; Ubuntu 20.04 and older and some variant kernels were not out on 2026-11-10. Until then, drop IPv4 TCP packets whose header carries IP options before the TCP stack sees them, tested first on one non-production host because it also drops legitimate option-bearing traffic; disabling MPTCP alone does not remove the path (CIQ, 2026-10-30).

    Exposure · detection
    Exposure

    A Linux host on a kernel below the fixed builds that accepts IPv4 TCP connections from an attacker; the demonstrated exploit needs an MPTCP listener, which sudo ss -M -l -n -p -e lists and which Go programs enable on Linux listen sockets by default since Go 1.24 unless the multipathtcp GODEBUG setting or a per-socket option overrides it (Akamai, 2026-11-02; Go team, 2026-10-29). CIQ's testing found that setting net.mptcp.enabled to 0 leaves the plain-TCP path reachable (CIQ, 2026-10-30), and Akamai reports a similar flaw when request-socket migration is on (Akamai, 2026-11-02).

    Detection

    No source publishes an indicator. Because the trigger is a SYN packet with IP options (CIQ, 2026-10-30) and a lost race only fails the handshake, so the attacker can retry (Anthropic, 2026-10-27), repeated option-bearing SYNs from one source toward a listener in firewall or flow telemetry are the pattern the mechanism implies.

    2026-11-04NOTABLEBitdefender: a 3AM affiliate joined a school estate's AD domains with new trusts after stealing Veeam credentials

    Defender takeaway

    Alert on any new domain trust and on additions to the domain-administrator groups, alert on credential-reading access to backup-software databases and on saves of the SECURITY, SYSTEM or SAM hives outside known backup or administration jobs, put an endpoint agent on every machine because the staging host here was unmanaged, and limit remote execution and administrative shares to known management hosts (Bitdefender, 2026-11-03).

    Exposure · detection
    Exposure

    A Windows estate that runs Veeam Backup & Replication and has several Active Directory domains or a flat network that an unmanaged internal host can reach; the unmanaged host is the gap, because it ran no agent and sat outside Bitdefender's visibility.

    Detection

    In directory-service change events, new trust relationships between domains, which Bitdefender calls a rare change that is cheap to alert on, and new domain-administrator group members; in backup-server logs, Veeam web-interface calls and credential-store reads from hosts that are not backup administrators'; in endpoint telemetry, saves of the SECURITY, SYSTEM or SAM registry hives by any process that is not a known backup or administration job, LSASS access, a Windows Defender exclusion for the temporary directory, and the same command re-issued with small edits at a steady cadence; across hosts, file contents staged into registry values, which Bitdefender calls an unusual channel and a strong indicator to hunt for, and sent out by HTTP POST to an internal host, and probe or confirmation artifacts such as a scheduled task named for the probe left on production hosts; in authentication logs, unmanaged hosts authenticating to domain controllers (Bitdefender, 2026-11-03).

    Exposure

    Veeam publishes no indicator. For Veeam ONE, an MFA setting switched off followed by an Administrator sign-in is the sequence the flaw describes.

    NOTABLECVE-2026-98432updatedNATOB2

    CVE-2026-98432, Linux kernel IPv4 TCP: a use-after-free in connection setup, present since 4.4, has an Anthropic-built remote root exploit against MPTCP listeners that CloudLinux could not reproduce; Citrix XenServer, XCP-ng, MikroTik, Red Hat, Debian, CIQ, Amazon Linux, Ubuntu's generic kernels for 22.04 to 26.10 and Sophos have fixes, Ubuntu 20.04 and older and some HWE, FIPS, NVIDIA and Azure variant kernels are in progress and WatchGuard and Fortinet have none for their products (CVSS 9.8)

    The Linux kernel CVE team published CVE-2026-98432 on 2026-10-15; the kernel.org CNA scores it 9.8 while upstream rates it 8.1 with high attack complexity (CIQ, 2026-10-30). It is a use-after-free in the IPv4 TCP connection setup path, introduced in Linux 4.4 and fixed upstream in 6.12.113, 6.18.56, 7.2.10 and 7.3-rc7 (Linux kernel CVE team, 2026-10-15). An unauthenticated peer starts it by sending TCP SYN packets that carry IPv4 options, and a retransmitted SYN can then touch the freed option memory (CIQ, 2026-10-30).

    Anthropic wrote on 2026-10-27 that Claude produced an exploit that gives a remote attacker root on a Linux server with a multipath TCP (MPTCP) listener (Anthropic, 2026-10-27), but CloudLinux's kernel team could not reproduce the claim (CloudLinux, 2026-11-02). Akamai is not aware of a public working exploit and says disabling MPTCP alone does not prevent exploitation (Akamai, 2026-11-02), whereas Vates, XCP-ng and WatchGuard say a public exploit exists or circulates (XCP-ng, 2026-11-04; Vates, 2026-11-04; WatchGuard, 2026-11-03). No source reports attacks, and NCSC-NL judges large-scale abuse unlikely given the exploit's complexity (NCSC-NL, 2026-10-30).

    Debian, Red Hat, CIQ and AWS have fixed kernels (Debian Security Tracker, 2026-11-03; Red Hat, 2026-11-03; CIQ, 2026-11-01; AWS, 2026-11-02), and Ubuntu's tracker, last updated 2026-11-10, lists 22.04 LTS to 26.10 as fixed (linux 5.15.0-203.213, 6.8.0-149.149, 7.0.0-43.43 and 7.3.0-10.10) while 20.04, 18.04 and 16.04 are still in progress (Canonical, 2026-11-10). Citrix has fixed its XenServer appliances (Citrix, 2026-11-03). XCP-ng released a kernel fix (XCP-ng, 2026-11-04), MikroTik's RouterOS 7.25.1 and 7.24.6 changelogs list the CVE (MikroTik, 2026-11-02; MikroTik, 2026-10-30), Sophos released Sophos Firewall hotfix HF110626.1 on 2026-11-06 and SD-RED firmware 3.0.012 on 2026-11-05 (Sophos, 2026-11-06), and Veeam's KB4966 says its Software and Infrastructure Appliances, workers, helper appliances and recovery media include an affected kernel, delivered fixed through Veeam Updater (Veeam, 2026-11-10). WatchGuard lists Fireware OS, AP and Dimension as potentially affected with no fix (WatchGuard, 2026-11-03); Fortinet names no fixed build but added an IPS virtual patch in FMWP database update 26.113 on 2026-11-07 (Fortinet, 2026-11-07).

    Exposure
    A Linux host on a kernel below the fixed builds that accepts IPv4 TCP connections from an attacker; the demonstrated exploit needs an MPTCP listener, which sudo ss -M -l -n -p -e lists and which Go programs enable on Linux listen sockets by default since Go 1.24 unless the multipathtcp GODEBUG setting or a per-socket option overrides it (Akamai, 2026-11-02; Go team, 2026-10-29). CIQ's testing found that setting net.mptcp.enabled to 0 leaves the plain-TCP path reachable (CIQ, 2026-10-30), and Akamai reports a similar flaw when request-socket migration is on (Akamai, 2026-11-02).
    Detection
    No source publishes an indicator. Because the trigger is a SYN packet with IP options (CIQ, 2026-10-30) and a lost race only fails the handshake, so the attacker can retry (Anthropic, 2026-10-27), repeated option-bearing SYNs from one source toward a listener in firewall or flow telemetry are the pattern the mechanism implies.
    Defender takeaway
    Install the distribution kernel and reboot as soon as it ships and confirm the running version afterwards; Ubuntu 20.04 and older and some variant kernels were not out on 2026-11-10. Until then, drop IPv4 TCP packets whose header carries IP options before the TCP stack sees them, tested first on one non-production host because it also drops legitimate option-bearing traffic; disabling MPTCP alone does not remove the path (CIQ, 2026-10-30).

    NOTABLENATOB2

    3AM ransomware affiliate in a UK school estate: Bitdefender documents backup-credential theft, rogue domain admins and new two-way trusts between Active Directory domains, with a command-retry pattern it reads as a model-driven loop

    Bitdefender MDR attributes the intrusion to a 3AM (ThreeAM) ransomware affiliate on the encryptor build and its command-line pattern; the target was a school estate in the UK whose domains began as separate Active Directory environments, and initial access is unknown (Bitdefender, 2026-11-03). In September 2026 the attacker first took credentials from the backup software: a modified copy of a public script read the credentials stored in Veeam's databases on three backup servers and decrypted them with the Windows Data Protection API, and a browser credential database was copied from a terminal server (Bitdefender, 2026-11-03). It then worked with built-in tools (PowerShell, WMI, reg, netsh, rundll32) and a few public ones (an Impacket-like remote-execution tool that returns output over administrative shares, Mimikatz renamed to look like a monitoring binary), enumerated domain trusts from a domain controller, searched SYSVOL logon scripts for the names and subnets of other schools, created two backdoor domain-administrator accounts, joined three separate domains with two-way trusts within about three hours, tried to remove EDR agents, which anti-tampering controls blocked, deleted system-state backups and encrypted machines with a Rust-based encryptor (Bitdefender, 2026-11-03).

    Bitdefender's reading, which it calls interpretation and not a finding, is that a model drove part of the work: commands call the Veeam web interface on a port and with a login method that do not match the vendor documentation, output is self-labelled, scripts carry numbered revisions, and retries arrive 40 to 101 seconds apart whatever the size of the change, while a new task takes minutes. Every attacker action Bitdefender saw came from an unmanaged internal host with no agent, so the automation itself was never seen, and Bitdefender says it could not document anything about a language model (Bitdefender, 2026-11-03).

    Exposure
    A Windows estate that runs Veeam Backup & Replication and has several Active Directory domains or a flat network that an unmanaged internal host can reach; the unmanaged host is the gap, because it ran no agent and sat outside Bitdefender's visibility.

    NOTABLECVE-2026-108142 +5NATOA2

    CVE-2026-108142, Veeam Backup & Replication: an unauthenticated authorization bypass on the CDP Coordinator Service of 13.x backup servers (CVSS 4.0 9.1), fixed in 13.1.2 and 13.0.3, with a Backup for Microsoft 365 SQL injection to code execution and a Veeam ONE MFA bypass fixed the same day

    Veeam published three advisories on 2026-10-27. In Backup & Replication, CVE-2026-108142 (CVSS 4.0 9.1, critical) lets an unauthenticated attacker bypass authorization on the CDP Coordinator Service of Windows-based Backup & Replication and of the Veeam Software Appliance; it affects 13.1.1.18 and all earlier 13.1 builds and 13.0.2.29 and all earlier 13.0 builds, is fixed in 13.1.2 (build 13.1.2.57) and 13.0.3 (build 13.0.3.63), and does not affect 12.x (Veeam KB4948, 2026-10-27). The same advisory fixes two medium path-traversal flaws that need the Restore Operator role plus control over the contents of a backed-up NAS share and that write attacker-controlled files to an arbitrary path on the backup server, and a local privilege escalation in Veeam Agent for Linux version 13.1.1.4 and earlier that applies only to agents managed by a Backup & Replication server (Veeam KB4948, 2026-10-27). Veeam Backup for Microsoft 365 8.5.0.1014 and earlier carry CVE-2026-106076 (9.0, critical): an authenticated organization-transfer peer injects SQL into the source server's configuration database, which gives cross-tenant read and write of configuration data and remote code execution as the PostgreSQL service account; the fix is 8.6 (build 8.6.0.1102), as it is for CVE-2026-106077 (8.3), which lets a user with the Backup for Microsoft 365 Administrator role read arbitrary files on the backup server as LocalSystem; two further flaws, an unauthenticated REST API authentication bypass with a forged federation token (6.9) and an installer file-write (4.3), need 8.6 Patch 1 (build 8.6.0.5011) (Veeam KB4957, 2026-10-27). Veeam ONE 13.1.0.7233 and earlier let an attacker with valid Administrator credentials disable multi-factor authentication globally before completing MFA verification (8.5, high; fixed in 13.1 P1, build 13.1.0.7940) (Veeam KB4951, 2026-10-27).

    NCSC Switzerland relayed the Backup & Replication and Veeam ONE advisories on 2026-10-28, lists the exploitation status as unknown with the vendor reporting no evidence of active exploitation, and gives the prerequisite for the critical flaw as network access to the backup server's CDP Coordinator Service (NCSC Switzerland, 2026-10-28). heise adds that backup servers are a favourite target of ransomware groups (translated from German) (heise online, 2026-10-28), and Veeam itself says attackers will likely try to reverse-engineer a disclosed patch to exploit unpatched deployments (Veeam KB4948, 2026-10-27).

    Exposure
    A Veeam Backup & Replication or Veeam Software Appliance on a 13.x build below 13.1.2 or 13.0.3 whose CDP Coordinator Service accepts connections from a network the attacker can reach; 12.x is out of scope (Veeam KB4948, 2026-10-27). Veeam Backup for Microsoft 365 version 8 below 8.6 Patch 1 (Veeam KB4957, 2026-10-27) and Veeam ONE 13.1 below Patch 1 (Veeam KB4951, 2026-10-27) are the other affected builds.
    Detection
    Veeam publishes no indicator. The telemetry that bears on this flaw is authentication and authorization events and service-account activity on the backup server, and new or changed backup jobs, repositories, stored credentials and restore operators; this is an inference from the described flaw, not a Veeam statement. For Veeam ONE, an MFA setting switched off followed by an Administrator sign-in is the sequence the flaw describes.
    Defender takeaway
    Install the fixed builds on every backup server first, since backup infrastructure is what ransomware groups try to reach before encrypting, and keep backup servers off networks that untrusted hosts can reach; where a backup server was reachable and unpatched, review its jobs, repositories and credentials for changes nobody made.
