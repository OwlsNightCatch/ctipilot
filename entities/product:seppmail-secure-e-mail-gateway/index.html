    Triage

    An unauthenticated password reset on a GINA account that is not yet registered is legitimate, since the fix keeps it for unregistered accounts only; the same request taking effect on an already registered account without the security-question step is the abuse (SEPPmail, 2026-11-24).

    Detection

    NOTABLECVE-2026-130637 +10NATOA2

    SEPPmail Secure E-Mail Gateway before 15.1.2: an unauthenticated template injection on the GINA login page can read and take over any GINA account (CVE-2026-130637, vendor score 9.3) and ten more flaws are fixed in the 2026-11-24 patch release; no exploitation or workaround stated

    SEPPmail's revision history lists patch release 15.1.2 of 2026-11-24 with eleven security fixes, each marked as affecting versions before 15.1.2 (SEPPmail, 2026-11-24). The worst is CVE-2026-130637 (vendor score 9.3): request values reflected on the GINA login page were processed by the template engine, which could let an unauthenticated attacker read attributes of any GINA account and take it over, and the fix stops expanding request values as template placeholders. Two further rows score 9.2: CVE-2026-124840, where a session created by answering the security question was also accepted by the registration and settings workflows, so an attacker who knows the security answer could replace the password, and CVE-2026-124843, where a hard-coded fallback secret was used if the appliance's key material could not be loaded, which could let encrypted Large File Transfer attachments be decrypted outside the appliance (SEPPmail, 2026-11-24).

    The remaining rows are CVE-2026-124844 (8.7), unauthenticated GINA uploads that were never removed and could fill the disk; CVE-2026-124838 (8.5), a configuration-service socket open to every local user; CVE-2026-124842 (8.3), an unauthenticated GINA request that reset the password of a registered account without the security question; CVE-2026-124839 (7.7), a crafted GINA account address that reached a shell command in a maintenance script at start, with elevated privileges; and four rows at 6.9 to 6.3 covering unescaped LDAP filter values (CVE-2026-124841, CVE-2026-124836), a crafted DKIM signature that injects forged Authentication-Results later covered by the gateway's ARC seal (CVE-2026-124837) and a GINA domain lookup that falls back to the default domain settings (CVE-2026-124845) (SEPPmail, 2026-11-24). The page names no exploitation and no workaround, and does not say whether the 15.0 branch, whose last release is 15.0.7, is affected.

    Exposure
    A SEPPmail Secure E-Mail Gateway before 15.1.2 whose GINA web interface is reachable from outside; the revision history says release 15.1.0 added support for restricting the file types that external communication partners can upload through GINA, which shows external recipients use it (SEPPmail, 2026-11-24). The page does not state the CVSS vector of any score.
    Detection
    In GINA web access logs, login-page requests whose parameters carry template placeholder syntax, unauthenticated password-reset requests for accounts that are already registered, calls to the registration and settings workflows that follow a security-question recovery, and bursts of unauthenticated uploads; in the gateway's audit log, GINA password changes without the usual recovery sequence. The fixes do not undo an account already taken over, so review GINA password-change and sign-in history for the period before the update. These checks follow from the mechanisms the vendor names; the page publishes no indicator.

    Triage: an unauthenticated password reset on a GINA account that is not yet registered is legitimate, since the fix keeps it for unregistered accounts only; the same request taking effect on an already registered account without the security-question step is the abuse (SEPPmail, 2026-11-24).

    NOTABLECVE-2026-114424 +4NATOA2

    CVE-2026-114424 and CVE-2026-114425, SEPPmail Secure Email Gateway before 15.1.1: an unauthenticated mail sender can reach root command execution through a replacement rule and root file access through Large File Transfer, with three more flaws fixed in the same release and no fix for the 15.0 branch (CVSS 4.0 9.2)

    SEPPmail's revision history lists patch release 15.1.1 of 2026-11-03 with five security fixes in the Secure Email Gateway, all for versions before 15.1.1 (SEPPmail, 2026-11-03). Two are unauthenticated and rated 9.2: in CVE-2026-114424 attacker-influenced replacement text in sender or recipient address-replacement rules is evaluated as Perl code, so a remote sender can run operating-system commands in the mail-processing worker when an active rule uses message-derived replacement data and its search condition matches, and the validated worker context was root (ENISA EUVD, 2026-11-04); in CVE-2026-114425 a file path supplied in the attachment metadata of an incoming message lets the worker disclose, move or delete an accessible file when Large File Transfer is enabled, also as root (ENISA EUVD, 2026-11-04). CVE-2026-114426 lets an unauthenticated attacker exhaust workers and disk because the upload interface processed data before checking authentication (ENISA EUVD, 2026-11-04), and two flaws in the GINA webmail let an unauthenticated attacker take over a created but unregistered account with an empty initial password (CVE-2026-114421) and enumerate email addresses through an unescaped LDAP filter (CVE-2026-114420) (ENISA EUVD, 2026-11-04; ENISA EUVD, 2026-11-04). The vendor says 15.0.7 of 2026-09-02 is the last release of the 15.0 branch, so the fix for a 15.0.x gateway is the move to 15.1 (SEPPmail, 2026-11-03). None of the sources read reports exploitation.

    HIGHCVE-2026-44128 +6updatedNATOA2

    SEPPmail Secure E-Mail Gateway: unauthenticated code execution and five more flaws in NCSC-CH's advisory (CVE-2026-44128 et al., CVSS up to 9.3), fixed by 15.0.4

    NCSC-CH's Security Hub post 12551 of 2026-05-08 lists six CVEs in the SEPPmail Secure E-Mail Gateway, scored from 6.9 to 9.3, with exploitation status unknown and vendor patches available since 2026-04-24 (NCSC-CH, 2026-05-08). SEPPmail's 15.0.4 release notes say test endpoints intended only for development had been left active in the beta GINA v2 web interface and are now removed (SEPPmail release notes). CVE-2026-44128 (9.3) is unauthenticated remote code execution through a parameter passed to Perl eval() and was already fixed in 15.0.2.1 (NCSC-CH, 2026-05-08) (InfoGuard Labs, 2026-05-18); CVE-2026-44126 (9.2), an insecure deserialization, was fixed in 15.0.3 (InfoGuard Labs, 2026-05-18), while NCSC-CH's advisory says the vulnerabilities were fixed in 15.0.4 (NCSC-CH, 2026-05-08); CVE-2026-44125 (9.3, missing authorization on GINA v2 endpoints), CVE-2026-44127 (8.8, file inclusion and arbitrary file deletion), CVE-2026-44129 (8.3, server-side template injection) and CVE-2026-7864 (6.9, exposure of sensitive information) were fixed in 15.0.4 (InfoGuard Labs, 2026-05-18); the scores are NCSC-CH's (NCSC-CH, 2026-05-08). The appliance is OpenBSD-based with Perl web applications, and self-registration, enabled by default, gives an attacker an authenticated session (InfoGuard Labs, 2026-05-18).

    Exposure
    SEPPmail appliances on a release older than 15.0.4 with the GINA v2 interface exposed; GINA v2 has to be explicitly activated in the system settings, which is how to tell whether its flaws apply (InfoGuard Labs, 2026-05-18). InfoGuard describes SEPPmail as widely used in the DACH region and counts several thousand public instances on Censys (InfoGuard Labs, 2026-05-18).
    Detection
    Internet requests to /v1/file.app, whose JSON body carries the path traversal in its file field (visible where a WAF or reverse proxy logs request bodies), and on the appliance a changed /etc/syslog.conf or an unexpected process started by syslogd after the 15-minute log-rotation reload, the chain InfoGuard uses for CVE-2026-2743 (InfoGuard Labs, 2026-05-18); an appliance that ran an affected build exposed to the internet needs that check after patching.
    Defender takeaway
    The GINA interface is internet-facing by design, so every appliance should run the current 15.0.x release, and an appliance that ran an affected build with GINA v2 exposed warrants a compromise check rather than a patch alone.
    Update20 May 2026 05:00 UTCrun 2026-05-20-a0f7b07factionscvesregionssectorssourcestagsbody

    InfoGuard Labs, which found CVE-2026-2743 and the GINA v2 flaws, published its technical write-up on 2026-05-18 (InfoGuard Labs, 2026-05-18). CVE-2026-2743 (CVSS 10.0 (The Hacker News, 2026-05-19)) is a pre-authentication path traversal in the Large File Transfer (LFT) component's /v1/file.app endpoint that writes files as the nobody user; because nobody can write /etc/syslog.conf, and newsyslog runs every 15 minutes and makes syslogd reload its configuration, the write becomes command execution (InfoGuard Labs, 2026-05-18). Only instances with LFT, which InfoGuard says most customers enable, are affected; /v1/file.app returning HTTP 404 means not affected (InfoGuard Labs, 2026-05-18). CVE-2026-2743 is not new: SEPPmail's 15.0.3 release notes already close it (SEPPmail release notes). The Hacker News reported the write-up (The Hacker News, 2026-05-19).

    Contradiction: SEPPmail's release notes place the CVE-2026-2743 fix in 15.0.3 (SEPPmail release notes), while InfoGuard's table lists 15.0.4 (InfoGuard Labs, 2026-05-18); 15.0.4 or later covers both readings. InfoGuard also places the CVE-2026-44126 fix in 15.0.3 (InfoGuard Labs, 2026-05-18), while NCSC-CH's advisory says the vulnerabilities were fixed in 15.0.4 (NCSC-CH, 2026-05-08), so 15.0.4 is the safe floor for that flaw too.
