    2026-08-07NOTABLEMicrosoft documents the cloaking layer in front of a ClickFix campaign, researchers and scanners get a decoy, qualified Macs get the payload

    Defender takeaway

    Treat a clean verdict on one of these URLs as no evidence at all, and move detection to the endpoint, where the gate has no vote. The user still has to paste a command into a terminal, and that action is what leaves a durable trace. Detection concepts, telemetry class first: in process-creation telemetry with parent lineage, a terminal process spawning a network-fetch utility that pipes its output into an interpreter, shortly after browser activity, is the sequence to alert on regardless of which domain served it; in egress and proxy telemetry, a fetch from a very recently registered host immediately following a user-initiated browser session is the corroborating signal Microsoft points to. There is also one network-side pivot that survives the cloaking, and it is a generation rule rather than a blocklist: Microsoft's own guidance is to "hunt the generation pattern" and, "where feasible, alert the file<word><word> domain pattern rather than maintaining a list of individual domains" (Microsoft Threat Intelligence, 2026-08-05), which is durable in a way that the individual hostnames, rotated constantly, are not. Hardening has to target the paste, not the download, because the download protections never engage: Microsoft's point is that "because execution starts from a user-run Terminal command rather than a downloaded app bundle, the flow can avoid parts of the normal macOS application trust path, including quarantine handling, code-signing evaluation, and notarization checks typically applied to downloaded applications" (Microsoft Threat Intelligence, 2026-08-05). The platform lever that does apply is recent: "on macOS 26.4 and later, Apple introduced a mitigation that displays a warning when a user attempts to paste a potentially malicious command into Terminal, directly addressing the ClickFix delivery mechanism" (Microsoft Threat Intelligence, 2026-08-05), so estate-wide upgrade to 26.4 or later is the one control that breaks this pattern at the delivery step.

    Triage
    Triage

    Developers legitimately fetch install scripts with curl and pipe them to a shell, so the command shape alone is not the signal; the discriminators are the age and reputation of the host being fetched, the absence of the long-lived vendor domain a real install script would use, and the preceding browser navigation that supplied the command; a paste-and-run whose source was a page the user reached from an advertisement or search result, rather than a repository README they were already working in.

    2026-08-07NOTABLEmacOS malware picks up .NET: one downloader codebase now targets Mac and Windows, and the Go payload is Garble-obfuscated to break static analysis

    Defender takeaway

    Two of this chain's properties defeat controls that usually work, and both are checkable. The .NET-in-Mach-O structure means a macOS binary that embeds dozens of PE files is itself anomalous, a legitimate self-contained .NET macOS application looks structurally similar, so the discriminating detail Jamf supplies is that the bundled DLL's only plaintext strings imitate a different vendor's product metadata. And Garble means that recovering the payload's logic will not come cheap: teams that rely on Go symbol recovery should expect that workflow to fail on this family and plan for behavioural analysis in a detonation environment instead. Detection concepts, telemetry class first: in process-creation telemetry with parent lineage, the sequence to alert on is an installer-named process writing an executable into a temporary directory and launching it detached, which is not something a real Zoom installation does; in egress telemetry, an outbound WebSocket to a non-standard port from a freshly installed conferencing application is the hunt trigger; endpoint policy that blocks execution from temporary directories removes the staging step outright.

    Triage
    Triage

    A working Zoom install is not evidence of benignity here, because the downloader fetches and installs the genuine client alongside its payload, so "the application the user expected is present and functional" must be treated as consistent with compromise rather than as a clear. Legitimate conferencing clients also connect out over TLS immediately after installation, so egress alone is not the signal either. The discriminators are the temporary-directory staging and the detached second process, the non-standard destination port, and the destination host's age and resemblance to the vendor's real domain; the staging step is the least ambiguous, since a genuine installer places its binaries in an application directory rather than running one from a scratch path.

    NOTABLECVE-2026-91403 +3updatedNATOA1

    eMudhra: the private keys of eight ECDSA intermediate CA certificates were trivially recoverable, so anyone could forge trusted HTTPS certificates, and eight RSA intermediates were revoked on 2026-11-07 for key handling eMudhra cannot show compliant; browsers block them, clients with their own trust store or no revocation checking need an update (CVE-2026-111943 in Go)

    On 2026-10-17 a researcher reported to the Chrome Root Program, and Mozilla received a report the same day, that the private keys of eight eMudhra subordinate CA certificates were compromised: the keys were so weak that anyone could forge trusted HTTPS certificates to impersonate any website against clients that have not removed trust in those CAs; Google describes the cause as insufficient randomness (Google, 2026-10-20; Mozilla, 2026-10-20). BleepingComputer, citing Mozilla's incident report, says all eight were P-384 keys generated in April 2025 with values below 256, so testing 256 numbers recovers a key (BleepingComputer, 2026-10-20). eMudhra's incident report of 2026-11-10 says the keys were generated correctly on its hardware module at a ceremony on 2025-04-30 and then passed through a custom Python wrap/unwrap script that truncated the eight ECDSA private values; the keys of eight RSA-4096 issuers (G2B and G2C) stayed intact but were handled in that script's process memory, so eMudhra cannot show compliance with its certification practice statement, and it revoked them on 2026-11-07 with the reason cessationOfOperation after having said on 2026-10-19 that they were not impacted; its G2C issuers had issued end-entity certificates, the last on 2026-11-03, and no source says any RSA key leaked (eMudhra, Mozilla bug 2083449, 2026-11-10; eMudhra, Mozilla bug 2083449, 2026-10-19; BleepingComputer, 2026-11-11). The tracker says it is not known whether attackers used the flaw against other clients (Dennis Jackson, 2026-10-20).

    Chrome blocked the intermediates on 2026-10-17, Firefox through OneCRL the same day, Microsoft platforms on 2026-10-20 and Apple products on 2026-10-22, and eMudhra revoked all eight (Dennis Jackson, 2026-10-20; BleepingComputer, 2026-10-20). Microsoft went further: an out-of-band Windows update of 2026-10-26 removes seven certificates, six eMudhra G3 roots and an AAA Certificate Services cross-sign, from the Windows trust list, and the same seven left the Edge trust list on 2026-10-27 (Microsoft, 2026-10-26). Google removed the root that signed them, emSign ECC Root CA - G3, from the Chrome Root Store, with the removal expected to reach devices on 2026-10-27 (Google, 2026-10-20). Go 1.27.3 and 1.26.10 filter chains that contain the intermediates in crypto/x509, tracked as CVE-2026-111943 (Go team, 2026-10-20), and GitLab's release of 2026-10-29 removes trust for the eight intermediates in self-managed CE and EE, with Runner 19.5.1 and the AI Gateway updated separately (GitLab, 2026-10-29).

    Oracle's Security Alert of 2026-10-21 for CVE-2026-91403 (CVSS 3.1 9.1, JSSE) provided Java updates that distrust the impacted eMudhra intermediate CA certificates (Oracle, 2026-10-21), and a second Security Alert of 2026-10-24, CVE-2026-114820, removes the impacted root CA certificates and also covers the Java component of Oracle Database Server, Autonomous Health Framework and OPatch (Oracle, 2026-10-30). OpenJDK's guidance tells users of a standalone runtime to act immediately even if they updated in the past few days (OpenJDK, 2026-10-24).

    Exposure
    Any software that keeps its own CA bundle or does not check revocation keeps trusting the intermediates until updated; Python 3.15.2, 3.14.10, 3.13.18, 3.12.16 and 3.11.18 carry a built-in denylist (Python Insider, 2026-10-26); Apple says the curl, git, python3, ruby, perl and openssl that ship with macOS or the Xcode command-line tools read /etc/ssl/cert.pem, check neither Apple's block nor revocation and keep trusting them until macOS 27.2.1, 26.7.3 or 15.8.3 (Apple, 2026-11-10). SonicOS firewalls with Client DPI-SSL enabled re-signed the chains with their own DPI-SSL CA, so client browsers could not reject a forged one, until SonicOS 7.3.4-7015 (Gen7) and 8.2.3-8015 (Gen8) (SonicWall, 2026-11-10; SonicWall advisory data, 2026-11-10).
    Detection
    EMudhra says it found no evidence that the intermediates were used to issue end-user certificates (BleepingComputer, 2026-10-20), so a server certificate chain seen in TLS session metadata, proxy or EDR network telemetry that contains one of the eight intermediates or their Sectigo cross-signs, which the tracker lists, is worth treating as a possible forged certificate (Dennis Jackson, 2026-10-20). CT monitoring will not show one, because Google found no certificate chaining to the six TLS intermediates logged before it blocked them (Google, 2026-10-20).

    Triage: a site that still chains to emSign ECC Root CA - G3 failing in Chrome after 2026-10-27, or a certificate that chains to one of the seven certificates Microsoft removed failing in Windows or Edge once the change reaches the device, is the announced root removal, not an attack (Google, 2026-10-20; Microsoft, 2026-10-26).

    Defender takeaway
    Update trust bundles and toolchains on every non-browser client, rebuild container images that embed an old bundle, and do not rely on revocation or CT for those clients; website operators with certificates chaining to emSign ECC Root CA - G3 need one from another hierarchy now (Google, 2026-10-20), and so does anything issued under emSign Root CA - G1 after 2026-11-16, because Chrome 153 and higher will not trust such a certificate by default when its earliest SCT is later (Google, 2026-11-04). Certificates from the eight revoked RSA G2B and G2C issuers are revoked and eMudhra says its subscribers were migrated, so check inventories for any holder still on them.

    CVE-2026-86950, Apple iOS, iPadOS and macOS CoreGraphics: out-of-bounds write exploited in an extremely sophisticated attack on targeted iOS users, CISA KEV-listed (CVSS 8.8)

    CVE-2026-86950 is an out-of-bounds write in CoreGraphics, the graphics component shared by iOS, iPadOS and macOS, and processing a maliciously crafted file can lead to arbitrary code execution (Apple, 2026-09-28). Apple states that it "is aware of a report that this issue may have been exploited in an extremely sophisticated attack against specific targeted individuals on versions of iOS before iOS 27" (Apple, 2026-09-28). The fix, "improved bounds checking", ships in iOS and iPadOS 26.7.1 (Apple, 2026-09-28), in iOS and iPadOS 18.7.11 for iPhone XS, XS Max, XR and iPad 7th generation (Apple, 2026-10-26), macOS Tahoe 26.7.1 (Apple, 2026-09-28) and macOS Sequoia 15.8.1 (Apple, 2026-09-28); Meta Product Security is credited with the report. CISA added the flaw to its Known Exploited Vulnerabilities catalog on 2026-09-29 (CISA, 2026-09-29). ENISA's vulnerability database scores it CVSS 3.1 8.8, network vector with user interaction required (ENISA EUVD, 2026-09-29). The macOS advisories repeat Apple's iOS-scoped exploitation sentence, so Apple does not claim exploitation on macOS.

    Nothing about the attack itself is public: Apple gave no details on how many people were targeted, whether any attempt succeeded, or when exploitation began (The Hacker News, 2026-09-29), and no delivery mechanism is stated. SecurityWeek reads the component's role in 2D graphics and PDF rendering as meaning a file could arrive through web pages, email attachments or messaging apps, where automatic previews could allow zero-click exploitation; that is SecurityWeek's inference, and it also notes Meta would not say whether WhatsApp was involved (SecurityWeek, 2026-09-29). It also says iOS 27 and macOS Golden Gate 27 do not appear to be affected. No indicators or behavioural detections have been published by Apple, Meta or CISA, so version compliance is the only measurable lever: device-management inventory of iPhones and iPads below iOS or iPadOS 26.7.1 (below 18.7.11 on iPhone XS, XS Max, XR and iPad 7th generation), and of Macs on Tahoe or Sequoia below the fixed builds.

    Defender takeaway
    Apple describes an attack on specific targeted individuals, so the staff an adversary would single out are the first whose devices need the update. A device that ran a vulnerable build is not evidence of compromise, and no published signature exists to check for one.
