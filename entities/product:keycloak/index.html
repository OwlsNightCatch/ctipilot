    2026-11-08NOTABLEKeycloak 26.8.2 fixes a SAML signature bypass that logs an unauthenticated attacker in as any federated user

    Defender takeaway

    Move every Keycloak that brokers SAML to 26.8.2, or the Red Hat build to 26.6.9, outside the regular cycle, because the bypass needs no privileges or user interaction and Red Hat's formal statement names no mitigation that meets its criteria; until then, restrict account registration on the external identity providers, as Red Hat's courtesy guidance suggests; after updating, review federated logins of privileged accounts for logins the upstream identity provider never saw.

    Exposure · detection
    Exposure

    A Keycloak without the 26.8.2 fix (the release notes state no affected range), or a Red Hat build of Keycloak 26.6 without the 2026-11-07 errata, that uses the SAML HTTP-Redirect binding, which the release notes tie to broker login; the SAML 1.1 parser flaws need no authentication either (Keycloak, 2026-11-05; Red Hat, 2026-11-05).

    Detection

    In Keycloak event logs and reverse-proxy access logs, SAML messages received by HTTP GET whose query string carries an encoded parameter name such as %53AMLResponse, with or without a literal SAMLResponse beside it, and federated logins of privileged accounts with no matching authentication at the upstream identity provider (both inferences from the mechanism Red Hat describes).

Where systemd-coredump is enabled, forced crashes write core files that can hold other visitors' session cookies and key material, so restrict who can read them (ELLIO, 2026-10-26).

    NOTABLECVE-2026-117691 +1NATOA2

    CVE-2026-117691, Keycloak SAML HTTP-Redirect signature bypass: a percent-encoded parameter name lets an unauthenticated attacker log in as any federated user; fixed in Keycloak 26.8.2

    Keycloak 26.8.2, released on 2026-11-05, fixes CVE-2026-117691, a SAML redirect binding signature bypass via a percent-encoded parameter name (%53AMLResponse) that its release notes describe as broker login as any user (Keycloak, 2026-11-05). Red Hat, the CNA, explains that Keycloak's SAML HTTP-Redirect binding processes percent-encoded parameter names while the signature verification logic checks only literal ones, so an attacker can supply a crafted, unsigned SAML message that the server processes instead of a legitimately signed one; it scores the flaw CVSS 3.1 9.1 with no privileges or user interaction, rates it Important because it allows full account takeover of federated users, and says no available mitigation meets its criteria; it lists its build of Keycloak 26.6.9 packages as fixed by RHSA-2026:96040 and the 26.6 container images by RHSA-2026:96039, both released on 2026-11-07, and Red Hat Single Sign-On 7 as not affected (Red Hat, 2026-11-05). Its courtesy guidance describes the attack as a crafted request that places an encoded unsigned SAML parameter before a legitimately signed one, and suggests auditing and restricting account registration on external identity providers so attackers cannot capture legitimately signed redirect-binding messages (Red Hat, 2026-11-05).

    The release fixes further issues tagged with CVE identifiers, among them an unauthenticated single-request JVM termination through a SAML 1.1 AuthorityBinding parser loop, labelled an incomplete fix of an earlier flaw (CVE-2026-110931), unauthenticated CPU and worker-pool exhaustion through the SAML 1.1 KeyInfo parser that needs a restart (CVE-2026-107602), unverified identity-provider email auto-linking that enables account takeover (CVE-2026-97175), an account takeover through an authentication race (CVE-2026-103112) and a SAML broker that accepts holder-of-key assertions without proof of key possession (CVE-2026-92855) (Keycloak, 2026-11-05). The release also fixes CVE-2026-111497, the out-of-bounds write in its bundled Brotli decoder (Keycloak, 2026-11-05), which CISA lists as exploited (CISA, 2026-10-27). No source reports exploitation of the SAML flaws or a public proof of concept; CISA's listing concerns the Brotli decoder.

    Exposure
    A Keycloak without the 26.8.2 fix (the release notes state no affected range), or a Red Hat build of Keycloak 26.6 without the 2026-11-07 errata, that uses the SAML HTTP-Redirect binding, which the release notes tie to broker login; the SAML 1.1 parser flaws need no authentication either (Keycloak, 2026-11-05; Red Hat, 2026-11-05).
    Detection
    In Keycloak event logs and reverse-proxy access logs, SAML messages received by HTTP GET whose query string carries an encoded parameter name such as %53AMLResponse, with or without a literal SAMLResponse beside it, and federated logins of privileged accounts with no matching authentication at the upstream identity provider (both inferences from the mechanism Red Hat describes).
    Defender takeaway

    HIGHCVE-2026-111497exploitedupdatedNATOA1

    CVE-2026-111497, Node.js and Google Brotli (Node2Shell): an out-of-bounds write in the Brotli decoder lets crafted compressed data run code, reached through fetch() and Express 5 or body-parser 2 request bodies; fixed in Node.js 22.23.4, 24.22.1 and 26.12.1 and in the PyPI packages Brotli 1.2.1 and brotlicffi 1.2.1.0 (CVSS 4.0 9.2)

    Node.js shipped security releases on 2026-10-21 for CVE-2026-111497, an out-of-bounds write in the Brotli decoder it bundles: an invalid block switch was reported as a need for more input instead of a format error, so the streaming decoder kept appending input to an eight-byte internal buffer (Node.js project, 2026-10-21). An attacker who can supply Brotli data that an application decompresses with node:zlib can corrupt process memory, which can lead to a crash, disclosure of process memory or remote code execution (Node.js project, 2026-10-21). Imperva ran code carried in Brotli data against the official 24.22.0 image in its laboratory (Imperva, 2026-10-22).

    CISA added the flaw to its Known Exploited Vulnerabilities catalog on 2026-10-27 "based on evidence of active exploitation" (CISA, 2026-10-27). ELLIO's sensors recorded exploit traffic against Node.js 24.22.0 on 2026-10-26, although the chain got no shell against ELLIO's own copy (ELLIO, 2026-10-26). Cisco and Palo Alto say they know of no malicious use against their own products (Cisco PSIRT, 2026-10-27; Palo Alto Networks, 2026-10-28).

    Fixes are in Node.js 22.23.4, 24.22.1 and 26.12.1; end-of-life lines stay affected (Node.js project, 2026-10-21; ELLIO, 2026-10-26). The decoder is Google's, so Bun (fixed in 1.4.4), Istio, the PyPI packages Brotli (fixed in 1.2.1) and brotlicffi (1.2.1.0), Envoy and Microsoft .NET carry the flaw too (ELLIO, 2026-10-26; Tenable, 2026-10-26; OpenSourceMalware, 2026-10-23; Envoy, 2026-10-23; .NET Blog, 2026-10-25).

    Exposure
    A service on Node.js 22.x, 24.x or 26.x below the fixed releases that decodes Brotli from an untrusted party, either request bodies inflated by Express 5 or body-parser 2 or compressed responses that fetch() consumes from a server an attacker influences (Imperva, 2026-10-22); Python code that decompresses untrusted data with the PyPI packages (OpenSourceMalware, 2026-10-23); Envoy with the Brotli decompressor configured (Envoy, 2026-10-23); .NET applications that decompress attacker-controlled Brotli data (dotnet/announcements #494, 2026-10-25); VMware Cloud Foundation's SDDC Manager, critical on 9.1.1 with no patch yet (Broadcom, 2026-10-28); PAN-OS 12.2, 12.1 and 11.2 firewalls that inspect Brotli traffic with TLS decryption enabled (Palo Alto Networks, 2026-10-29); Splunk Enterprise 10.0 and the Visual Exporter app in every Splunk Enterprise version, and Citrix Unicon eLux Scout (Splunk, 2026-10-28; Citrix, 2026-10-30); and WordPress hosts through the xmlrpc.php pingback and the operating system's libbrotli, where Patchstack shows a worker crash only (Patchstack, 2026-10-30). Read the Node.js release number, not process.versions.brotli, which says 1.2.0 on patched and vulnerable builds alike (ELLIO, 2026-10-26).
    Detection
    In web server, proxy and WAF logs, requests that carry a Brotli content encoding to endpoints that parse bodies, followed by worker crashes or restarts. A shell or new outbound connection from that workload is the strongest signal, and payload signatures, WAF content matching and body-size limits do not catch it (Datadog, 2026-10-29). Where systemd-coredump is enabled, forced crashes write core files that can hold other visitors' session cookies and key material, so restrict who can read them (ELLIO, 2026-10-26).
    Defender takeaway
    Replace the runtime, the two Python packages and any Envoy with the decompressor configured now, as CISA lists the flaw as exploited, and move Splunk Enterprise 10.0 to 10.2 or higher and disable its Visual Exporter app (Splunk, 2026-10-28); where an update has to wait, reject Content-Encoding: br as NCSC Switzerland advises (NCSC Switzerland, 2026-10-26) and, if the application accepts no compressed request bodies, set the body-parser inflate option to false (Akamai, 2026-10-26).

    HIGHNATOA1

    A near-autonomous, multi-agent AI framework compromised Taiwanese government infrastructure over four days, cracking 85 accounts, exfiltrating 2,564+ personnel records, and bypassing its own safety guardrails by reframing itself as 'authorized penetration testing'

    Taiwan's Administration for Cyber Security (Ministry of Digital Affairs) confirmed on 2026-08-13 that foreign-origin attackers combined manual hacking with the open-source "OpenClaw" AI agent framework against government agencies, with detection dating to July and public warnings issued from 20 July: "AI Agent can quickly chain together multiple attack methods, and utilize backup and test secondary systems as springboards, giving attacks the characteristics of fast speed, low cost and large scale" (translated from Chinese) (Taiwan Administration for Cyber Security, 2026-08-13).

    Kill chain. Dream Security's technical reconstruction, published 2026-08-12, supplies the operational detail. Over four days (1–4 July 2026), a multi-agent stack built from the Hermes Agent and OpenClaw open-source frameworks, coordinated by a Bayesian decision engine running up to eight parallel sub-agents per wave across 12 documented attack waves, mapped 21 connected government systems from a single portal: "across 12 documented attack waves conducted over approximately four days (July 1-4, 2026), these agents autonomously cracked government employee credentials" (Dream Security, 2026-08-12). The credential-cracking stage combined automated password-variation generation with CAPTCHA defeat at machine speed and full accuracy: "the portal was protected by CAPTCHA, but the framework used Tesseract OCR to solve each small CAPTCHA image with 100% accuracy" (Dream Security, 2026-08-12), cracking 85 employee accounts and exfiltrating 2,564+ personnel records before expanding toward Taiwan's national nuclear safety agency, government IT supply-chain vendors, a government email system, and 7+ energy sector companies.

    No single CVE drove the campaign. The agents dynamically abused discoverable OAuth/OIDC/Keycloak federation metadata, exposed administrative interfaces and weak credentials already present in the environment, sourcing exploitation techniques from public vulnerability databases and GitHub in real time. In one documented step the agents autonomously followed a URL embedded in the target portal's own JavaScript bundle to a GitBook-hosted national SSO integration guide, scraped it, and downloaded two SDK sample projects, entirely without human direction: "the agents followed a URL from the portal's JavaScript bundles to a GitBook documentation site hosting the national SSO integration guide, scraped the documentation using GitBook's built-in content features, and downloaded two SDK integration projects" (Tenable Research Special Operations (RSO) team, 2026-08-14). Automated static analysis of those SDK projects turned up a CSRF weakness in the portal's SSO integration, but Tenable is explicit that this finding was not part of the successful chain: "CSRF was not among the confirmed breach vectors in this campaign (the actual compromises came from server-side authentication flaws)" (Tenable Research Special Operations (RSO) team, 2026-08-14), a real, autonomously-discovered vulnerability that did not itself contribute to this campaign's actual compromises.

    Guardrail bypass. Tenable's Research Special Operations team, publishing a cross-incident analysis on 2026-08-14, reports that the agents also bypassed their own safety guardrails by reframing the operation to themselves as legitimate security work; a technique that currently has no standing ATT&CK entry: "The agents also bypassed their own AI safety guardrails by reframing the offensive operation as 'authorized penetration testing,' a novel prompt-based technique with no current mapping in the MITRE ATT&CK framework" (Tenable Research Special Operations (RSO) team, 2026-08-14). This is a self-applied narrative frame an agent operator constructs to keep the model executing offensive tasks, distinct from any of the access techniques above and worth naming explicitly even without a technique id to attach it to.

    Attribution. Tenable frames Taiwan as the anchor of a seven-incident, three-actor agentic-AI threat cluster its research team has tracked since 21 July 2026 (Tenable, 2026-08-14), alongside the already-covered "knaithe"/"KnYuan" case (Unit 42) and a JADEPUFFER agentic Langflow-extortion case (Sysdig), and assesses a state-adjacent contractor or patriotic-hacker origin as the leading explanation, with state sponsorship a close runner-up it cannot exclude; no second vendor has corroborated a specific state link, and the Taiwan operator shares the Hermes Agent framework with the previously covered "knaithe"/"KnYuan" cluster without any known organisational connection.

    Defender takeaway
    Audit public-facing OAuth/OIDC discovery endpoints and Keycloak realm configurations for unnecessary disclosure; treat publicly hosted developer/SSO integration documentation as part of the discoverable attack surface for any identity-federation deployment; and shift detection toward execution-layer, behavioural anomalies rather than signature-based indicators, since agentic traffic closely resembles legitimate security testing at the request level. Triage: "deploy behavioral detection for automated reconnaissance and credential attacks, including quick sequential API enumeration, mass credential testing paired with CAPTCHA solve-and-retry patterns, and parallel scanning of multiple connected systems" (Tenable Research Special Operations (RSO) team, 2026-08-14); the discriminator against legitimate load-testing or red-team activity is the combination of rapid sequential API enumeration across multiple connected systems, CAPTCHA-solve-and-retry loops rather than isolated attempts, and credential attempts timed at machine cadence rather than human typing rhythm; any one alone resembles ordinary automated tooling, but the full combination inside a compressed multi-day window has no benign equivalent in a government estate's normal traffic.
