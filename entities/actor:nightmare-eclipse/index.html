    2026-05-15NOTABLELeaked BitLocker bypass "YellowKey" and CTFMON privilege escalation "GreenPlasma" were fixed in the June 2026 updates

    Defender takeaway

    The June 2026 Windows update fixes YellowKey (MSRC CVE-2026-45585) and GreenPlasma (MSRC CVE-2026-45586), and Microsoft's interim WinRE script need not be reverted, since the update keeps its behavior (MSRC CVE-2026-45585). Microsoft says TPM+PIN makes YellowKey not exploitable (MSRC CVE-2026-45585), which the researcher disputes (BleepingComputer, 2026-05-13), and Kevin Beaumont advised TPM+PIN along with a BIOS password (BleepingComputer, 2026-05-13).

    Exposure · detection
    Exposure

    For YellowKey, TPM-only BitLocker devices (BleepingComputer, 2026-05-13) on Windows 11 24H2, 25H2 or 26H1 or Windows Server 2025 below the fixed builds, given physical access (MSRC CVE-2026-45585). For GreenPlasma, any Windows 10, Windows 11 or Windows Server 2012 to 2025 system without the June 2026 update, for an attacker who already runs code as a local user (MSRC CVE-2026-45586).

    Detection

    No cited source describes an artifact YellowKey leaves inside Windows; the attacker's media carries \System Volume Information\FsTx directories that WinRE replays at boot (BleepingComputer, 2026-05-13). GreenPlasma's public partial PoC raises a UAC consent prompt in default configurations (The Register, 2026-05-13).

    2026-10-08NOTABLEA Defender bypass that needs no vulnerability: fill the disk during every update and the engine stays up, stale

    Defender takeaway

    Add an alert on Defender security-intelligence age and on repeated update failures, since a running service no longer proves current protection, and keep the handle correlation as the hunt for a process that is actively doing it (LevelBlue SpiderLabs, 2026-10-05).

    Exposure · triage · detection
    Exposure

    Windows endpoints running Defender Antivirus; it ran under a standard user account in LevelBlue's testing (Dark Reading, 2026-10-06), and an estate shows the effect as endpoints whose security-intelligence age keeps growing (LevelBlue SpiderLabs, 2026-10-05).

    Triage

    A handle on the volume device alone is low-specificity because svchost, SearchIndexer, dllhost and TiWorker hold the same kind of handle in normal operation; in LevelBlue's tested environment only the Defender service processes and TrustedInstaller legitimately held a handle on MRT.exe (LevelBlue SpiderLabs, 2026-10-05).

    Detection

    Monitor whether Defender's content is staying current rather than whether the service runs: repeated update failures with error 0x80070643 and no installer activity, and an abrupt drop of free space on the system volume while the update chain (platform update, signature stub, recovery) runs and fails (LevelBlue SpiderLabs, 2026-10-05). In endpoint file-handle or ETW telemetry, a non-Defender, non-TrustedInstaller process holding a handle on MRT.exe is a high-confidence signal, and the same process also holding a raw handle on the volume device is rated critical; short-lived hidden GUID-named files in the user temp directory during update failures corroborate it (LevelBlue SpiderLabs, 2026-10-05).

    2026-08-12NOTABLEMicrosoft has now shipped an engine fix (1.1.26080.3), and the same researcher claims a partial bypass of it

    Defender takeaway

    Update the Defender engine to 1.1.26080.3 or later and verify it as an engine version, and keep the hunting in place while the researcher's ShieldCrash partial-bypass claim remains unconfirmed (SOCRadar, 2026-09-10).

    Latest update · exposure · detection
    Latest update · 2026-09-13

    Patch to engine 1.1.26080.3 or later and verify it as an engine version, not an OS build; that is now a real control where previously there was none. Do not retire the detection package in the 2026-08-24 update on the strength of the patch: the researcher who wrote the original working exploit says the fix leaves a reachable path, the claim is unrefuted as well as unconfirmed, and the hunting signals above key on the abuse of Defender's own remediation path rather than on any particular build. Arbitrary file read as SYSTEM is materially less severe than the original's full SYSTEM execution, so the residual risk after patching is lower than the pre-patch position, not equal to it.

    Exposure

    Any Windows host whose Microsoft Malware Protection Engine is older than 1.1.26080.3, the first build Microsoft lists as fixed (Microsoft MSRC). The engine updates on its own cadence, separately from the OS patch level (see the 2026-09-13 update).

    Detection

    LevelBlue's hunting guidance keys on the sequence rather than a single event: a process outside Defender's own small set loading MpClient.dll and resolving its scan and clean functions, a sync-root registration by a process that is not a cloud-sync client, and the QueueReporting task started through the Task Scheduler COM interface (LevelBlue SpiderLabs, 2026-08-19).

    2026-09-06HIGHCrowdStrike, Gen Digital and Kaspersky have all now remediated one researcher's four security-product PrivEsc PoCs, per LevelBlue's follow-up analysis

    Defender takeaway

    An endpoint agent's own remediation logic runs at SYSTEM on every managed host, which makes a flaw in it a full-estate local privilege escalation rather than a single-host bug, and it sits precisely where a defender is least likely to be watching. Both CrowdStrike and Gen Digital are now reported to have remediated their respective flaws (see the update below): confirm every Avast Antivirus install is on 26.7.11086 fix 992, 26.8.11125 fix 993, or later, and confirm every CrowdStrike Falcon sensor is on the current release, since no CrowdStrike source names a specific fixed build to check against.

    Latest update · triage
    Latest update · 2026-09-10

    LevelBlue's detection table is directly reusable for EDR/SIEM engineering: flag process-lineage anomalies on avpui.exe (a real caller other than the expected Kaspersky parent, or explorer.exe reported as parent for a process that was not user-launched), any non-Avast caller of \\.\aswSnx, and unexpected CMSTPLUA/ICMLuaUtil COM instantiation outside a normal UAC-elevation flow; all three are host-visible regardless of whether the specific PoC binaries are the ones seen.

    Triage

    These exploits ride a security agent's legitimate high-privilege routines, so the signal is not the agent acting with privilege, which it always does. What separates abuse is what the privileged action produces: a remediation or sandbox operation followed by a process spawning from an unexpected parent under a low-privileged user's session, a write into a system directory that the agent's normal cleanup does not target, or SAM access originating from the antivirus process tree rather than from a backup or credential-management workflow. Because the code is public and the researcher notes detections may already exist, an endpoint alert naming the agent's own remediation component is worth treating as an exploitation attempt rather than a product fault.

    2026-07-29NOTABLELevelBlue reproduces Nightmare Eclipse's latest Windows PoC on a July-2026-patched build, no CVE, no fix, and the abuse uses only legitimate APIs

    Defender takeaway

    Because there is nothing to patch, this converts entirely into a detection and credential-hygiene problem, and the strongest available signal is an unusually clean one. LevelBlue names user-mode invocation of NtCreateDirectoryObjectEx and NtCreateSymbolicLinkObject as rare outside system components, debugging tools and research utilities, and says seeing both from the same process should immediately warrant investigation (LevelBlue SpiderLabs, 2026-07-27). Two further telemetry classes are worth wiring up: file-access events showing ntuser.dat or UsrClass.dat being read or written outside their canonical per-profile locations, which is detectable independently of what the hive contains; and the per-user Volatile Environment registry key, where a %LOCALAPPDATA% value resolving into a kernel namespace rather than a filesystem path is a durable forensic artifact of a successful hijack. On the credential side, the prerequisite is the lever: the technique needs a second local account's password, so reducing how many accounts hold reusable local credentials with cross-account logon rights removes the precondition rather than the capability.

    Triage
    Triage

    Every individual operation here is legitimate (offline hive editing, an oplock on a profile hive, a logon-with-profile process launch) and LevelBlue's explicit position is that each is legitimate in isolation while observing them together in a short window is highly unusual and well suited to behavioural correlation. Note specifically that the target executable carries no discriminating value: LevelBlue demonstrates the PoC's notepad.exe is trivially substitutable, so detection must anchor on the calling pattern (a cross-account CreateProcessWithLogonW using LOGON_WITH_PROFILE, routed through the seclogon service) rather than on any process name.

    Microsoft calls Nightmare Eclipse's six uncoordinated Windows zero-day releases "never justifiable"; the three May drops were fixed in June 2026

    In a blog post on 2026-05-27, the Microsoft Security Response Center said the vulnerabilities known as RedSun, UnDefend, BlueHammer, YellowKey, GreenPlasma and MiniPlasma "were not responsibly disclosed" and that uncoordinated disclosures putting proof-of-concept code for unpatched flaws "into the hands of bad actors are never justifiable"; it added that its Digital Crimes Unit "will continue bringing cases against these actors and those that enable their criminal activity" (Microsoft MSRC blog, 2026-05-27).     Contradiction: the outlets read the statement differently. The Record says Microsoft "stopped short of directly threatening legal action" (The Record, 2026-05-29), while heise writes that the company "is threatening lawsuits and the police" (heise Security, 2026-05-29).

    The first three drops, BlueHammer (CVE-2026-33825), UnDefend (CVE-2026-45498) and RedSun (CVE-2026-41091), all disclosed in April, have been exploited in live intrusions and appear on CISA's Known Exploited Vulnerabilities catalogue (The Record, 2026-05-29); UnDefend lets a standard user block Microsoft Defender definition updates (BleepingComputer, 2026-06-10). The three May drops had no patch and no confirmed exploitation when The Record reported (The Record, 2026-05-29). YellowKey, tracked as CVE-2026-45585, is a BitLocker security feature bypass that needs physical access (Microsoft MSRC). The researcher says MiniPlasma abuses the HsmOsBlockPlaceholderAccess routine of the Cloud Filter driver cldflt.sys, and that it is the flaw Google Project Zero reported in 2020 as CVE-2020-17103, "still present, unpatched"; BleepingComputer's test on a fully patched Windows 11 Pro system with the May 2026 updates opened a SYSTEM command prompt from a standard user account (BleepingComputer, 2026-05-17).

    Microsoft fixed the three May drops on 2026-06-09: GreenPlasma as CVE-2026-45586, a CTFMON elevation of privilege that can give SYSTEM (MSRC CVE-2026-45586), MiniPlasma by re-releasing CVE-2020-17103 with the June 2026 updates (MSRC CVE-2020-17103), and YellowKey in the same Patch Tuesday (BleepingComputer, 2026-06-10).

    NOTABLECVE-2026-45585 +1updatedNATOA1

    Windows BitLocker "YellowKey" (CVE-2026-45585) and CTFMON "GreenPlasma" (CVE-2026-45586) zero-days: public PoCs in May, fixed in the June 2026 Windows updates

    On 2026-05-13 BleepingComputer and The Register reported that the researcher Nightmare Eclipse (also Chaotic Eclipse) had published exploit code for two Windows zero-days, YellowKey and GreenPlasma (BleepingComputer, 2026-05-13) (The Register, 2026-05-13). The researcher's earlier BlueHammer (CVE-2026-33825) and RedSun drops began to be exploited in the wild shortly after release (BleepingComputer, 2026-05-13).

    YellowKey is a BitLocker bypass that needs physical access. The researcher says it affects Windows 11 and Windows Server 2022/2025 and works by placing crafted FsTx files on a USB drive or the EFI partition, rebooting into the Windows Recovery Environment (WinRE) and holding CTRL to trigger a shell (BleepingComputer, 2026-05-13). Will Dormann reproduced it with the files on a USB drive but not on the EFI partition: to boot WinRE, Windows replays the NTFS logs in \System Volume Information\FsTx directories on attached drives, the replay deletes X:\Windows\System32\winpeshl.ini, and WinRE then opens CMD.EXE instead of the recovery environment, with the disk still unlocked (BleepingComputer, 2026-05-13). Because it abuses TPM-only automatic unlock, the public exploit works only on the original device, not on a removed drive, and does not work with TPM+PIN (BleepingComputer, 2026-05-13). Microsoft tracks it as CVE-2026-45585, a security feature bypass by physical attack (CWE-77, CVSS 6.8), publicly disclosed and not exploited; its fixed builds are Windows 11 24H2 build 10.0.26100.8655, 25H2 build 10.0.26200.8655, 26H1 build 10.0.28000.2269 and Windows Server 2025 build 10.0.26100.32995, and its product table does not list Windows Server 2022 (MSRC CVE-2026-45585).

    Contradiction: the researcher says an unpublished variant also defeats TPM+PIN (BleepingComputer, 2026-05-13); Microsoft states that "if you are using TPM+PIN the vulnerability is not exploitable" (MSRC CVE-2026-45585).

    GreenPlasma is a local privilege escalation in CTFMON: an unprivileged user can create arbitrary memory-section objects within directory objects writable by SYSTEM, and the leaked PoC lacks the component needed for a full SYSTEM shell (BleepingComputer, 2026-05-13); in its current state it triggers a UAC consent prompt in default Windows configurations (The Register, 2026-05-13). Microsoft tracks it as CVE-2026-45586, a link-following flaw (CWE-59, CVSS 7.8) in the Windows Collaborative Translation Framework that lets an authorized local attacker gain SYSTEM privileges, released on 2026-06-09 with fixes for Windows 10, Windows 11 and Windows Server 2012 to 2025, publicly disclosed and not exploited (MSRC CVE-2026-45586).

    Exposure
    For YellowKey, TPM-only BitLocker devices (BleepingComputer, 2026-05-13) on Windows 11 24H2, 25H2 or 26H1 or Windows Server 2025 below the fixed builds, given physical access (MSRC CVE-2026-45585). For GreenPlasma, any Windows 10, Windows 11 or Windows Server 2012 to 2025 system without the June 2026 update, for an attacker who already runs code as a local user (MSRC CVE-2026-45586).
    Detection
    No cited source describes an artifact YellowKey leaves inside Windows; the attacker's media carries \System Volume Information\FsTx directories that WinRE replays at boot (BleepingComputer, 2026-05-13). GreenPlasma's public partial PoC raises a UAC consent prompt in default configurations (The Register, 2026-05-13).
    Defender takeaway
    The June 2026 Windows update fixes YellowKey (MSRC CVE-2026-45585) and GreenPlasma (MSRC CVE-2026-45586), and Microsoft's interim WinRE script need not be reverted, since the update keeps its behavior (MSRC CVE-2026-45585). Microsoft says TPM+PIN makes YellowKey not exploitable (MSRC CVE-2026-45585), which the researcher disputes (BleepingComputer, 2026-05-13), and Kevin Beaumont advised TPM+PIN along with a BIOS password (BleepingComputer, 2026-05-13).

    NOTABLENATOB2

    BigDiskBuster: a roughly 300-line Windows proof of concept keeps Microsoft Defender from updating by claiming all free disk space, with no CVE and no patch

    LevelBlue SpiderLabs reproduced BigDiskBuster, a proof of concept published on GitHub on 2026-09-19 by the actor known as MSNightmare (Nightmare Eclipse) that needs no vulnerability to keep Microsoft Defender from updating (LevelBlue SpiderLabs, 2026-10-05). It watches the C: volume for Defender update activity and, when an update begins, creates a hidden file whose allocation claims essentially all free space; the update runs out of room and fails, Defender cleans up its staging directory and the tool repeats the process on the next attempt (LevelBlue SpiderLabs, 2026-10-05). The Defender service keeps running and real-time protection stays on; in LevelBlue's lab no alert appeared, and the only visible artifact was a stale security-intelligence version and the generic update error 0x80070643 (LevelBlue SpiderLabs, 2026-10-05). The roughly 300 lines of C++ use no memory corruption or kernel component: a raw handle on the volume device, a file opened relative to that handle, a recursive watch of the volume and an oversized allocation, with the file hidden and deleted on close (LevelBlue SpiderLabs, 2026-10-05). It ran under a standard user account on a default Defender installation (Dark Reading, 2026-10-06).

    No CVE, patch or Microsoft advisory exists; a Microsoft spokesperson told Dark Reading that Defender Antivirus includes detections and preventions against the proof of concept and that customers should keep security intelligence and platform updates current (Dark Reading, 2026-10-06). The GitHub repository has been taken down, and Dark Reading notes that the technique could in theory extend the life of malicious tooling already on a machine by withholding new detections (Dark Reading, 2026-10-06). No source reports use in an attack.

    Exposure
    Windows endpoints running Defender Antivirus; it ran under a standard user account in LevelBlue's testing (Dark Reading, 2026-10-06), and an estate shows the effect as endpoints whose security-intelligence age keeps growing (LevelBlue SpiderLabs, 2026-10-05).
    Detection
    Monitor whether Defender's content is staying current rather than whether the service runs: repeated update failures with error 0x80070643 and no installer activity, and an abrupt drop of free space on the system volume while the update chain (platform update, signature stub, recovery) runs and fails (LevelBlue SpiderLabs, 2026-10-05). In endpoint file-handle or ETW telemetry, a non-Defender, non-TrustedInstaller process holding a handle on MRT.exe is a high-confidence signal, and the same process also holding a raw handle on the volume device is rated critical; short-lived hidden GUID-named files in the user temp directory during update failures corroborate it (LevelBlue SpiderLabs, 2026-10-05).

    Triage: a handle on the volume device alone is low-specificity because svchost, SearchIndexer, dllhost and TiWorker hold the same kind of handle in normal operation; in LevelBlue's tested environment only the Defender service processes and TrustedInstaller legitimately held a handle on MRT.exe (LevelBlue SpiderLabs, 2026-10-05).

    Defender takeaway
    Add an alert on Defender security-intelligence age and on repeated update failures, since a running service no longer proves current protection, and keep the handle correlation as the hunt for a process that is actively doing it (LevelBlue SpiderLabs, 2026-10-05).
