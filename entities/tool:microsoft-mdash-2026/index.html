    Defender takeaway

    Confirm the April 2026 updates on IKEv2 responders and the May 2026 updates on domain controllers and other Windows hosts, prioritising the systems that expose these services, since Microsoft scores all four as exploitable over the network with no privileges required (MSRC, CVE-2026-33827; MSRC, CVE-2026-33824; MSRC, CVE-2026-41089; MSRC, CVE-2026-41096). MDASH's prove stage confirms that a bug exists by triggering it; for exploitability, Microsoft's advisory ratings are the reference (Microsoft, 2026-05-12). Where IKEv2 hosts cannot be patched at once, Microsoft's interim step is to block inbound UDP 500 and 4500 on systems that do not use IKE, or allow them only from known peer addresses, which reduces the attack surface but does not replace the update (MSRC, CVE-2026-33824).

    Exposure · detection
    Exposure

    CVE-2026-33824 is reachable without credentials over UDP/500 on any host configured as an IKEv2 responder (RRAS VPN, DirectAccess, Always-On VPN infrastructure, or any machine with an inbound connection security rule); a host with the IKEEXT service but no responder policy is not vulnerable, and where a responder policy exists the service starts on the first inbound IKE packet (Microsoft, 2026-05-12). CVE-2026-41089 is attacked with a crafted network request to a Windows server acting as a domain controller (MSRC, CVE-2026-41089).

    Detection

    In network telemetry on UDP/500, the IKEv2 trigger Microsoft describes: an IKE_SA_INIT carrying Microsoft's "IPsec Security Realm Id" vendor-ID payload followed by a single IKEv2 fragment that reassembles immediately (Microsoft, 2026-05-12).

    Microsoft MDASH: multi-model agentic scanning harness credited with 16 Windows networking and authentication CVEs, four of them Critical remote code execution flaws

    Microsoft's Autonomous Code Security team disclosed MDASH on 2026-05-12, a harness that orchestrates more than 100 specialised agents across an ensemble of frontier and distilled models in a prepare, scan, validate, dedupe and prove pipeline: debater agents argue each finding's reachability and exploitability, and the prove stage constructs and executes triggering inputs where the bug class admits it, to prove the vulnerability exists (Microsoft, 2026-05-12). Microsoft lists 16 CVEs its engineering teams found with MDASH across the Windows network stack and adjacent services, 10 kernel-mode and 6 user-mode, most of them reachable from a network position with no credentials (Microsoft, 2026-05-12).

    Four are Critical remote code execution flaws: CVE-2026-33827, a race-driven use-after-free in tcpip.sys; CVE-2026-33824, a double-free in the IKEEXT service, which runs as LocalSystem, triggered by two UDP packets; CVE-2026-41089, an unauthenticated CLDAP filter stack overflow in netlogon.dll; and CVE-2026-41096, a heap out-of-bounds flaw in dnsapi.dll triggered by a crafted UDP DNS response (Microsoft, 2026-05-12). Microsoft released the first two on 2026-04-14, scored 8.1 with high attack complexity and 9.8, both rated Exploitation Less Likely (MSRC, CVE-2026-33827; MSRC, CVE-2026-33824), and the other two on 2026-05-12, both scored 9.8, the Netlogon flaw rated Exploitation Less Likely and the DNS client flaw Exploitation Unlikely (MSRC, CVE-2026-41089; MSRC, CVE-2026-41096). The MDASH write-up describes the tcpip.sys trigger as crafted IPv4 packets carrying the Strict Source and Record Route option (Microsoft, 2026-05-12), while the advisory's FAQ describes a crafted IPv6 packet sent to a node where IPsec is enabled (MSRC, CVE-2026-33827).

    Microsoft's benchmark figures are its own: all 21 vulnerabilities planted in a private test driver found with zero false positives, recall of 96% on 28 historical MSRC cases in clfs.sys and 100% on 7 in tcpip.sys, which it describes as retrospective recall on internal code with a finite case count, and an 88.45% success rate on CyberGym's 1,507 vulnerability reproduction tasks drawn from 188 OSS-Fuzz projects (Microsoft, 2026-05-12). The harness is used by Microsoft security engineering teams and tested by a small set of customers in a limited private preview (Microsoft, 2026-05-12; The Register, 2026-05-13).

    Exposure
    CVE-2026-33824 is reachable without credentials over UDP/500 on any host configured as an IKEv2 responder (RRAS VPN, DirectAccess, Always-On VPN infrastructure, or any machine with an inbound connection security rule); a host with the IKEEXT service but no responder policy is not vulnerable, and where a responder policy exists the service starts on the first inbound IKE packet (Microsoft, 2026-05-12). CVE-2026-41089 is attacked with a crafted network request to a Windows server acting as a domain controller (MSRC, CVE-2026-41089).
    Detection
    In network telemetry on UDP/500, the IKEv2 trigger Microsoft describes: an IKE_SA_INIT carrying Microsoft's "IPsec Security Realm Id" vendor-ID payload followed by a single IKEv2 fragment that reassembles immediately (Microsoft, 2026-05-12).
    Defender takeaway
    Confirm the April 2026 updates on IKEv2 responders and the May 2026 updates on domain controllers and other Windows hosts, prioritising the systems that expose these services, since Microsoft scores all four as exploitable over the network with no privileges required (MSRC, CVE-2026-33827; MSRC, CVE-2026-33824; MSRC, CVE-2026-41089; MSRC, CVE-2026-41096). MDASH's prove stage confirms that a bug exists by triggering it; for exploitability, Microsoft's advisory ratings are the reference (Microsoft, 2026-05-12). Where IKEv2 hosts cannot be patched at once, Microsoft's interim step is to block inbound UDP 500 and 4500 on systems that do not use IKE, or allow them only from known peer addresses, which reduces the attack surface but does not replace the update (MSRC, CVE-2026-33824).

    Microsoft describes MDASH's prove stage as constructing and executing triggering inputs where the bug class admits it, to prove that a vulnerability exists (Microsoft, 2026-05-12); it does not say every finding was proven exploitable, and its advisories rate CVE-2026-33827, CVE-2026-33824 and CVE-2026-41089 Exploitation Less Likely and CVE-2026-41096 Exploitation Unlikely (MSRC, CVE-2026-33827; MSRC, CVE-2026-33824; MSRC, CVE-2026-41089; MSRC, CVE-2026-41096). CVE-2026-33827 and CVE-2026-33824 were patched in April 2026, not in the May update, and six of the 16 bugs are user-mode while the cohort also covers http.sys and telnet.exe, so they are not all network-stack kernel flaws (Microsoft, 2026-05-12).

    Microsoft did not call the 16 CVEs a first production run, and gives no June date: the harness is already being tested by a small set of customers in a limited private preview (Microsoft, 2026-05-12). The benchmark figures come from Microsoft's blog rather than The Register, and the tcpip.sys recall covers 7 historical MSRC cases (Microsoft, 2026-05-12). No cited source describes DirectAccess or Always-On VPN deployment in Swiss or EU government estates; the IKEv2 flaw is reachable only on hosts configured as IKEv2 responders (Microsoft, 2026-05-12).
