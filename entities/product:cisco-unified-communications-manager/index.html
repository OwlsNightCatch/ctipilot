    NOTABLECVE-2026-76466 +4NATOA2

    CVE-2026-76466, Cisco Expressway-C and Expressway-E: unauthenticated root command execution on clustered devices, fixed in X15.5.20 with no workaround (CVSS 9.8), alongside same-day hardening releases for Unified CM, Unity Connection and Snort 3

    Cisco's advisory of 2026-10-21 fixes CVE-2026-76466 (CVSS 3.1 9.8, network, no privileges, no user interaction) in the database service of Expressway-C and Expressway-E, virtual and appliance: an unauthenticated remote attacker with network access can run operating-system commands as root (Cisco PSIRT, 2026-10-21). The cause is the use of persistent cookies together with insufficient validation of client certificates for clustering, even when TLS Verify Mode is enabled; an attacker who possesses the cookies connects to the database service and invokes remote procedure call commands, and Cisco does not say how an attacker obtains the cookies (Cisco PSIRT, 2026-10-21). Only devices configured in a cluster are affected; X15.5.3 and earlier are fixed in X15.5.20, X14 and earlier must migrate to a fixed release, there is no workaround, and Cisco's PSIRT is not aware of any public announcement or malicious use (Cisco PSIRT, 2026-10-21). The X15.5.20 release also carries Expressway's own hardening fixes, whose worst class scores 8.6 (Cisco PSIRT, 2026-10-21).

    The same day Cisco ships two further hardening releases whose worst classes are exploitable over the network without authentication. For Emergency Responder, Prime Collaboration Deployment, Unified CM, Unified CM IM&P, Unified CM SME and Unity Connection, regardless of device configuration, the worst classes score 9.8 (CVE-2026-76473, improper control of a resource through its lifetime, and CVE-2026-76474, improper authentication); release 15 is fixed in 15SU5 and release 14 must migrate (Cisco PSIRT, 2026-10-21). For Snort 3 in Secure Firewall Threat Defense, Cyber Vision, Unified Threat Defense (UTD) on IOS XE and other Snort-based products, the worst classes score 9.0 with high attack complexity (CVE-2026-20043, an out-of-bounds write, and CVE-2026-20236, an incorrect calculation); FTD is fixed in 7.0.10, 7.2.12, 7.4.8, 7.6.6, 7.7.13, 10.0.2 and 10.1.0, Snort in 3.12.4.0, Cyber Vision in 5.6.0 and UTD on IOS XE in 17.12.8, 17.15.6, 17.18.5, 26.1.2 and 26.2.1, while Meraki MX devices that are online and connected to the Dashboard and Cisco's cloud firewall services were updated automatically on 2026-10-21 (Cisco PSIRT, 2026-10-21). Cisco says the flaws were found during internal security testing using existing processes as well as frontier AI models, and are not known to be actively exploited (Cisco PSIRT, 2026-10-21; Cisco PSIRT, 2026-10-21).

    HIGHCVE-2026-20230exploitedupdatedNATOA1

    CVE-2026-20230: Cisco Unified CM WebDialer SSRF to root file write, exploited and KEV-listed; WebDialer is off by default

    CVE-2026-20230 (CVSS 8.6) is a server-side request forgery in Cisco Unified Communications Manager and Unified CM Session Management Edition that lets an unauthenticated remote attacker write files and, Cisco says, elevate privileges to root, which is why it rates the advisory Critical (Cisco PSIRT). Only systems with the WebDialer service enabled are affected, and WebDialer is disabled by default; there is no workaround, but disabling WebDialer mitigates until a fix is applied (Cisco PSIRT). Fixed releases are 14SU6 and, for Release 15, 15SU5 (September 2026) or a version-specific COP patch (Cisco PSIRT).

    Defused reported exploitation over the weekend before 2026-06-23 from a single IP address, using file:// payloads to create files on the device in what appears to be a check for vulnerable systems; after that disclosure SSD Secure Disclosure, which reported the flaw to Cisco, published a technical write-up and proof-of-concept exploit (BleepingComputer, 2026-06-23). SSD's chain reads the node's true hostname from an unauthenticated WebDialer page, then abuses an unauthenticated cluster-install status endpoint as the SSRF, passing a full path in place of a node hostname to write a file that registers a new web service, and uses that service to write a JSP web shell (SSD Secure Disclosure, 2026-06-23). CISA added the flaw to its Known Exploited Vulnerabilities catalog on 2026-06-25 (CISA KEV catalog, 2026-06-25), and Cisco updated its advisory on 2026-07-01 to say it became aware of active exploitation in June and that proof-of-concept code is available (Cisco PSIRT).

    Exposure
    Unified CM or Unified CM SME with the Cisco WebDialer Web Service shown as Started under Control Center Feature Services, on Release 14 before 14SU6 or Release 15 without 15SU5 or the COP (Cisco PSIRT).
    Detection
    In the Unified CM web tier's access logs, the request sequence of SSD's chain: an unauthenticated GET of /webdialer/Version.jws?wsdl, then /cmplatform/installClusterStatusExecute with action=clusterNodeInstallStatus and a hostname parameter carrying a percent-encoded full path with XML markup instead of a bare node name, then calls to a new service under /webdialer/services/ and to new JSP files under /platform-services/axis2-web/ (SSD Secure Disclosure, 2026-06-23). Also look for requests to the WebDialer service whose parameters carry file:// URLs, the payload form Defused saw in the exploitation, and files created on the appliance that no administrative change accounts for (BleepingComputer, 2026-06-23).
    Defender takeaway
    Where WebDialer is not needed, disable it now; where it is, apply 14SU6 or the Release 15 COP, and check the appliance for files written outside normal administration since June (Cisco PSIRT) (BleepingComputer, 2026-06-23).
