    Defender insights

    What each entry about GitHub Actions tells a defender to do, newest first.

    2026-10-29NOTABLESafeDep and JFrog: the testmetest npm worm now runs on import, so --ignore-scripts does not stop it; 42 repos armed

    Defender takeaway

    An install that ran with scripts disabled is not clean once the package has been imported; for an affected host SafeDep's order is to disconnect it, remove persistence first, rotate all credentials, check the accounts for the repositories and commits above and reinstall the operating system (SafeDep, 2026-10-27). Because the wiper is triggered by the token's revocation, the host is isolated and cleaned before the GitHub token is revoked.

    Exposure · detection
    Exposure

    Any developer endpoint, build agent or CI runner that installed or imported one of the operator's packages, and any GitHub or GitLab account whose token such a host held (SafeDep, 2026-10-27).

    Detection

    In package metadata, a binding.gyp whose sources field runs node in a package with no C or C++ sources, a postinstall that requires a .node file and discards errors beside a large high-entropy file, and prebuilt addons with no native source; on endpoints and CI runners, a node process that downloads or finds and runs the Bun runtime and a child node process started from a temporary path named after its process ID; in GitHub and GitLab audit logs, a new public repository in a developer's own account with a generic project description, commits with a fixed automated-sync message, commits that add AI-assistant configuration files (.claude, .cursor, .gemini, .vscode tasks, CLAUDE.md or AGENTS.md), an injected CI job that requests OIDC tokens, and unexpected patch releases of your own packages (SafeDep, 2026-10-27).

    2026-10-27NOTABLEGheist abuses stolen GitHub tokens to dump secrets through Actions; GitHub's hold covers public repositories only

    Defender takeaway

    Rotate every secret available to a repository where a planted branch exists, revoke the tokens that pushed the commits and check their owners' devices for infostealers, treat a self-hosted runner host and its instance role as compromised if a planted branch ran there, and scope OIDC trust to protected branches or environments with required reviewers on environments that hold production secrets (Wiz, 2026-10-25).

    Exposure · triage · detection
    Exposure

    Organizations whose developers or automation accounts hold GitHub tokens that an infostealer or earlier compromise could have exposed, above all with private repositories, GitHub Enterprise Server, cloud OIDC workflows or self-hosted runners (Wiz, 2026-10-25).

    Triage

    The planted commit is unsigned but authored as the token's owner, so the author name alone proves nothing; one new workflow file with a fixed commit message on a branch the owner did not create is the pattern (Wiz, 2026-10-25).

    Detection

    In GitHub audit logs, workflow runs on a branch named ci-sync- plus six random characters that were deleted within a minute of completing, and API activity with the user agent gheist; in cloud audit logs, role assumptions whose OIDC subject names such a branch, which shows Actions ran on an attacker branch even where GitHub logs are not collected; on self-hosted runners, the helper files Wiz lists (Wiz, 2026-10-25).

    2026-10-10NOTABLEGhostAction: fake security workflows now harvest whole git histories; rotating Actions secrets is not enough

    Defender takeaway

    Search the GitHub organisations your teams and suppliers administer for security-themed workflow files (audit, check or Actions security); on a hit revoke the committing credential and rotate everything in the repository's full history. StepSecurity saw requiring approval for workflow runs stop the exfiltration and names branch protection on .github/workflows so workflow changes need pull-request review (StepSecurity, 2026-10-09).

    Exposure · triage · detection
    Exposure

    Any GitHub account whose token or session credential has leaked, and every repository it can write to; StepSecurity says a workflow posing as a security audit or an Actions security workflow that appeared in a repository you maintain since 2026-08-31 means treat it as a confirmed breach (StepSecurity, 2026-10-09).

    Triage

    The audit-log pattern separates this from a team adding a scanning workflow: no pull request, unsigned commits across many repositories, and a manual dispatch right after creation (StepSecurity, 2026-10-09).

    Detection

    Source-control audit logs: workflow files added straight to default branches without a pull request by a maintainer identity, unsigned commits landing in many repositories within minutes; an organisation-scoped code search with StepSecurity's published content-marker queries for security-themed workflow files (audit, check or Actions security); runner egress logs: an HTTP POST to a bare IP address with no preceding DNS lookup (StepSecurity, 2026-10-09). Removing the workflow does not undo the theft: StepSecurity says any secret ever committed to a repository must be treated as compromised, so treat each run as an exfiltration, scan the full history and rotate every credential found (StepSecurity, 2026-10-09); GitGuardian adds that the GitHub credential that allowed the injection must be revoked too, or someone else will reuse it (GitGuardian, 2026-10-07).

    2026-08-06HIGHexploitedA self-propagating npm worm reaches packages totalling 1.3 billion monthly downloads, and its C2 address lives on-chain

    Defender takeaway

    Hunt on the execution shape rather than on package names, because the package list is a moving target and the payload hash is stable across two filenames. In process-execution telemetry with parent lineage, the signal is a package-manager install spawning a script interpreter, and specifically a newly downloaded runtime binary being fetched and executed from a temporary directory during an install and then deleted. In file-creation telemetry, look for .vscode/tasks.json and .claude/settings.json appearing or changing in repositories that no engineer edited, across many branches: the 50-branch injection is noisy in commit history in a way the install-time compromise is not. In egress telemetry, connections from build agents and developer endpoints to Ethereum RPC providers are the anomaly worth surfacing; blockchain RPC is not normal build traffic in most enterprise estates, and because it is the resolution step it happens before any exfiltration does. Elastic ships detection rules for the trojanised-install and pre/post-install script-execution patterns (Elastic Security Labs, 2026-08-06).

    Latest update · triage
    Latest update · 2026-08-08

    Provenance attestation has been the reassuring answer to "how do we know this build is what it claims to be", and it still answers that question correctly; it just turns out that was never the question worth asking once the workflow itself is hostile.

    Triage

    Developer and CI hosts legitimately run script interpreters from package-manager parents on every build, and legitimately download toolchains, so neither alone discriminates. The separating features are that the runtime is fetched mid-install rather than during provisioning and its directory is removed immediately afterwards; that the process reads credential stores belonging to unrelated tools (cloud CLIs, SSH, Kubernetes, AI assistants) in one burst, which no ordinary build step does; and that outbound blockchain RPC follows the credential reads in the same process tree. Any one of these is weak on its own; the sequence is the signal.

    2026-09-17NOTABLEA bug-bounty hunter builds their own npm infostealer to manufacture the compromises they then report for a payout

    Defender takeaway

    Hunt for preinstall/postinstall npm lifecycle-script execution spawning outbound HTTP connections to non-registry hosts immediately after npm install, and for CI/CD runner processes making outbound connections to IP-lookup services (e.g. ipify.org-style APIs) followed by GET/POST exfiltration traffic. Ensure CI/CD pipelines run on a current npm major version so unapproved preinstall scripts are blocked by default, and treat any package.json dependency specified via a raw URL rather than a registry reference as a hard stop in code review.

    Triage
    Triage

    A legitimate build tool's own telemetry or update-check call is the benign lookalike; the discriminators are the absence of any corresponding, expected package purpose for the network call and a destination domain pattern that is freshly registered or "artifact"/"registry"-themed rather than a known vendor telemetry endpoint.

    2026-08-28NOTABLEAn AI red-team agent hit a syntax error mid-exploit, diagnosed it, fixed its own payload, and retried, without a human in the loop

    Triage
    Triage

    GitHub Actions workflows that interpolate untrusted issue or pull-request titles directly into shell steps, rather than passing them through env: variables with jq --arg-style safe parsing, are the systemic pattern this flaw exemplifies, an audit of any organisation's public-repository workflows for this exact interpolation shape is the actionable takeaway, independent of this specific incident.

    testmetest: an npm worm in the Miasma and Shai-Hulud family now starts when an application imports the package, so install with --ignore-scripts no longer protects, and JFrog finds 42 third-party GitHub repositories already armed with its publisher

    SafeDep counts 19 npm packages from the same operator between 2026-10-19 and 2026-10-27, eight of them published through four npm accounts, that carry a worm sharing code with the June Miasma worm and adding the token-revocation wiper of Mini Shai-Hulud; SafeDep has not confirmed the lineage, and JFrog says its evidence does not establish that the original Miasma operators are responsible (SafeDep, 2026-10-27; JFrog Security Research, 2026-10-26). The install trigger has changed twice: first a command expansion in a binding.gyp file, with no install script; then a postinstall script that loads a native addon which decodes and starts the worm; and, since SafeDep's update of 27 October, an addon that runs when an application imports the package, so a hardening step that disables install scripts does not stop it (SafeDep, 2026-10-27).

    The payload exits on CIS locales and in known analysis sandboxes. It steals SSH keys, registry and Git credentials, .env files, browser logins, AI-tool, cloud, Vault and Kubernetes secrets and GitHub Actions secrets read from runner memory (SafeDep, 2026-10-27). It exfiltrates by committing encrypted data, with the victim's encrypted GitHub token, to a new public repository in the victim's own account, injects a GitLab CI job that requests npm and PyPI OIDC tokens, adds its loader to the victim's npm packages and publishes new patch versions, republishes to PyPI and RubyGems, commits a fake CodeQL workflow and AI-agent configuration files that infect the host again, and copies itself over SSH to the hosts in known_hosts (SafeDep, 2026-10-27). A persistence service checks the stolen GitHub token every 45 seconds for 48 hours and on an authentication failure deletes the home directory (SafeDep, 2026-10-27). JFrog found 42 armed third-party GitHub repositories of 11 legitimate owners with hooks for AI coding assistants and IDEs, and says the payload blobs were large enough to evade GitHub's search and API paths (JFrog Security Research, 2026-10-26).

    Exposure
    Any developer endpoint, build agent or CI runner that installed or imported one of the operator's packages, and any GitHub or GitLab account whose token such a host held (SafeDep, 2026-10-27).
    Detection
    In package metadata, a binding.gyp whose sources field runs node in a package with no C or C++ sources, a postinstall that requires a .node file and discards errors beside a large high-entropy file, and prebuilt addons with no native source; on endpoints and CI runners, a node process that downloads or finds and runs the Bun runtime and a child node process started from a temporary path named after its process ID; in GitHub and GitLab audit logs, a new public repository in a developer's own account with a generic project description, commits with a fixed automated-sync message, commits that add AI-assistant configuration files (.claude, .cursor, .gemini, .vscode tasks, CLAUDE.md or AGENTS.md), an injected CI job that requests OIDC tokens, and unexpected patch releases of your own packages (SafeDep, 2026-10-27).

    Gheist: stolen GitHub tokens plant a secret-dumping workflow in every repository they reach; GitHub's July approval hold stops it on public github.com repositories but not on private ones or GitHub Enterprise Server

    Wiz Research has tracked since 2026-09-15 a campaign it calls Gheist, after the user agent on its API calls, that uses stolen GitHub access tokens to create a branch and commit a workflow named sync-check in every repository each token can reach: more than 13,500 planted branches from more than 850 compromised accounts, from personal projects to private enterprise repositories (Wiz, 2026-10-25). Wiz traces the tokens to infostealer logs and earlier supply-chain compromises (Wiz, 2026-10-25). The push triggers the workflow, which prints the repository's secrets, and those of any deployment environment, into its own run log; GitHub masks secret values only when they appear verbatim, so a base32-encoded value prints in full, the tool downloads the log through the GitHub API and deletes the run seconds later, and because the secrets leave through GitHub's own API there is no attacker domain or connection to block (Wiz, 2026-10-25). In private repositories and GitHub Enterprise environments Wiz saw runs on the attacker branches complete and be deleted, and cloud audit logs showed the organizations' own workflows running on those branches and assuming AWS roles (Wiz, 2026-10-25). As of 2026-10-24 Wiz called the attack ongoing and distinct from the earlier GhostAction campaign (Wiz, 2026-10-25).

    Exposure
    Organizations whose developers or automation accounts hold GitHub tokens that an infostealer or earlier compromise could have exposed, above all with private repositories, GitHub Enterprise Server, cloud OIDC workflows or self-hosted runners (Wiz, 2026-10-25).

    In GitHub audit logs, workflow runs on a branch named ci-sync- plus six random characters that were deleted within a minute of completing, and API activity with the user agent gheist; in cloud audit logs, role assumptions whose OIDC subject names such a branch, which shows Actions ran on an attacker branch even where GitHub logs are not collected; on self-hosted runners, the helper files Wiz lists (Wiz, 2026-10-25).

    Rotate every secret available to a repository where a planted branch exists, revoke the tokens that pushed the commits and check their owners' devices for infostealers, treat a self-hosted runner host and its instance role as compromised if a planted branch ran there, and scope OIDC trust to protected branches or environments with required reviewers on environments that hold production secrets (Wiz, 2026-10-25).
