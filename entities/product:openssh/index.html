    2026-11-11NOTABLECheck Point: a Sparrow-framework supplier fronts government watering holes with a fake Chrome certificate warning

    Defender takeaway

    Treat a browser page that offers a "certificate fix" installer as an incident trigger and stop standard users running MSI installers from a browser download; web teams of government and research sites should check for injected third-party script and input-handling flaws, because a compromised site becomes a delivery vehicle for its peers.

    Exposure · triage · detection
    Exposure

    Staff of public bodies, shipping, IT and research organisations who browse peer websites, web teams whose sites accept unsanitised input, and Windows endpoints that let a standard user run an MSI from a browser download.

    Triage

    WinDivert is legitimate in VPN and firewall products, so the signal is a parent that is a sideloaded DLL or backdoor rather than the vendor's signed service; SoftEther is legitimate software, but not under a system-process name in a non-system path; a genuine Chrome SSL warning is never cleared by installing an MSI.

    Detection

    In endpoint telemetry, a browser followed by msiexec running an installer named like a certificate repair utility and a new Run key value with an update-themed name; in module-load telemetry, DLL sideloading by rarely abused executables, and the WinDivert driver loaded by a process that is not a VPN or firewall product; in account telemetry, a new local administrator account; on Linux, ssh and sshd binaries that differ from the package-manager copy and frpc or chisel binaries; in DNS, MX-query volume from servers that send no mail.

    2026-11-06NOTABLEexploitedCISA lists the OpenSSH musl password bypass as exploited; update to 10.6p2 or turn passwords off

    Defender takeaway

    Install OpenSSH 10.6p2 or the distribution's fixed package on every musl-based host that runs sshd and restart sshd, because updating the package alone does not replace the SSH server that is already running, and rebuild container and cloud images from a fixed base (OX Security, 2026-11-05); until then set PasswordAuthentication no and restart sshd, as NCSC Switzerland advises (NCSC Switzerland, 2026-11-05). Patching does not remove a key or service planted before it, so review the accepted password logins, the authorized_keys files of root and the default user and the init services on every musl host that allowed password logins before patching.

    Exposure · triage · detection
    Exposure

    Sshd on a musl-based Linux system built without PAM, such as Alpine, OpenWrt and the other musl distributions NCSC Switzerland lists, with password logins enabled (NCSC Switzerland, 2026-11-05) and, per OX Security, an account whose /etc/shadow password field is * (OX Security, 2026-11-05). Containers that do not run an OpenSSH server are not affected (Alpine Linux, 2026-11-05).

    Triage

    An accepted password login is normal for an account with a real hash; the same event for an account whose password field is * has no benign explanation, because such an account cannot match any password.

    Detection

    Alpine advises looking in /var/log/messages for sshd lines reading Accepted password for an account that has no password (alpine, root or any key-only user) and treating the machine as compromised if a login cannot be ruled out (Alpine Linux, 2026-11-05). GreyNoise's gridpoint sessions show what follows a successful login: sshd-session spawning sh -c that runs id, uname and reads /etc/os-release, requests to the AWS, Azure and Alibaba Cloud metadata services, attempts to read root's SSH keys and /etc/shadow through doas, a new key written into the default alpine user's authorized_keys (GreyNoise, 2026-11-10).

    NOTABLENATOB2

    CopperDragon: Check Point ties three China-nexus intrusion sets to one Sparrow-framework supplier, among them SilentDelivery watering holes on government, shipping, IT and research sites that show a fake Chrome certificate warning (Czech Republic, Germany and France in its telemetry)

    Check Point Research's year-long investigation groups three intrusion sets under one malware-supply entity it calls CopperDragon, a possible "digital quartermaster" for China-nexus actors that use the cross-platform Sparrow framework (FamousSparrow and Earth Estries among them); Check Point itself cautions that the use of the same backdoor or C2 infrastructure "does not necessarily mean" the same actor ran two intrusions, so this is a hypothesis (Check Point Research, 2026-11-10).

    SilentDelivery, active since early 2026 against Europe and Asia, is the set nearest the constituency. Compromised government, shipping, IT and research websites, one through cross-site scripting in an unsanitised input field, carry obfuscated JavaScript that fingerprints the visitor and replaces the page with a language-localised fake Google Chrome SSL warning urging a "Certificate Fix" utility; the MSI, served from compromised cloud storage buckets, installs the new SquadC backdoor or a SparrowDoor variant (Check Point Research, 2026-11-10). SquadC can be set to run only while a browser process is alive, persists through a Run key named WindowsUpdateAssist, and offers file operations, command execution and screenshots. A second route is a spear-phishing RAR whose LNK abuses ftp.exe, with the same C2 (Check Point Research, 2026-11-10). Positive Technologies independently documented the same fake-certificate chain, with victims in Taiwan, Germany, Indonesia and the Czech Republic (Positive Technologies, 2026-08-21).

    The other two sets show what follows an intrusion. OceanGate in Asia starts from an exploited internet-facing Linux server and moves through trojanised ssh and sshd binaries that log passwords, a Linux backdoor that can load a kernel rootkit, FRP and Chisel tunnels, a hidden local administrator account and an LSA security-package credential interceptor; recent SparrowDoor builds embed the WinDivert driver to share a service port such as 443. DarkWire against Latin American telecom and government bodies uses DLL sideloading of uncommon executables, SoftEther VPN renamed to system-process names, DNS MX tunnelling and WMI lateral movement (Check Point Research, 2026-11-10). No Swiss victim is named.

    Exposure
    Staff of public bodies, shipping, IT and research organisations who browse peer websites, web teams whose sites accept unsanitised input, and Windows endpoints that let a standard user run an MSI from a browser download.
    Detection
    In endpoint telemetry, a browser followed by msiexec running an installer named like a certificate repair utility and a new Run key value with an update-themed name; in module-load telemetry, DLL sideloading by rarely abused executables, and the WinDivert driver loaded by a process that is not a VPN or firewall product; in account telemetry, a new local administrator account; on Linux, ssh and sshd binaries that differ from the package-manager copy and frpc or chisel binaries; in DNS, MX-query volume from servers that send no mail.

    Triage: WinDivert is legitimate in VPN and firewall products, so the signal is a parent that is a sideloaded DLL or backdoor rather than the vendor's signed service; SoftEther is legitimate software, but not under a system-process name in a non-system path; a genuine Chrome SSL warning is never cleared by installing an MSI.

    Defender takeaway
    Treat a browser page that offers a "certificate fix" installer as an incident trigger and stop standard users running MSI installers from a browser download; web teams of government and research sites should check for injected third-party script and input-handling flaws, because a compromised site becomes a delivery vehicle for its peers.

    NOTABLECVE-2026-123158exploitedupdatedNATOA2

    CVE-2026-123158, OpenSSH Portable before 10.6p2 (*sshole): on Linux with musl libc and no PAM, a password of 257 to 1,024 bytes logs in to accounts whose password field is *; NCSC Switzerland issued an advisory (CVSS 3.1 8.1)

    Portable OpenSSH 10.6p2 carries what its release notes call a critical security workaround for Linux systems that use the musl libc with PAM disabled (OpenSSH, 2026-11-05). OX Security explains the mechanism: musl's crypt() refuses inputs over 256 bytes and returns the string *, * is also what /etc/shadow holds for an account with no valid password, and OpenSSH reads the two matching values as a successful login; the conditions are sshd on musl without PAM, password logins enabled, an account whose password field is * and at least one other account with a real password, and OX scores the flaw CVSS 3.1 8.1 (OX Security, 2026-11-05). On Alpine's tiny-cloud images the passwordless alpine user can run doas without a password, so the bypass chains to root (OX Security, 2026-11-05), but Alpine says those images are safe on first boot and become exploitable as soon as any $6$ hash exists on the machine (Alpine Linux, 2026-11-05).

    CISA added the flaw to its Known Exploited Vulnerabilities catalog on 2026-11-09 on evidence of active exploitation, and describes no victim or behavior (CISA, 2026-11-09). GreyNoise says its first successful exploitation came on 2026-11-07 against one of its vulnerable gridpoints and calls the flaw trivial to exploit (GreyNoise, 2026-11-10). Alpine pushed the fix to every branch back to 3.16 (Alpine Linux, 2026-11-05), and NCSC Switzerland adds that other software using similar authentication paths may also be affected (NCSC Switzerland, 2026-11-05). watchTowr saw botnet and cryptomining use, and GreyNoise says its 16 successful chains are not representative of the broader activity (BleepingComputer, 2026-11-09).

    Exposure
    Sshd on a musl-based Linux system built without PAM, such as Alpine, OpenWrt and the other musl distributions NCSC Switzerland lists, with password logins enabled (NCSC Switzerland, 2026-11-05) and, per OX Security, an account whose /etc/shadow password field is * (OX Security, 2026-11-05). Containers that do not run an OpenSSH server are not affected (Alpine Linux, 2026-11-05).
    Detection
    Alpine advises looking in /var/log/messages for sshd lines reading Accepted password for an account that has no password (alpine, root or any key-only user) and treating the machine as compromised if a login cannot be ruled out (Alpine Linux, 2026-11-05). GreyNoise's gridpoint sessions show what follows a successful login: sshd-session spawning sh -c that runs id, uname and reads /etc/os-release, requests to the AWS, Azure and Alibaba Cloud metadata services, attempts to read root's SSH keys and /etc/shadow through doas, a new key written into the default alpine user's authorized_keys (GreyNoise, 2026-11-10).

    Triage: an accepted password login is normal for an account with a real hash; the same event for an account whose password field is * has no benign explanation, because such an account cannot match any password.

    Defender takeaway
    Install OpenSSH 10.6p2 or the distribution's fixed package on every musl-based host that runs sshd and restart sshd, because updating the package alone does not replace the SSH server that is already running, and rebuild container and cloud images from a fixed base (OX Security, 2026-11-05); until then set PasswordAuthentication no and restart sshd, as NCSC Switzerland advises (NCSC Switzerland, 2026-11-05). Patching does not remove a key or service planted before it, so review the accepted password logins, the authorized_keys files of root and the default user and the init services on every musl host that allowed password logins before patching.
