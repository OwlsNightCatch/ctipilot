    NOTABLEupdatedNATOB2

    Cisco Talos: the "demo.pdb" BadIIS variant is commodity IIS-module malware for SEO fraud, likely sold among Chinese-speaking crime groups and built by the author "lwxat"

    Since 2024 Talos has investigated attacks, mainly in the Asia-Pacific region and a few in South Africa, Europe and North America, that use a BadIIS variant marked by "demo.pdb" strings, which it assesses with moderate confidence is commodity malware sold privately or shared among several Chinese-speaking cybercrime groups under a malware-as-a-service model (Cisco Talos, 2026-05-19). The BadIIS variants of the DragonRank and UAT-8099 groups Talos documented before relied on hardcoded C2 and statically compiled payloads, whereas this variant is configured with a recovered builder that injects parameters for JavaScript redirection of visitors to illicit sites, reverse proxying of illicit content to search-engine crawlers, site-wide content hijacking and backlink injection, and that encodes the C2 address with single-byte XOR (Cisco Talos, 2026-05-19). Service-based installers from the same author impersonate Windows services such as Winlogin, FaxService or AudiosService, authenticate to a C2 server, download further payloads, hide their command lines with custom Base64 and register the BadIIS DLL in the globalModules and modules sections of the IIS configuration, and the latest copies the DLL to a hidden backup location so it is restored every time IIS restarts (Cisco Talos, 2026-05-19). Talos ties development from at least September 2021 to January 2026, including a build to bypass Norton, to the alias "lwxat" with moderate-to-high confidence, from the builder's authentication string, a configuration parameter and a custom user agent seen in samples (Cisco Talos, 2026-05-19). Talos does not describe how the attackers first gain access to the IIS servers.

    Exposure
    Internet-facing Microsoft IIS servers that have already been compromised by means Talos does not describe; the victims it observed are mostly in the Asia-Pacific region (Cisco Talos, 2026-05-19).
    Detection
    In the IIS server configuration, unknown native modules in the globalModules and modules sections; in the file system, a second copy of the module DLL in a hidden backup location; in service telemetry, new services named like Windows components that run command lines altering the IIS module list (Cisco Talos, 2026-05-19). Deleting the DLL alone does not clean the server, because the backup copy returns it at the next IIS restart (Cisco Talos, 2026-05-19).
    Defender takeaway
    Operators of internet-facing IIS servers should check the server-level module list for modules they did not install; on a finding, remove the backup copy and the impersonating service along with the module, or BadIIS comes back at the next restart (Cisco Talos, 2026-05-19).

    The variant is not an ISAPI filter or extension: its installers register the malicious DLL in the globalModules and modules sections of the IIS configuration at server level, and the latest one keeps a hidden backup copy that restores it every time IIS restarts, so the place to look is the server module list and the backup location (Cisco Talos, 2026-05-19). Talos does not place it in DragonRank or UAT-8099 activity; it contrasts it with those groups' BadIIS variants, which used hardcoded C2 and static payloads, assesses it as commodity malware likely sold or shared among several Chinese-speaking cybercrime groups, and says the attacks are difficult to attribute to a single actor (Cisco Talos, 2026-05-19). The "lwxat" alias rests on the builder's authentication string, a configuration parameter and a custom user agent, and Talos does not say how attackers first reach the IIS servers (Cisco Talos, 2026-05-19).
