    Exposure

    Windows users of Chrome or Edge, above all developer workstations with VS Code, cached Azure tokens or PowerShell on the Bypass or Unrestricted execution policy, and estates that enable OneDrive Known Folder Move; the attack needs a user to choose a folder and confirm a second prompt (Oneconsult, 2026-11-02).

    File-write telemetry for PowerShell profile paths, PowerShell module folders and .vscode\extensions, and changes to the Zone.Identifier stream there, whose ReferrerUrl and HostUrl fields keep the origin of the page that wrote the file (Oneconsult, 2026-11-02).     Oneconsult on the File System Access API: after two clicks a website holds read and write access to folders such as .vscode, .Azure, the public desktop and SMB shares in Chrome and Edge, enough for token theft and persistence without a process on the host

    Oneconsult analyses, from the Chromium source and tests on Windows 11 with Chrome and Edge 150.0.7871.101, what a website can reach through the File System Access API once a user selects a folder and grants permission: the handle stays valid as long as the tab is open and is obtained after just two user clicks (Oneconsult, 2026-11-02). Chrome rejects blocklisted paths, but a path that is not in its table and not an ancestor of a blocked path is allowed, and the kDontBlockChildren rule leaves the subfolders of listed directories selectable; Oneconsult confirmed .vscode, the Azure token cache, C:\Users\Public and SMB shares as accessible (Oneconsult, 2026-11-02).

    Oneconsult demonstrates these paths. A site can search a granted folder and take files such as cached Azure tokens and .env files. It can drop a fake VS Code extension into .vscode/extensions, which runs inside the normal code.exe process and is unaffected by Mark of the Web because Node.js does not check the Zone.Identifier stream. It can plant PowerShell profile and module backdoors, which work only with the Bypass or Unrestricted execution policy because the API stamps every written file with ZoneId=3 and RemoteSigned refuses such files. It can drop files on the public desktop, where they appear for all users and trigger a warning that a certain percentage of users acknowledge. And it can run an interactive file proxy through the still-open tab, where EDR sees only the browser reading and writing files (Oneconsult, 2026-11-02). A OneDrive Known Folder Move enabled while Chrome is running leaves a stale blocklist, so the redirected Desktop was writable; Oneconsult notes that the bypass has been reported to Google, which made the issue public, and that Google classed reading a single dragged file from a blocked folder as "not a security issue" (Oneconsult, 2026-11-02).

    Daniel Oz's July write-up of the same technique has a website edit a file the user already holds. He says the user-gesture requirement does not prevent phishing, only automatic picker invocation, and that signed or complex files may fail, be blocked or break in a way that prevents execution (Oz, 2026-07-05).

    Exposure
    Windows users of Chrome or Edge, above all developer workstations with VS Code, cached Azure tokens or PowerShell on the Bypass or Unrestricted execution policy, and estates that enable OneDrive Known Folder Move; the attack needs a user to choose a folder and confirm a second prompt (Oneconsult, 2026-11-02).
    Detection
    File-write telemetry for PowerShell profile paths, PowerShell module folders and .vscode\extensions, and changes to the Zone.Identifier stream there, whose ReferrerUrl and HostUrl fields keep the origin of the page that wrote the file (Oneconsult, 2026-11-02). Oz says editing a file does not automatically reclassify it as downloaded, so the stream is a possible marker, not a guaranteed one (Oz, 2026-07-05).

    Triage: browsers legitimately read and write files for web editors such as Google Docs and VS Code for Web, as Oneconsult notes; the signal is a browser process writing into a persistence location, not the file activity itself.

    Defender takeaway
    Restrict file system read and write access with the Chrome Enterprise policies Oneconsult names, FileSystemReadAskForUrls, FileSystemWriteAskForUrls and the respective AskForUrls policies, alert on writes to PowerShell profiles and VS Code extension folders, and treat a website's request to choose a local folder as a social-engineering step (Oneconsult, 2026-11-02).

    NOTABLECVE-2026-91403 +2updatedNATOA1

    eMudhra: the private keys of eight intermediate CA certificates were trivially recoverable, so anyone could forge trusted HTTPS certificates; browsers block them, clients with their own trust store or no revocation checking need an update (CVE-2026-111943 in Go)

    On 2026-10-17 a researcher reported to the Chrome Root Program, and Mozilla received a report the same day, that the private keys of eight eMudhra subordinate CA certificates were compromised: the keys were generated with insufficient randomness, which lets anyone forge trusted HTTPS certificates to impersonate any website against clients that have not removed trust in those CAs (Google, 2026-10-20; Mozilla, 2026-10-20). BleepingComputer, citing Mozilla's incident report, says all eight were P-384 keys generated in April 2025 with values below 256, so testing 256 numbers recovers a key, and that eMudhra blames a key-generation script error and found no evidence of end-user certificates (BleepingComputer, 2026-10-20). Google reports that no certificates chaining to the six TLS intermediates were logged to Certificate Transparency before it blocked them, so CT-enforcing clients such as Chrome could not have been attacked (Google, 2026-10-20); the tracker says it is not known whether attackers used the flaw against other clients (Dennis Jackson, 2026-10-20).

    Chrome blocked the intermediates on 2026-10-17, Firefox through OneCRL the same day, Microsoft platforms on 2026-10-20 and Apple devices on 2026-10-22, and eMudhra revoked all eight (Dennis Jackson, 2026-10-20; BleepingComputer, 2026-10-20). Microsoft went further: an out-of-band Windows update of 2026-10-26 removes seven certificates, six eMudhra G3 roots and an AAA Certificate Services cross-sign, from the Windows trust list, and the same seven left the Edge trust list on 2026-10-27 (Microsoft, 2026-10-26). Google removed the root that signed them, emSign ECC Root CA - G3, from the Chrome Root Store, with the removal expected to reach devices on 2026-10-27, after which some legitimate certificates chaining to it will stop working in Chrome (Google, 2026-10-20). Go 1.27.3 and 1.26.10 filter chains that contain the intermediates in crypto/x509, tracked as CVE-2026-111943 (Go team, 2026-10-20), and GitLab's release of 2026-10-29 removes trust for the eight intermediates in self-managed CE and EE, with GitLab Runner 19.5.1 and the AI Gateway needing separate updates (GitLab, 2026-10-29).

    Oracle's Security Alert of 2026-10-21 for CVE-2026-91403 (CVSS 3.1 9.1, component JSSE, remotely exploitable without authentication through the component's APIs) provided Java updates that distrust the impacted eMudhra intermediate CA certificates (Oracle, 2026-10-21), and a second Security Alert of 2026-10-24, CVE-2026-114820 (CVSS 3.1 9.1, same component and exposure), provides updates that remove the impacted root CA certificates and, from its revision of 2026-10-30, also covers the Java component of Oracle Database Server (not client-only installations), Autonomous Health Framework and OPatch (Oracle, 2026-10-30). OpenJDK's guidance tells users of a standalone runtime to act immediately even if they updated in the past few days, preferably by installing an update whose release note names JDK-8395690 and CVE-2026-114820 (OpenJDK, 2026-10-24). If no update is available, OpenJDK gives two alternatives: delete the aliases emsignrootcag1, emsignrootcag2, emsigneccrootcag3 and comodoaaaca from the runtime's cacerts keystore and restart it, repeating for each installation, or enable revocation checking with -Dcom.sun.net.ssl.checkRevocation=true and -Dcom.sun.security.enableCRLDP=true on the application's java command line (OpenJDK, 2026-10-24). OpenJDK packages from Red Hat, Oracle Linux, Fedora, Arch Linux and Gentoo most likely use the operating system's certificates; Debian, Devuan and Ubuntu need a manual workaround because updating ca-certificates and ca-certificates-java does not refresh the keystore (as superuser, remove /etc/ssl/certs/java/cacerts and run update-ca-certificates --fresh) (OpenJDK, 2026-10-24).

    Exposure
    Any software that keeps its own CA bundle or does not check revocation keeps trusting the intermediates until updated; Python 3.15.2, 3.14.10, 3.13.18, 3.12.16 and 3.11.18 carry a built-in denylist (Python Insider, 2026-10-26), and the tracker lists fixed versions for pip (26.2.2), certifi, rustls-webpki, the curl CA bundle and distribution packages and lists Bottlerocket, HarmonyOS, certbot, containerd, Godot and LibreOffice as still pending; its update of 28 October says the git, curl and python3 that ship with macOS still trust them (Dennis Jackson, 2026-10-28). A client's state is read with the tracker's test hosts: a certificate error means the client does not trust the intermediates (Dennis Jackson, 2026-10-20).
    Detection
    EMudhra says it found no evidence that the intermediates were used to issue end-user certificates (BleepingComputer, 2026-10-20), so a server certificate chain seen in TLS session metadata, proxy or EDR network telemetry that contains one of the eight intermediates or their Sectigo cross-signs, which the tracker lists, is worth treating as a possible forged certificate (Dennis Jackson, 2026-10-20). CT monitoring will not show one, because Google found no certificate chaining to the six TLS intermediates logged before it blocked them (Google, 2026-10-20).

    Triage: a site that still chains to emSign ECC Root CA - G3 failing in Chrome after 2026-10-27, or a certificate that chains to one of the seven certificates Microsoft removed failing in Windows or Edge once the change reaches the device, is the announced root removal, not an attack (Google, 2026-10-20; Microsoft, 2026-10-26).

    Defender takeaway
    Update trust bundles and toolchains on every non-browser client, rebuild container images that embed an old bundle, and do not rely on revocation or CT for those clients; website operators with certificates chaining to emSign ECC Root CA - G3 need one from another hierarchy now, Chrome's removal of that root having been due to reach devices on 2026-10-27 (Google, 2026-10-20), and Windows devices that do not receive automatic certificate-trust updates need the updated Disallowed Certificate Trust List and the trust-list changes, including Microsoft's out-of-band update of 2026-10-26 (Microsoft, 2026-10-26). A Java runtime updated in the past few days needs the update of 2026-10-24 (OpenJDK, 2026-10-24), and an ACME client will not replace a certificate under that root outside its renewal window unless it supports ACME Renewal Information, so trigger the renewal by hand (The Hacker News, 2026-10-22).
