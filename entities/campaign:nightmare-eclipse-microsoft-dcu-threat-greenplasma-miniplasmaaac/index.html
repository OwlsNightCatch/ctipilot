    Microsoft calls Nightmare Eclipse's six uncoordinated Windows zero-day releases "never justifiable"; the three May drops were fixed in June 2026

    In a blog post on 2026-05-27, the Microsoft Security Response Center said the vulnerabilities known as RedSun, UnDefend, BlueHammer, YellowKey, GreenPlasma and MiniPlasma "were not responsibly disclosed" and that uncoordinated disclosures putting proof-of-concept code for unpatched flaws "into the hands of bad actors are never justifiable"; it added that its Digital Crimes Unit "will continue bringing cases against these actors and those that enable their criminal activity" (Microsoft MSRC blog, 2026-05-27). The Record reported the post on 2026-05-29 as Microsoft's first response to the release campaign, noted that the researcher's GitHub account had since been removed, and reported that the researcher threatened a further release on 14 July 2026, the date of Microsoft's July Patch Tuesday (The Record, 2026-05-29).

    Contradiction: the outlets read the statement differently. The Record says Microsoft "stopped short of directly threatening legal action" (The Record, 2026-05-29), while heise writes that the company "is threatening lawsuits and the police" (heise Security, 2026-05-29).

    The first three drops, BlueHammer (CVE-2026-33825), UnDefend (CVE-2026-45498) and RedSun (CVE-2026-41091), all disclosed in April, have been exploited in live intrusions and appear on CISA's Known Exploited Vulnerabilities catalogue (The Record, 2026-05-29); UnDefend lets a standard user block Microsoft Defender definition updates (BleepingComputer, 2026-06-10). The three May drops had no patch and no confirmed exploitation when The Record reported (The Record, 2026-05-29). YellowKey, tracked as CVE-2026-45585, is a BitLocker security feature bypass that needs physical access (Microsoft MSRC). The researcher says MiniPlasma abuses the HsmOsBlockPlaceholderAccess routine of the Cloud Filter driver cldflt.sys, and that it is the flaw Google Project Zero reported in 2020 as CVE-2020-17103, "still present, unpatched"; BleepingComputer's test on a fully patched Windows 11 Pro system with the May 2026 updates opened a SYSTEM command prompt from a standard user account (BleepingComputer, 2026-05-17).

    Microsoft fixed the three May drops on 2026-06-09: GreenPlasma as CVE-2026-45586, a CTFMON elevation of privilege that can give SYSTEM (MSRC CVE-2026-45586), MiniPlasma by re-releasing CVE-2020-17103 with the June 2026 updates (MSRC CVE-2020-17103), and YellowKey in the same Patch Tuesday (BleepingComputer, 2026-06-10).

    Exposure
    Windows systems without the June 2026 updates: GreenPlasma and MiniPlasma are local privilege escalations open to any logged-on user (MSRC CVE-2026-45586) (MSRC CVE-2020-17103), and YellowKey needs physical access to a BitLocker device not protected by TPM+PIN (Microsoft MSRC).
    Detection
    For MiniPlasma, ThreatLocker advised watching registry-modification telemetry from the EDR for changes under the user hive's Software\Policies\Microsoft\CloudFiles\BlockedApps key and the .DEFAULT\Volatile Environment key (BleepingComputer, 2026-05-17).

    NOTABLECVE-2026-45585 +1updatedNATOA1

    Windows BitLocker "YellowKey" (CVE-2026-45585) and CTFMON "GreenPlasma" (CVE-2026-45586) zero-days: public PoCs in May, fixed in the June 2026 Windows updates

    On 2026-05-13 BleepingComputer and The Register reported that the researcher Nightmare Eclipse (also Chaotic Eclipse) had published exploit code for two Windows zero-days, YellowKey and GreenPlasma (BleepingComputer, 2026-05-13) (The Register, 2026-05-13). The researcher's earlier BlueHammer (CVE-2026-33825) and RedSun drops began to be exploited in the wild shortly after release (BleepingComputer, 2026-05-13).

    YellowKey is a BitLocker bypass that needs physical access. The researcher says it affects Windows 11 and Windows Server 2022/2025 and works by placing crafted FsTx files on a USB drive or the EFI partition, rebooting into the Windows Recovery Environment (WinRE) and holding CTRL to trigger a shell (BleepingComputer, 2026-05-13). Will Dormann reproduced it with the files on a USB drive but not on the EFI partition: to boot WinRE, Windows replays the NTFS logs in \System Volume Information\FsTx directories on attached drives, the replay deletes X:\Windows\System32\winpeshl.ini, and WinRE then opens CMD.EXE instead of the recovery environment, with the disk still unlocked (BleepingComputer, 2026-05-13). Because it abuses TPM-only automatic unlock, the public exploit works only on the original device, not on a removed drive, and does not work with TPM+PIN (BleepingComputer, 2026-05-13). Microsoft tracks it as CVE-2026-45585, a security feature bypass by physical attack (CWE-77, CVSS 6.8), publicly disclosed and not exploited; its fixed builds are Windows 11 24H2 build 10.0.26100.8655, 25H2 build 10.0.26200.8655, 26H1 build 10.0.28000.2269 and Windows Server 2025 build 10.0.26100.32995, and its product table does not list Windows Server 2022 (MSRC CVE-2026-45585).

    Contradiction: the researcher says an unpublished variant also defeats TPM+PIN (BleepingComputer, 2026-05-13); Microsoft states that "if you are using TPM+PIN the vulnerability is not exploitable" (MSRC CVE-2026-45585).

    GreenPlasma is a local privilege escalation in CTFMON: an unprivileged user can create arbitrary memory-section objects within directory objects writable by SYSTEM, and the leaked PoC lacks the component needed for a full SYSTEM shell (BleepingComputer, 2026-05-13); in its current state it triggers a UAC consent prompt in default Windows configurations (The Register, 2026-05-13). Microsoft tracks it as CVE-2026-45586, a link-following flaw (CWE-59, CVSS 7.8) in the Windows Collaborative Translation Framework that lets an authorized local attacker gain SYSTEM privileges, released on 2026-06-09 with fixes for Windows 10, Windows 11 and Windows Server 2012 to 2025, publicly disclosed and not exploited (MSRC CVE-2026-45586).

    Exposure
    For YellowKey, TPM-only BitLocker devices (BleepingComputer, 2026-05-13) on Windows 11 24H2, 25H2 or 26H1 or Windows Server 2025 below the fixed builds, given physical access (MSRC CVE-2026-45585). For GreenPlasma, any Windows 10, Windows 11 or Windows Server 2012 to 2025 system without the June 2026 update, for an attacker who already runs code as a local user (MSRC CVE-2026-45586).
    Detection
    No cited source describes an artifact YellowKey leaves inside Windows; the attacker's media carries \System Volume Information\FsTx directories that WinRE replays at boot (BleepingComputer, 2026-05-13). GreenPlasma's public partial PoC raises a UAC consent prompt in default configurations (The Register, 2026-05-13).
    Defender takeaway
    The June 2026 Windows update fixes YellowKey (MSRC CVE-2026-45585) and GreenPlasma (MSRC CVE-2026-45586), and Microsoft's interim WinRE script need not be reverted, since the update keeps its behavior (MSRC CVE-2026-45585). Microsoft says TPM+PIN makes YellowKey not exploitable (MSRC CVE-2026-45585), which the researcher disputes (BleepingComputer, 2026-05-13), and Kevin Beaumont advised TPM+PIN along with a BIOS password (BleepingComputer, 2026-05-13).
    Update20 May 2026 05:00 UTCrun 2026-05-20-a0f7b07factionscvessourcesbody

    Microsoft formally assigned CVE-2026-45585 to the BitLocker / WinRE bypass disclosed by "Nightmare Eclipse" on 2026-05-12 and confirmed there is still no security update. The MSRC update guide entry, published 2026-05-19, classifies it as CWE-77 (command injection in BitLocker / Windows Recovery Environment), CVSS 6.8 (AV:P/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H), with exploit-code maturity rated E:P (proof-of-concept) and remediation level RL:W (workaround only).

    Microsoft's interim mitigation, which it recommends that customers "consider implementing" if they are concerned their devices and data are at risk of being compromised or stolen, is per-device work: mount the WinRE image, remove the autofstx.exe entry from the BootExecute registry value inside the WinRE image, commit the image, then re-establish BitLocker trust for WinRE (MSRC CVE-2026-45585). The MSRC FAQ states: "A successful attacker could bypass the BitLocker Device Encryption feature on the system storage device. An attacker with physical access to the target could exploit this vulnerability to gain access to encrypted data."

    A pre-boot PIN avoids depending on the WinRE edit: the public exploit relies on TPM-only automatic unlock and does not work with TPM+PIN (BleepingComputer, 2026-05-13), and NCSC-CH advises that BIOS passwords and a BitLocker PIN mitigate the current public PoC (NCSC-CH Security Hub #12574, 2026-05-14).

    ROUTINECVE-2026-50656updatedNATOA2

    CVE-2026-50656: Microsoft Defender engine 'RoguePlanet' local privilege escalation now patched; NCSC-CH tracks the ongoing 'Nightmare Eclipse' zero-day series

    NCSC-CH's running tracker on the "Nightmare Eclipse" (aka Chaotic Eclipse) researcher's 2026 zero-day PoC series was updated on 2026-07-09 to record that a CVE has been assigned to RoguePlanet: CVE-2026-50656, a local privilege-escalation vulnerability (CWE-59, improper link resolution before file access / "link following") in the Microsoft Malware Protection Engine that underpins Microsoft Defender, System Center Endpoint Protection and Microsoft Security Essentials (NCSC-CH, 2026-07-09) (Microsoft MSRC, 2026-07-08). The researcher first disclosed RoguePlanet as an unpatched zero-day on 2026-06-09, Patch Tuesday, describing a race condition in Defender that lets a local attacker "execute arbitrary code or spawn a command shell with SYSTEM-level privileges", at which point NCSC-CH logged its status as "Proof of Concept Available, no patch available" (NCSC-CH, 2026-07-09). Microsoft's own record shows the CVE was published 2026-06-16 (CVSS 3.1 7.8, AV:L/AC:L/PR:L/UI:N, rated "Exploitation More Likely", exploitation status "No") and remained without a fix for over three weeks; a revision dated 2026-07-08 confirms Microsoft has now shipped an engine update that closes it: last vulnerable Malware Protection Engine build 1.1.26050.11, first fixed build 1.1.26060.3008 (Microsoft MSRC, 2026-07-08).

    NCSC-CH later recorded that a proof of concept dubbed ShieldBreak allegedly bypasses this fix; Microsoft tracks it as CVE-2026-69414 (NCSC-CH, 2026-07-09) and lists engine 1.1.26080.3 as the first build that addresses it (Microsoft Security Response Center, CVE-2026-69414).

    Exposure
    The Malware Protection Engine (mpengine.dll) at build 1.1.26050.11 or earlier, in Microsoft Defender, which runs on all supported versions of Windows, and in System Center Endpoint Protection and Microsoft Security Essentials; hosts with Defender disabled are not in an exploitable state even though vulnerability scanners flag the binaries still on disk (Microsoft MSRC, 2026-07-08).
    Defender takeaway
    Engine updates install automatically by default, so most estates already carry the fixed build and Microsoft's guidance is that no manual action is normally required, but it advises verifying that automatic deployment of engine updates works as expected (Microsoft MSRC, 2026-07-08); in analyst judgement that check matters most where engine updates are pinned, WSUS-gated, air-gapped or centrally deferred, such as System Center Endpoint Protection deployments and offline or OT-adjacent Windows hosts, and the build to confirm there is 1.1.26080.3 or later, which also carries the ShieldBreak fix (Microsoft Security Response Center, CVE-2026-69414).

    Neither Microsoft's advisory nor NCSC-CH's tracker describes the exploitation mechanism beyond link following and a race condition, so the earlier triage guidance on symlink races against scanned files and on the engine's child processes is withdrawn. NCSC-CH has since recorded that a proof of concept dubbed ShieldBreak allegedly bypasses this fix, tracked by Microsoft as CVE-2026-69414 (NCSC-CH, 2026-07-09); Microsoft lists engine 1.1.26080.3 as the first build that addresses it (Microsoft Security Response Center, CVE-2026-69414). The priority moves from notable to routine: the flaw is local and the engine fix installs automatically. A pinned estate should therefore verify that build rather than the RoguePlanet fix alone.
