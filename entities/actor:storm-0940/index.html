    Defender insights

    What each entry about Storm-0940 tells a defender to do, newest first.

    2026-10-18HIGHexploitedConnectWise SkyKick app credential used in 162+ Microsoft 365 tenants; disabling it does not undo planted access

    Defender takeaway

    Where any ConnectWise or SkyKick app is consented, disable it by client ID without deleting it, keep it disabled (ConnectWise's restoration works through a new application that each tenant consents separately), and review credentials, roles, owners, consents and Conditional Access exclusions since 13 October (ConnectWise, 2026-10-19; Huntress, 2026-10-16). An MSP should review its own management and security tools first, since a foothold there can reach its customers, but the review covers every application, because Huntress saw secrets planted on apparently random ones (Huntress, 2026-10-16). ConnectWise cannot independently determine whether a given partner or customer tenant was affected, so the answer for a tenant has to come from its own sign-in and audit logs (ConnectWise, 2026-10-19).

    Exposure · triage · detection
    Exposure

    Every Entra tenant, including each customer tenant an MSP manages, in which a ConnectWise or SkyKick Cloud Backup or Cloud Management app was ever consented, dormant connections included; ConnectWise lists seven application client IDs, among them Cloud Backup (506e08f9-6e9a-4da4-942b-a099a03644ae), and says to match on client ID (ConnectWise, 2026-10-19). Todyl identifies the application as "ConnectWise Cloud Backup" (formerly SkyKick Backup), app ID 506e08f9-6e9a-4da4-942b-a099a03644ae; SpecterOps hunts for applications owned by the ConnectWise tenant (ID 3f9cd7a0-127a-4ed4-bf06-2f830d5616b7) and notes that older tenants may list them under SkyKick names (Todyl, 2026-10-15; SpecterOps, 2026-10-17).

    Triage

    The vendor's apps sign in from Azure addresses with a .NET SDK user agent, while the credential additions used a Python user agent; Python and curl are common in administration, so Huntress says the combination of actor, operation and user agent is the signal (Huntress, 2026-10-16). Role self-assignments carrying the vendor's own user agent are not proven benign, since Huntress has not confirmed vendor automation (Huntress, 2026-10-16).

    Detection

    Entra service-principal sign-in logs for these apps from any address outside Microsoft and Azure ranges, which misses the credential additions, made from private Azure space (Huntress, 2026-10-16); the sweep of sign-ins itself, which Sophos saw come from a single virtual private server in strictly ascending tenant-ID order with Python HTTP-library user agents (Sophos, 2026-10-19); directory audit events Add member to role, Update application and Add service principal credentials initiated by a ConnectWise or SkyKick app (Huntress, 2026-10-16); Graph activity logs (Entra ID P1 or P2, not retroactive) for per-request source addresses (Todyl, 2026-10-15); and mailbox forwarding, inbox and transport rule and delegation changes (ConnectWise, 2026-10-19). Huntress notes that Microsoft Graph directory reads leave no audit record, so a clean audit log does not rule out reads of the directory (Huntress, 2026-10-16). Disabling the apps does not remove credentials, roles or consents already planted, and revoking user sessions does not end this access (ConnectWise, 2026-10-19; Todyl, 2026-10-15). Disabling an app stops new tokens only: a token issued before the disable stays valid for up to 90 minutes (Todyl, 2026-10-15; SpecterOps, 2026-10-17), and ConnectWise says that after its own certificate revocation previously issued tokens may remain usable until they expire (ConnectWise, 2026-10-19). The service-principal sign-in log records an application's authentication (ConnectWise, 2026-10-19), while per-request use of a token appears in the Graph activity logs named above (Todyl, 2026-10-15), so the review of that period belongs there. Microsoft asks tenants to review service-principal sign-ins from at least 2026-10-15, and from 2026-10-01 where records exist, and to search by application ID rather than display name (Microsoft, 2026-10-21). As of 2026-10-19, any alerting a tenant took from ConnectWise SaaS Security was out of service while that service was suspended (ConnectWise, 2026-10-19).

    2026-10-22NOTABLEMicrosoft: Storm-0940 runs the ARTEX agent framework at machine speed; Expel adds an Okta self-registration technique

    Defender takeaway

    Expel's reading is that the framework adds speed, not a new vulnerability, so the levers are the identity controls it runs into: least privilege on multi-tenant application permissions and consent grants, alerting on credential additions and privileged role assignments by applications, and a review of self-registered Okta accounts since 2026-10-13 (Microsoft, 2026-10-21; Expel, 2026-10-21).

    Exposure · triage · detection
    Exposure

    Any tenant that relies on password sign-in or grants OAuth consent to applications, and any Okta org with self-service registration enabled; not using ConnectWise does not exclude exposure (Expel, 2026-10-21).

    Triage

    Python and curl user agents match common legitimate automation, so Expel treats them as supporting evidence only, and a Python user agent on an application that normally calls Microsoft Graph with a .NET SDK is the anomaly (Expel, 2026-10-21).

    Detection

    In the authentication logs of every identity provider in use, bursts of failed logons and lockouts spread over many accounts; in the Okta system log, newly self-registered accounts that enrol Okta Verify and start single sign-on within minutes; and in the Entra audit log, credentials or certificates added to applications that nobody on your team created and any application that assigns itself a directory role (Microsoft, 2026-10-21; Expel, 2026-10-21). A clean audit log is not proof of no access, because Microsoft Graph directory reads leave no Entra audit record (Expel, 2026-10-21). In web access logs of an application exposed to the same actor, Wiz points to source-map and OpenAPI downloads followed minutes later by calls to internal routes that appear only in those files, and to sign-in telemetry showing a new user agent for each burst of attempts at a one-second cadence (Wiz, 2026-10-22).

    ConnectWise says it identified unauthorized access to application identities within its Cloud Backup (formerly SkyKick) environment; on 2026-10-17 it disabled seven application identities, suspended the service, says the shared Cloud Backup credentials are no longer valid, and warns that disabling does not reverse changes already made in a tenant (ConnectWise, 2026-10-19). As of ConnectWise's update of 2026-10-19 01:15 UTC, Cloud Backup, SaaS Security and Cloud Management remained suspended with no confirmed restoration time (ConnectWise, 2026-10-19), and its status page of 2026-10-28 says partners can now re-authorize Microsoft 365 backup and restore through a new application (ConnectWise status page, 2026-10-28); ConnectWise reports no successful threat activity in the environments it monitors since it implemented mitigations (ConnectWise, 2026-10-19) and says it cannot independently determine whether a given partner or customer tenant was affected (ConnectWise, 2026-10-19). Huntress and Todyl report that on 2026-10-15 the app's identity signed in to customer Microsoft 365 tenants from one hosting-provider address and received app-only Microsoft Graph tokens; the credential sits in the vendor's own tenant, so no user, MFA prompt or user Conditional Access was involved, and the app's consent covers read and write access to mail, files and Teams chats (Huntress, 2026-10-16; Todyl, 2026-10-15). Huntress confirmed unauthorized sign-ins in 162 tenants by 2026-10-16 and later counted almost 1,000 tenants with sign-in activity from that address, over 300 successful, after password spraying against four law-firm tenants on 13 and 14 October, and a separate failed wave targeted 16 tenants in policy and national-security sectors (Huntress, 2026-10-16). In about 50 of its tenants, ConnectWise Cloud Management apps assigned themselves directory roles, mostly Exchange Administrator; in one the Teams app added itself to Global Administrator and client secrets were added to an MSP management application and to Huntress's own application within about five minutes, the credential additions from private Azure space (Huntress, 2026-10-16). Huntress later identified a second tenant with the same sequence, the application granting itself Global Administrator and then planting a new secret on a small number of other applications, within two minutes of the first around 03:45 UTC on 2026-10-15, with the choice of applications apparently random (Huntress, 2026-10-16). It says the unauthorized sign-ins with the credential were bunched across the morning of 2026-10-15 UTC, that the last successful one it observed was at 08:44 UTC that day with only failed attempts afterwards in the tenants where it can read sign-in logs, and that in the two tenants it reviewed it found no mailbox or file manipulation and no user or policy changes (Huntress, 2026-10-16). Microsoft Threat Intelligence, as BleepingComputer relays it, called it an active supply-chain attack and assessed likely abuse of existing permissions including Directory.ReadWrite.All (BleepingComputer, 2026-10-17). Microsoft Threat Intelligence later assessed that Storm-0940, a China-state aligned actor, was responsible, using the ARTEX agentic-AI framework to attempt sign-ins to more than 2,250 tenants (Microsoft, 2026-10-21).     ARTEX: Microsoft reports Storm-0940, a China-state aligned actor, running an open-source multi-agent LLM penetration-testing framework against hundreds of organizations, with privileged cloud access in under three hours in some cases, and Expel sees the same infrastructure abuse Okta self-service registration

    Microsoft Threat Intelligence reports that as early as September 2026 Storm-0940, a China-state aligned actor active since 2021, used the agentic penetration-testing framework ARTEX to automate attacks on hundreds of organizations across many industries, government and military among them (Microsoft, 2026-10-21). ARTEX is an open-source multi-agent LLM system that can use any AI model and runs a penetration test from reconnaissance to exfiltration with little human involvement (Microsoft, 2026-10-21). Microsoft says ARTEX accelerated the abuse of compromised applications already granted access to Microsoft 365 tenants (Microsoft, 2026-10-21), and Expel adds that it is not a vulnerability and only speeds up familiar techniques such as password spraying and OAuth-application abuse (Expel, 2026-10-21); most targeting failed, yet several cases went from first targeting to privileged cloud access in under three hours (Microsoft, 2026-10-21). Microsoft assesses the same actor was behind the ConnectWise Cloud Backup application-credential abuse (Microsoft, 2026-10-21).

    Expel saw Storm-0940 infrastructure scan a customer and, from 2026-10-13, abuse its Okta self-service registration with no ConnectWise application involved: the attacker created five accounts of its own, enrolled Okta Verify on three of them about a minute after activation, made 50 single sign-on logins with more than 100 OAuth tokens issued and ran a password spray that Okta ThreatInsight blocked (Expel, 2026-10-21). Expel says the shared source address is its only link to Storm-0940, the activity alone does not prove ARTEX was used, and it had not seen the technique reported before (Expel, 2026-10-21). Other actors use it: CrowdStrike analysed an unnamed, probably Chinese-speaking and financially motivated actor that ran ARTEX against South Korean financial institutions from late September (CrowdStrike, 2026-10-07), and Recorded Future, which tracks that activity as TAG-217, says use of ARTEX and other AI penetration-testing tools is not limited to it (Recorded Future, 2026-10-16).

    Wiz Research independently reports that throughout October 2026 it tracked an actor using ARTEX-associated tooling, overlapping with Storm-0940, against IT and software vendors, focused on identity providers (Okta, Entra, Cognito) and Microsoft 365 integrations, and says that most attempts failed and that none of the techniques is novel (Wiz, 2026-10-22). It describes a consistent sequence: downloading JavaScript bundles, exposed source maps, runtime configuration and OpenAPI documents, then calling internal API routes by name minutes later; fabricated authorization codes and malformed state values against Microsoft OAuth callbacks; unsigned JWTs tried against more than 60 SSO route variants in two minutes; and account-recovery, sign-up and Cognito calls such as InitiateAuth, ForgotPassword and ResendConfirmationCode (Wiz, 2026-10-22). Its password sprays against Entra and Okta hit hundreds of users, mainly software engineers, in bursts of 20 to 60 minutes with a unique user agent per burst, a median gap of one second between attempts and new source addresses within minutes of a block (Wiz, 2026-10-22).

    Exposure
    Any tenant that relies on password sign-in or grants OAuth consent to applications, and any Okta org with self-service registration enabled; not using ConnectWise does not exclude exposure (Expel, 2026-10-21).
    Detection
    In the authentication logs of every identity provider in use, bursts of failed logons and lockouts spread over many accounts; in the Okta system log, newly self-registered accounts that enrol Okta Verify and start single sign-on within minutes; and in the Entra audit log, credentials or certificates added to applications that nobody on your team created and any application that assigns itself a directory role (Microsoft, 2026-10-21; Expel, 2026-10-21). A clean audit log is not proof of no access, because Microsoft Graph directory reads leave no Entra audit record (Expel, 2026-10-21). In web access logs of an application exposed to the same actor, Wiz points to source-map and OpenAPI downloads followed minutes later by calls to internal routes that appear only in those files, and to sign-in telemetry showing a new user agent for each burst of attempts at a one-second cadence (Wiz, 2026-10-22).

    Triage: Python and curl user agents match common legitimate automation, so Expel treats them as supporting evidence only, and a Python user agent on an application that normally calls Microsoft Graph with a .NET SDK is the anomaly (Expel, 2026-10-21).

    Defender takeaway
    Expel's reading is that the framework adds speed, not a new vulnerability, so the levers are the identity controls it runs into: least privilege on multi-tenant application permissions and consent grants, alerting on credential additions and privileged role assignments by applications, and a review of self-registered Okta accounts since 2026-10-13 (Microsoft, 2026-10-21; Expel, 2026-10-21).
