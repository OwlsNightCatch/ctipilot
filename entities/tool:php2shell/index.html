    2026-10-21CRITICALexploitedPHP2Shell: CISA lists both flaws as exploited after honeypot code execution; update the runtime, not the CMS

    Defender takeaway

    Update the PHP runtime on every internet-facing host today and restart the workers, internet-facing systems first and then internal and embedded installations, and take the management interface of every appliance that embeds PHP off the internet; where an update must wait, CERT-EU advises isolating internet-facing applications from public networks until the fix is applied and verified (CERT-EU, 2026-10-21). The project's interim settings (disable session upload progress, enforce memory_limit=-1 administratively, a low post_max_size, block multipart requests at the proxy where uploads are not needed) reduce only some attack paths, and BACS says a web application firewall alone is not enough (BACS, 2026-10-21; PHP, 2026-10-21). PHP 8.1 and older need a vendor backport, the project's source backports or an upgrade, ASLR is not a safe reason to wait on x86-64 given VulnCheck's exploit, and an update does not remove an attacker who is already in. The October releases do not fix CVE-2026-115560, so keep session upload progress disabled on updated hosts until PHP's next regular release (PHP, 2026-10-23). Because the flaws can disclose worker memory, rotating session secrets, API keys and other credentials that the PHP workers handled is a reasonable step on hosts that were reachable while unpatched.

    Exposure · detection
    Exposure

    Every internet-facing server or container image that runs PHP, and every product, appliance or administration interface that embeds it, internal ones included; BACS stresses that operators often do not know a product uses PHP, and that distribution packages can carry the fix under an unchanged version number, so the running version and the vendor's security information decide (BACS, 2026-10-21). On WordPress the running PHP version is shown under Tools > Site Health > Info > Server (Wordfence, 2026-10-20).

    Detection

    AWS, as relayed by Inside IT, advises an operator who cannot exclude a compromise to start the investigation at least from 2026-10-17, its earliest honeypot exploit attempt (Inside IT, 2026-10-22); the telemetry is, in web access logs, multipart POST requests to PHP endpoints from unfamiliar sources, including multipart requests that use the upload-progress code path, which VulnCheck's canaries saw scanners send (VulnCheck, 2026-10-21); in PHP error logs and process telemetry, worker crashes and fatal errors, and processes started by the web server or PHP worker account, since the code runs with the web worker's privileges (PHP, 2026-10-21), above all a shell started directly by an Apache worker, as in Karimi's honeypots and, since 2026-10-28, on GreyNoise's sensors, where it went on to open bash reverse shells over /dev/tcp, and create a .ssh directory under /var/www (Karimi, 2026-10-24; GreyNoise, 2026-11-01), which CISA also names as the behaviour to watch for (CISA, 2026-10-26); on Windows servers running IIS with PHP-CGI, Morphisec reports the web worker w3wp.exe starting php-cgi.exe, which started cmd.exe and a packed payload that tried to open a reverse shell (Morphisec, 2026-10-28); and in the web root, new or changed files. BACS asks operators to examine logs and systems for unusual requests, crashes, changed files and unexpected processes, and says an update does not remove a compromise that has already happened (BACS, 2026-10-21). ReliaQuest, which reproduced exploitation of CVE-2026-109618 in controlled labs, reports a sequence across the PHP error, Apache access, Apache error and system logs: a POST that returns HTTP 500, PHP memory exhaustion reported "in Unknown on line 0" where an ordinary memory error names the application file and line, heap corruption, and an abort of the Apache worker that handled the request within seconds; each event can be benign alone, the full sequence on the same process is the stronger indication, and linking request to crash needs the process ID in the Apache access log as well as the error log (ReliaQuest, 2026-10-22).
