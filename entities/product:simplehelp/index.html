    Defender takeaway

    A compromised RMM server is a ready-made deployment channel to every managed endpoint, so patching must be followed by removing unrecognised technicians, invalidating their sessions and checking managed hosts for the loader (Horizon3.ai, 2026-06-12) (BleepingComputer, 2026-06-29). Where patching must wait, restrict where technicians can log in from under Administration > Login Security (Horizon3.ai, 2026-06-12); SimpleHelp says these technician login IP restrictions block the login from excluded ranges (SimpleHelp guide).

    Exposure · detection
    Exposure

    SimpleHelp servers on 5.5.15 or earlier, or on an affected 6.0 beta or release-candidate build, with OIDC group-authenticated technician logins enabled (SimpleHelp guide) (Horizon3.ai, 2026-06-12): an enabled OIDC authentication service and a Technician Group that has both that service and "Allow group authenticated logins" enabled, a setting in the Group's General Properties tab that is off by default for new Groups; servers without such a Group cannot be exploited this way (SimpleHelp guide).

    Detection

    In SimpleHelp, unfamiliar technicians under Administration > Technicians with "Show Group Authenticated Users" checked, and server-log lines registering a technician login or a configuration save by an unknown group-authenticated user (Horizon3.ai, 2026-06-12); on managed endpoints, the RMM software launching Node.js, PowerShell, Python, Deno or Bun, particularly from temporary, download, remote-support or user-writable directories (Blackpoint Cyber, 2026-06-29).

    CRITICALCVE-2026-48558exploitedupdatedNATOB1

    CVE-2026-48558: SimpleHelp RMM OIDC authentication bypass (CVSS 3.1 10.0) exploited to plant technician sessions that deliver the TaskWeaver loader and Djinn Stealer

    CVE-2026-48558, scored CVSS 3.1 10.0 (CCB Belgium, 2026-06-19), is an authentication bypass in the OpenID Connect login flow of SimpleHelp 5.5.15 and earlier and of some 6.0 beta and release-candidate builds (SimpleHelp guide); SimpleHelp fixed it in 5.5.16 and 6.0 RC2 (SimpleHelp). CCB Belgium describes the flaw: with OIDC authentication configured, identity tokens submitted at login are accepted without verifying their cryptographic signature, so an unauthenticated attacker can submit a forged token with arbitrary identity claims and obtain a fully authenticated technician session (CCB Belgium, 2026-06-19). Horizon3, which found it, describes the conditions: an OIDC provider associated with at least one Technician group that has "Allow group authenticated logins" enabled; an attacker can then log in as a new technician, and MFA does not stop it because technicians register their own MFA method at first login (Horizon3.ai, 2026-06-12). Horizon3 found about 7.2% of a sample of exposed servers configured this way (Horizon3.ai, 2026-06-12).

    Blackpoint investigated an intrusion in which an attacker used the bypass to open a technician session on an internet-facing SimpleHelp server and then used the RMM's trusted channel to run commands on managed systems: the TaskWeaver loader, an obfuscated script named to resemble a jQuery library and fetched from a temporary Cloudflare domain, installed Djinn Stealer, a cross-platform information stealer (BleepingComputer, 2026-06-29). CISA added the flaw to its Known Exploited Vulnerabilities catalog on 2026-06-29 (CISA KEV catalog, 2026-06-29), and CCB Belgium reports it actively exploited (CCB Belgium, 2026-06-19).

    Exposure
    SimpleHelp servers on 5.5.15 or earlier, or on an affected 6.0 beta or release-candidate build, with OIDC group-authenticated technician logins enabled (SimpleHelp guide) (Horizon3.ai, 2026-06-12): an enabled OIDC authentication service and a Technician Group that has both that service and "Allow group authenticated logins" enabled, a setting in the Group's General Properties tab that is off by default for new Groups; servers without such a Group cannot be exploited this way (SimpleHelp guide).
    Detection
    In SimpleHelp, unfamiliar technicians under Administration > Technicians with "Show Group Authenticated Users" checked, and server-log lines registering a technician login or a configuration save by an unknown group-authenticated user (Horizon3.ai, 2026-06-12); on managed endpoints, the RMM software launching Node.js, PowerShell, Python, Deno or Bun, particularly from temporary, download, remote-support or user-writable directories (Blackpoint Cyber, 2026-06-29).
    Defender takeaway
    A compromised RMM server is a ready-made deployment channel to every managed endpoint, so patching must be followed by removing unrecognised technicians, invalidating their sessions and checking managed hosts for the loader (Horizon3.ai, 2026-06-12) (BleepingComputer, 2026-06-29). Where patching must wait, restrict where technicians can log in from under Administration > Login Security (Horizon3.ai, 2026-06-12); SimpleHelp says these technician login IP restrictions block the login from excluded ranges (SimpleHelp guide).
