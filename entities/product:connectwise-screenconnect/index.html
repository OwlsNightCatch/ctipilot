    Defender insights

    What each entry about ConnectWise ScreenConnect tells a defender to do, newest first.

    2026-11-12HIGHScreenConnect SCKit: second wave hits on-prem; disable RMM+, update technician clients to 26.6.5+

    Defender takeaway

    Treat Run Command or Toolbox executions you did not start as a compromise; disable RMM+ and the four other extensions the first notice named, update every technician host client to 26.6.5 or later, rotate ScreenConnect credentials and revoke active sessions and the browser and identity-provider sessions the toolkit could steal, and keep hosts and technician workstations out of service until the rogue client and persistence are gone (Huntress, 2026-11-11; Microsoft, 2026-11-13). Removing the rogue client alone leaves the persistence and the web sessions, and the cleanup script found in the kit must not be used (Microsoft, 2026-11-13).

    Exposure · detection
    Exposure

    A ScreenConnect instance whose panel can run commands on managed endpoints, run by the organisation or an IT provider; an RMM+ extension at any version, since ConnectWise's record names a static default secret, with versions 1.0.31 and 1.0.32 and a blank key as the condition Huntress describes; a technician host client older than 26.6.5; an endpoint with a second client service pointing at a foreign relay.

    Detection

    ScreenConnect instance audit logs, Run Command and Toolbox history for mass executions nobody started and RMM+ requests with no matching login (Huntress, 2026-11-11), and file-transfer-and-run events (event ID 201, per Blackpoint) (Blackpoint, 2026-11-13); process-creation telemetry with the ScreenConnect client service as parent of cmd, PowerShell or msiexec, curl or PowerShell downloads followed by a silent msiexec install (the Sophos pattern) (Sophos, 2026-11-11), a scheduled-task PowerShell watcher that compiles an executable with the .NET compiler (Microsoft, 2026-11-13), and a client service named like a Windows component (Huntress, 2026-11-13).

    2026-10-29NOTABLEHuntress: phished MDM enrolments push ScreenConnect back after removal; the RMM is not the root of the intrusion

    Defender takeaway

    Treat an unexpected MDM enrolment as a security event and keep an inventory of authorised tenants; after removing a rogue RMM, unenrol the device from the unauthorised tenant, disable accounts the attacker created, revoke sessions and tokens, reset credentials and reimage the endpoint if its integrity cannot be confirmed, as Huntress advises (Huntress, 2026-10-28).

    Exposure · triage · detection
    Exposure

    A managed Windows endpoint whose user can run an installer or follow an enrolment link, in an organisation without an inventory of its authorised MDM tenants, agents and RMM instances (Huntress, 2026-10-28).

    Triage

    A corporate enrolment started by IT looks similar in process telemetry; the discriminators are a tenant that is not in the authorised inventory, a trigger that is an emailed link or a user-run installer instead of IT's enrolment workflow, and an RMM install within minutes (an inference from Huntress's two cases).

    Detection

    The chain Huntress describes as a stronger signal is social engineering, then a new MDM enrolment, then an RMM installation, then outbound communication with an unfamiliar relay, correlated across identity, MDM, endpoint and network telemetry; in endpoint telemetry that is an MSI run from a browser download folder that installs an MDM agent, an enrolment registry key on a device nobody enrolled, a new SYSTEM-level agent in a vendor directory shortly after a click, and an RMM installed by that agent (Huntress, 2026-10-28). A repeat of the same RMM relay after the RMM was removed, as in the Hexnode case, points to a remaining MDM client as a possible source (Huntress, 2026-10-28).

    2026-10-08NOTABLEHuntress: a Power BI-hosted phishing link installs rogue ScreenConnect clients; in one case a script removed the first

    Defender takeaway

    Treat a link on a trusted cloud-hosted domain that leads to a download as untrusted in mail protection and user-reporting workflows, restrict remote-management software to approved instances, and check endpoints with more than one remote-management client, looking back to 2026-09-10 (Huntress, 2026-10-07).

    Exposure · triage · detection
    Exposure

    Microsoft 365 mailboxes where links to Power BI view pages reach users, and Windows endpoints where a user can run an installer for a remote-management tool; no sector or region is stated (Huntress, 2026-10-07).

    Triage

    ScreenConnect is legitimate where the organisation runs it; the discriminators are an instance that is not the organisation's own and an installer that arrived through a browser download from a web page rather than through IT's deployment tooling (Huntress, 2026-10-07).

    Detection

    In web proxy or mail click logs, a click on a Power BI view link followed within seconds by a new tab on an unfamiliar domain and an executable download; in endpoint process telemetry, a ScreenConnect client installer started from a browser download, a client service connecting to a ScreenConnect instance that is not the organisation's own, that client spawning a command shell and PowerShell from a temp directory, a second remote-management client appearing as the first is removed, and a scheduled task that re-runs a script every two minutes (Huntress, 2026-10-07).

    2026-09-12HIGHexploitedConnectWise patches a ScreenConnect flaw Huntress had already watched turn every infected connection into the next one's launch point

    Defender takeaway

    Any MSP-managed or self-hosted ScreenConnect deployment (including the IT-service-provider chain that reaches public-sector customers) should patch to 26.6.5 immediately and treat every pre-patch client as a potential re-infection vector, not just the host that was originally targeted.

    Triage
    Triage

    A benign ScreenConnect file-transfer message is initiated by a human technician against a session they are actively working; the worm's signature is a file-transfer action auto-queued the moment a new Host connection appears, with no corresponding operator action, immediately followed by wscript.exe spawning multiple child .vbs processes.

    2026-08-08NOTABLEInteractive fake-update modals, cloud-hosted payloads and self-registering RMM installers deployed at guest permission to stay quiet

    Defender takeaway

    Blocking ScreenConnect outright is not available to most organisations, because it is a legitimate remote-support product many helpdesks and suppliers use, and the payload here is the genuine signed client rather than a trojanised build. That is what makes the relay binding the useful control: a legitimately deployed client points at a relay your organisation or your managed-service provider operates, and this campaign's clients cannot; the operator's relay is compiled into the installer by key. An allow-list of sanctioned relay hostnames turns an unblockable application into a decidable one.

    Triage
    Triage

    The benign lookalike is a real support session, and it is common. The discriminators the cited mechanics support, in order of strength: the relay hostname the client registers to; installation at guest-level permission with no corresponding helpdesk ticket; and the process lineage, a browser spawning a batch script or PowerShell that calls msiexec.exe /quiet, which is not how a user or an administrator installs remote-support software deliberately. The fingerprinting gate also means an analyst re-visiting the lure URL from a sandbox or a non-Windows client will usually be served a decoy rather than the installer, so failure to reproduce the payload is not evidence the report is wrong.

    HIGHCVE-2026-127063updatedNATOB1

    ScreenConnect: commands pushed through Run Command to at least 288 managed endpoints at 48 Huntress customers within 90 minutes on 2026-11-11 installed a rogue second client and the SCKit toolkit; Huntress links the activity to the RMM+ extension, whose versions 1.0.31 and 1.0.32 accepted a blank access key

    On 2026-11-11 Huntress observed an operator using access to several cloud-hosted ScreenConnect panels to run commands as SYSTEM on groups of managed endpoints through the Run Command feature, hitting at least 288 hosts at 48 organisations within 90 minutes (Huntress, 2026-11-11). Each host installed an attacker-controlled second client and fetched SCKit, a 16-file toolkit delivered encrypted that sets the legitimate client to manual start so the attacker's copy replaces it and runs a per-host executable from a scheduled task (Huntress, 2026-11-11). A second wave on 2026-11-13 hit 205 hosts at 41 organisations with no follow-on executions observed (Huntress, 2026-11-13), and Blackpoint says it appears to target on-premises instances where mitigations are still pending (Blackpoint, 2026-11-13).

    Huntress's later update says the activity seems related to RMM+, a third-party extension that bypasses ScreenConnect's accounts, roles and MFA: versions 1.0.31 and 1.0.32 accepted a blank access key when an administrator had never set one (Huntress, 2026-11-11). ConnectWise, as CNA, published CVE-2026-127063 (CVSS 4.0 9.3) saying the extension uses a static API secret by default; it names no fixed version, removed the extension from cloud-hosted instances and tells on-premises customers to disable it and not reinstall it (ConnectWise, 2026-11-12).

    Microsoft describes the technician stage: RelayTrap, a replacement client compiled on the endpoint with the .NET C# compiler and designed to deliver a payload to the technician who connects, and browser-access code that searches Chrome, Edge and Opera profiles for cookies named .ASPXAUTH, with a component designed to queue payloads through the console's Shared Toolbox (Microsoft, 2026-11-13). ConnectWise says clients 26.6.5 and later block the transfer, and Microsoft adds that a cloud-console update does not update technician clients (Microsoft, 2026-11-13); Huntress and Blackpoint saw no successful technician compromise (Huntress, 2026-11-11; Blackpoint, 2026-11-13).

    Exposure
    A ScreenConnect instance whose panel can run commands on managed endpoints, run by the organisation or an IT provider; an RMM+ extension at any version, since ConnectWise's record names a static default secret, with versions 1.0.31 and 1.0.32 and a blank key as the condition Huntress describes; a technician host client older than 26.6.5; an endpoint with a second client service pointing at a foreign relay.
    Detection
    ScreenConnect instance audit logs, Run Command and Toolbox history for mass executions nobody started and RMM+ requests with no matching login (Huntress, 2026-11-11), and file-transfer-and-run events (event ID 201, per Blackpoint) (Blackpoint, 2026-11-13); process-creation telemetry with the ScreenConnect client service as parent of cmd, PowerShell or msiexec, curl or PowerShell downloads followed by a silent msiexec install (the Sophos pattern) (Sophos, 2026-11-11), a scheduled-task PowerShell watcher that compiles an executable with the .NET compiler (Microsoft, 2026-11-13), and a client service named like a Windows component (Huntress, 2026-11-13).
    Defender takeaway
    Treat Run Command or Toolbox executions you did not start as a compromise; disable RMM+ and the four other extensions the first notice named, update every technician host client to 26.6.5 or later, rotate ScreenConnect credentials and revoke active sessions and the browser and identity-provider sessions the toolkit could steal, and keep hosts and technician workstations out of service until the rogue client and persistence are gone (Huntress, 2026-11-11; Microsoft, 2026-11-13). Removing the rogue client alone leaves the persistence and the web sessions, and the cleanup script found in the kit must not be used (Microsoft, 2026-11-13).

    NOTABLENATOB2

    Huntress: phished MDM enrolments in Hexnode and Rippling give attackers a management path that brings ScreenConnect back after it has been removed

    Huntress reports several recent incidents in which attackers used legitimate mobile-device-management platforms, not flaws in them, as a trusted management path, naming Hexnode and Rippling as the two it saw and noting the list is not definitive (Huntress, 2026-10-28). In the first case, proposal-themed emails led a user to download an MSI named like a DocuSign installer that installed Hexnode components (gateway, agent and PostgreSQL components); ScreenConnect followed shortly after and connected to an attacker relay, the managed-service provider removed it, and it came back several hours later to the same relay while the Hexnode client was still installed (Huntress, 2026-10-28). In the second, a receptionist clicked a link in an email about tax planning that led to a fake Teams calendar page; about a minute later a Rippling enrolment registry key appeared, the agent was downloaded into a SYSTEM profile path and installed with SYSTEM rights, and about 35 minutes after that the attacker used the MDM to stage and run a ScreenConnect installer as SYSTEM (Huntress, 2026-10-28).

    Exposure
    A managed Windows endpoint whose user can run an installer or follow an enrolment link, in an organisation without an inventory of its authorised MDM tenants, agents and RMM instances (Huntress, 2026-10-28).
    Detection
    The chain Huntress describes as a stronger signal is social engineering, then a new MDM enrolment, then an RMM installation, then outbound communication with an unfamiliar relay, correlated across identity, MDM, endpoint and network telemetry; in endpoint telemetry that is an MSI run from a browser download folder that installs an MDM agent, an enrolment registry key on a device nobody enrolled, a new SYSTEM-level agent in a vendor directory shortly after a click, and an RMM installed by that agent (Huntress, 2026-10-28). A repeat of the same RMM relay after the RMM was removed, as in the Hexnode case, points to a remaining MDM client as a possible source (Huntress, 2026-10-28).

    Triage: a corporate enrolment started by IT looks similar in process telemetry; the discriminators are a tenant that is not in the authorised inventory, a trigger that is an emailed link or a user-run installer instead of IT's enrolment workflow, and an RMM install within minutes (an inference from Huntress's two cases).

    Defender takeaway
    Treat an unexpected MDM enrolment as a security event and keep an inventory of authorised tenants; after removing a rogue RMM, unenrol the device from the unauthorised tenant, disable accounts the attacker created, revoke sessions and tokens, reset credentials and reimage the endpoint if its integrity cannot be confirmed, as Huntress advises (Huntress, 2026-10-28).

    NOTABLENATOB2

    A phishing link on Microsoft's own Power BI domain slips past mail filters and installs rogue ScreenConnect clients, then, in one incident, a script replaces the first remote-management tool with a second

    Huntress describes a phishing campaign it has seen since 2026-09-10 in which an Outlook email carries a link that leads to a fake reference document on a legitimate Power BI domain (Huntress, 2026-10-07). Huntress notes that threat actors have previously abused Power BI in this way, building a real dashboard under an account of their own (usually compromised or throwaway), embedding a malicious link and setting its sharing to public, and that because the link points to Microsoft's real domain it passes Microsoft 365 mail filters and other gateways that trust that domain; it does not say how this campaign's page was set up (Huntress, 2026-10-07). A "Download Reference" button opens a new tab on an attacker domain that fingerprints the visitor (operating system, browser, automation indicators, cloud-provider cookies), reports victims to a Telegram bot and redirects visitors who fail its checks; after a delay a script clicks a hidden download link for a ScreenConnect installer (Huntress, 2026-10-07).

    The installer deploys a first rogue ScreenConnect client, which establishes a second one pointed at different infrastructure (Huntress, 2026-10-07). In one incident the first client ran a command-shell script that launched a PowerShell script from the temp directory; that script downloaded and ran the installer for the second client and uninstalled the first, in a likely effort to evade detection, and a scheduled task re-ran it every two minutes before the attack was shut down (Huntress, 2026-10-07). After deployment the clients also ran a tool Huntress assessed as designed to hide the attacker's activity from the user and security software (Huntress, 2026-10-07). A handful of endpoints were hit from 2026-09-10, and the configuration of one of the rogue clients also appeared on 22 other endpoints in separate incidents (Huntress, 2026-10-07). The original email and lure wording are unknown.

    Exposure
    Microsoft 365 mailboxes where links to Power BI view pages reach users, and Windows endpoints where a user can run an installer for a remote-management tool; no sector or region is stated (Huntress, 2026-10-07).
    Detection
    In web proxy or mail click logs, a click on a Power BI view link followed within seconds by a new tab on an unfamiliar domain and an executable download; in endpoint process telemetry, a ScreenConnect client installer started from a browser download, a client service connecting to a ScreenConnect instance that is not the organisation's own, that client spawning a command shell and PowerShell from a temp directory, a second remote-management client appearing as the first is removed, and a scheduled task that re-runs a script every two minutes (Huntress, 2026-10-07).

    Triage: ScreenConnect is legitimate where the organisation runs it; the discriminators are an instance that is not the organisation's own and an installer that arrived through a browser download from a web page rather than through IT's deployment tooling (Huntress, 2026-10-07).

    Defender takeaway
    Treat a link on a trusted cloud-hosted domain that leads to a download as untrusted in mail protection and user-reporting workflows, restrict remote-management software to approved instances, and check endpoints with more than one remote-management client, looking back to 2026-09-10 (Huntress, 2026-10-07).
