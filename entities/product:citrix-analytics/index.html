    Update and restart, internet-reachable and identity services first. Where an update waits, Calif gives two JVM options, -XX:-UseBASE64Intrinsics or -XX:UseAVX=2 on x86-64 hosts only, because OpenJDK on ARM does not recognize it and fails to start (Calif, 2026-11-17).

    Exposure · detection
    Exposure

    A Java 17, 21, 25 or 27 runtime, or the Java 8 performance build, at or below the affected builds (Oracle, 2026-11-17), fixed in Oracle's 17.0.21.1, 21.0.13.1, 25.0.5.1, 27.0.1.1 and 8u513-perf (Tenable, 2026-11-17); BACS says to check that the running applications actually use the corrected Java version (BACS, 2026-11-18). The CPU must report the avx512f, avx512bw, avx512vbmi and bmi2 flags, which means Intel Ice Lake to Granite Rapids and AMD Zen 4 or newer (Upwind, 2026-11-17). Pre-authentication reach depends on the application decoding attacker-controlled Base64 with the basic or URL decoder of java.util.Base64 before it authenticates the caller (Upwind, 2026-11-17). Cisco's advisory (version 1.4) lists Secure Network Analytics and Secure Workload as affected and Catalyst Center, IOS XE and ISE as not (Cisco, 2026-11-23); Fortinet lists none as confirmed affected and dozens as under investigation (Fortinet, 2026-11-18); BACS adds internal systems and supplier-run Java software (translated from German) (BACS, 2026-11-18).

    Detection

    Unexplained hs_err_pid crash logs on internet-facing Java applications, where the log may not name Base64 because the crash comes later (Equixly, 2026-11-17); child processes of the server and administrative activity on identity, build and artifact platforms follow from Calif's chains. In request and application logs, Upwind suggests Base64-alphabet tokens of 32 or more characters that end in = with a length not a multiple of 4, starting with Authorization headers, and bursts of IllegalArgumentException from java.util.Base64$Decoder or of restarts (Upwind, 2026-11-17). An update does not remove a compromise that has already happened (BACS, 2026-11-18).

    HIGHCVE-2026-114938updatedNATOA2

    Java4Shell, CVE-2026-114938, OpenJDK 17.0.6 and later and Oracle Java SE on x86-64 CPUs with AVX-512 VBMI: a heap overflow in the Base64 decoder that Calif chains into pre-authentication code execution in Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate; fixed in 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1, GreyNoise reports exploitation attempts, none confirmed successful against its sensors (CVSS 3.1 8.1)

    Oracle's Critical Security Patch Update and the OpenJDK advisory of 2026-11-17 list CVE-2026-114938 in the hotspot compiler component, which Oracle rates CVSS 3.1 8.1 with high attack complexity (Oracle, 2026-11-17; OpenJDK, 2026-11-17). Calif, one of the two reporters Oracle credits (Oracle, 2026-11-17), says HotSpot's x86-64 Base64 intrinsic, which uses AVX-512 VBMI instructions, calculates a negative output length for a short padded input and that length becomes a full 64-byte write that sends 62 bytes past the end of the array; only the landing position of the write is controllable, a misplaced write can crash the JVM (Calif, 2026-11-17). It scores the flaw CVSS 4.0 9.2 and reports pre-authentication code execution in the default configurations of Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate, authenticated execution in several further server products, and a client-side path in which a Java program that opens a TLS connection to a malicious server is compromised (Calif, 2026-11-17). Tenable relays Immersive's claim of a working exploit with no release stated (Tenable, 2026-11-17).

    The flaw needs an x86-64 processor with AVX-512 VBMI and affects OpenJDK from 17.0.6 on, ARM64 hosts are not affected (Calif, 2026-11-17). CISA published an alert to patch immediately (CISA, 2026-11-17), and the NCSC.ch Cyber Security Hub says the published research demonstrates exploitation without establishing malicious exploitation (NCSC.ch, 2026-11-17); Talos has seen no exploitation in the wild yet and expects probing (Talos, 2026-11-18), while Tenable relays GreyNoise's report of exploitation attempts as of 2026-11-18, none confirmed successful against its sensors, and VulnCheck's statement that a working RCE exploit is available to its customers (Tenable, 2026-11-17).

    Exposure
    A Java 17, 21, 25 or 27 runtime, or the Java 8 performance build, at or below the affected builds (Oracle, 2026-11-17), fixed in Oracle's 17.0.21.1, 21.0.13.1, 25.0.5.1, 27.0.1.1 and 8u513-perf (Tenable, 2026-11-17); BACS says to check that the running applications actually use the corrected Java version (BACS, 2026-11-18). The CPU must report the avx512f, avx512bw, avx512vbmi and bmi2 flags, which means Intel Ice Lake to Granite Rapids and AMD Zen 4 or newer (Upwind, 2026-11-17). Pre-authentication reach depends on the application decoding attacker-controlled Base64 with the basic or URL decoder of java.util.Base64 before it authenticates the caller (Upwind, 2026-11-17). Cisco's advisory (version 1.4) lists Secure Network Analytics and Secure Workload as affected and Catalyst Center, IOS XE and ISE as not (Cisco, 2026-11-23); Fortinet lists none as confirmed affected and dozens as under investigation (Fortinet, 2026-11-18); BACS adds internal systems and supplier-run Java software (translated from German) (BACS, 2026-11-18).
    Detection
    Unexplained hs_err_pid crash logs on internet-facing Java applications, where the log may not name Base64 because the crash comes later (Equixly, 2026-11-17); child processes of the server and administrative activity on identity, build and artifact platforms follow from Calif's chains. In request and application logs, Upwind suggests Base64-alphabet tokens of 32 or more characters that end in = with a length not a multiple of 4, starting with Authorization headers, and bursts of IllegalArgumentException from java.util.Base64$Decoder or of restarts (Upwind, 2026-11-17). An update does not remove a compromise that has already happened (BACS, 2026-11-18).
    Defender takeaway
    Update and restart, internet-reachable and identity services first. Where an update waits, Calif gives two JVM options, -XX:-UseBASE64Intrinsics or -XX:UseAVX=2 on x86-64 hosts only, because OpenJDK on ARM does not recognize it and fails to start (Calif, 2026-11-17).
    Update19 Nov 2026 05:03 UTCrun 2026-11-19T0355Z-intelaffected_productsbodycvesevidencesourcessummaryheadlinesourcing_notetitleentities

    Cisco's product impact: Secure Network Analytics, Secure Workload and further products are affected, Cisco offers no workaround, and its PSIRT is aware of proof-of-concept code but not of malicious use (Cisco, 2026-11-23). Fortinet says it is investigating the impact on its products and lists none as confirmed affected, with dozens under investigation (Fortinet, 2026-11-18). Tenable relays GreyNoise's report of exploitation attempts as of 2026-11-18, none confirmed successful against its sensors, and VulnCheck's statement that a working RCE exploit is available to its customers (Tenable, 2026-11-17). BACS's warning of 2026-11-18 asks operators to prioritise internet-reachable applications and central sign-in services, to include internal systems, to clarify other Java software such as banking software with their suppliers and to have externally operated services confirm the fix, and says an update removes no compromise that has already happened (translated from German) (BACS, 2026-11-18). Tenable adds that as of 2026-11-18 Red Hat and Ubuntu had released no fix and Debian had fixed only its unstable branch, so hosts on those distributions had no stable vendor build yet, and that the Keycloak project recommended starting its server with -XX:-UseBASE64Intrinsics as an interim mitigation, its x86-64 container images tagged 26.8.2-1 and 26.8.2-2 carrying an affected Java build (Tenable, 2026-11-17).

    Update20 Nov 2026 05:12 UTCrun 2026-11-20T0356Z-intelentitiesaffected_productssourcesbodysummarycves

    Three more vendors published product status. Elastic says Elasticsearch 7.17.3 and later is affected with mitigating factors: remote code execution needs an authenticated user with at least read access on an affected CPU architecture, while unauthenticated actors can cause denial of service; Logstash 8.6.2 and later is affected only through the elastic_integration filter when an ingest pipeline decodes Base64 from an untrusted source, with a crash as the result, and Kibana, Beats, Elastic Agent, APM Server, the ECK operator and Elastic Maps Server are not affected, while Elasticsearch clusters that ECK manages follow the Elasticsearch rule (Elastic, 2026-11-19). Elastic plans fixes in 8.19.26, 9.4.10, 9.5.7 and 9.6.0 with a bundled JDK 27.0.1.1+4 and gives no dates, hot-fixed Elastic Cloud Serverless on 2026-11-18, and says fewer than about 5% of Elastic Cloud Hosted deployments, on Azure only, run an affected CPU architecture; a self-managed node is affected only on an x86-64 CPU with AVX512_VBMI (Elastic, 2026-11-19).

    Broadcom's Tanzu advisory TNZ-2026-1107 says several Tanzu products ship affected Java runtimes and lists released fixes: Java Buildpack 5.5.0 and 5.5.1, Ruby Buildpack 1.10.104, Tanzu OpenJDK 17.0.21.1+5, 21.0.13.1+5 and 25.0.5.1+5 and Foundation Core 3.1.19, 3.3.10 and 11.0.3, where the identity service and CredHub carry an affected Java 25 runtime that Tanzu has not yet confirmed from the bill of materials; it names -XX:-UseBASE64Intrinsics as the preferred workaround (Broadcom, 2026-11-19). Palo Alto Networks lists fixed builds of Privilege Threat Analytics, Remote Access Connector and the Secure Access HTML5 Gateway, says PAN-OS is not affected, offers no workaround and is not aware of any malicious exploitation (Palo Alto Networks, 2026-11-20). None of these statuses changes the exploitation picture above.

    Update26 Nov 2026 05:07 UTCrun 2026-11-26T0356Z-intelsummarysourcesaffected_productsentitiescvesbodyupdated_at

    HPE Networking's bulletin HPESBNW05193 of 2026-11-25 (status Investigating) lists as known affected Central On-Premises 2.5.8 build 12 and below, New Central On-Premises 3.0.4.4 and below, NetEdit 2.19.0 and below, Analytics and Location Engine 5.2.0 and below, AirWave 8.3.0.7 and below, ClearPass Policy Manager 6.14.x and SD-WAN Orchestrator 9.7.x. It says exposure depends on the environment: an instance whose CPU does not expose the avx512vbmi feature is not vulnerable, which HPE checks with a search of /proc/cpuinfo for that flag (HPE Networking, 2026-11-25). Fixed builds are AirWave 8.3.0.8 and above, SD-WAN Orchestrator 9.7.2.41110 and 9.7.1.42066 and ClearPass 6.14.1-HF3 (expected 2026-12-01); Central On-Premises 2.5.8 build 13, NetEdit 2.19.1, Analytics and Location Engine 5.2.1 and the New Central On-Premises build have no date yet (HPE Networking, 2026-11-25).

    HPE's workaround for virtual machines is to hide the avx512vbmi feature from the guest at the hypervisor (a per-VM mask or an EVC baseline of Skylake or Cascade Lake generation on VMware, and equivalent settings on QEMU/KVM, Proxmox, OpenStack Nova, Xen, VirtualBox and Firecracker), followed by a power cycle; Hyper-V cannot mask a single feature and public clouds need an instance family without VBMI. Central On-Premises, New Central On-Premises and bare-metal ClearPass cannot hide the flag, so HPE says to restrict management access to a dedicated segment or firewall policy, and it names no JVM option. HPE knows of no public discussion or exploit code against its products (HPE Networking, 2026-11-25).

    Cisco's advisory now reads version 1.4: Catalyst Center, ISE, IOS XE, IOS XR and NX-OS read not affected, about 26 other products are listed as affected with the release or date still to be determined, patches for Secure Network Analytics are planned for 7.6.1, 7.6.0 and 7.5.3, and Cisco says no workaround addresses the vulnerability (Cisco, 2026-11-23). Siemens' advisory SSA-810379, at version 1.1 of 2026-11-23, adds Desigo CC Advanced Reporting V8 and V9 as affected with no fix (Siemens, 2026-11-19).
