    Defender insights

    What each entry about Microsoft 365 device-code phishing in French-speaking Switzerland (November 2026) tells a defender to do, newest first.

    Defender takeaway

    Where the tenant has no documented need for device code flow, Microsoft recommends blocking it with a Conditional Access policy, testing in report-only mode and auditing existing use first (Microsoft Learn, 2026-04-07). Tell users never to enter a Microsoft login code at a third party's request, and that anyone who has entered a code or validated an authentication request must call IT support at once, which is the canton's own instruction (Canton of Vaud, 2026-11-04).

    Exposure · triage · detection
    Exposure

    Any Microsoft 365 tenant whose users can complete the device code flow, which Microsoft describes as meant for devices without local input such as shared devices or digital signage and as a high-risk method that phishing can use (Microsoft Learn, 2026-03-24).

    Triage

    Microsoft documents device code sign-in for shared devices and signage; a device-code sign-in by a user who has no such device, soon after that user received a mailed link, falls outside that use (Microsoft Learn, 2026-03-24).

    Detection

    Mail, web proxy and DNS telemetry for links to workers.dev subdomains of the structure above; in the Entra sign-in logs, device code events found with the authentication protocol filter (Microsoft Learn, 2026-03-24). Microsoft says protocol tracking persists through token refreshes, so later sign-ins in the same session can fall under an authentication-flows policy, and it records an original transfer method property in the activity details of the Conditional Access sign-in logs (Microsoft Learn, 2026-03-24).

    Valid accounts in cloud environments may allow adversaries to perform actions to achieve Initial Access, Persistence, Privilege Escalation, or Defense Evasion.     Entries about Microsoft 365 device-code phishing in French-speaking Switzerland (November 2026) (1)

    2026-11-05 · view entry permalink →

    HIGHNATOA2

    Canton Vaud warns of a device-code phishing campaign against Microsoft 365 accounts running in French-speaking Switzerland, with several organisations already affected

    The canton of Vaud said on 2026-11-04 that a phishing campaign is currently running in French-speaking Switzerland and that several organisations have already been affected (translated from French) (Canton of Vaud, 2026-11-04). The messages can appear to come from a company or a known contact and invite the reader to view an invoice, open a document or verify information through a link; the campaign uses device-code phishing, which gets the victim to type a code on a genuine Microsoft authentication page and so gives the attackers fraudulent access to the Microsoft 365 account (Canton of Vaud, 2026-11-04). The links printed in the notice combine a company-style name and a portal word on a workers.dev subdomain whose second label starts with a cloud-storage word and an identifier, and the canton says other addresses can be used too (Canton of Vaud, 2026-11-04); workers.dev is the route assigned to every Cloudflare Worker (Cloudflare Docs, 2026-09-22). The notice names no actor, kit, count of organisations, sector or start date.

    Exposure
    Any Microsoft 365 tenant whose users can complete the device code flow, which Microsoft describes as meant for devices without local input such as shared devices or digital signage and as a high-risk method that phishing can use (Microsoft Learn, 2026-03-24).
    Detection
    Mail, web proxy and DNS telemetry for links to workers.dev subdomains of the structure above; in the Entra sign-in logs, device code events found with the authentication protocol filter (Microsoft Learn, 2026-03-24). Microsoft says protocol tracking persists through token refreshes, so later sign-ins in the same session can fall under an authentication-flows policy, and it records an original transfer method property in the activity details of the Conditional Access sign-in logs (Microsoft Learn, 2026-03-24).

    Triage: Microsoft documents device code sign-in for shared devices and signage; a device-code sign-in by a user who has no such device, soon after that user received a mailed link, falls outside that use (Microsoft Learn, 2026-03-24).

    Defender takeaway
    Where the tenant has no documented need for device code flow, Microsoft recommends blocking it with a Conditional Access policy, testing in report-only mode and auditing existing use first (Microsoft Learn, 2026-04-07). Tell users never to enter a Microsoft login code at a third party's request, and that anyone who has entered a code or validated an authentication request must call IT support at once, which is the canton's own instruction (Canton of Vaud, 2026-11-04).
