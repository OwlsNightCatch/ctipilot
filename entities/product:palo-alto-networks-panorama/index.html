    2026-11-19HIGHnginx2root: five unauthenticated flaws reach worker RCE, Rapid7 PoC public; update to 1.31.10, 1.30.8, Plus 37.3.1.1

    Defender takeaway

    Update and restart nginx, because a configuration reload does not replace the running executable; disabling HTTP/2 on exposed listeners blocks only the two HTTP/2 flaws (Xint, 2026-11-18) and, if it stays on elsewhere, leaves connection pressure (Unit 42, 2026-11-24), and Xint gives interim measures for the others: a fixed upstream group in place of request-time DNS lookups for CVE-2026-123634, no QUIC listeners for CVE-2026-121810 and bound or firewalled mail listeners for CVE-2026-113425 (Xint, 2026-11-18). An empty execution-audit result after the update cannot rule out an earlier compromise, and Xint chained CVE-2026-123007 with a separate Linux kernel SCTP flaw, unpatched when it published, to reach root on the host and escape a Docker container; hosts that do not use SCTP can block the module from loading (Xint, 2026-11-18).

    Exposure · triage · detection
    Exposure

    An nginx build from the first affected release of each flaw (1.9.5, 1.19.7, 0.6.18, 1.25.0 and 0.5.33) up to 1.31.8 whose configuration uses the feature: an HTTP/2 or HTTP/3 listener, the resolver with variable proxy_pass destinations plus mirror or SSI, or the mail proxy with auth_http (nginx.org, 2026-11-18; Xint, 2026-11-18). A distribution backport can fix a flaw without changing the version nginx -v reports (Xint, 2026-11-18). Veeam Software Appliance and Infrastructure Appliance 13.1 are affected by the two HTTP/2 flaws and cannot disable HTTP/2; Veeam ships the fix through Veeam Updater (Veeam, 2026-11-25). GitLab's Linux package and Docker images carry nginx 1.31.9 from 19.6.2, 19.5.9 and 19.4.11 (GitLab, 2026-11-25).

    Triage

    A large upload is a legitimate cause of an inbound-heavy connection and workers crash for unrelated reasons, so a program started by the worker is the discriminator, not the traffic shape alone (Xint, 2026-11-18).

    Detection

    Process-creation or audit telemetry for any program started by the worker's user, since a normal nginx worker runs no external programs and that is the clearest sign of success; worker exits and core dumps in the error log mark attempts, not successes (Xint, 2026-11-18; CERT-EU, 2026-11-18).

    Defender takeaway

    Move management access behind a jump box or trusted internal addresses, as Palo Alto recommends (Palo Alto Networks, 2026-10-27), and install the hotfix for your maintenance line. An interface that was internet-reachable and unpatched is a possible root compromise until those checks are clean; where a web shell or tunnel turns up, rotate what the device held: the directory bind account, HA replication keys, certificate private keys and device authentication keys (Dream Research, 2026-10-29).

    Exposure · detection
    Exposure

    Every PAN-OS firewall and Panorama appliance below its train's hotfix through its management web interface; it is reachable from the internet where the management port, or a dataplane interface with a management profile, answers from outside the administrator range (Palo Alto Networks, 2026-11-24).

    Detection

    In management-plane web access logs, very large multipart POST requests from outside the administrator range (Dream Research, 2026-10-29). A hotfix does not remove an attacker already in: on an interface that was internet-reachable and unpatched, look for a PHP file nobody deployed in a web-reachable directory of the management web server, a systemd service or rc.local entry that starts scripts from a hidden directory under /usr/local/lib, and outbound SSH from the management plane; in directory logs, bulk LDAP enumeration and password-spray bursts against all users, launched from the firewall management server (Dream Research, 2026-10-29).

It lists no workaround; Threat Prevention IDs 510046 and 510047 give limited coverage and only when management traffic is routed through a data-plane interface and decrypted, and Palo Alto warns that variations of the attack may not be detected (Palo Alto Networks PSIRT, 2026-10-14). Fixes ship per train; a unit on 11.2.14 or 11.2.15 had no fixed build when the advisory appeared, and 11.2.16, the fix for those two releases, was published on 2026-10-15 (Palo Alto Networks PSIRT, 2026-10-14). The advisory does not say how the attackers obtained the credentials the flaw requires, when exploitation began or who is behind it, and BleepingComputer says it asked Palo Alto when exploitation began, who is behind the attacks and whether attackers compromised firewalls or used them to reach internal networks (BleepingComputer, 2026-10-14).

    Exposure
    Any PA-Series or VM-Series firewall or Panorama (virtual or M-Series) on PAN-OS 10.2, 11.1, 11.2, 12.1 or 12.2 below the fixed build of its train, with no configuration needed; the exposure is greatest where the management interface accepts connections from outside trusted internal addresses (Palo Alto Networks PSIRT, 2026-10-14). BleepingComputer reads the advisory as requiring existing credentials and network access to the management interface (BleepingComputer, 2026-10-14).
    Detection
    Look at authentication and administrator-change records on the management interface, and at inbound connections to the management address in upstream firewall or provider logs, for logins from unfamiliar sources; Palo Alto's advisory FAQ lists three source addresses associated with the limited exploit attempts to compare against (Palo Alto Networks PSIRT, 2026-10-14). Root code execution means an upgrade does not evict an attacker who is already in, and the advisory gives no file or process artifact, so a device that was reachable from untrusted networks before the fix needs a compromise assessment as well as the patch.
    Defender takeaway
    Take the management interface off every network but trusted internal addresses, with a jump box as the tightest setting Palo Alto describes, and upgrade to the fixed build of each train; units on 11.2.14 and 11.2.15 upgrade to 11.2.16, which Palo Alto published on 2026-10-15 (Palo Alto Networks PSIRT, 2026-10-14).
