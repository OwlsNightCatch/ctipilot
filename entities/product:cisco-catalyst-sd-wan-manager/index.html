    2026-10-29HIGHexploitedTalos: UAT-11473 implants KeyDrift in Cisco SD-WAN controllers through CVE-2026-20127 to collect data-plane keys

    Defender takeaway

    Upgrade to the fixed releases and restrict the control components' management ports, then treat any controller that was internet-reachable on a vulnerable release as a compromise-assessment target, because Lumen dates exploitation of the flaw to late 2025, before Cisco's February disclosure, and the implant runs in the process that handles the fabric's control sessions.

    Exposure · triage · detection
    Exposure

    Every Catalyst SD-WAN Controller, Manager and Validator regardless of configuration, on-premises or in Cisco's hosted clouds, on a release below the first fixed one in the advisory's table; Cisco says controllers with ports exposed to the internet are at risk (Cisco PSIRT, 2026-10-28).

    Triage

    An aaamgr service that runs as a compiled ELF is the discriminator, because the legitimate component is a Python package and does not normally appear that way (Cisco Talos, 2026-10-28).

    Detection

    On the controller's authentication log, Cisco says to audit /var/log/auth.log for accepted public-key logins of the vmanage-admin account from addresses that are not among the configured System IPs, and to validate control-connection peering events, those of peer type vmanage first, against maintenance windows and asset inventory (Cisco PSIRT, 2026-10-28). On the host, Talos names modified runit run scripts that remount the overlay root executable and start a background script, an aaamgr service that runs a compiled, packed ELF, extra libraries mapped into vdaemon with ptrace activity against it and encrypted staging files under /var/tmp (Cisco Talos, 2026-10-28). Cisco asks for admin-tech files and a TAC case when compromise is suspected (Cisco PSIRT, 2026-10-28).

    2026-10-02CRITICALexploitedCisco confirms exploitation of an unauthenticated admin bypass in the SD-WAN controller; no workaround, fixes per train

    Defender takeaway

    Upgrade to the fixed release of the train now and remove internet reachability of the Manager in the meantime (known trusted hosts only, behind a filtering device, per Cisco's hardening guide), treating Cisco's Live Protect shield as a temporary partial layer on top of that and not as a fix; a Manager that was reachable and unpatched needs the log review and TAC check above before it is considered clean.

    Exposure · triage · detection
    Exposure

    An on-premises Manager whose web or API listener is reachable from the internet or from untrusted segments; Cisco says Managers exposed to the internet with open ports are at risk, and fixed releases exist for the 20.9 and later trains, while earlier releases must migrate (Cisco PSIRT, 2026-09-30).

    Triage

    Cisco warns that these log entries can also occur during standard operation and must be assessed against normal network posture; a viptela-reserved- name is an internal service account, so the signal is a login-path request with an encoded character from an address that is not part of the fabric (Cisco PSIRT, 2026-09-30).

    Detection

    In web and application access logs on the Manager, Cisco names two sources: serviceproxy-access.log (under /var/log/nms/containers/service-proxy/) for POSTs to the login path with an encoded character from unknown or unauthorized addresses, and vmanage-server.log for lines about that path tied to usernames starting viptela-reserved- (Cisco PSIRT, 2026-09-30). To judge whether a Manager was already accessed, Cisco says customers may open a Severity 3 TAC case with the CVE id in the title and encourages them to run request admin-tech first so the file can be provided to TAC (Cisco PSIRT, 2026-09-30).

    Adversaries may execute their own malicious payloads by hijacking environment variables the dynamic linker uses to load shared libraries.     HIGHCVE-2026-20127exploitedNATOB2

    KeyDrift: Talos reports UAT-11473 exploiting CVE-2026-20127 in Cisco Catalyst SD-WAN controllers to run an implant inside the control-plane daemon that collects data-plane keys, with infrastructure overlapping Volt Typhoon's Silent Train network

    Cisco Talos reports that UAT-11473 exploited CVE-2026-20127, an authentication bypass in the peering authentication of Cisco Catalyst SD-WAN Controller (Cisco PSIRT, 2026-10-28), and then installed a custom framework it calls KeyDrift (Cisco Talos, 2026-10-28). CISA has listed the flaw in its Known Exploited Vulnerabilities catalog since 2026-02-25 (CISA KEV, 2026-10-28). Cisco's advisory (CVSS 10.0) says an unauthenticated remote attacker can log in as an internal high-privileged non-root user and reach NETCONF to change the SD-WAN fabric configuration, and that there is no workaround (Cisco PSIRT, 2026-10-28). Cisco's advisory, revised on 2026-10-28 to link Talos's post, says its PSIRT is aware of limited exploitation (Cisco PSIRT, 2026-10-28). Lumen's Black Lotus Labs reported on 2026-10-28 that Volt Typhoon had exploited the flaw since late 2025 and after Cisco's February disclosure (Lumen Black Lotus Labs, 2026-10-28), and Talos assesses with high confidence that UAT-11473's operating infrastructure overlaps considerably with Volt Typhoon's Silent Train network (Cisco Talos, 2026-10-28).

    KeyDrift runs inside the control-plane daemon. The actor edits the runit launchers of sshd and of a look-alike aaamgr service and remounts /rootfs.rw executable: the sshd launcher starts a script that injects the PolyFlame library into every running vdaemon process by ptrace, and the aaamgr launcher runs a packed PolyFlame loader directly (Cisco Talos, 2026-10-28). PolyFlame is tasked in-band over the control-plane traffic and offers a command, file-write and file-read backdoor and an intermediate command relay; Talos recovered no hardcoded address, port or domain (Cisco Talos, 2026-10-28). A second component, LittleFilch, hooks SSL_read in vdaemon and collects peer system addresses and 32-byte values Talos assesses to be OMP-distributed IPsec data-plane keys, writing them RSA-encrypted to /var/tmp (Cisco Talos, 2026-10-28). Talos lists observed targeting as space and satellite services, defense and aerospace technology, and policy research, calls the activity historical and does not say how many controllers were affected (Cisco Talos, 2026-10-28).

    Exposure
    Every Catalyst SD-WAN Controller, Manager and Validator regardless of configuration, on-premises or in Cisco's hosted clouds, on a release below the first fixed one in the advisory's table; Cisco says controllers with ports exposed to the internet are at risk (Cisco PSIRT, 2026-10-28).
    Detection
    On the controller's authentication log, Cisco says to audit /var/log/auth.log for accepted public-key logins of the vmanage-admin account from addresses that are not among the configured System IPs, and to validate control-connection peering events, those of peer type vmanage first, against maintenance windows and asset inventory (Cisco PSIRT, 2026-10-28). On the host, Talos names modified runit run scripts that remount the overlay root executable and start a background script, an aaamgr service that runs a compiled, packed ELF, extra libraries mapped into vdaemon with ptrace activity against it and encrypted staging files under /var/tmp (Cisco Talos, 2026-10-28). Cisco asks for admin-tech files and a TAC case when compromise is suspected (Cisco PSIRT, 2026-10-28).

    Triage: an aaamgr service that runs as a compiled ELF is the discriminator, because the legitimate component is a Python package and does not normally appear that way (Cisco Talos, 2026-10-28).

    Defender takeaway
    Upgrade to the fixed releases and restrict the control components' management ports, then treat any controller that was internet-reachable on a vulnerable release as a compromise-assessment target, because Lumen dates exploitation of the flaw to late 2025, before Cisco's February disclosure, and the implant runs in the process that handles the fabric's control sessions.

    CRITICALCVE-2026-76504exploitedupdatedNATOA1

    CVE-2026-76504, Cisco Catalyst SD-WAN Manager: one percent-encoded character in the login path skips the password check and mints an admin API session, exploited in the wild (CVSS 9.8)

    Cisco published an advisory on 2026-09-30 for CVE-2026-76504, an authentication bypass in the API session management of Cisco Catalyst SD-WAN Manager that lets an unauthenticated remote attacker reach the API with the privileges of the admin user (Cisco PSIRT, 2026-09-30). Cisco states its PSIRT became aware of active exploitation in September 2026 (Cisco PSIRT, 2026-09-30), CISA added the CVE to its Known Exploited Vulnerabilities catalog the same day (CISA, 2026-09-30), and no source names an actor. The flaw affects the Manager regardless of configuration and Cisco lists no workaround (Cisco PSIRT, 2026-09-30); Cisco's revision of 2026-10-02 adds a Live Protect shield that it describes as temporary, partial protection, and says the only way to remediate is to upgrade to the first fixed release (Cisco PSIRT, 2026-09-30).

    VulnCheck's reproduction explains the mechanism. The application server decodes the request path when it matches its login security constraint, but Cisco's login module tests the raw, undecoded path for the string j_security_check before it decides whether to run the real password check, so a request to /%6a_security_check skips the password check (VulnCheck, 2026-10-01). The request then falls into a branch written for continuing an already trusted session, whose only gate is a substring match against four internal viptela-reserved- account names, and supplying any of them builds a fresh login session (VulnCheck, 2026-10-01). Two of the four accounts hit role checks on admin-only endpoints and two are expected to carry the needed permissions (VulnCheck, 2026-10-01). Cisco stresses that any single encoded character works, not only %6a (Cisco PSIRT, 2026-09-30). VulnCheck counts about 1,500 internet-exposed Managers and found no legitimate public exploit as of 2026-10-01; it rejected a fake proof-of-concept repository (VulnCheck, 2026-10-01).

    Cisco's first fixed releases are 20.9.10.1, 20.12.8.2, 20.15.6.1, 20.18.4.1, 26.1.2.1 and 26.2.1; releases earlier than 20.9 must migrate to a fixed train, and the Cisco-managed cloud service (release 20.15.605) needed no customer action (Cisco PSIRT, 2026-09-30). NCSC Switzerland posted its own advisory on 2026-09-30 and lists the flaw as actively exploited (NCSC Switzerland, 2026-09-30).

    Exposure
    An on-premises Manager whose web or API listener is reachable from the internet or from untrusted segments; Cisco says Managers exposed to the internet with open ports are at risk, and fixed releases exist for the 20.9 and later trains, while earlier releases must migrate (Cisco PSIRT, 2026-09-30).
    Detection
    In web and application access logs on the Manager, Cisco names two sources: serviceproxy-access.log (under /var/log/nms/containers/service-proxy/) for POSTs to the login path with an encoded character from unknown or unauthorized addresses, and vmanage-server.log for lines about that path tied to usernames starting viptela-reserved- (Cisco PSIRT, 2026-09-30). To judge whether a Manager was already accessed, Cisco says customers may open a Severity 3 TAC case with the CVE id in the title and encourages them to run request admin-tech first so the file can be provided to TAC (Cisco PSIRT, 2026-09-30).

    Triage: Cisco warns that these log entries can also occur during standard operation and must be assessed against normal network posture; a viptela-reserved- name is an internal service account, so the signal is a login-path request with an encoded character from an address that is not part of the fabric (Cisco PSIRT, 2026-09-30).

    Defender takeaway
    Upgrade to the fixed release of the train now and remove internet reachability of the Manager in the meantime (known trusted hosts only, behind a filtering device, per Cisco's hardening guide), treating Cisco's Live Protect shield as a temporary partial layer on top of that and not as a fix; a Manager that was reachable and unpatched needs the log review and TAC check above before it is considered clean.
    Update03 Oct 2026 04:55 UTCrun 2026-10-03T0404Z-intelsummaryimmediate_actionactionsbodysourcesevidence

    Cisco revised its advisory to version 1.1 on 2026-10-02 ("Added information about Live Protect shield availability") and now states it has released a Live Protect shield for CVE-2026-76504 "to provide temporary security coverage" while upgrades are planned (Cisco PSIRT, 2026-09-30). Cisco says the shield offers only temporary partial protection and that, once applied, a legitimate user with URI encoding might not be able to log in to the Manager (Cisco PSIRT, 2026-09-30). Cisco's Live Protect page lists the feature from Catalyst SD-WAN Control Components release 20.18.3, describes a monitoring mode that shows exploit attempts without enforcing and an enforce mode that applies the mitigation, and says Cisco creates shields for the release current when a shield is published and for the two immediately preceding releases in each supported release train that includes Live Protect, so older releases may have no shield (Cisco, 2026-09-22).     HIGHCVE-2026-20245 +2exploitedupdatedNATOA1

    CVE-2026-20245: Cisco Catalyst SD-WAN netadmin-to-root command injection exploited as a zero-day; fixed releases and a Live Protect shield available

    CVE-2026-20245 (CVSS 7.8) is a privilege escalation in the CLI of Cisco Catalyst SD-WAN Controller, Manager and Validator: an authenticated, local attacker with netadmin privileges can inject commands through a crafted file and execute them as root (Cisco PSIRT). Netadmin access requires valid credentials or exploitation of the earlier authentication bypasses CVE-2026-20182 or CVE-2026-20127 (Cisco PSIRT). Cisco became aware of exploitation in June 2026 and has seen limited cases where it resulted in a configuration change pushed to edge devices (Cisco PSIRT), NCSC Switzerland relayed the advisory (NCSC-CH, 2026-06-05), and CISA added the flaw to its Known Exploited Vulnerabilities catalog on 2026-06-09 (CISA KEV catalog, 2026-06-09). First fixed releases are 20.9.9.2, 20.12.7.2, 20.15.4.5, 20.15.5.3, 20.18.3.1 and 26.1.1.2; Cisco's Live Protect shield gives only temporary partial protection while upgrades are planned (Cisco PSIRT).

    Exposure
    Catalyst SD-WAN Controller, Manager or Validator below the first fixed release for its train, in particular Manager systems with ports exposed to the internet (Cisco PSIRT).
    Detection
    In /var/log/scripts.log, runs of the CLI upload scripts Cisco lists, vconfd_script_upload_tenant_list.sh, vconfd_script_upload_vsmart_serial_numbers.sh and vconfd_script_upload_chassis_number_file.sh (in Cisco's examples with a -cli path file under /home/admin), whose entries look the same for legitimate and malicious runs (Cisco PSIRT). In /var/log/auth.log, vmanage-admin logins from unexpected sources, admin password changes set and then reverted, and a successful su from admin to an unauthorized account; also password delta commits under /var/confd/rollback/ and the upload command in the CLI's show history (Mandiant, 2026-06-24).
    Defender takeaway
    Collect request admin-tech from each control component and retain logs before upgrading, then check for the indicators and verify the configuration of the edge devices; on a system confirmed compromised, the update alone does not resolve the vulnerability and Cisco TAC provides the remediation steps (Cisco PSIRT). Mandiant's actor restored the system configurations it modified and checked that its root account was gone, so an absent account does not clear a system (Mandiant, 2026-06-24); netadmin access on these systems should be treated as root.
