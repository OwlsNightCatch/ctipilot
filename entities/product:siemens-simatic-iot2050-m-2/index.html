    Defender takeaway

    Update every IoT2050 to V4.3.4-1 or later or uninstall Node-RED where it is not used, and take the Node-RED interface of any device off networks that untrusted hosts can reach, because exploitation takes one request and is now observed; on any exposed Node-RED, review the deployed flows for planted exec nodes and http-in endpoints.

    Exposure · triage · detection
    Exposure

    A SIMATIC IoT2050 (Advanced, Basic, M.2 or SM) below V4.3.4-1 running Industrial OS with Node-RED installed and its HTTP interface reachable by an attacker (Siemens ProductCERT, 2026-08-11); VulnCheck says Node-RED instances without adminAuth are being found and exploited automatically and that Node-RED is embedded in other ICS and OT products (VulnCheck, 2026-11-01).

    Triage

    Legitimate engineering deployments also POST to /flows; the signal is a deployment from a non-engineering address whose exec node carries encoded shell or a download-and-execute chain (an inference from the described mechanism).

    Detection

    In web or reverse-proxy access logs, POST requests to the Node-RED /flows endpoint from sources that are not engineering workstations, above all bodies that deploy an exec node carrying a base64 string piped into sh, which a filter matching only wget or curl misses; on the host, hidden files started from /dev/shm or /tmp and detached with setsid or nohup by the Node-RED process, and deployed flows with exec nodes or http-in endpoints that nobody built, since the web-shell flows survive the loss of the memory-resident implant (VulnCheck, 2026-11-01).

    Entries about Siemens SIMATIC IoT2050 M.2 (1)

    HIGHCVE-2026-58115exploitedupdatedNATOA2

    CVE-2026-58115, Siemens SIMATIC IoT2050 Advanced, Basic, M.2 and SM ship a Node-RED interface with no authentication, so one unauthenticated HTTP request runs code with maximum privileges on an OT edge gateway (CVSS 10.0); VulnCheck's canary caught exploitation

    Siemens ProductCERT published SSA-834709 on 2026-08-11 for CVE-2026-58115 in SIMATIC IoT2050 devices running Industrial OS with Node-RED installed (the current advisory, V1.1 of 2026-11-04, lists the Advanced, Basic, M.2 and SM variants): affected devices "do not enforce authentication on the Node-RED HTTP interface, allowing unauthenticated access to programming nodes that are capable of executing system commands on the server", so an unauthenticated remote attacker can create malicious flows and run code with maximum privileges. Siemens scores it 10.0 under CVSS 3.1 and 4.0 (CWE-306), names V4.3.4-1 as the fix for every earlier version, and offers uninstalling Node-RED or hardening it per its User Guide as interim mitigations (Siemens ProductCERT, 2026-08-11). CERT-FR and NCSC-NL carried the advisory in August and list only the Advanced variant (CERT-FR, 2026-08-12; NCSC-NL, 2026-08-11).

    VulnCheck reports that on 2026-10-30 one of its canaries caught an attacker exploiting CVE-2026-58115 with a single POST to the Node-RED /flows endpoint: an inject node wired to an exec node ran a base64-wrapped shell command that downloaded a Linux bot into the RAM-backed /dev/shm as a hidden file and started it detached (VulnCheck, 2026-11-01). By 2026-11-01 the same address had produced 16 events against this CVE with further payloads, among them flows that expose an http-in endpoint wired to an exec node as a persistent web shell; VulnCheck did not retrieve the bot, so its function is unknown, and it reads the address as opportunistic mass-scanning infrastructure rather than a campaign (VulnCheck, 2026-11-01). The target was a canary, not a Siemens device, and CISA's catalog did not list the flaw as VulnCheck wrote (VulnCheck, 2026-11-01); The Register relays the finding (The Register, 2026-11-02).

    Exposure
    A SIMATIC IoT2050 (Advanced, Basic, M.2 or SM) below V4.3.4-1 running Industrial OS with Node-RED installed and its HTTP interface reachable by an attacker (Siemens ProductCERT, 2026-08-11); VulnCheck says Node-RED instances without adminAuth are being found and exploited automatically and that Node-RED is embedded in other ICS and OT products (VulnCheck, 2026-11-01).
    Detection
    In web or reverse-proxy access logs, POST requests to the Node-RED /flows endpoint from sources that are not engineering workstations, above all bodies that deploy an exec node carrying a base64 string piped into sh, which a filter matching only wget or curl misses; on the host, hidden files started from /dev/shm or /tmp and detached with setsid or nohup by the Node-RED process, and deployed flows with exec nodes or http-in endpoints that nobody built, since the web-shell flows survive the loss of the memory-resident implant (VulnCheck, 2026-11-01).

    Triage: legitimate engineering deployments also POST to /flows; the signal is a deployment from a non-engineering address whose exec node carries encoded shell or a download-and-execute chain (an inference from the described mechanism).
