    Defender insights

    What each entry about F5 NGINX Plus tells a defender to do, newest first.

    2026-11-19HIGHnginx2root: five unauthenticated flaws reach worker RCE, Rapid7 PoC public; update to 1.31.10, 1.30.8, Plus 37.3.1.1

    Defender takeaway

    Update and restart nginx, because a configuration reload does not replace the running executable; disabling HTTP/2 on exposed listeners blocks only the two HTTP/2 flaws (Xint, 2026-11-18) and, if it stays on elsewhere, leaves connection pressure (Unit 42, 2026-11-24), and Xint gives interim measures for the others: a fixed upstream group in place of request-time DNS lookups for CVE-2026-123634, no QUIC listeners for CVE-2026-121810 and bound or firewalled mail listeners for CVE-2026-113425 (Xint, 2026-11-18). An empty execution-audit result after the update cannot rule out an earlier compromise, and Xint chained CVE-2026-123007 with a separate Linux kernel SCTP flaw, unpatched when it published, to reach root on the host and escape a Docker container; hosts that do not use SCTP can block the module from loading (Xint, 2026-11-18).

    Exposure · triage · detection
    Exposure

    An nginx build from the first affected release of each flaw (1.9.5, 1.19.7, 0.6.18, 1.25.0 and 0.5.33) up to 1.31.8 whose configuration uses the feature: an HTTP/2 or HTTP/3 listener, the resolver with variable proxy_pass destinations plus mirror or SSI, or the mail proxy with auth_http (nginx.org, 2026-11-18; Xint, 2026-11-18). A distribution backport can fix a flaw without changing the version nginx -v reports (Xint, 2026-11-18). Veeam Software Appliance and Infrastructure Appliance 13.1 are affected by the two HTTP/2 flaws and cannot disable HTTP/2; Veeam ships the fix through Veeam Updater (Veeam, 2026-11-25). GitLab's Linux package and Docker images carry nginx 1.31.9 from 19.6.2, 19.5.9 and 19.4.11 (GitLab, 2026-11-25).

    Triage

    A large upload is a legitimate cause of an inbound-heavy connection and workers crash for unrelated reasons, so a program started by the worker is the discriminator, not the traffic shape alone (Xint, 2026-11-18).

    Detection

    Process-creation or audit telemetry for any program started by the worker's user, since a normal nginx worker runs no external programs and that is the clearest sign of success; worker exits and core dumps in the error log mark attempts, not successes (Xint, 2026-11-18; CERT-EU, 2026-11-18).

    2026-10-20NOTABLEThree configuration-dependent NGINX heap flaws (CVSS 9.2) are fixed in 1.30.6, 1.31.7 and Debian trixie, not bookworm

    Defender takeaway

    Upgrade to 1.30.6 or 1.31.7 (NGINX Plus 37.0.5.1 or 37.1.0.1), starting with internet-facing instances whose configuration matches a pattern above; until a package is fixed, F5's workarounds are aio off or ssi off for CVE-2026-97205, named captures confined to the matching block for CVE-2026-93479, and no alias in the affected locations or no $request_filename reference for CVE-2026-15176 (Daily CyberSecurity, 2026-10-14).

    Exposure · detection
    Exposure

    Nginx 0.1.29 to 1.31.6 depending on the flaw, with branches older than 1.30 outside the range of CVE-2026-93479, and NGINX Plus R33 to R36 and 37.0.0 to 37.1.0 for the first two (nginx.org, 2026-10-14; Centre for Cybersecurity Belgium, 2026-10-19). A build is affected only if its configuration matches one of the patterns above, which nginx -T prints with every include; the version string alone is not enough, because distribution packages carry their own fixes. Debian fixed trixie with DSA-6575-1 (trixie-security 1.26.3-3+deb13u10) (Debian Security Tracker, 2026-10-25), while its tracker still marks bookworm (1.22.1-9+deb12u10) vulnerable (Debian Security Tracker, 2026-10-20).

    Detection

    F5 says the overflow leads to a worker restart, so process-supervision and error-log telemetry for unexpected worker exits and respawn bursts, matched against the unauthenticated requests to the affected locations in the access log, is the signal (Debian Security Tracker, 2026-10-20). Patching does not remediate a compromise that already happened (Centre for Cybersecurity Belgium, 2026-10-19).

    2026-07-20HIGHF5 out-of-band patches a 15-year-old pre-auth heap overflow in nginx's script engine; credited researcher shows it reaches RCE

    Defender takeaway

    Nginx and NGINX Plus terminate internet-facing traffic across virtually every public-sector e-government portal, CI-operator API gateway and public service, so exposure is broad even though the trigger depends on a specific config pattern. Because F5's advisory understates the ceiling as DoS, treat this as a pre-auth RCE candidate on exposed edge and prioritise the out-of-band patch on that basis, not on the DoS reading. The config-pattern dependency is the discriminator that turns "patch everything" into "know your exposure first": most nginx deployments will not combine a regex capture with a later regex-map reference in one evaluated string, and the ones that do are the immediate-risk set. The public PoC gives each mode its own signature. The crash mode and a missed RCE attempt show as anomalously large or malformed requests immediately followed by nginx worker-process crashes and restarts on edge hosts, and a miss repeats the same way because the respawned worker keeps the heap layout. The leak mode is a single GET whose response body carries uninitialised heap memory and does not crash the worker (Stan Shaw, revised since). A two-request info-leak-GET-then-overflow-POST shape is inferable from the mechanism but not a source-stated detection rule. The author's public static config scanner (github.com/0xCyberstan/CVE-2026-42533-Config-Scanner) follows includes, handles cross-directive triggering and distinguishes exploitable from safe ordering; run it against every internet-facing config now to enumerate which vhosts were exposed before you patch.

    HIGHCVE-2026-123007 +10updatedNATOA1

    NGINX nginx2root: five unauthenticated memory-corruption flaws (CVE-2026-123007 and CVE-2026-123633 in HTTP/2, CVE-2026-121810 in HTTP/3, CVE-2026-123634 in the resolver, CVE-2026-113425 in the mail proxy) can lead to code execution as the worker process; fixed in nginx 1.31.9 and 1.30.7 and NGINX Plus 37.3.0.1 and 37.0.8.1, Rapid7 proof of concept public, no exploitation reported (CVSS 4.0 9.2)

    F5 and the nginx project published the nginx2root fixes (nginx.org, 2026-11-18); CERT-EU counts five vulnerabilities, all able to lead to unauthenticated code execution with the privileges of the NGINX worker process (CERT-EU, 2026-11-18). CVE-2026-123007 is an HTTP/2 flow-control overflow: cancelling queued response data makes nginx use an invalid length when copying a later response (Rapid7, 2026-11-18), and Wiz demonstrated code execution on nginx serving ordinary static files (Wiz Research, 2026-11-18).

    Rapid7 published a working proof of concept for CVE-2026-123007 against nginx 1.31.8; the exploit needs about 128 GB of HTTP/2 traffic and likely fails with concurrent clients (Rapid7, 2026-11-18; Rapid7 repository, 2026-11-18). CERT-EU reports no exploitation in the wild and NCSC.ch rates exploitation unknown with a proof of concept available (CERT-EU, 2026-11-18; NCSC.ch, 2026-11-18).

    The memory-corruption fixes are in nginx 1.31.9 and 1.30.7 (nginx.org, 2026-11-18); nginx 1.31.10 and 1.30.8 of 2026-11-23 add a fix for CPU exhaustion when ssl_early_data is on (CVE-2026-132779, affecting 1.21.4 to 1.31.9 per nginx.org, 2026-11-27), as do NGINX Plus 37.3.1.1 and 37.0.9.1 (nginx.org, 2026-11-23; nginx.org, 2026-11-23; F5 NGINX Plus release notes, 2026-11-23). CERT.at lists NGINX Plus 37.3.0.1 and 37.0.8.1 as fixing four of the five (CVE-2026-123007, CVE-2026-121810, CVE-2026-123633 and CVE-2026-113425); it also says 37.2.0.1 and 37.0.7.1 already carry the fix for CVE-2026-123633 but stay affected by CVE-2026-123007 and CVE-2026-121810, and NGINX Plus R33 to R36 have no update (translated from German) (CERT.at, 2026-11-18).

    NOTABLECVE-2026-15176 +4updatedNATOA2

    CVE-2026-15176 / CVE-2026-93479 / CVE-2026-97205, NGINX Open Source and NGINX Plus: three unauthenticated heap-corruption flaws rated CVSS 4.0 9.2, reachable only in specific configurations and fixed in 1.30.6 and 1.31.7

    nginx's change log for 1.30.6, dated 14 October 2026, lists five security fixes, which nginx.org's advisories page ties to 1.30.6 (stable) and 1.31.7 (mainline) (nginx.org change log, 2026-10-14; nginx.org, 2026-10-14); three of them are CVE-2026-15176, a heap buffer overflow in the core module that CCB describes as reachable where a location uses alias together with rewrite and a set or return directive referencing $request_filename, or where $request_filename appears in an access-log format; CVE-2026-93479, a heap buffer overflow in script evaluation that affects configurations whose regex map captures are referenced in root or an access-log format before the map's output variable, or that use a non-cacheable variable in a string expression; and CVE-2026-97205, a use-after-free when asynchronous file I/O is enabled, which Daily CyberSecurity relays from F5 as triggered by an SSI page with include virtual commands (Centre for Cybersecurity Belgium, 2026-10-19; Daily CyberSecurity, 2026-10-14). Each is scored CVSS 4.0 9.2 and reachable by an unauthenticated network attacker, the first two under conditions beyond the attacker's control, with CCB's warning and vector covering the first two and Daily CyberSecurity all three (Centre for Cybersecurity Belgium, 2026-10-19; Daily CyberSecurity, 2026-10-14). F5's CNA text says the overflow may restart the worker process and that attackers can execute code where ASLR is disabled or can be bypassed (Debian Security Tracker, 2026-10-20). Daily CyberSecurity reports that F5 has confirmed no public proof of concept for any of the three, and no exploitation is reported (Daily CyberSecurity, 2026-10-14). Help Net Security reports that VulnCheck flagged exploitation attempts against an earlier NGINX flaw, CVE-2026-42945, three days after the flaw and its proof of concept were public (Help Net Security, 2026-05-18). The other two are CVE-2026-95101 (with HTTP/3, part of an unknown frame might be treated as the request body, bypassing client_max_body_size or injecting data into the proxied request) and CVE-2026-97629 (with TLS session ticket key rotation, one key was left uninitialised, which might allow forging a session) (nginx.org change log, 2026-10-14); nginx.org rates all five medium (nginx.org, 2026-10-14).

    Exposure
    Nginx 0.1.29 to 1.31.6 depending on the flaw, with branches older than 1.30 outside the range of CVE-2026-93479, and NGINX Plus R33 to R36 and 37.0.0 to 37.1.0 for the first two (nginx.org, 2026-10-14; Centre for Cybersecurity Belgium, 2026-10-19). A build is affected only if its configuration matches one of the patterns above, which nginx -T prints with every include; the version string alone is not enough, because distribution packages carry their own fixes. Debian fixed trixie with DSA-6575-1 (trixie-security 1.26.3-3+deb13u10) (Debian Security Tracker, 2026-10-25), while its tracker still marks bookworm (1.22.1-9+deb12u10) vulnerable (Debian Security Tracker, 2026-10-20).
    Detection
    F5 says the overflow leads to a worker restart, so process-supervision and error-log telemetry for unexpected worker exits and respawn bursts, matched against the unauthenticated requests to the affected locations in the access log, is the signal (Debian Security Tracker, 2026-10-20). Patching does not remediate a compromise that already happened (Centre for Cybersecurity Belgium, 2026-10-19).
    Defender takeaway
    Upgrade to 1.30.6 or 1.31.7 (NGINX Plus 37.0.5.1 or 37.1.0.1), starting with internet-facing instances whose configuration matches a pattern above; until a package is fixed, F5's workarounds are aio off or ssi off for CVE-2026-97205, named captures confined to the matching block for CVE-2026-93479, and no alias in the affected locations or no $request_filename reference for CVE-2026-15176 (Daily CyberSecurity, 2026-10-14).

    HIGHCVE-2026-42533updatedNATOB2

    CVE-2026-42533, nginx / NGINX Plus: PCRE capture-clobber pre-auth heap overflow, researcher demonstrates RCE beyond F5's DoS-only framing (CVSS 9.2)

    CVE-2026-42533 is a missing save/restore of PCRE capture state across nginx's two-pass script-expression engine. nginx evaluates a compiled expression in a LEN pass that measures the result size and a VALUE pass that writes into a buffer sized by the LEN pass, and both passes resolve capture references such as $1 by reading r->captures, a shared mutable array on the request (Stan Shaw, 2026-07-19). When a map directive using a regex pattern is evaluated between the two passes, i.e. a config where a regex capture source (location, server_name, rewrite, or if) produces captures that appear before a regex map variable in the same evaluated buffer; the map's own regex evaluation clobbers the shared capture state, so the LEN and VALUE passes disagree on the buffer size. The result is an unauthenticated, pre-auth heap buffer overflow triggerable by crafted HTTP requests, reachable from any directive that evaluates a compiled expression (proxy_set_header, fastcgi_param, return, add_header, rewrite, set, root, alias, access_log, and more). The clobber is not specific to one call site: the same LEN/VALUE pattern appears in at least 13 independent call sites across 9 source files (Stan Shaw, 2026-07-19).

    The bug has existed since nginx 0.9.6 (2011, when map gained regex support). F5 (which owns nginx) shipped an out-of-band fix on 2026-07-15/16 in nginx 1.30.4 (stable) and 1.31.3 (mainline), and in NGINX Plus R36 P7 and release 37.0.3.1, rating it CVSS 4.0 9.2 (critical) / CVSS 3.1 8.1 (high) (SecurityWeek, 2026-07-16). F5's advisory frames real-world risk on ASLR-enabled systems as primarily denial-of-service, a characterization the credited discoverer directly disputes (Stan Shaw, 2026-07-19; The Hacker News, 2026-07-19). The credited discoverer, Stan Shaw, disputes the DoS-only framing and demonstrates two chainable primitives: an information-leak variant (a clobbered capture smaller than the original) that returns uninitialised heap residue (on Ubuntu 24.04 with glibc 2.39 a libc pointer at offset 0x08 and a heap pointer at 0x10, enough to defeat ASLR in one unauthenticated GET) and a heap-overflow variant (a clobbered capture larger than the original) that writes attacker-controlled request-body content past the buffer and hijacks control flow through nginx's pool-cleanup mechanism, which the original post reported at 10/10 reliability with full ASLR enabled (Stan Shaw, 2026-07-19). The revised write-up refines that figure, as the update of 2026-09-29 below records. "A reader of the F5 advisory could reasonably conclude this is DoS-only on default systems. It is not," Shaw told The Hacker News (2026-07-19).

    The author held back the proof of concept and the full write-up for about three weeks after the patch and has since published both (see the update below); no in-the-wild exploitation has been reported and the CVE is not in CISA KEV. The precedent the author cites is directly relevant: CVE-2026-42945 ("Rift"), a weaker flaw in the same nginx script engine that only mattered with ASLR disabled, "saw active exploitation shortly after its PoC dropped" (Stan Shaw, 2026-07-19; Rift's confirmed in-the-wild exploitation was covered here on 2026-05-18). This bug does not require ASLR to be off, so the same trajectory should be assumed now that the PoC is public.

    Defender takeaway
    Nginx and NGINX Plus terminate internet-facing traffic across virtually every public-sector e-government portal, CI-operator API gateway and public service, so exposure is broad even though the trigger depends on a specific config pattern. Because F5's advisory understates the ceiling as DoS, treat this as a pre-auth RCE candidate on exposed edge and prioritise the out-of-band patch on that basis, not on the DoS reading. The config-pattern dependency is the discriminator that turns "patch everything" into "know your exposure first": most nginx deployments will not combine a regex capture with a later regex-map reference in one evaluated string, and the ones that do are the immediate-risk set. The public PoC gives each mode its own signature. The crash mode and a missed RCE attempt show as anomalously large or malformed requests immediately followed by nginx worker-process crashes and restarts on edge hosts, and a miss repeats the same way because the respawned worker keeps the heap layout. The leak mode is a single GET whose response body carries uninitialised heap memory and does not crash the worker (Stan Shaw, revised since). A two-request info-leak-GET-then-overflow-POST shape is inferable from the mechanism but not a source-stated detection rule. The author's public static config scanner (github.com/0xCyberstan/CVE-2026-42533-Config-Scanner) follows includes, handles cross-directive triggering and distinguishes exploitable from safe ordering; run it against every internet-facing config now to enumerate which vhosts were exposed before you patch.
    Update29 Sep 2026 23:32 UTCrun 2026-09-29T2134Z-auditsummarytagscvesevidencesourcing_notebody

    The proof of concept is public. Three weeks after the patch the discoverer released it with the full exploitation write-up, writing that "the patch has shipped and deployment windows have passed, so the proof of concept and the full exploitation write-up are now public" (Stan Shaw, revised since). The PoC has three modes, crash, leak and RCE, plus a deterministic RCE variant. The crash and leak modes reproduce on any build of an affected version, which makes a worker crash and a heap-pointer leak available to anyone who can reach a vulnerable configuration. The RCE mode was developed against nginx 1.30.1 built from source on Ubuntu 24.04 with full ASLR, and the author notes that the deterministic variant depends on a controlled configuration whose heap layout is reproducible, which a stock deployment is not (0xCyberstan, CVE-2026-42533-POC; Stan Shaw, revised since). No in-the-wild exploitation has been reported and the CVE is not in CISA's KEV catalog as of 2026-09-29. The precedent the author gave for holding the PoC back, CVE-2026-42945, was exploited shortly after its own PoC appeared, so an unpatched instance with a regex map configuration should be treated as exposed to at least the crash and the leak today.

    The revised write-up also refines the reliability figure the original post gave as 10/10. The leak worked on 100 out of 100 requests, but on a stock deployment a single exploit attempt lands "about two thirds of the time", and a miss crashes the worker, whose respawn inherits the same heap layout and misses the same way (Stan Shaw, revised since). Repeated worker crashes on a vulnerable configuration are therefore a plausible trace of a failed attempt.
