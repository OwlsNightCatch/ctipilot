    What each entry about Microsoft 365 tells a defender to do, newest first.

    2026-11-14NOTABLEReliaQuest: Luna Moth has staff hand over a Graph token from Copilot on a video call; no sign-in event follows

    Defender takeaway

    Disable developer tools through Group Policy on managed browsers and block Graph Explorer and the browser net-export pages, because the handoff depends on users reading tokens out of browsers; pilot Continuous Access Evaluation with strict location enforcement, defining every egress address including secure web gateway ranges as a named location; and tell staff that IT will never ask for developer tools or tokens and that they should verify IT requests by callback (ReliaQuest, 2026-11-12). ReliaQuest notes that default Microsoft access tokens last 60 to 90 minutes and that Continuous Access Evaluation can extend supported tokens to as long as 28 hours (ReliaQuest, 2026-11-12).

    Exposure · detection
    Exposure

    A Microsoft 365 tenant whose staff can open browser developer tools and take calls from outside IT, with Microsoft 365 Copilot reachable in the browser; ReliaQuest says law firms are the current focus and other sectors holding similarly sensitive data could be next (ReliaQuest, 2026-11-12).

    Detection

    With no malware or endpoint alert, the evidence is ordinary-looking events, a blank email, an external video-call session and Graph access from an unfamiliar address, which ReliaQuest says to correlate across email, video-call and Microsoft 365 logs; a video-call screen share, a Copilot session, a visit to a text-sharing site and Graph file access from an unfamiliar address are each ordinary alone and together can indicate a token handoff (ReliaQuest, 2026-11-12). Video-call platform logs, web proxy or DNS logs and Microsoft 365 audit logs each record part of the handoff but rarely reach a detection pipeline (ReliaQuest, 2026-11-12).

    2026-11-13NOTABLEHuntress: device-code phishing posing as a Teams booking skips URL reputation checks; hunt Cmsi:Cmsi sign-ins

    Defender takeaway

    Restrict or monitor device-code authentication where it is not needed, enforce phishing-resistant MFA, and investigate unfamiliar device sign-ins from unmanaged devices, new regions or residential proxy networks (Huntress, 2026-11-12).

    Exposure · triage · detection
    Exposure

    A Microsoft 365 tenant that allows the device-code flow for users with no device that needs it, particularly accounts without MFA.

    Triage

    Huntress treats a device-code prompt that follows a link, a booking request or another unexpected interaction as suspicious, and the captured session shows up as a replay from another ASN and region within one session (Huntress, 2026-11-12).

    Detection

    In Entra sign-in logs, a successful device-code authentication shown as Cmsi:Cmsi, programmatic user agents such as python-requests and node afterwards (often only in the non-interactive log), and a change of ASN and region inside the same session ID; in mail and proxy telemetry, a Google share link that redirects to a freshly registered lookalike domain (Huntress, 2026-11-12).

    2026-11-11HIGHexploitedOutlook zero-day CVE-2026-124194 exploited: a crafted message file leaks authentication data; install the Office update

    Defender takeaway

    Install the November Office update now rather than in the normal cycle, because the flaw is exploited and a patched machine still leaves earlier captured credentials valid; reset the accounts of users whose Outlook reached an external destination.

    Exposure · triage · detection
    Exposure

    Every Outlook desktop below those builds; the build shows under File, Office Account, and the delivery path is mail or a download that carries a message file, which the user must open.

    Triage

    Outlook legitimately contacts SharePoint, OneDrive and corporate file servers; the discriminator is an external, non-corporate destination preceded by the opening of a message file.

    Detection

    Outbound connections to non-corporate addresses over SMB (TCP 445), WebDAV or HTTPS from OUTLOOK.EXE or from the user's session shortly after a message-file attachment is opened, authentication events carrying the user's identity toward an external address, and mail-gateway logs for message-file attachments from unknown senders. Because the credential material may already have been captured before the patch, the check also covers the weeks before it. The disclosed material is the user's NTLMv2 hash, which can be cracked offline or used to impersonate the user, so also watch for later logons by the account from unfamiliar hosts.

    2026-11-06HIGHEntra app-credential abuse: agents hunt GitHub for secrets, an operator reaches MSP clients, government among them

    Defender takeaway

    Inventory the client secrets on app registrations and hunt the sign-in pattern above in every tenant you run or manage, MSP-managed communal tenants included; on an affected app remove every client secret, certificate and federated credential, including those the actor added, and rotate what any Key Vault it could read holds, because tokens already issued stay valid until expiry (Microsoft Threat Intelligence, 2026-11-05).

    Exposure · triage · detection
    Exposure

    Any Entra tenant, an MSP's or a customer's, that holds app registrations with client secrets, above all multitenant, delegated-admin and Partner Center applications and Azure DevOps service connections, security-tool integration apps among those abused (Todyl, 2026-11-03); Conditional Access for workload identities needs the Workload ID Premium licence and covers only single-tenant apps (Microsoft Threat Intelligence, 2026-11-05).

    Triage

    The invalid-secret and expired-secret errors alone only show that someone holds an old or wrong credential for the app; Microsoft treats a failure followed by a success as the urgent case (Microsoft Threat Intelligence, 2026-11-05).

    Detection

    In Entra service-principal and non-interactive sign-in logs, an invalid-secret or expired-secret error for an application followed by a success, one address authenticating as service principals in several unrelated tenants within 24 hours, an Azure Resource Manager token followed at once by a Key Vault token and then by previously unused apps authenticating, and failed service-principal sign-ins from hosting space that never succeed, which success-only logic misses (Todyl, 2026-11-03). In Azure DevOps auditing, personal access token creation and first use, federated service connections and pipeline edits (Microsoft Threat Intelligence, 2026-11-05).

    2026-11-06NOTABLEMicrosoft Q3 email report: overrides let authentication-failing spoofed mail through; SVG CAPTCHA phishing returns

    Defender takeaway

    Review the tenant and user overrides in your mail protection for entries that cover well-known service sender domains, because the override, not the detection, decided delivery; Microsoft's own advice is to check its recommended settings for Exchange Online Protection and Defender for Office 365 (Microsoft Threat Intelligence, 2026-11-05).

    Exposure · detection
    Exposure

    A Microsoft 365 tenant that has tenant- or user-level allow or override entries covering the sender domains of widely used business services, since a message that fails authentication and is detected as malicious can still be delivered when such an override applies.

    Detection

    In mail-flow and message-trace telemetry, delivered messages that claim a business service's domain but fail SPF, DKIM and DMARC, together with the override that applied; in mail-gateway logs, SVG attachments that lead to a CAPTCHA page; in Teams audit, first-contact chats and calls from external tenants whose display name is a personal name but whose account address carries help-desk or service wording; in sign-in logs, device-code flow sign-ins.

    2026-11-05HIGHVaud: device-code phishing against Microsoft 365 is running in Romandie; several organisations already affected

    Defender takeaway

    Where the tenant has no documented need for device code flow, Microsoft recommends blocking it with a Conditional Access policy, testing in report-only mode and auditing existing use first (Microsoft Learn, 2026-04-07). Tell users never to enter a Microsoft login code at a third party's request, and that anyone who has entered a code or validated an authentication request must call IT support at once, which is the canton's own instruction (Canton of Vaud, 2026-11-04).

    Exposure · triage · detection
    Exposure

    Any Microsoft 365 tenant whose users can complete the device code flow, which Microsoft describes as meant for devices without local input such as shared devices or digital signage and as a high-risk method that phishing can use (Microsoft Learn, 2026-03-24).

    Triage

    Microsoft documents device code sign-in for shared devices and signage; a device-code sign-in by a user who has no such device, soon after that user received a mailed link, falls outside that use (Microsoft Learn, 2026-03-24).

    Detection

    Mail, web proxy and DNS telemetry for links to workers.dev subdomains of the structure above; in the Entra sign-in logs, device code events found with the authentication protocol filter (Microsoft Learn, 2026-03-24). Microsoft says protocol tracking persists through token refreshes, so later sign-ins in the same session can fall under an authentication-flows policy, and it records an original transfer method property in the activity details of the Conditional Access sign-in logs (Microsoft Learn, 2026-03-24).

Phishing for information is different from Phishing in that the objective is gathering data from the victim rather than executing malicious code.

    Adversaries may use voice communications to elicit sensitive information that can be used during targeting.
