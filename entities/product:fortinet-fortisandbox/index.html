    NOTABLECVE-2026-107656 +1updatedNATOA2

    Fortinet FortiSandbox GUI authentication bypass (CVE-2026-107656, CVSS 9.6) and FortiSIEM 7.5.0 unauthenticated path traversal to code execution (CVE-2026-106173, CVSS 9.4): both critical, fixed 2026-10-13, neither reported exploited

    Fortinet's PSIRT published two critical advisories for security-operations products on 2026-10-13. FG-IR-26-185 describes an authentication bypass through an alternate path or channel in the FortiSandbox GUI that a remote unauthenticated attacker can trigger with crafted HTTP requests, listed as CVE-2026-107656 with CVSS 3.1 9.6 and an impact of unauthorized code or command execution (Fortinet PSIRT FG-IR-26-185, 2026-10-13). FG-IR-26-180 describes a path traversal in the FortiSIEM phQueryMaster service ("arbitrary file write in grpc phQueryMaster") that lets an unauthenticated attacker execute unauthorized code or commands through specially crafted packets, listed as CVE-2026-106173 with CVSS 3.1 9.4 (Fortinet PSIRT FG-IR-26-180, 2026-10-13). Both pages state that neither flaw is known to be exploited, and both carry temporal vector strings with an exploit-code maturity of functional (FortiSandbox) and high (FortiSIEM) that the advisories do not explain (Fortinet PSIRT FG-IR-26-185, 2026-10-13; Fortinet PSIRT FG-IR-26-180, 2026-10-13).

    For FortiSandbox, versions 5.0.0 through 5.0.6 and 4.4.0 through 4.4.9 are affected and 5.0.7 and 4.4.10 fix it; 5.2 is not affected; FortiSandbox PaaS 5.0.0 through 5.0.6 is affected, and every PaaS 4.4 version must migrate to a fixed release (Fortinet PSIRT FG-IR-26-185, 2026-10-13). The ranges include 5.0.6 and 4.4.9 (Fortinet PSIRT FG-IR-26-185, 2026-10-13). Defused reported exploitation of three FortiSandbox flaws in June, CVE-2026-39813, CVE-2026-39808 and CVE-2026-25089 (Help Net Security, 2026-06-16), and the build that fixes CVE-2026-25089 is 5.0.6 on the 5.0 branch and 4.4.9 on 4.4 (Fortinet PSIRT FG-IR-26-141, 2026-06-09), so a unit patched for that flaw is not patched for this one. For FortiSIEM only 7.5.0 is affected and 7.5.1 fixes it; 7.6 and FortiSIEM Cloud are not affected, and Fortinet's workaround is to restrict access on tcp port 27918 (Fortinet PSIRT FG-IR-26-180, 2026-10-13).

    Horizon3.ai published a deep dive and a proof of concept for the FortiSIEM flaw on 2026-10-20: the phQueryMaster gRPC service listens on tcp 27918 on every interface and does not request a client certificate, so any remote client can reach its SendQueryResult method, whose query-id metadata is joined into a file path without validation, and a NUL byte in it discards the suffix the service appends, which turns the write into an overwrite of a chosen file (Horizon3.ai, 2026-10-20). Horizon3 uses it to replace a health-check script that a cron job runs every 60 seconds, which gives code execution within a minute (Horizon3.ai, 2026-10-20; The Hacker News, 2026-10-20). Fortinet's advisory says the flaw is not known to be exploited (Fortinet PSIRT FG-IR-26-180, 2026-10-13).

    Exposure
    FortiSandbox appliances, virtual machines and PaaS instances on the affected ranges whose GUI an unauthenticated client can reach, and FortiSIEM 7.5.0 nodes where tcp port 27918 is reachable from outside the deployment (Fortinet PSIRT FG-IR-26-185, 2026-10-13; Fortinet PSIRT FG-IR-26-180, 2026-10-13).
    Detection
    Fortinet publishes no indicator or post-compromise check for either flaw (Fortinet PSIRT FG-IR-26-185, 2026-10-13; Fortinet PSIRT FG-IR-26-180, 2026-10-13). The behaviors to look for follow from the mechanisms: on FortiSandbox, administrator-level GUI actions that have no matching login event, and on FortiSIEM, connections to tcp port 27918 from addresses outside the deployment followed by new files or processes on the node. Horizon3 found no application logs that would reveal exploitation and advises inspecting the write and modification timestamps of a script that a cron job runs, such as the charting health-check script, and of other files of interest such as the license tool, for any that do not match the surrounding files (Horizon3.ai, 2026-10-20).

    Move FortiSandbox to 5.0.7 or 4.4.10 (PaaS 4.4 migrates) and FortiSIEM 7.5.0 to 7.5.1, treating the FortiSIEM upgrade or the port restriction as out of cycle now that a proof of concept is public; a FortiSandbox at 5.0.6 or 4.4.9 still needs this upgrade (Fortinet PSIRT FG-IR-26-185, 2026-10-13; Fortinet PSIRT FG-IR-26-180, 2026-10-13). Fortinet's only workaround is for FortiSIEM, restricting access on tcp port 27918 (Fortinet PSIRT FG-IR-26-180, 2026-10-13); it names none for FortiSandbox, where limiting GUI access to an administrator network is the usual precaution rather than a Fortinet instruction.

    HIGHCVE-2026-25089 +2exploitedupdatedNATOA2

    CVE-2026-25089, Fortinet FortiSandbox: unauthenticated OS command injection in the web UI's VNC-launch handler (CVSS 9.8 base)

    Fortinet patched CVE-2026-25089 (CWE-78) on 2026-06-09: the FortiSandbox web interface's "start vnc" feature passes attacker-controlled JSON input to an OS command, a second-order injection that "may allow an unauthenticated attacker to execute unauthorized commands via specifically crafted HTTP requests" (Fortinet PSIRT FG-IR-26-141, 2026-06-09). Affected are FortiSandbox 5.0.0 through 5.0.5 and 4.4.0 through 4.4.8 plus FortiSandbox Cloud and PaaS 5.0.4 through 5.0.5; the fix is 5.0.6 or 4.4.9, and the 5.2 branch is not affected (Fortinet PSIRT FG-IR-26-141, 2026-06-09). CCB Belgium urged immediate patching and warned that a public proof-of-concept raises the likelihood of exploitation (CCB Belgium, 2026-06-11).

    The same upgrade closes two April flaws that Defused reported under attack alongside it. CVE-2026-39813 is a path traversal in the JRPC API that lets an unauthenticated attacker bypass authentication on 5.0.0 through 5.0.5 and 4.4.0 through 4.4.8 (Fortinet PSIRT FG-IR-26-112, 2026-04-14). CVE-2026-39808 is an OS command injection through an API endpoint that gives an unauthenticated attacker command execution on 4.4.0 through 4.4.8, with 5.0 not affected (Fortinet PSIRT FG-IR-26-100, 2026-04-14). Fortinet's three advisories give all three flaws the same CVSS 3.1 vector, which scores 9.8 before the temporal adjustment behind the 9.1 they display (Fortinet PSIRT FG-IR-26-141, 2026-06-09) (Fortinet PSIRT FG-IR-26-112, 2026-04-14) (Fortinet PSIRT FG-IR-26-100, 2026-04-14). No exploitation was reported as of the 2026-06-09 disclosure. Defused then reported attacks on all three, and Help Net Security noted Fortinet had not yet confirmed them (Help Net Security, 2026-06-16). CISA added CVE-2026-25089 and CVE-2026-39808 to its Known Exploited Vulnerabilities catalog on 2026-07-16 (CISA KEV catalog, 2026-07-16), while Fortinet's three advisories list none of the flaws as known exploited (Fortinet PSIRT FG-IR-26-141, 2026-06-09) (Fortinet PSIRT FG-IR-26-112, 2026-04-14) (Fortinet PSIRT FG-IR-26-100, 2026-04-14).

    Help Net Security describes FortiSandbox as a platform that other Fortinet security products depend on for threat verdicts to enforce blocking decisions and trigger automated responses (Help Net Security, 2026-06-16).
