    HIGHCVE-2026-109618 +2exploitedupdatedNATOA2

    CVE-2026-109618 / CVE-2026-109619 and CVE-2026-123039, Check Point Force, Spark and Cloud firewalls: PHP2Shell on the Mobile Access and VPN web interfaces, chained with a local root escalation, is exploited against unpatched gateways (implant, ESXi wiper); the fix is in Jumbo takes R81.20 take 174, R82 take 132, R82.10 take 52 and R82.20 take 14

    Check Point's advisory sk1000302 says that under certain circumstances the PHP flaws CVE-2026-109618 and CVE-2026-109619, both scored CVSS 9.2, may allow remote code execution through firewall web interfaces; affected are Force, Spark and Cloud firewalls that use Mobile Access Portal (not Spark), Remote Access VPN with SSL Network Extender (not Spark) or with SAML realm authentication, the Identity Awareness captive portal, the UserCheck portal or Zero Phishing, on R81.20, R82, R82.10 and R82.20 and on Spark R81.10.x and R82.00.x, and end-of-support lines are also listed (Check Point, 2026-11-12). The standalone hotfix of 2026-10-23 implements the PHP 7.4 fix and needs a reboot (Check Point, 2026-10-29); the sk now says the fix is included in Jumbo Hotfix Accumulator R82.20 take 14, R82.10 take 52, R82 take 132 and R81.20 take 174, names Spark fixes from builds B998002843 and B996005005, and keeps the R81.10 hotfix (Check Point, 2026-11-12). Until then, Check Point's mitigation is a cp-httpd.conf block denying multipart Content-Type requests, removed before the hotfix (Check Point, 2026-10-29).

    Check Point Research reports that from 2026-10-30, about a week after the fix, an attacker exploited unpatched gateways through Mobile Access portals with PHP2Shell and escalated to root with CVE-2026-123039: the first wave targeted Israeli organisations and included destructive activity against some, and a wider wave on 2026-11-02 targeted organisations in several countries (Check Point Research, 2026-11-12). CVE-2026-123039 is a local escalation: the root dynamic_server process runs whatever command it receives on a world-writable local socket without authenticating the caller, and Check Point says it observed an active exploit against a couple of dozen customers (Check Point, 2026-11-12). After root the attacker placed PHP web shells in the directory the Mobile Access portal uses for its login pages and the TSGA implant, a root-run passive backdoor that Check Point says provides encrypted remote access, configuration theft, backup and snapshot persistence, process injection and firewall-log tampering; it ran a scanner, moved by SSH to a VMware ESXi host and ran a wiper there (Check Point Research, 2026-11-12). The standalone PHP hotfix text names only the two PHP CVEs (Check Point, 2026-10-29), and sk1000362 lists no Jumbo take for R81.10 or R81, so protection there is not stated (Check Point, 2026-11-12).

    Exposure
    For the PHP flaws, a gateway on a listed release with at least one of the six portal or VPN features in use (Check Point, 2026-11-12); for CVE-2026-123039, a Force gateway, management or log server, Multi-Domain server or Maestro on R81 to R82.20 below those Jumbo takes (Check Point, 2026-11-12).
    Detection
    The vulnerable daemon logs every command it receives to /var/log/dynamicCli.log, and Check Point says any command that does not use the legitimate Clish wrapper may indicate a command executed as root and requires investigation (Check Point, 2026-11-12); Check Point Research also describes the web-shell, listener and SSH-to-ESXi behavior above (Check Point Research, 2026-11-12).
    Defender takeaway
    Install the Jumbo take that carries both fixes on gateways and on management and log servers, apply the cp-httpd.conf mitigation and stop dynamic_server where it has to wait (Check Point, 2026-11-12; Check Point, 2026-11-12), and treat a gateway that was exposed and unpatched since 2026-10-30 as needing a compromise check, because a hotfix is not stated to remove an implant already installed, which is an inference from the persistence Check Point Research describes (Check Point Research, 2026-11-12).

    Update13 Nov 2026 03:59 UTCrun 2026-11-13T0256Z-inteltitleheadlinesummaryprioritytagstechniquescvesactionssourcesevidencesourcing_notebody

    Check Point Research reports that exploitation of unpatched Check Point gateways began on 2026-10-30 and says it escalated to root with a second flaw, CVE-2026-123039, which Check Point rates CVSS 7.8 and says it saw exploited against a couple of dozen customers (Check Point Research, 2026-11-12; Check Point, 2026-11-12). The attacker left PHP web shells and a root-run backdoor with backup and snapshot persistence, and in the first wave moved by SSH from the gateway to a VMware ESXi host and deleted files there (Check Point Research, 2026-11-12); sk1000302 itself still carries no exploitation statement (Check Point, 2026-11-12). The fix for both flaws is in Jumbo Hotfix Accumulator R82.20 take 14, R82.10 take 52, R82 take 132 and R81.20 take 174 or later (Check Point, 2026-11-12; Check Point, 2026-11-12), none is listed for R81.10 or R81 (Check Point, 2026-11-12), and the Spark fixes are now stated as builds from B998002843 and B996005005 (Check Point, 2026-11-12). Check Point Research describes the TSGA backdoor and its embedded TSProxy library as modified variants of PhiliKit, a framework ESET associated with the China-nexus cluster UNC5221, and says the evidence does not allow a high-confidence assessment of who ran the operation: a single actor, an initial access broker or a false-flag operation all remain plausible (Check Point Research, 2026-11-12).
