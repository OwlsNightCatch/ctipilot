    Defender insights

    What each entry about Anthropic Claude Code tells a defender to do, newest first.

    2026-11-17NOTABLEGTIG quarterly: exploit_agent automates n-day exploitation, suspected DPRK cluster abuses .claude/settings.json

    Defender takeaway

    Review a change to a project-level Claude Code settings file like a code-execution change, and move internet-facing web components to the fastest patch lane, because GTIG describes patch diffs being turned into executed exploits without a human.

    Exposure · detection
    Exposure

    Organizations whose developers run Claude Code against shared repositories, where a committed project settings file executes at startup, and internet-facing web applications and plugins whose patches are public, since exploit_agent works from patch diffs.

    Detection

    Repository change monitoring for edits to .claude/settings.json and its hook or startup commands, and GitHub audit events that create personal access tokens named after a vendor assistant; for agentic scanning, the forensic traffic, recognizable identifiers and code-level traces that GTIG says pentest frameworks leave behind (GTIG, 2026-11-16).

    2026-10-31NOTABLECursor marketplace served a trojanised Claude Code extension for 11 hours; uninstalling leaves the SSH backdoor

    Defender takeaway

    Treat a host that ran either version as backdoored whether or not the tunnel connected: remove the key, the persistence and the tunnel processes, rebuild where compromise cannot be excluded, and rotate credentials reachable from it. heise reports a cleaned release, with 2.1.314 as the minimum to install (heise online, 2026-10-30).

    Exposure · triage · detection
    Exposure

    Any macOS or Windows host on which Cursor installed or auto-updated Anthropic.claude-code 2.1.312 or 2.1.313 inside the window; the code also carries Linux routines though Cursor names only macOS and Windows packages (heise online, 2026-10-30). Extension-install telemetry shows the version. NCSC Switzerland's post of 2026-10-30 places the extension on Open VSX (NCSC Switzerland, 2026-10-30); Cursor says Open VSX never had it (Cursor, 2026-11-13). Cursor says coding-agent traces from sessions outside Privacy Mode were exposed for fewer than 0.05% of users, all notified, so a user with no notice was not among them (Cursor, 2026-11-13).

    Triage

    A running SSH process is not proof the attacker got in, since both ends must allow the connection (Microsoft Threat Intelligence, 2026-10-30); administrators run tunnels too, and what separates this one is an editor extension as the parent process and persistence written to user-writable locations rather than a managed service.

    Detection

    In process-creation telemetry, an editor's extension host starting ssh or autossh with remote port forwarding and no command; in file-write telemetry, an editor process modifying authorized_keys; and, shortly after an extension update, a new LaunchAgent, scheduled task, Startup-folder script or @reboot crontab entry named after system-monitoring components. Phorion advises matching the attacker key's fingerprint rather than the comment string it carries (Phorion, 2026-10-30). Removing the extension does not remove the persistence scripts, which keep running (Cursor, 2026-10-29).

    2026-11-08ROUTINEClaude Code's don't-ask-again file leaks secrets: 1,122 public copies on GitHub hold a real one

    Defender takeaway

    Treat every secret found in these files as exposed and rotate it first, then stop tracking the file with git rm --cached and add it to the repository's own .gitignore and the organisation's templates (Apiiro, 2026-11-05).

    Exposure · detection
    Exposure

    Any repository where a developer used Claude Code and approved a command containing a password, token or key with "don't ask again", and every laptop where that was done, because the file sits in plain text there too (Apiiro, 2026-11-05). To tell, search the organisation's repositories for the two settings files and look in their history, as Apiiro advises (Apiiro, 2026-11-05).

    Detection

    In pre-commit and CI secret scanning, include git history and make sure the scanner catches passwords typed inside commands, not only known key formats (The Hacker News, 2026-11-07); history matters because removing the file does not undo the leak, older versions staying in git history and in forks (The Hacker News, 2026-11-07).

    2026-09-22NOTABLEAI coding agents' plugin SHA-pinning is bypassable, mainly via plugins hosted on Bitbucket or self-hosted git, and only consumer Gemini CLI stays unfixed

    Defender takeaway

    Update Codex, Claude Code and Copilot now, keeping in mind that the Claude Code fix rests on AIR's account and the Copilot fix on GitHub support's statement as reported by heise online. Consumer Gemini CLI will not be fixed (AIR Security, 2026-09-17), and it is not established that installing its plugins only from GitHub avoids the flaw (The Hacker News, 2026-09-18), so verify plugin commit hashes manually or move off it.

    Triage · detection
    Triage

    Routine background plugin auto-update produces the same git clone and checkout telemetry as the attack, so a single update event is not itself suspicious. The discriminator is a resolved HEAD that differs from the pinned SHA, not the presence of an update.

    Detection

    Monitor the coding agent's plugin-manager child processes (process-creation events for the git binary spawned by the agent), and after a plugin install or update compare the commit actually checked out in the plugin directory (git rev-parse HEAD) with the marketplace-pinned SHA. AIR names this check of the resolved HEAD, rather than of the requested ref, as the assertion that closes both variants (AIR Security, 2026-09-17).

    2026-09-03NOTABLEOpening a repository received as files, not cloned, can hand an attacker a shell before the agent has asked a single question

    Defender takeaway

    Any organisation standardising on a CLI AI coding agent should treat "received as files, not cloned" as its own trust boundary, confirm which of the four still-unpatched sinks apply to the agents actually in use, and patch or restrict them rather than assuming clone-based delivery covers every path a repository reaches a developer's machine.

    Triage
    Triage

    A git subprocess spawned by an AI coding agent that itself spawns a further, unrelated child process, particularly one launched before the agent has logged any user prompt or shown a trust dialog, is not normal agent startup behaviour and is the observable signature the mechanism supports.

    2026-08-10NOTABLEA validator that strips quoted text before inspecting it, and an agent instruction file rewritten between two passes of one shared checkout

    Defender takeaway

    The transferable rule is that an agent's instruction file is executable input, and any pipeline stage that can write it controls every later stage that reads it. Where a public-sector organisation runs coding agents in CI, the questions to ask are whether multiple agent passes share a workspace, whether the agent's instruction file is treated as protected metadata or as ordinary repository content, and (for the two patched products) whether the versions in use are past the fixed releases. The first of those has no vendor answer at all, and it is also the one no CVE feed will ever tell you about.

    Three findings from GTIG's quarterly update on adversary use of AI, published 2026-11-16, change what defenders can look for (GTIG, 2026-11-16).     Cursor marketplace: a tampered Claude Code extension (versions 2.1.312 and 2.1.313) planted an SSH key, a reverse tunnel and persistence for about eleven hours on 2026-10-29; uninstalling it does not remove the persistence

    Between about 2:27am PT and 1:35pm PT on 2026-10-29 (09:27 to 20:35 UTC) a maliciously modified copy of Anthropic's Claude Code extension, versions 2.1.312 and 2.1.313 for macOS and Windows, was served from the Cursor VS Code Extension Marketplace; Cursor removed it, rebuilt the marketplace, rotated its keys and had the attacker's server taken offline (Cursor, 2026-10-29). Anthropic told Microsoft its systems were not compromised and that it did not build the package, and Microsoft confirms the packages were never published to the Visual Studio Marketplace or npm (Microsoft Threat Intelligence, 2026-10-30). Cursor's report of 2026-11-13 says the attacker wrote the copies onto the marketplace cache with a credential taken through a key exposed at its vendor Fireworks, and that at most 5,000 users potentially received the build (Cursor, 2026-11-13).

    The injected loader runs when the extension module loads (Microsoft Threat Intelligence, 2026-10-30). It reports host and user data (hostname, username, operating system, directories, Git email, environment-variable names and public IP address), appends an attacker-controlled SSH public key to authorized_keys, tries to enable the local SSH service and open a reverse SSH tunnel, and installs persistence outside the extension: a LaunchAgent on macOS, and on Windows a scheduled task that asks to run as SYSTEM with a Startup-folder fallback, with background scripts retrying the tunnel about every 60 seconds (Cursor, 2026-10-29). Microsoft's analysis adds a user crontab entry for Linux (Microsoft Threat Intelligence, 2026-10-30). Because of coding errors, enabling SSH fails unless Cursor was started with administrator privileges, so on most hosts the attacker could not log in through the tunnel, but the key, persistence and host report remained (Cursor, 2026-10-29).

    Exposure
    Any macOS or Windows host on which Cursor installed or auto-updated Anthropic.claude-code 2.1.312 or 2.1.313 inside the window; the code also carries Linux routines though Cursor names only macOS and Windows packages (heise online, 2026-10-30). Extension-install telemetry shows the version. NCSC Switzerland's post of 2026-10-30 places the extension on Open VSX (NCSC Switzerland, 2026-10-30); Cursor says Open VSX never had it (Cursor, 2026-11-13). Cursor says coding-agent traces from sessions outside Privacy Mode were exposed for fewer than 0.05% of users, all notified, so a user with no notice was not among them (Cursor, 2026-11-13).
    Detection
    In process-creation telemetry, an editor's extension host starting ssh or autossh with remote port forwarding and no command; in file-write telemetry, an editor process modifying authorized_keys; and, shortly after an extension update, a new LaunchAgent, scheduled task, Startup-folder script or @reboot crontab entry named after system-monitoring components. Phorion advises matching the attacker key's fingerprint rather than the comment string it carries (Phorion, 2026-10-30). Removing the extension does not remove the persistence scripts, which keep running (Cursor, 2026-10-29).

    Triage: a running SSH process is not proof the attacker got in, since both ends must allow the connection (Microsoft Threat Intelligence, 2026-10-30); administrators run tunnels too, and what separates this one is an editor extension as the parent process and persistence written to user-writable locations rather than a managed service.

    Defender takeaway
    Treat a host that ran either version as backdoored whether or not the tunnel connected: remove the key, the persistence and the tunnel processes, rebuild where compromise cannot be excluded, and rotate credentials reachable from it. heise reports a cleaned release, with 2.1.314 as the minimum to install (heise online, 2026-10-30).

    ROUTINENATOB2

    Claude Code's 'Yes, and don't ask again' saves the approved command, secrets included, in .claude/settings.local.json: Apiiro finds a real secret in 1,122 of 104,185 public copies of the file on GitHub, and common secret scanners miss a fifth of them

    Apiiro reports that when a developer chooses "Yes, and don't ask again" on a shell command that carries a secret, Claude Code saves that exact command, secret included, in plain text in .claude/settings.local.json inside the project (Apiiro, 2026-11-05). Anthropic's documentation confirms that the approval is saved as an allow rule in that file, and that Claude Code adds the file to the user's global git excludes the first time it writes it, so it stays out of that user's commits (Anthropic, 2026-11-04). Apiiro points out that this protection lives in one user's git settings on one machine: it does not cover a folder that becomes a repository later, a clone on another machine or a file already committed, and the rule never goes into the repository's own .gitignore (Apiiro, 2026-11-05).

    Apiiro found 104,185 public copies of the file in 103,617 repositories; 1,122 of those files hold at least one secret, 1,379 distinct secrets in all: 379 database passwords, 122 Supabase service-role keys, 43 SSH logins, 42 GitHub, GitLab and npm tokens and 23 AWS keys among them (Apiiro, 2026-11-05). Counting git history, the shared settings.json and saved agent transcripts, it counts 2,539 secrets in 1,994 repositories (Apiiro, 2026-11-05). Gitleaks flagged 564 and TruffleHog 643 of the 1,122 files, and 215 were flagged by neither, mostly because a password typed after PGPASSWORD=, sshpass -p or mysql -p looks like an ordinary word in a command line (Apiiro, 2026-11-05).

    Exposure
    Any repository where a developer used Claude Code and approved a command containing a password, token or key with "don't ask again", and every laptop where that was done, because the file sits in plain text there too (Apiiro, 2026-11-05). To tell, search the organisation's repositories for the two settings files and look in their history, as Apiiro advises (Apiiro, 2026-11-05).
    Detection
    In pre-commit and CI secret scanning, include git history and make sure the scanner catches passwords typed inside commands, not only known key formats (The Hacker News, 2026-11-07); history matters because removing the file does not undo the leak, older versions staying in git history and in forks (The Hacker News, 2026-11-07).
    Defender takeaway
    Treat every secret found in these files as exposed and rotate it first, then stop tracking the file with git rm --cached and add it to the repository's own .gitignore and the organisation's templates (Apiiro, 2026-11-05).
