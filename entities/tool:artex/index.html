    Defender insights

    What each entry about ARTEX tells a defender to do, newest first.

    2026-10-30NOTABLECrowdStrike: VAPOR PANDA runs ARTEX against 200+ organisations, European foreign ministries among them

    Defender takeaway

    Rotate keys held in old directory exports and backups, require signed SAML assertions and IMDSv2, and hunt authentication and cloud audit logs for the parallel, many-target pattern an operator-steered agent produces; CrowdStrike expects China-nexus actors to keep adopting agent frameworks.

    Exposure · detection
    Exposure

    Government, mail, identity and VPN estates where a directory export or backup holding authentication keys has never been rotated, SAML service providers that accept unsigned assertions, and cloud instances that still allow instance metadata service version 1; CrowdStrike names foreign ministries and government entities in Europe among the targets.

    Detection

    Telemetry classes are authentication logs (password spraying and credential scanning against many accounts, an administrator token minted outside the identity provider, VPN logins that use a configuration or key from an old mailbox or leak), cloud control-plane audit (administration commands issued to many instances through the cloud systems manager, instance metadata queries from an application), process lineage (a legitimate GameHook binary renamed svchost.exe loading a malicious DLL) and endpoint inventory queries for hosts without the security agent; CrowdStrike lists ARTEX-named command-line parameters, cloud roles and a directory under ProgramData as hunt markers (CrowdStrike, 2026-10-29).

    2026-10-22NOTABLEMicrosoft: Storm-0940 runs the ARTEX agent framework at machine speed; Expel adds an Okta self-registration technique

    Defender takeaway

    Expel's reading is that the framework adds speed, not a new vulnerability, so the levers are the identity controls it runs into: least privilege on multi-tenant application permissions and consent grants, alerting on credential additions and privileged role assignments by applications, and a review of self-registered Okta accounts since 2026-10-13 (Microsoft, 2026-10-21; Expel, 2026-10-21).

    Exposure · triage · detection
    Exposure

    Any tenant that relies on password sign-in or grants OAuth consent to applications, and any Okta org with self-service registration enabled; not using ConnectWise does not exclude exposure (Expel, 2026-10-21).

    Triage

    Python and curl user agents match common legitimate automation, so Expel treats them as supporting evidence only, and a Python user agent on an application that normally calls Microsoft Graph with a .NET SDK is the anomaly (Expel, 2026-10-21).

    Detection

    In the authentication logs of every identity provider in use, bursts of failed logons and lockouts spread over many accounts; in the Okta system log, newly self-registered accounts that enrol Okta Verify and start single sign-on within minutes; and in the Entra audit log, credentials or certificates added to applications that nobody on your team created and any application that assigns itself a directory role (Microsoft, 2026-10-21; Expel, 2026-10-21). A clean audit log is not proof of no access, because Microsoft Graph directory reads leave no Entra audit record (Expel, 2026-10-21). In web access logs of an application exposed to the same actor, Wiz points to source-map and OpenAPI downloads followed minutes later by calls to internal routes that appear only in those files, and to sign-in telemetry showing a new user agent for each burst of attempts at a one-second cadence (Wiz, 2026-10-22).

    2026-10-26NOTABLEJPCERT/CC and NICT: attackers decompile the public app, then call internal APIs; AI platforms scan exposed web apps

    Defender takeaway

    Treat the published app package as public and test the backend for authorisation gaps on internal endpoints (IDOR and BOLA), server-side request forgery, remote code execution and SQL injection (NICT, 2026-10-13). JPCERT/CC's measures are per-endpoint and per-method access control including non-public APIs, expiring least-privilege API tokens with fast revocation, rate limits on login, password reset, SMS and search, no long-lived secrets in apps, and no management functions on the internet (JPCERT/CC, 2026-10-23; JPCERT/CC Eyes, 2026-10-21).

    Exposure · triage · detection
    Exposure

    An organisation that publishes a mobile app with a backend API, runs internet-facing web applications, or leaves BI tools, staff-management systems or WSUS servers reachable from the internet (JPCERT/CC, 2026-10-23); NICT asks operators to inventory public APIs and servers and check their access logs (NICT, 2026-10-13).

    Triage

    The app's own User-Agent proves nothing, because JPCERT/CC saw attack requests carrying it; the endpoints called and the sequence (header toggling, malformed tokens, role changes) discriminate, and a TLS fingerprint that matches a generic Python client does not identify the attacker alone (JPCERT/CC, 2026-10-23).

    Detection

    In API and web access logs, calls to internal or management endpoints from clients that never load the app screens, role-change and account-creation calls outside the admin console, one endpoint called in sequence with and without a header or with malformed tokens, blind NoSQL-injection-style probing of account lookups, and use of API keys extracted from the app; in web server telemetry, scans for exposed configuration and backup files and .war deployments to application servers (JPCERT/CC, 2026-10-23).

    T1090.003Proxy: Multi-hop Proxy×2

    Adversaries may chain together multiple proxies to disguise the source of malicious traffic.     VAPOR PANDA: CrowdStrike reports a China-nexus actor running the ARTEX agent framework against more than 200 organisations from 17 October, among them foreign ministries in Europe and a Greek government entity, and deploying the BLOODALCHEMY backdoor

    CrowdStrike OverWatch reports that from 2026-10-17 a single ARTEX controller linked to VAPOR PANDA infrastructure directed exploitation against entities in at least 14 countries over 11 days, and that the campaign reached more than 200 organisations, including foreign ministries in Europe (CrowdStrike, 2026-10-29). One engagement focused on a single European country, its foreign ministry, presidency, prime minister's office and defence, justice, finance and intelligence entities, and another targeted 19 US organisations in pharmaceuticals, semiconductors, defence, nuclear and finance (CrowdStrike, 2026-10-29). CrowdStrike confirmed post-exploitation at nine organisations and password spraying and credential scanning against at least 12 more, among them government entities in Europe (CrowdStrike, 2026-10-29). CrowdStrike states that the campaign is separate from the Storm-0940 ARTEX activity Microsoft reported and is VAPOR PANDA's first observed use of AI-driven tooling (CrowdStrike, 2026-10-29).

    The framework ran mainly on the DeepSeek model, with a human operator steering the agents at decision points while they pursued web, cloud, container, Active Directory, mail and VPN paths in parallel (CrowdStrike, 2026-10-29). In transcripts at a US pharmaceutical company the agent chained an unsigned SAML assertion with an XML external entity flaw to query the cloud instance metadata service and obtain a role that could issue administration commands to thousands of instances; at a second it deployed web shells, abused an unauthenticated orchestration service for root in a container environment, read LAPS passwords and abused resource-based constrained delegation (CrowdStrike, 2026-10-29). Against a Greek government entity the operator supplied a 2022 directory export from the mail server whose authentication keys had likely not been rotated; the agent forged an administrator token, read mailboxes and used VPN configurations from a user's sent mail, with a VPN client key the operator described as coming from a May 2024 email leak, to reach the internal network (CrowdStrike, 2026-10-29). The operator also told the agents to find domain Windows hosts without the CrowdStrike Falcon sensor (CrowdStrike, 2026-10-29). At a Middle East interior ministry and a Latin American foreign ministry the actor loaded the BLOODALCHEMY backdoor through a legitimate GameHook binary renamed svchost.exe that loads a malicious DLL (CrowdStrike, 2026-10-29). No Swiss target is named.

    Exposure
    Government, mail, identity and VPN estates where a directory export or backup holding authentication keys has never been rotated, SAML service providers that accept unsigned assertions, and cloud instances that still allow instance metadata service version 1; CrowdStrike names foreign ministries and government entities in Europe among the targets.
    Detection
    Telemetry classes are authentication logs (password spraying and credential scanning against many accounts, an administrator token minted outside the identity provider, VPN logins that use a configuration or key from an old mailbox or leak), cloud control-plane audit (administration commands issued to many instances through the cloud systems manager, instance metadata queries from an application), process lineage (a legitimate GameHook binary renamed svchost.exe loading a malicious DLL) and endpoint inventory queries for hosts without the security agent; CrowdStrike lists ARTEX-named command-line parameters, cloud roles and a directory under ProgramData as hunt markers (CrowdStrike, 2026-10-29).
    Defender takeaway
    Rotate keys held in old directory exports and backups, require signed SAML assertions and IMDSv2, and hunt authentication and cloud audit logs for the parallel, many-target pattern an operator-steered agent produces; CrowdStrike expects China-nexus actors to keep adopting agent frameworks.

    NOTABLEupdatedNATOB2

    ARTEX: Microsoft reports Storm-0940, a China-state aligned actor, running an open-source multi-agent LLM penetration-testing framework against hundreds of organizations, with privileged cloud access in under three hours in some cases, and Expel sees the same infrastructure abuse Okta self-service registration

    Microsoft Threat Intelligence reports that as early as September 2026 Storm-0940, a China-state aligned actor active since 2021, used the agentic penetration-testing framework ARTEX to automate attacks on hundreds of organizations across many industries, government and military among them (Microsoft, 2026-10-21). ARTEX is an open-source multi-agent LLM system that can use any AI model and runs a penetration test from reconnaissance to exfiltration with little human involvement (Microsoft, 2026-10-21). Microsoft says ARTEX accelerated the abuse of compromised applications already granted access to Microsoft 365 tenants (Microsoft, 2026-10-21), and Expel adds that it is not a vulnerability and only speeds up familiar techniques such as password spraying and OAuth-application abuse (Expel, 2026-10-21); most targeting failed, yet several cases went from first targeting to privileged cloud access in under three hours (Microsoft, 2026-10-21). Microsoft assesses the same actor was behind the ConnectWise Cloud Backup application-credential abuse (Microsoft, 2026-10-21).

    Expel saw Storm-0940 infrastructure scan a customer and, from 2026-10-13, abuse its Okta self-service registration with no ConnectWise application involved: the attacker created five accounts of its own, enrolled Okta Verify on three of them about a minute after activation, made 50 single sign-on logins with more than 100 OAuth tokens issued and ran a password spray that Okta ThreatInsight blocked (Expel, 2026-10-21). Expel says the shared source address is its only link to Storm-0940, the activity alone does not prove ARTEX was used, and it had not seen the technique reported before (Expel, 2026-10-21). Other actors use it: CrowdStrike analysed an unnamed, probably Chinese-speaking and financially motivated actor that ran ARTEX against South Korean financial institutions from late September (CrowdStrike, 2026-10-07), and Recorded Future, which tracks that activity as TAG-217, says use of ARTEX and other AI penetration-testing tools is not limited to it (Recorded Future, 2026-10-16).

    Wiz Research independently reports that throughout October 2026 it tracked an actor using ARTEX-associated tooling, overlapping with Storm-0940, against IT and software vendors, focused on identity providers (Okta, Entra, Cognito) and Microsoft 365 integrations, and says that most attempts failed and that none of the techniques is novel (Wiz, 2026-10-22). It describes a consistent sequence: downloading JavaScript bundles, exposed source maps, runtime configuration and OpenAPI documents, then calling internal API routes by name minutes later; fabricated authorization codes and malformed state values against Microsoft OAuth callbacks; unsigned JWTs tried against more than 60 SSO route variants in two minutes; and account-recovery, sign-up and Cognito calls such as InitiateAuth, ForgotPassword and ResendConfirmationCode (Wiz, 2026-10-22). Its password sprays against Entra and Okta hit hundreds of users, mainly software engineers, in bursts of 20 to 60 minutes with a unique user agent per burst, a median gap of one second between attempts and new source addresses within minutes of a block (Wiz, 2026-10-22).

    Exposure
    Any tenant that relies on password sign-in or grants OAuth consent to applications, and any Okta org with self-service registration enabled; not using ConnectWise does not exclude exposure (Expel, 2026-10-21).
    Detection
    In the authentication logs of every identity provider in use, bursts of failed logons and lockouts spread over many accounts; in the Okta system log, newly self-registered accounts that enrol Okta Verify and start single sign-on within minutes; and in the Entra audit log, credentials or certificates added to applications that nobody on your team created and any application that assigns itself a directory role (Microsoft, 2026-10-21; Expel, 2026-10-21). A clean audit log is not proof of no access, because Microsoft Graph directory reads leave no Entra audit record (Expel, 2026-10-21). In web access logs of an application exposed to the same actor, Wiz points to source-map and OpenAPI downloads followed minutes later by calls to internal routes that appear only in those files, and to sign-in telemetry showing a new user agent for each burst of attempts at a one-second cadence (Wiz, 2026-10-22).

    Triage: Python and curl user agents match common legitimate automation, so Expel treats them as supporting evidence only, and a Python user agent on an application that normally calls Microsoft Graph with a .NET SDK is the anomaly (Expel, 2026-10-21).

    Defender takeaway
    Expel's reading is that the framework adds speed, not a new vulnerability, so the levers are the identity controls it runs into: least privilege on multi-tenant application permissions and consent grants, alerting on credential additions and privileged role assignments by applications, and a review of self-registered Okta accounts since 2026-10-13 (Microsoft, 2026-10-21; Expel, 2026-10-21).

    NOTABLENATOA2

    Japan's wave of personal-data theft from web systems: JPCERT/CC and NICT describe attackers who decompile the published Android app to find internal APIs, drop JSP web shells as .war files on application servers, and run AI penetration-testing platforms against exposed web applications and WSUS servers

    JPCERT/CC's alert of 2026-10-08, updated on 2026-10-23, says that around September 2026 Japanese organisations disclosed a run of personal-data leaks through unauthorised access, and singles out an attack type that may be increasing: systems the operator never expected strangers to reach, such as business-intelligence tools and staff-management systems, were hit alongside public apps (JPCERT/CC, 2026-10-23). It does not tie them to one method and groups them in five: per-target scanning for known flaws and exposed configuration and backup files; unauthorised calls to application management APIs; the Metabase SQL injection CVE-2026-72898; .war files carrying a JSP web shell that runs commands passed in query parameters, placed on application servers reachable from the public web server; and, added on 2026-10-23, attempts through AI penetration-testing platforms it names as Cairn, CyberStrikeAI and ARTEX, including against exposed WSUS servers (JPCERT/CC, 2026-10-23).

    In the API case the attackers analyse the published smartphone app to find endpoints and keys, then attack internal APIs the app screens cannot reach: changing user rights, creating accounts, toggling a header or sending malformed tokens to compare responses, and blind NoSQL injection to find account data; some use API keys stolen elsewhere (JPCERT/CC, 2026-10-23). NICT calls this an app-to-backend attack: the app need not be vulnerable, and backend authentication, authorisation or input-validation faults leak data (NICT, 2026-10-13). On attack servers JPCERT/CC found Android packages, reverse-engineering tools and a Python script that answers requests with HTTP 302 redirects and appears to have been used to test for server-side request forgery (JPCERT/CC Eyes, 2026-10-21).

    No source names an actor. JPCERT/CC says it confirmed that the attackers used AI to scan for known vulnerabilities and attack through APIs (JPCERT/CC Eyes, 2026-10-21), while Macnica could not confirm AI use (Recorded Future, 2026-10-22). API-attack access also arrives through Tor exit nodes and residential proxies (JPCERT/CC, 2026-10-23).

    Exposure
    An organisation that publishes a mobile app with a backend API, runs internet-facing web applications, or leaves BI tools, staff-management systems or WSUS servers reachable from the internet (JPCERT/CC, 2026-10-23); NICT asks operators to inventory public APIs and servers and check their access logs (NICT, 2026-10-13).
    Detection
    In API and web access logs, calls to internal or management endpoints from clients that never load the app screens, role-change and account-creation calls outside the admin console, one endpoint called in sequence with and without a header or with malformed tokens, blind NoSQL-injection-style probing of account lookups, and use of API keys extracted from the app; in web server telemetry, scans for exposed configuration and backup files and .war deployments to application servers (JPCERT/CC, 2026-10-23).

    Triage: the app's own User-Agent proves nothing, because JPCERT/CC saw attack requests carrying it; the endpoints called and the sequence (header toggling, malformed tokens, role changes) discriminate, and a TLS fingerprint that matches a generic Python client does not identify the attacker alone (JPCERT/CC, 2026-10-23).

    Defender takeaway
    Treat the published app package as public and test the backend for authorisation gaps on internal endpoints (IDOR and BOLA), server-side request forgery, remote code execution and SQL injection (NICT, 2026-10-13). JPCERT/CC's measures are per-endpoint and per-method access control including non-public APIs, expiring least-privilege API tokens with fast revocation, rate limits on login, password reset, SMS and search, no long-lived secrets in apps, and no management functions on the internet (JPCERT/CC, 2026-10-23; JPCERT/CC Eyes, 2026-10-21).
