    ROUTINECVE-2026-50656updatedNATOA2

    CVE-2026-50656: Microsoft Defender engine 'RoguePlanet' local privilege escalation now patched; NCSC-CH tracks the ongoing 'Nightmare Eclipse' zero-day series

    NCSC-CH's running tracker on the "Nightmare Eclipse" (aka Chaotic Eclipse) researcher's 2026 zero-day PoC series was updated on 2026-07-09 to record that a CVE has been assigned to RoguePlanet: CVE-2026-50656, a local privilege-escalation vulnerability (CWE-59, improper link resolution before file access / "link following") in the Microsoft Malware Protection Engine that underpins Microsoft Defender, System Center Endpoint Protection and Microsoft Security Essentials (NCSC-CH, 2026-07-09) (Microsoft MSRC, 2026-07-08). The researcher first disclosed RoguePlanet as an unpatched zero-day on 2026-06-09, Patch Tuesday, describing a race condition in Defender that lets a local attacker "execute arbitrary code or spawn a command shell with SYSTEM-level privileges", at which point NCSC-CH logged its status as "Proof of Concept Available, no patch available" (NCSC-CH, 2026-07-09). Microsoft's own record shows the CVE was published 2026-06-16 (CVSS 3.1 7.8, AV:L/AC:L/PR:L/UI:N, rated "Exploitation More Likely", exploitation status "No") and remained without a fix for over three weeks; a revision dated 2026-07-08 confirms Microsoft has now shipped an engine update that closes it: last vulnerable Malware Protection Engine build 1.1.26050.11, first fixed build 1.1.26060.3008 (Microsoft MSRC, 2026-07-08).

    NCSC-CH later recorded that a proof of concept dubbed ShieldBreak allegedly bypasses this fix; Microsoft tracks it as CVE-2026-69414 (NCSC-CH, 2026-07-09) and lists engine 1.1.26080.3 as the first build that addresses it (Microsoft Security Response Center, CVE-2026-69414).

    Exposure
    The Malware Protection Engine (mpengine.dll) at build 1.1.26050.11 or earlier, in Microsoft Defender, which runs on all supported versions of Windows, and in System Center Endpoint Protection and Microsoft Security Essentials; hosts with Defender disabled are not in an exploitable state even though vulnerability scanners flag the binaries still on disk (Microsoft MSRC, 2026-07-08).
    Defender takeaway
    Engine updates install automatically by default, so most estates already carry the fixed build and Microsoft's guidance is that no manual action is normally required, but it advises verifying that automatic deployment of engine updates works as expected (Microsoft MSRC, 2026-07-08); in analyst judgement that check matters most where engine updates are pinned, WSUS-gated, air-gapped or centrally deferred, such as System Center Endpoint Protection deployments and offline or OT-adjacent Windows hosts, and the build to confirm there is 1.1.26080.3 or later, which also carries the ShieldBreak fix (Microsoft Security Response Center, CVE-2026-69414).

    Neither Microsoft's advisory nor NCSC-CH's tracker describes the exploitation mechanism beyond link following and a race condition, so the earlier triage guidance on symlink races against scanned files and on the engine's child processes is withdrawn. NCSC-CH has since recorded that a proof of concept dubbed ShieldBreak allegedly bypasses this fix, tracked by Microsoft as CVE-2026-69414 (NCSC-CH, 2026-07-09); Microsoft lists engine 1.1.26080.3 as the first build that addresses it (Microsoft Security Response Center, CVE-2026-69414). The priority moves from notable to routine: the flaw is local and the engine fix installs automatically. A pinned estate should therefore verify that build rather than the RoguePlanet fix alone.

    HIGHCVE-2026-41091 +1exploitedupdatedNATOA1

    CVE-2026-41091: exploited Microsoft Defender link-following privilege escalation to SYSTEM, with the CVE-2026-45498 Defender denial of service

    Microsoft published CVE-2026-41091 on 2026-05-19 as exploited and publicly disclosed: improper link resolution before file access (CWE-59) in Microsoft Defender lets an authorized attacker elevate privileges locally and gain SYSTEM, scored CVSS 7.8 (MSRC, 2026-05-19). The flaw sits in the Microsoft Malware Protection Engine (mpengine.dll); the last affected build is Engine version 1.1.26030.3008 and the first fixed build is Engine version 1.1.26040.8 (MSRC, 2026-05-19). Microsoft marked CVE-2026-45498, a Defender denial of service (CWE-400, CVSS 3.1 base score 4.0), as exploited the same day and fixed it separately in Antimalware Platform version 4.18.26040.7 (MSRC, 2026-05-19); CISA added both to its Known Exploited Vulnerabilities catalog on 2026-05-20 based on evidence of active exploitation (CISA, 2026-05-20). The researcher Nightmare Eclipse published the RedSun and UnDefend exploits on 2026-04-16 (Help Net Security, 2026-04-17) and has said that CVE-2026-41091 is RedSun and CVE-2026-45498 is UnDefend (The Hacker News, 2026-05-21); UnDefend lets a standard user block Defender from receiving signature updates (Help Net Security, 2026-04-17). RedSun baits Defender's real-time protection with an embedded EICAR test string and, using the Cloud Files API, oplocks and a directory junction, redirects the file rewrite of the resulting remediation into a protected system path, after which the Cloud Files infrastructure runs the attacker's binary as SYSTEM (Vectra AI, 2026-04-21).

    Exposure
    Defender runs on all supported versions of Windows, and System Center Endpoint Protection and Microsoft Security Essentials use the same engine; systems that have disabled Defender are not in an exploitable state, although scanners still flag their files on disk (MSRC, 2026-05-19). The running platform version shows as the Antimalware ClientVersion under Settings, About in the Windows Security program (MSRC, 2026-05-19).
    Detection
    Endpoint process and file telemetry. In the intrusion Huntress observed on 2026-04-16 the attacker dropped the exploit files into the user's Pictures and Downloads folders and renamed them, then ran commands that mapped user privileges, stored credentials and the Active Directory structure before launching the exploits (Help Net Security, 2026-04-17). RedSun then shows as a Defender remediation of an EICAR detection in a user-writable path followed by a SYSTEM process started from that path, and UnDefend was seen running as a child of cmd.exe under Explorer (Vectra AI, 2026-04-21). Patching does not undo a SYSTEM compromise: on hosts that ran an affected engine, look back to mid-April for SYSTEM processes launched from user profile folders.

    Triage: an EICAR detection on its own is what an antivirus test produces; the RedSun pattern adds a directory junction that redirects the remediation's file rewrite into a protected system path and a SYSTEM-context process launched right after the remediation (Vectra AI, 2026-04-21).

    Defender takeaway
    Where Defender updates itself, the default configuration installs the fixed engine and platform with no action (MSRC, 2026-05-19); the decision is to verify, as Microsoft recommends, that engine and platform updates actually reach every host, offline and update-controlled machines first, and to hunt back on any host that ran Engine version 1.1.26030.3008 or earlier.
    Update22 May 2026 05:00 UTCrun 2026-05-22-5b90d5a1actionscvesevidencesourcesbody

    Microsoft also marks CVE-2026-45498 as exploited: a Microsoft Defender denial of service (CVSS 3.1 base score 4.0) fixed in Antimalware Platform version 4.18.26040.7 (MSRC, 2026-05-19), while CVE-2026-41091 is fixed in Malware Protection Engine version 1.1.26040.8 (MSRC, 2026-05-19). CISA added both to its Known Exploited Vulnerabilities catalog on 2026-05-20 (CISA, 2026-05-20). The Hacker News notes that the two descriptions overlap with RedSun and UnDefend, the Defender zero-days Nightmare Eclipse disclosed in April, and that Huntress has observed exploitation of both (The Hacker News, 2026-05-21).

    Correction21 Oct 2026 16:01 UTCrun 2026-10-21T1148Z-auditactionsaffected_productsbodyclassificationcvesevidenceheadlinesourcessourcing_notesummarytagstechniquestitleverification

    The two flaws are fixed by separate updates rather than one combined out-of-band release: Malware Protection Engine version 1.1.26040.8 fixes CVE-2026-41091, and Microsoft typically ships engine updates once a month or as needed (MSRC, 2026-05-19); Antimalware Platform version 4.18.26040.7 fixes CVE-2026-45498, which is a denial of service (CWE-400), not a privilege escalation (MSRC, 2026-05-19). The "Turn off routine remediation" policy named earlier only decides whether Defender remediates detected threats automatically or prompts the user (Microsoft Learn); it does not hold back engine updates, so the check is whether engine and platform updates reach each host.

    The hunt signals given earlier, junction events on Defender paths and SYSTEM processes spawned by MsMpEng.exe, have no source. The behavior observed in the wild is renamed exploit binaries staged in the user's Pictures and Downloads folders (Help Net Security, 2026-04-17) and, for RedSun, a Defender remediation of an EICAR test string whose file rewrite is redirected so that the Cloud Files infrastructure runs the attacker's binary as SYSTEM (Vectra AI, 2026-04-21). The researcher has since said CVE-2026-41091 is RedSun and CVE-2026-45498 is UnDefend (The Hacker News, 2026-05-21).

    CVE-2026-45584: Microsoft Defender heap buffer overflow gives code execution when Defender scans a malicious quarantined file

    Microsoft disclosed CVE-2026-45584 on 2026-05-19: a heap-based buffer overflow (CWE-122) in Microsoft Defender allows an unauthorized attacker to execute code over a network, scored CVSS 8.1 with high attack complexity (MSRC, 2026-05-19). Microsoft says a remote, unauthenticated attacker would have to entice a local user to take multiple actions that result in Defender scanning a malicious file that has been quarantined (MSRC, 2026-05-19). MSRC listed the flaw as neither exploited nor publicly disclosed at release (MSRC, 2026-05-19), and The Hacker News found no evidence of in-the-wild exploitation (The Hacker News, 2026-05-21). The last affected build is Malware Protection Engine version 1.1.26030.3008 and the first fixed build is Engine version 1.1.26040.8 (MSRC, 2026-05-19), the same engine release that fixes the exploited CVE-2026-41091 (The Hacker News, 2026-05-21).

    Exposure
    Defender runs on all supported versions of Windows, and System Center Endpoint Protection and Microsoft Security Essentials use the same engine; systems that have disabled Defender are not in an exploitable state, although scanners still flag their files on disk (MSRC, 2026-05-19).
    Defender takeaway
    No out-of-band step where Defender updates itself, because the default configuration keeps the engine up to date automatically (MSRC, 2026-05-19); confirm, as Microsoft recommends, that engine updates actually reach every host, offline and update-controlled machines first.
    Correction21 Oct 2026 16:03 UTCrun 2026-10-21T1148Z-auditaffected_productsbodyclassificationcvesevidenceheadlinesourcessourcing_notesummarytechniquestitlepriority

    Exploitation is not zero-click: Microsoft says a remote, unauthenticated attacker would have to entice a local user to take multiple actions that result in Defender scanning a malicious file that has been quarantined, and rates the attack complexity high (MSRC, 2026-05-19). The advisory does not say the attacker's code runs in the Defender process context. Malware Protection Engine version 1.1.26030.3008 and earlier are affected and Engine version 1.1.26040.8 fixes the flaw (MSRC, 2026-05-19).
