    Defender takeaway

    An install that ran with scripts disabled is not clean once the package has been imported; for an affected host SafeDep's order is to disconnect it, remove persistence first, rotate all credentials, check the accounts for the repositories and commits above and reinstall the operating system (SafeDep, 2026-10-27). Because the wiper is triggered by the token's revocation, the host is isolated and cleaned before the GitHub token is revoked.

    Exposure · detection
    Exposure

    Any developer endpoint, build agent or CI runner that installed or imported one of the operator's packages, and any GitHub or GitLab account whose token such a host held (SafeDep, 2026-10-27).

    Detection

    In package metadata, a binding.gyp whose sources field runs node in a package with no C or C++ sources, a postinstall that requires a .node file and discards errors beside a large high-entropy file, and prebuilt addons with no native source; on endpoints and CI runners, a node process that downloads or finds and runs the Bun runtime and a child node process started from a temporary path named after its process ID; in GitHub and GitLab audit logs, a new public repository in a developer's own account with a generic project description, commits with a fixed automated-sync message, commits that add AI-assistant configuration files (.claude, .cursor, .gemini, .vscode tasks, CLAUDE.md or AGENTS.md), an injected CI job that requests OIDC tokens, and unexpected patch releases of your own packages (SafeDep, 2026-10-27).

    NOTABLENATOB2

    testmetest: an npm worm in the Miasma and Shai-Hulud family now starts when an application imports the package, so install with --ignore-scripts no longer protects, and JFrog finds 42 third-party GitHub repositories already armed with its publisher

    SafeDep counts 19 npm packages from the same operator between 2026-10-19 and 2026-10-27, eight of them published through four npm accounts, that carry a worm sharing code with the June Miasma worm and adding the token-revocation wiper of Mini Shai-Hulud; SafeDep has not confirmed the lineage, and JFrog says its evidence does not establish that the original Miasma operators are responsible (SafeDep, 2026-10-27; JFrog Security Research, 2026-10-26). The install trigger has changed twice: first a command expansion in a binding.gyp file, with no install script; then a postinstall script that loads a native addon which decodes and starts the worm; and, since SafeDep's update of 27 October, an addon that runs when an application imports the package, so a hardening step that disables install scripts does not stop it (SafeDep, 2026-10-27).

    The payload exits on CIS locales and in known analysis sandboxes. It steals SSH keys, registry and Git credentials, .env files, browser logins, AI-tool, cloud, Vault and Kubernetes secrets and GitHub Actions secrets read from runner memory (SafeDep, 2026-10-27). It exfiltrates by committing encrypted data, with the victim's encrypted GitHub token, to a new public repository in the victim's own account, injects a GitLab CI job that requests npm and PyPI OIDC tokens, adds its loader to the victim's npm packages and publishes new patch versions, republishes to PyPI and RubyGems, commits a fake CodeQL workflow and AI-agent configuration files that infect the host again, and copies itself over SSH to the hosts in known_hosts (SafeDep, 2026-10-27). A persistence service checks the stolen GitHub token every 45 seconds for 48 hours and on an authentication failure deletes the home directory (SafeDep, 2026-10-27). JFrog found 42 armed third-party GitHub repositories of 11 legitimate owners with hooks for AI coding assistants and IDEs, and says the payload blobs were large enough to evade GitHub's search and API paths (JFrog Security Research, 2026-10-26).

    Exposure
    Any developer endpoint, build agent or CI runner that installed or imported one of the operator's packages, and any GitHub or GitLab account whose token such a host held (SafeDep, 2026-10-27).
    Detection
    In package metadata, a binding.gyp whose sources field runs node in a package with no C or C++ sources, a postinstall that requires a .node file and discards errors beside a large high-entropy file, and prebuilt addons with no native source; on endpoints and CI runners, a node process that downloads or finds and runs the Bun runtime and a child node process started from a temporary path named after its process ID; in GitHub and GitLab audit logs, a new public repository in a developer's own account with a generic project description, commits with a fixed automated-sync message, commits that add AI-assistant configuration files (.claude, .cursor, .gemini, .vscode tasks, CLAUDE.md or AGENTS.md), an injected CI job that requests OIDC tokens, and unexpected patch releases of your own packages (SafeDep, 2026-10-27).
